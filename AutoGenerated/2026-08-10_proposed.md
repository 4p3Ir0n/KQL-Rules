## 1) ClickFix / ClearFake: Suspicious command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste  
**Severity:** High  
**Purpose:** ClearFake and IClickFix lures instruct victims to paste an attacker-supplied command into the Win+R Run dialog. Windows records pasted Run commands in the Explorer RunMRU registry key, making this a high-fidelity, IOC-independent detection of the ClickFix social-engineering chain.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","msiexec","rundll32","regsvr32","wscript","cscript","conhost","forfiles","http://","https://","\\\\","FromBase64String","-enc","iex","Invoke-Expression","-w h","hidden")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Very low volume in most environments. Allowlist admin/helpdesk accounts and known internal tooling strings (e.g. \\fileserver\share UNC paths, mmc, gpupdate). Pivot on the same DeviceId in DeviceProcessEvents/DeviceNetworkEvents within +/-5 minutes to confirm payload retrieval. Consider dropping the bare 'http://' term first if browser-URL pastes are common.

## 2) ClearFake: Explorer spawning script interpreter with remote-download or encoded command line

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake infections where explorer.exe (the Run dialog or a pasted shortcut) launches an interpreter that downloads and executes a remote payload, bypassing browser-download telemetry.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","msiexec.exe","rundll32.exe","regsvr32.exe","bitsadmin.exe","certutil.exe")
| where ProcessCommandLine has_any ("http://","https://","FromBase64String","-enc","-ec ","-e ","IEX","Invoke-Expression","Invoke-WebRequest","DownloadString","DownloadFile","irm ","iwr ","-w hidden","-windowstyle h","-nop","-noni","Start-BitsTransfer","urlmon","Net.WebClient")
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, SHA256, ReportId
```

**Tuning notes:** Explorer-parented cmd.exe/powershell.exe is normal for interactive admins; scope out known admin accounts or require ProcessCommandLine to contain a URL/encoding indicator only. Add allowlist for internal software-deployment URLs and signed vendor scripts. Raise fidelity by joining to DeviceNetworkEvents for the resulting outbound connection.

## 3) IClickFix: Fake CAPTCHA / 'verification' lure strings and comment padding in command lines

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste  
**Severity:** High  
**Purpose:** IClickFix and related ClickFix kits embed decoy text ('I am not a robot', 'Ray ID', 'Verification') and long whitespace padding in the pasted command so the malicious portion scrolls out of view. Detects the lure artefact itself rather than perishable domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","conhost.exe","msiexec.exe")
| where ProcessCommandLine has_any ("not a robot","I am not a robot","captcha","reCAPTCHA","Ray ID","Verification ID","verify you are","human verification","Cloudflare Verification","Press Enter to verify","Fix it","DisplayFix")
    or ProcessCommandLine matches regex @"\s{25,}(#|::|rem\s)"
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, SHA256, ReportId
```

**Tuning notes:** Extremely low false-positive rate; the regex for whitespace-padded comments may fire on generated build scripts - allowlist by InitiatingProcessFileName (e.g. CI agents, msbuild) if needed. Extend the lure string list as new ClickFix themes appear (Teams, Zoom, Word update).

## 4) ClearFake EtherHiding: browser or script host contacting blockchain RPC / Web3 endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102 - Web Service  
**Severity:** Medium  
**Purpose:** ClearFake stores its next-stage payload in smart contracts and retrieves it via public BNB/Ethereum RPC nodes (EtherHiding). Detects hosts resolving/connecting to blockchain RPC infrastructure, especially from non-browser processes.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("bsc-dataseed","binance.org","bscrpc","cloudflare-eth.com","rpc.ankr.com","eth.llamarpc","infura.io","alchemyapi.io","g.alchemy.com","publicnode.com","web3","nodereal.io","quiknode","drpc.org")
| where InitiatingProcessFileName !in~ ("MsMpEng.exe","SenseIR.exe")
| summarize Connections=count(), UrlSample=make_set(RemoteUrl, 10), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, Connections, UrlSample
```

**Tuning notes:** Filter out legitimate crypto/wallet users and developer workstations by DeviceId or by InitiatingProcessFileName (MetaMask-hosting browsers, node.exe on dev boxes). Highest fidelity when the initiating process is powershell.exe, mshta.exe, curl.exe or an unsigned binary in AppData/Temp - add that constraint if volume is high.

## 5) ScreenConnect / ConnectWise and other RMM agent executed from user-writable path or scripted installer

**Tactic:** CommandAndControl  
**ATT&CK:** T1219 - Remote Access Software  
**Severity:** High  
**Purpose:** Campaigns in this feed abuse ConnectWise ScreenConnect and similar RMM tooling for hands-on access after ClickFix or phishing delivery. Detects RMM binaries running from Temp/Downloads/ProgramData or installed by an interpreter, browser or mail client.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("ScreenConnect.ClientService.exe","ScreenConnect.WindowsClient.exe","ConnectWiseControl.Client.exe","AnyDesk.exe","rustdesk.exe","MeshAgent.exe","atera_agent.exe","AteraAgent.exe","Syncro.exe","SRService.exe","SplashtopStreamer.exe","rutserv.exe","TeamViewer.exe","UltraViewer_Desktop.exe")
    or ProcessCommandLine has_any ("ScreenConnect.ClientSetup","connectwisecontrol","&e=Access&y=Guest","screenconnect.com/Bin")
| where FolderPath has_any (@"\appdata\local\temp", @"\appdata\roaming", @"\downloads", @"\programdata", @"\users\public", @"\windows\temp")
    or InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","msiexec.exe","rundll32.exe","curl.exe","outlook.exe","chrome.exe","msedge.exe","firefox.exe","winrar.exe","7zFM.exe")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Remove the RMM products your organisation legitimately deploys from the FileName list, or allowlist by SHA256/signer and by the deploying process (SCCM, Intune, your own RMM). Keep the Temp/Downloads condition even for sanctioned tools - legitimate agents install to Program Files.

## 6) SVG attachment written by mail client/browser followed by payload file creation

**Tactic:** InitialAccess  
**ATT&CK:** T1566.001 - Spearphishing Attachment  
**Severity:** Medium  
**Purpose:** Feed tags indicate SVG-based phishing delivery (embedded JS/HTML smuggling). Detects an .svg file landing from Outlook/browser/archive tool and a script, installer or archive being created on the same host minutes later - the smuggling-to-payload sequence.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FileName endswith ".svg"
| where InitiatingProcessFileName in~ ("outlook.exe","msedge.exe","chrome.exe","firefox.exe","brave.exe","winrar.exe","7zFM.exe","winzip32.exe","explorer.exe","olk.exe")
| where FolderPath has_any (@"\downloads", @"\appdata\local\temp", @"\content.outlook", @"\inetcache")
| project SvgTime=Timestamp, DeviceId, DeviceName, SvgFile=FileName, SvgPath=FolderPath, SvgWriter=InitiatingProcessFileName, AccountName=InitiatingProcessAccountName
| join kind=inner (
    DeviceFileEvents
    | where Timestamp > ago(1d)
    | where FileName has_any (".exe",".msi",".js",".jse",".hta",".vbs",".lnk",".zip",".rar",".iso",".ps1",".bat",".cmd")
    | where FolderPath has_any (@"\downloads", @"\appdata\local\temp", @"\appdata\roaming", @"\programdata", @"\users\public")
    | project PayloadTime=Timestamp, DeviceId, PayloadFile=FileName, PayloadPath=FolderPath, PayloadWriter=InitiatingProcessFileName, PayloadSHA256=SHA256
) on DeviceId
| where PayloadTime between (SvgTime .. SvgTime + 10m)
| project SvgTime, PayloadTime, DeviceName, DeviceId, AccountName, SvgFile, SvgPath, SvgWriter, PayloadFile, PayloadPath, PayloadWriter, PayloadSHA256
```

**Tuning notes:** Designers and marketing users legitimately download SVGs - allowlist those device groups or require the payload file to be unsigned/newly seen. Tighten the 10-minute window to 2-3 minutes to cut noise, and exclude payload writers that are software-update services (OneDrive.exe, setup hosts, MsMpEng.exe).

## 7) Vidar-style stealer touching browser credential and cookie stores

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003 - Credentials from Web Browsers  
**Severity:** High  
**Purpose:** Vidar and similar infostealers copy Chromium/Gecko credential databases (Login Data, Cookies, key4.db, logins.json, Local State) out of browser profiles. Detects those artefacts being created/copied by a process that is not a browser.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FileName in~ ("Login Data","Login Data For Account","Cookies","Web Data","Local State","key4.db","key3.db","logins.json","cert9.db","formhistory.sqlite","places.sqlite","signons.sqlite")
    or FileName in~ ("nss3.dll","freebl3.dll","mozglue.dll","softokn3.dll","msvcp140.dll","vcruntime140.dll")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","opera_gx.exe","vivaldi.exe","msedgewebview2.exe","chrome_proxy.exe","iexplore.exe","MsMpEng.exe","OneDrive.exe","backgroundTaskHost.exe","setup.exe")
| where FolderPath has_any (@"\appdata\local\temp", @"\appdata\roaming", @"\programdata", @"\users\public", @"\windows\temp", @"\downloads")
    or InitiatingProcessFolderPath has_any (@"\appdata\local\temp", @"\appdata\roaming", @"\programdata", @"\users\public", @"\windows\temp", @"\downloads")
| summarize Artifacts=make_set(FileName, 20), Paths=make_set(FolderPath, 10), FileCount=count(), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, FileCount, Artifacts, Paths
```

**Tuning notes:** Allowlist backup/DLP/browser-migration and profile-sync agents by InitiatingProcessSHA256 or signer. The DLL names catch stealers staging NSS decryption libraries next to their payload - drop them if legitimate installers in Temp create noise. Alert priority increases sharply when FileCount is high or the initiating binary is unsigned.

## 8) Non-browser process resolving C2 config from Steam/Telegram dead-drop profiles

**Tactic:** CommandAndControl  
**ATT&CK:** T1102.001 - Dead Drop Resolver  
**Severity:** High  
**Purpose:** Vidar retrieves its C2 address from attacker-controlled Steam Community profiles and Telegram channel descriptions. Detects a non-browser, non-client process fetching these dead-drop resolvers - a durable Vidar TTP independent of rotating C2 IPs.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("steamcommunity.com","t.me","telegra.ph","api.telegram.org","mastodon.social","ic3.gov") or RemoteUrl endswith "telegram.org"
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","vivaldi.exe","msedgewebview2.exe","steam.exe","steamwebhelper.exe","Telegram.exe","outlook.exe","olk.exe","teams.exe","ms-teams.exe","slack.exe")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, RemoteUrl, RemoteIP, RemotePort, ReportId
```

**Tuning notes:** Exclude enterprise proxy/inspection agents and any sanctioned chat integrations by process name. Highest confidence when InitiatingProcessFolderPath is under Temp/AppData/ProgramData or the process is unsigned; add that filter if a security or monitoring tool generates volume.

## 9) Linux shell history destruction or Atuin history tampering

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070.003 - Clear Command History  
**Severity:** Medium  
**Purpose:** Following the ISC diary on shell forensics with Atuin, this detects attackers disabling or wiping shell history (including the Atuin SQLite history store), a common anti-forensics step after interactive Linux access.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("history -c","history -d","history -w /dev/null","unset HISTFILE","HISTFILE=/dev/null","HISTFILE=\"\"","HISTSIZE=0","HISTFILESIZE=0","set +o history","export HISTCONTROL=ignorespace",".bash_history",".zsh_history",".sh_history","atuin history prune","atuin history delete","atuin store purge",".local/share/atuin/history.db")
| where FileName in~ ("bash","sh","zsh","dash","ksh","atuin","rm","shred","truncate","ln","unlink","sqlite3","export","env")
| project Timestamp, DeviceName, DeviceId, AccountName, ProcessCommandLine, FileName, FolderPath, ProcessId, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Some hardening/imaging scripts and dotfile managers legitimately touch HISTFILE settings - allowlist by InitiatingProcessCommandLine (e.g. ansible, cloud-init, packer) or by device group for build hosts. Correlate with preceding SSH logons in DeviceLogonEvents to prioritise sessions from unusual source IPs.

## 10) Web/appliance service process spawning shell or download utility (command-injection exploitation)

**Tactic:** InitialAccess  
**ATT&CK:** T1190 - Exploit Public-Facing Application  
**Severity:** High  
**Purpose:** CVE-2026-8037 in Progress LoadMaster allows unauthenticated command injection via web endpoints. Any Linux-onboarded web-facing service spawning a shell, downloader or recon binary is the generic, durable post-exploitation signal for this and similar command-injection CVEs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("httpd","apache2","nginx","lighttpd","php-fpm","php","perl","python3","java","tomcat","node","w3wp.exe","cgi-bin","webd","lighttpd-angel")
| where FileName in~ ("sh","bash","dash","zsh","curl","wget","nc","ncat","netcat","socat","python","python3","perl","chmod","chown","whoami","id","uname","busybox","crontab","openssl","base64","tftp")
| where ProcessCommandLine has_any ("-c ","http://","https://","/dev/tcp/","-e /bin/","base64","chmod +x","| sh","|sh","; ","&&","$(","`","crontab","authorized_keys","/tmp/","/dev/shm/")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessId, InitiatingProcessFileName, InitiatingProcessId, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Only fires on Defender-onboarded servers; LoadMaster appliances themselves are usually not onboarded, so pair with network/WAF telemetry for the appliance. Allowlist known CGI/health-check wrappers and deployment scripts by InitiatingProcessCommandLine. Reduce noise by dropping the generic ';' and '&&' terms first and keeping shell-spawn plus download/reverse-shell indicators.

## 11) Identity password spray: many failed authentications from one source followed by success

**Tactic:** CredentialAccess  
**ATT&CK:** T1110.003 - Password Spraying  
**Severity:** Medium  
**Purpose:** Supports the identity-front-door theme: detects a single source IP failing authentication against many distinct accounts within an hour and then succeeding on at least one, indicating a successful spray or credential-stuffing attempt against the directory.

```kusto
IdentityLogonEvents
| where Timestamp > ago(1d)
| where isnotempty(IPAddress) and isnotempty(AccountUpn)
| summarize FailedAttempts=countif(ActionType == "LogonFailed"), SuccessfulLogons=countif(ActionType == "LogonSuccess"), TargetedAccounts=dcount(AccountUpn), CompromisedAccounts=make_set_if(AccountUpn, ActionType == "LogonSuccess", 20), Applications=make_set(Application, 10), LogonTypes=make_set(LogonType, 10), FailureReasons=make_set(FailureReason, 10), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by IPAddress, bin(Timestamp, 1h)
| where FailedAttempts >= 20 and TargetedAccounts >= 10 and SuccessfulLogons >= 1
| project FirstSeen, LastSeen, IPAddress, FailedAttempts, SuccessfulLogons, TargetedAccounts, CompromisedAccounts, Applications, LogonTypes, FailureReasons
```

**Tuning notes:** Baseline thresholds per environment - large NAT egress IPs, VPN concentrators and legacy service accounts will trip 20/10 easily; allowlist those IPs or raise thresholds. Exclude known scanner/pentest sources. For internal-only visibility, mirror the same logic against DeviceLogonEvents with RemoteIP and FailureReason.
