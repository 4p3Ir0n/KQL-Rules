## 1) ClickFix: Command Written to Explorer RunMRU (Fake CAPTCHA Paste-and-Run)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake/ClickFix social engineering instructs victims to paste an attacker-supplied command into the Windows Run dialog. Every such paste is recorded in the Explorer RunMRU registry key, making it a high-fidelity, IOC-independent detection of the initial execution step.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where isnotempty(RegistryValueData)
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","msiexec","wscript","cscript","rundll32","regsvr32","conhost","forfiles","http://","https://","\\\\","-enc","-w h","IEX","Invoke-","FromBase64String","cmd /c","cmd.exe /c")
| extend PastedCommand = RegistryValueData
| project Timestamp, DeviceId, DeviceName, AccountName = InitiatingProcessAccountName, RegistryKey, RegistryValueName, PastedCommand, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Legitimate admin use of the Run dialog (e.g. 'cmd', 'powershell' with no arguments, \\server\share UNC browsing) will fire; consider requiring RegistryValueData length > 40 or the presence of a URL/base64 token. Allowlist known IT admin accounts and jump hosts. RunMRU values end with '\1' - strip before triage.

## 2) Interpreter or LOLBin Spawned Directly by explorer.exe with Download/Hidden Flags

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** ClearFake, ClickFix and similar paste-and-run chains cause explorer.exe (Run dialog / clipboard paste) to spawn an interpreter or LOLBin that pulls a stage-2 payload. Detects the execution behaviour regardless of the rotating ClearFake domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe","conhost.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","certutil.exe","bitsadmin.exe","msiexec.exe","rundll32.exe","regsvr32.exe","installutil.exe","forfiles.exe")
| where ProcessCommandLine has_any ("http://","https://","-enc","-EncodedCommand","FromBase64String","IEX","Invoke-Expression","Invoke-WebRequest","DownloadString","DownloadFile","-w hidden","-WindowStyle Hidden","-nop","-ep bypass","ExecutionPolicy Bypass","/urlcache","Start-BitsTransfer","webclient","curl ","msiexec /i http","Add-MpPreference")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Software-deployment shortcuts and admin-launched scripts from Explorer are the main FPs; allowlist by signed script paths, specific SCCM/Intune wrapper command lines, and known helpdesk accounts. Tighten by requiring both a URL and a hidden/bypass flag if volume is high.

## 3) Blockchain RPC / EtherHiding C2 Contacted by Non-Browser Process

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** High  
**Purpose:** ClearFake (EtherHiding) and the Aeternum loader retrieve payloads and C2 instructions from smart contracts on BNB Smart Chain / Polygon via public JSON-RPC endpoints. Scripting engines or unsigned binaries talking to blockchain RPC providers is a strong, durable C2 signal.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("bsc-dataseed","binance.org","polygon-rpc","maticvigil","rpc.ankr.com","cloudflare-eth","infura.io","alchemyapi","g.alchemy.com","llamarpc","publicnode.com","drpc.org","quiknode","quicknode","blastapi.io","nodereal.io","blockpi.network","1rpc.io","onfinality.io")
    or RemoteUrl has_any ("api.bscscan.com","api.polygonscan.com","api.etherscan.io")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","iexplore.exe","msedgewebview2.exe")
| summarize Connections = count(), Urls = make_set(RemoteUrl, 10), RemoteIPs = make_set(RemoteIP, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, Connections, Urls, RemoteIPs
```

**Tuning notes:** Allowlist legitimate crypto wallets/dev tooling (MetaMask desktop, Ledger Live, node.exe in developer repos, Docker) per host or per account. If browsers must be included for EtherHiding via compromised sites, run a separate variant scoped to browser child-process creation instead. RemoteUrl is only populated when URL inspection is available; consider joining known RPC IP ranges as a fallback.

## 4) Browser Credential and Cookie Store Access by Process Running from Temp/AppData (Vidar-style Stealer)

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003  
**Severity:** High  
**Purpose:** Vidar and similar infostealers copy or read browser credential databases, cookie stores and wallet files shortly after execution from a user-writable directory. Detects the collection behaviour rather than the rotating C2 domains/hashes.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FileName in~ ("Login Data","Login Data For Account","Web Data","Cookies","Network Action Predictor","Local State","key4.db","key3.db","logins.json","cookies.sqlite","formhistory.sqlite","wallet.dat")
    or FolderPath has_any ("\\Local Extension Settings\\", "\\Exodus\\exodus.wallet", "\\Ethereum\\keystore")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","iexplore.exe","msedgewebview2.exe","MsMpEng.exe","backup.exe")
| where InitiatingProcessFolderPath has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\Users\\Public\\","\\Windows\\Temp\\","\\Downloads\\","\\ProgramData\\")
    or InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe")
| summarize TargetedFiles = dcount(FolderPath), Files = make_set(FolderPath, 15), Actions = make_set(ActionType, 5), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName
| where TargetedFiles >= 3
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName, TargetedFiles, Files, Actions
```

**Tuning notes:** Backup agents, browser migration tools, DLP/forensics agents and password-manager importers are typical FPs - allowlist by InitiatingProcessSHA256 or signer. Lower the TargetedFiles threshold to 1 for high-value hosts, or raise it if noisy. Pair with DeviceFileEvents writes of archives (.zip/.rar) in Temp for stronger confirmation.

## 5) Autorun Registry Value Pointing to User-Writable Path (PureRAT/Loader Persistence)

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** Medium  
**Purpose:** PureRAT/PureHVNC and most commodity loaders persist by writing a Run/RunOnce value that references a payload in AppData, ProgramData, Temp or Public, often via a script host. Detects the persistence step independent of file hashes.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Policies\Explorer\Run", @"\Windows NT\CurrentVersion\Winlogon")
| where RegistryValueData has_any ("\\AppData\\Roaming\\","\\AppData\\Local\\Temp\\","\\AppData\\Local\\","\\ProgramData\\","\\Users\\Public\\","\\Windows\\Temp\\","\\Downloads\\")
    or RegistryValueData has_any ("powershell","pwsh","mshta","wscript","cscript","rundll32","regsvr32","cmd /c","FromBase64String","-enc","-w hidden")
| project Timestamp, DeviceId, DeviceName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Many legitimate user-scope apps (Teams, OneDrive, Slack, Spotify, Zoom updaters, GPU utilities) install into AppData - build an allowlist of RegistryValueName/RegistryValueData pairs and signed InitiatingProcessSHA256 values. Highest fidelity when the initiating process itself runs from Temp or is a script host.

## 6) Remote Monitoring Tool (ScreenConnect/ConnectWise-class) Launched from Temp or Spawned by Browser/Mail Client

**Tactic:** CommandAndControl  
**ATT&CK:** T1219  
**Severity:** High  
**Purpose:** ClickFix and DocuSign-themed lures deliver ConnectWise ScreenConnect and similar RMM clients as an initial remote-access foothold. Detects unauthorized RMM execution based on path and parent lineage rather than IOCs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName has_any ("ScreenConnect","ConnectWiseControl","AnyDesk","TeamViewer","atera","AteraAgent","splashtop","SRService","rustdesk","MeshAgent","Supremo","LogMeIn","GoToAssist","Syncro","ngrok","tacticalrmm","Action1","PDQ","dwagent")
    or ProcessCommandLine has_any ("e=Access&y=Guest","&p=&s=&k=","screenconnect.windowsclient","relay.screenconnect.com","instance-")
| where FolderPath has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\Users\\Public\\","\\Downloads\\","\\Windows\\Temp\\","\\ProgramData\\")
    or InitiatingProcessFileName in~ ("chrome.exe","msedge.exe","firefox.exe","outlook.exe","winrar.exe","7zfm.exe","explorer.exe","mshta.exe","powershell.exe","wscript.exe","msiexec.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Critical to allowlist the RMM products your IT/MSP legitimately uses, including their normal install paths and installer parents (msiexec launched by SCCM/Intune). If a sanctioned tool is also abused, pivot on unexpected relay hostnames or instance IDs in ProcessCommandLine instead of removing the tool from the list.

## 7) Inhibit System Recovery: Shadow Copy, Backup Catalog and Boot Recovery Tampering

**Tactic:** Impact  
**ATT&CK:** T1490  
**Severity:** Critical  
**Purpose:** DeadLock and virtually all human-operated ransomware destroy shadow copies, backup catalogs and Windows recovery options immediately before or during encryption. Detects the pre-encryption destructive stage in time to contain.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (FileName in~ ("vssadmin.exe","diskshadow.exe") and ProcessCommandLine has_any ("delete shadows","resize shadowstorage","delete shadowstorage"))
    or (FileName =~ "wmic.exe" and ProcessCommandLine has "shadowcopy" and ProcessCommandLine has "delete")
    or (FileName =~ "bcdedit.exe" and ProcessCommandLine has_any ("recoveryenabled no","recoveryenabled off","bootstatuspolicy ignoreallfailures"))
    or (FileName =~ "wbadmin.exe" and ProcessCommandLine has_any ("delete catalog","delete systemstatebackup","delete backup"))
    or (FileName in~ ("powershell.exe","pwsh.exe") and ProcessCommandLine has_any ("Win32_ShadowCopy","Remove-ComputerRestorePoint","Disable-ComputerRestore","Get-WmiObject Win32_Shadowcopy"))
    or (FileName =~ "reagentc.exe" and ProcessCommandLine has "/disable")
    or (FileName =~ "net.exe" and ProcessCommandLine has_all ("stop","vss"))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Backup software (Veeam, Acronis, Commvault) and imaging/OSD tasks legitimately resize or delete shadow storage - allowlist those specific parent processes and service accounts. Escalate to Critical when the initiating process runs from Temp/ProgramData, is unsigned, or when multiple distinct techniques fire on one host within minutes.

## 8) Mass File Encryption Behaviour: High-Volume Rename to Uniform Extension by Single Process

**Tactic:** Impact  
**ATT&CK:** T1486  
**Severity:** Critical  
**Purpose:** Detects the encryption stage of DeadLock's Rust encryptor and other ransomware by identifying a single process renaming or creating files with one uniform new extension across many directories in a short window.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileRenamed","FileModified","FileCreated")
| where isnotempty(FileName) and FileName contains "."
| extend NewExt = tolower(tostring(split(FileName, ".")[-1]))
| where strlen(NewExt) between (3 .. 12)
| where NewExt !in ("exe","dll","tmp","log","txt","docx","xlsx","pptx","pdf","png","jpg","jpeg","zip","json","xml","db","dat","bak","ini","lnk","cache","pst","ost","iso","vhdx","mp4","csv","msi","pyc")
| summarize AffectedFiles = dcount(FolderPath), Folders = dcount(strcat_array(array_slice(split(FolderPath, "\\"), 0, -2), "\\")), Sample = make_set(FolderPath, 8), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, NewExt, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessId, InitiatingProcessSHA256, InitiatingProcessAccountName
| where AffectedFiles >= 200 and Folders >= 5
| project FirstSeen, LastSeen, DeviceId, DeviceName, NewExt, AffectedFiles, Folders, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName, Sample
```

**Tuning notes:** Tune AffectedFiles/Folders thresholds per environment (file servers need higher; laptops lower). Add extensions produced by legitimate bulk tooling (build artifacts, media transcoders, backup .vbk/.spf chunks) to the exclusion list, and allowlist known compression/encryption agents by SHA256. Consider running at 15-30 minute intervals for containment speed.

## 9) Ransom Note Dropped Across Multiple Directories

**Tactic:** Impact  
**ATT&CK:** T1486  
**Severity:** High  
**Purpose:** Double-extortion operations such as DeadLock write a ransom note with recovery/negotiation instructions into every encrypted directory. Repeated identical note filenames across many folders is a reliable, extension-independent encryption indicator.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileRenamed")
| where FileName endswith ".txt" or FileName endswith ".hta" or FileName endswith ".html" or FileName endswith ".htm"
| where FileName has_any ("readme","read_me","read-me","how_to","howto","how-to-decrypt","decrypt","restore","recover","unlock","ransom","yourfiles","your_files","deadlock","!!!")
| summarize NoteCount = dcount(FolderPath), DistinctNames = make_set(FileName, 5), SampleFolders = make_set(FolderPath, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName, bin(Timestamp, 1h)
| where NoteCount >= 5
| project FirstSeen, LastSeen, DeviceId, DeviceName, NoteCount, DistinctNames, SampleFolders, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName
```

**Tuning notes:** Software distributions containing many README.txt files (dev repos, package caches, sync clients) are the main FP source - exclude \node_modules\, \.git\, package manager caches, and allowlist git.exe/msiexec.exe/setup installers. Raise NoteCount for build servers.
