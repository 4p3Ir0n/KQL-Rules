## 1) ClickFix / ClearFake: Command written to Explorer RunMRU (paste-and-run social engineering)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake/ClickFix lures instruct victims to paste an attacker-supplied command into the Windows Run dialog. Every Run-dialog execution is recorded in the Explorer RunMRU registry key, making it a durable, high-fidelity artifact of the technique regardless of the delivery domain or payload hash.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"CurrentVersion\Explorer\RunMRU"
| where isnotempty(RegistryValueData)
| where RegistryValueData has_any ("powershell","pwsh","mshta","cmd.exe /c","cmd /c","curl ","certutil","bitsadmin","msiexec","rundll32","regsvr32","wscript","cscript","conhost","forfiles","FromBase64String","IEX","Invoke-","http://","https://","\\\\")
| project Timestamp, DeviceName, DeviceId, AccountDomain, AccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Baseline legitimate admin Run-dialog usage per user (e.g. 'cmd', 'mmc', UNC share paths used by help desk). Consider suppressing entries where RegistryValueData only contains an internal UNC prefix. Raise severity when the value contains base64, 'hidden', or an external URL. Pair with detection #2 for confirmed execution.

## 2) Script interpreter spawned directly by explorer.exe with download/hidden-window arguments (ClickFix chain)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake lures where the pasted command runs as a direct child of explorer.exe (Run dialog, clipboard paste, or fake CAPTCHA) and immediately downloads or decodes a second stage.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe","conhost.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","msiexec.exe","bitsadmin.exe","certutil.exe")
| where ProcessCommandLine has_any ("-w hidden","-windowstyle hidden","-ep bypass","-executionpolicy bypass","-nop","-noprofile","-enc","-encodedcommand","frombase64string","iwr ","invoke-webrequest","invoke-expression","iex(","iex ","downloadstring","downloadfile","start-bitstransfer","http://","https://","mshta ","-urlcache","/transfer")
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessIntegrityLevel, SHA256, ReportId
```

**Tuning notes:** Exclude signed internal deployment/helpdesk scripts and known software-update shortcuts launched from Explorer. In developer-heavy environments allowlist specific parent shortcut paths or specific script URLs. Correlate within 5 minutes of a RunMRU write (detection #1) or of browser activity to a newly-seen domain to reduce false positives.

## 3) ClearFake EtherHiding: script host or LOLBin contacting blockchain RPC endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** Medium  
**Purpose:** ClearFake's EtherHiding technique retrieves payload/C2 configuration from smart contracts on public chains via RPC gateways. Script interpreters or LOLBins talking to blockchain RPC infrastructure is anomalous on endpoints and survives IOC rotation.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","rundll32.exe","regsvr32.exe","node.exe","cmd.exe")
| where RemoteUrl has_any ("bsc-dataseed","binance.org","bscrpc","cloudflare-eth","eth-mainnet","infura","alchemyapi","ankr.com","publicnode.com","web3","rpc.","quicknode","drpc.org")
| project Timestamp, DeviceName, DeviceId, AccountName, RemoteUrl, RemoteIP, RemotePort, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Allowlist developer/blockchain workstations and legitimate node.exe-based crypto tooling by device group or signed application path. Extend the RemoteUrl list as new public RPC gateways appear. Blockchain traffic from browsers is expected and intentionally excluded.

## 4) Vidar-style dead-drop resolver: non-browser process contacting Telegram/Steam/social profile pages

**Tactic:** CommandAndControl  
**ATT&CK:** T1102.001  
**Severity:** Medium  
**Purpose:** Vidar and related stealers retrieve their real C2 address from a hardcoded dead-drop profile (Telegram channel, Steam community profile, Mastodon/social bio). Detecting non-browser processes fetching these pages catches the family independently of rotating C2 IOCs.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("t.me/","telegram.me/","steamcommunity.com/profiles","steamcommunity.com/id","mastodon.social/@","ok.ru/profile","pastebin.com/raw","ip-api.com","api.ipify.org")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","iexplore.exe","msedgewebview2.exe","telegram.exe","steam.exe","steamwebhelper.exe")
| project Timestamp, DeviceName, DeviceId, AccountName, RemoteUrl, RemoteIP, RemotePort, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, ReportId
```

**Tuning notes:** Allowlist approved chat/game clients and monitoring agents that legitimately query ip-api/ipify. Highest confidence when the initiating process runs from %TEMP%, %APPDATA%, or Downloads — join with DeviceProcessEvents on InitiatingProcessId for lineage before alerting broadly.

## 5) Cobalt Strike sacrificial process: LOLBin launched with no command-line arguments

**Tactic:** DefenseEvasion  
**ATT&CK:** T1055  
**Severity:** High  
**Purpose:** Cobalt Strike's default spawnto/post-ex behavior starts a suspended sacrificial process (rundll32.exe, dllhost.exe, werfault.exe, gpupdate.exe) with no arguments and injects the post-exploitation DLL. Legitimate launches of these binaries almost always carry arguments.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("rundll32.exe","dllhost.exe","werfault.exe","gpupdate.exe","searchprotocolhost.exe","wusa.exe","sysprep.exe")
| where ProcessCommandLine matches regex @'(?i)^\"?([a-z]:\\[^\"]*\\)?(rundll32|dllhost|werfault|gpupdate|searchprotocolhost|wusa|sysprep)\.exe\"?\s*$'
| where InitiatingProcessFileName !in~ ("services.exe","wininit.exe","smss.exe")
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, FolderPath, ProcessCommandLine, ProcessId, ProcessIntegrityLevel, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessId, SHA256, ReportId
```

**Tuning notes:** werfault.exe and dllhost.exe occasionally launch argument-free from svchost/WerSvc — baseline per parent process and exclude the noisiest legitimate parent pairs. Strong escalation signals: parent is Office/browser/script host, parent runs from a user-writable path, or the child later makes outbound connections (join DeviceNetworkEvents on ProcessId/DeviceId).

## 6) MpCmdRun.exe abused as download proxy or to disable Defender definitions

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218  
**Severity:** High  
**Purpose:** Loaders referenced in fresh IOC tagging abuse the signed Microsoft Defender CLI (MpCmdRun.exe) to download payloads (-DownloadFile) or to remove signatures (-RemoveDefinitions), evading application control and AV.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "MpCmdRun.exe" or ProcessCommandLine has "MpCmdRun"
| where ProcessCommandLine has_any ("-DownloadFile","-url","-RemoveDefinitions","-DisableIfNeeded","-ValidateMapsConnection","-AddDynamicSignature","-RestoreDefaults")
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, FolderPath, ProcessCommandLine, ProcessIntegrityLevel, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Exclude scheduled maintenance from platform update tooling (SCCM/Intune) invoking -SignatureUpdate only. Any -DownloadFile with -url or -RemoveDefinitions outside a documented change window should be treated as malicious. Also review copies of MpCmdRun.exe running from non-Defender directories (FolderPath not under Program Files\Windows Defender or ProgramData\Microsoft\Windows Defender).

## 7) DLL side-loading: unsigned DLL loaded from user-writable directory alongside relocated signed EXE

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.002  
**Severity:** Medium  
**Purpose:** Detects the DLL-sideloading pattern flagged in current loader/Mythic/Covenant tooling: a legitimate signed executable is copied into %TEMP%/%APPDATA%/ProgramData together with a malicious DLL of the expected name, which is then loaded from the same directory.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FileName endswith ".dll"
| where FolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\Downloads\", @"\ProgramData\")
| where InitiatingProcessFolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\Downloads\", @"\ProgramData\")
| extend DllDir = tolower(substring(FolderPath, 0, strlen(FolderPath) - strlen(FileName)))
| extend ProcDir = tolower(substring(InitiatingProcessFolderPath, 0, strlen(InitiatingProcessFolderPath) - strlen(InitiatingProcessFileName)))
| where DllDir == ProcDir
| where InitiatingProcessFileName !in~ ("msiexec.exe","setup.exe","teams.exe","onedrive.exe","slack.exe","code.exe","chrome.exe","msedge.exe","firefox.exe","squirrel.exe","update.exe")
| summarize LoadedDlls = make_set(FileName, 25), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName, DllDir
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, DllDir, LoadedDlls
```

**Tuning notes:** Installers, Electron/Squirrel apps and self-extracting archives generate volume here — extend the InitiatingProcessFileName allowlist for your standard software estate and consider excluding folders matching a temp-installer pattern. Prioritize cases where the executable is a Microsoft/known-vendor signed binary relocated out of Program Files, and where the DLL name matches a common sideload target (version.dll, dbghelp.dll, wintrust.dll, textinputframework.dll, msvcr100.dll).

## 8) Java/web application server (Metabase, Tomcat) spawning OS command shell

**Tactic:** InitialAccess  
**ATT&CK:** T1190  
**Severity:** Critical  
**Purpose:** Post-exploitation of internet-facing app vulnerabilities such as the Metabase pre-auth SQL injection (CVE-2026-72898) typically manifests as the JVM or web server process spawning a shell, discovery command, or downloader on the host.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("java.exe","javaw.exe","java","tomcat.exe","tomcat9.exe","node.exe","w3wp.exe","httpd.exe","nginx.exe") or InitiatingProcessCommandLine has_any ("metabase.jar","metabase","catalina")
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","bash","sh","dash","curl","curl.exe","wget","certutil.exe","bitsadmin.exe","whoami.exe","whoami","net.exe","net1.exe","nltest.exe","schtasks.exe","reg.exe","rundll32.exe","python.exe","python3","perl")
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, FolderPath, ProcessCommandLine, ProcessIntegrityLevel, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessId, SHA256, ReportId
```

**Tuning notes:** Application servers that legitimately shell out (build agents, CI runners, monitoring plugins) must be allowlisted by device or by exact child command line. Focus first on internet-facing Metabase/Tomcat hosts. Follow-on triage: check for new files written by the JVM and for outbound connections from the spawned child within minutes.

## 9) Medium/low integrity process spawning a SYSTEM-integrity child (kernel LPE exploitation, e.g. AFD.sys CVE-2026-68820)

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1068  
**Severity:** High  
**Purpose:** Exploitation of local kernel elevation flaws such as the Windows Ancillary Function Driver for WinSock use-after-free typically results in a normal user-integrity process launching a SYSTEM-integrity child (token theft / stolen-token shell), without passing through a legitimate elevation broker.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessIntegrityLevel =~ "System"
| where InitiatingProcessIntegrityLevel in~ ("Medium","Low","Untrusted")
| where InitiatingProcessFileName !in~ ("services.exe","svchost.exe","wininit.exe","smss.exe","csrss.exe","lsass.exe","winlogon.exe","consent.exe","taskhostw.exe","msiexec.exe","trustedinstaller.exe","tiworker.exe","searchindexer.exe","wuauclt.exe","ccmexec.exe","sensendr.exe","mssense.exe")
| where AccountName in~ ("system","local service","network service") or AccountSid startswith "S-1-5-18"
| project Timestamp, DeviceName, DeviceId, AccountName, AccountSid, FileName, FolderPath, ProcessCommandLine, ProcessIntegrityLevel, ProcessTokenElevation, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessIntegrityLevel, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Baseline your management/EDR/patching agents and any in-house service-installer utilities and add them to the parent allowlist. Highest fidelity when the parent runs from a user-writable directory (Temp, AppData, Downloads) or is an interpreter (powershell.exe, cmd.exe, python.exe); consider splitting into a high-severity variant with that condition and a low-severity hunting variant without it.
