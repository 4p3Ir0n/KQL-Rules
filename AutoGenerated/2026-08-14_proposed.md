## 1) ClickFix / ClearFake: Command Pasted Into Windows Run Dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake and IClickFix social-engineering lures instruct the victim to paste an attacker-supplied command into the Windows Run dialog (Win+R). Windows records the pasted string under Explorer\RunMRU, giving a durable, high-fidelity artifact of ClickFix execution regardless of the payload domain or hash.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where ActionType in ("RegistryValueSet", "RegistryValueCreated")
| where RegistryValueData has_any ("powershell", "pwsh", "cmd.exe", "cmd /c", "mshta", "curl", "msiexec", "conhost", "rundll32", "certutil", "bitsadmin", "FromBase64String", "iwr ", "irm ", "Invoke-Expression", "IEX", "DavWWWRoot", "@SSL", "http://", "https://", "-w h", "-windowstyle hidden", "-enc")
| project Timestamp, DeviceName, InitiatingProcessAccountUpn, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, ReportId
| order by Timestamp desc
```

**Tuning notes:** Legitimate admin use of Run for \\server\share or mmc is common — allowlist internal UNC prefixes and known admin accounts. RunMRU values ending in a single letter suffix (e.g. \"cmd\\1\") are normal formatting; do not filter on that. Consider raising severity when RegistryValueData contains base64 blobs (>100 chars) or hidden-window switches.

## 2) Explorer-Spawned Script Interpreter With Download/Obfuscation Switches (ClickFix Chain)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the post-paste stage of ClearFake/IClickFix ClickFix lures: explorer.exe directly spawning powershell/cmd/mshta/curl/msiexec with hidden windows, base64, or remote download arguments. This targets the TTP rather than the 600+ perishable ClearFake domains and hashes.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "bitsadmin.exe", "certutil.exe")
| where ProcessCommandLine has_any ("-w hidden", "-windowstyle h", "-nop", "-noprofile", "-enc", "-e JAB", "FromBase64String", "Invoke-Expression", "IEX", "DownloadString", "DownloadFile", "iwr ", "irm ", "Invoke-WebRequest", "http://", "https://", "DavWWWRoot", "@SSL", "-urlcache", "/transfer", "Start-Process", "conhost --headless")
| project Timestamp, DeviceName, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, ProcessId, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Shortcut-driven admin scripts and software deployment tooling launched from Explorer can hit this; allowlist specific script paths and signed internal .lnk targets. Tighten by requiring an external RemoteUrl in a following DeviceNetworkEvents join if volume is high in VDI environments.

## 3) WebDAV UNC Payload Execution (ClearFake / HijackLoader Delivery)

**Tactic:** CommandAndControl  
**ATT&CK:** T1105  
**Severity:** High  
**Purpose:** ClearFake and related loaders (tagged WebDAV, DomainShadowing) stage payloads on remote WebDAV shares and execute them via UNC paths such as \\host@SSL\DavWWWRoot\ or search-ms: handlers, bypassing mark-of-the-web and download telemetry.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("DavWWWRoot", "@SSL", "@80", "@8080", "search-ms:", "searchConnectorDescription", "webdav")
   or InitiatingProcessCommandLine has_any ("DavWWWRoot", "@SSL", "search-ms:")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "mshta.exe", "rundll32.exe", "regsvr32.exe", "wscript.exe", "cscript.exe", "msiexec.exe", "explorer.exe", "curl.exe", "net.exe", "forfiles.exe")
   or FolderPath startswith @"\\"
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Organisations using SharePoint/OneDrive WebDAV mapping legitimately will generate hits — allowlist your tenant hostnames (e.g. *.sharepoint.com) in the command line. Executables actually running from a \\ path (FolderPath startswith \\\\) with a non-corporate host are the strongest signal.

## 4) Browser Credential / Cookie Store Copied by Non-Browser Process (Vidar Stealer)

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003  
**Severity:** High  
**Purpose:** Vidar and similar infostealers copy browser credential and cookie databases (Login Data, key4.db, logins.json, cookies.sqlite, Local State) into a staging folder before exfiltration. Detects the file-staging behaviour independent of the rotating Vidar hashes and C2 domains.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileModified", "FileRenamed")
| where FileName in~ ("Login Data", "Login Data For Account", "Web Data", "Cookies", "Local State", "key4.db", "key3.db", "logins.json", "cookies.sqlite", "formhistory.sqlite", "signons.sqlite", "wallet.dat")
   or FileName matches regex @"(?i)^(Login Data|Cookies).*\.(db|sqlite|tmp|bak)$"
| where not(InitiatingProcessFileName in~ ("chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "opera_gx.exe", "vivaldi.exe", "msedgewebview2.exe", "backgroundtaskhost.exe"))
| where not(InitiatingProcessFolderPath has_any (@"\Program Files\", @"\Program Files (x86)\") and InitiatingProcessFileName endswith ".exe" and FolderPath has @"\User Data\")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Backup agents, browser-migration tools, EDR/DLP scanners and profile-roaming solutions will copy these files — allowlist by InitiatingProcessSHA256 / signer. Highest fidelity when the initiating process runs from %TEMP%, %APPDATA%, C:\ProgramData or C:\Users\Public, or when the destination folder is outside the browser profile tree.

## 5) Payload Self-Deletion via Timeout/Ping Then Delete (Vidar / Loader Cleanup)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070.004  
**Severity:** Medium  
**Purpose:** Vidar and HijackLoader-style loaders terminate by spawning cmd.exe with a delay (timeout/ping/choice) followed by deletion of their own executable and staging directory, erasing forensic evidence after credential theft.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe")
| where ProcessCommandLine has_any ("timeout", "ping 127.0.0.1", "ping -n", "choice /t", "Start-Sleep")
| where ProcessCommandLine has_any ("del ", "erase ", "rmdir ", "rd /s", "Remove-Item", "/f /q")
| where InitiatingProcessFolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
   or ProcessCommandLine has_any (@"\AppData\Local\Temp\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\")
| project Timestamp, DeviceName, AccountName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Legitimate installers/uninstallers (MSI custom actions, Squirrel/Electron updaters) use this pattern from %TEMP% — allowlist known installer SHA256s and vendor folder names. Correlate with a preceding credential-store access or outbound connection from the same InitiatingProcessId to reduce noise.

## 6) Potentially Suspicious Mofcomp Execution (Sigma Translation)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218  
**Severity:** Medium  
**Purpose:** Faithful Defender XDR translation of Sigma rule 1dd05363: mofcomp.exe launched by a shell/script host or referencing a user-writable path, which indicates an attacker compiling a malicious MOF into the WMI repository for stealthy execution/persistence.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "mofcomp.exe" or ProcessVersionInfoOriginalFileName =~ "mofcomp.exe"
| where InitiatingProcessFileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wsl.exe", "wscript.exe", "cscript.exe")
   or ProcessCommandLine has_any (@"\AppData\Local\Temp", @"\Contacts\", @"\Favorites\", @"\Favourites\", @"\Music\", @"\Pictures\", @"\Users\Public\", @"\Videos\", @"\WINDOWS\Temp\", "%appdata%", "%temp%", "%tmp%")
| where not(InitiatingProcessFolderPath =~ @"C:\Windows\System32\wbem\WmiPrvSE.exe" and ProcessCommandLine has @"C:\Windows\TEMP\" and ProcessCommandLine endswith ".mof")
| where not(InitiatingProcessFileName =~ "InstallUtil.exe" and InitiatingProcessCommandLine has_all ("/Uninstall", @"C:\Windows\CCM\Microsoft.ConfigurationManager.SVProvider.dll") and ProcessCommandLine has_all (@"C:\Windows\TEMP", ".tmp"))
| where isnotempty(InitiatingProcessCommandLine)
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** SCCM/ConfigMgr and some hardware vendor agents legitimately compile MOFs from C:\Windows\TEMP — the two Sigma filters cover the common cases; extend with your management agent parent paths. Always retrieve and review the referenced .mof file content during triage.

## 7) Windows Firewall Allow Rule Added for Binary in Suspicious Path (Sigma Translation)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1562.004  
**Severity:** Medium  
**Purpose:** Defender-native equivalent of Sigma rule cde0a575 (firewall-as EventIDs 2004/2071/2097): detects new Windows Firewall allow rules whose application path lives in a user-writable/staging directory, a common step before attacker C2 or lateral-movement listeners.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"SharedAccess\Parameters\FirewallPolicy\FirewallRules"
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where isnotempty(RegistryValueData)
| where RegistryValueData has "Action=Allow"
| where RegistryValueData has_any (@"C:\PerfLogs\", @"C:\Temp\", @"C:\Tmp\", @"C:\Users\Public\", @"C:\Windows\Tasks\", @"C:\Windows\Temp\", @"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\Downloads\", @"C:\ProgramData\")
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RegistryKey, RegistryValueName, RegistryValueData, ReportId
| order by Timestamp desc
```

**Tuning notes:** Some legitimate agents install to C:\ProgramData — allowlist by vendor subfolder or by InitiatingProcessSHA256 (e.g. Defender platform, SCCM, backup agents). Pair with a companion query on DeviceProcessEvents for 'netsh advfirewall firewall add rule' and 'New-NetFirewallRule' to catch command-line rule creation.

## 8) DLL Side-Loading: Recently Written DLL Loaded From User-Writable Directory

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.002  
**Severity:** High  
**Purpose:** HijackLoader and the DLL-sideloading loaders in the fresh unknown-malware cluster drop a renamed legitimate EXE plus a malicious DLL into %APPDATA%/ProgramData/Temp and load the DLL by proxy. Detects DLLs loaded from user-writable paths that were created on the same host within the hunting window.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FileName endswith ".dll"
| where FolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| where InitiatingProcessFolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| join kind=inner (
    DeviceFileEvents
    | where Timestamp > ago(1d)
    | where ActionType in ("FileCreated", "FileRenamed", "FileModified")
    | where FileName endswith ".dll"
    | project DeviceId, SHA256, DllWriteTime = Timestamp, DllWrittenBy = InitiatingProcessFileName, DllWriterCmd = InitiatingProcessCommandLine
) on DeviceId, SHA256
| where DllWriteTime <= Timestamp
| project Timestamp, DeviceName, InitiatingProcessAccountName, LoadedDll = FolderPath, DllName = FileName, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, DllWriteTime, DllWrittenBy, DllWriterCmd, ReportId
| order by Timestamp desc
```

**Tuning notes:** Electron apps, Teams/Slack/Zoom updaters and .NET JIT/NGEN artifacts legitimately load freshly written DLLs from %LOCALAPPDATA% — allowlist by parent process signer/product name and by known app folder names. Prioritise cases where the loading EXE is a Microsoft-signed binary residing outside System32 (classic sideload host such as msdtc.exe, wersetup, or a renamed rundll32).

## 9) SYSTEM Process Spawned by Medium-Integrity Process From User-Writable Path (Kernel LPE Exploitation)

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1068  
**Severity:** High  
**Purpose:** Post-exploitation signal for local kernel privilege-escalation bugs such as CVE-2026-68820 (AFD.sys use-after-free): an unprivileged, user-path binary suddenly parents a process running as SYSTEM. The exploit itself is not directly observable, but the resulting integrity jump is.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessIntegrityLevel =~ "System"
| where AccountSid == "S-1-5-18" or AccountName in~ ("system", "local service", "network service")
| where InitiatingProcessIntegrityLevel in~ ("Medium", "Low", "Untrusted")
| where InitiatingProcessFolderPath has_any (@"\Users\", @"\AppData\", @"\ProgramData\", @"\Windows\Temp\", @"\PerfLogs\", @"\Downloads\", @"\Public\")
| where not(InitiatingProcessFileName in~ ("msiexec.exe", "setup.exe", "consent.exe"))
| project Timestamp, DeviceName, AccountName, AccountSid, FileName, FolderPath, ProcessCommandLine, ProcessIntegrityLevel, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessIntegrityLevel, InitiatingProcessAccountName, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Software installers/updaters that hand off to a SYSTEM service can appear — allowlist by InitiatingProcessSHA256/signer and by known updater paths (e.g. Chrome/Edge update, Zoom, Nvidia). Investigate any hit where the child is cmd.exe/powershell.exe or where the parent was written to disk in the last few hours; correlate with recent afd.sys-related crash or DeviceEvents exploit-protection telemetry.

## 10) Metabase / Java Application Server Spawning OS Shell (Web Exploitation Follow-On)

**Tactic:** InitialAccess  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** CVE-2026-72898 lets an unauthenticated attacker gain Metabase admin and pivot to command execution or credential theft. Detects the endpoint-visible consequence: the Metabase/Java process spawning a shell, recon, or download utility on a server.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("java.exe", "javaw.exe", "java", "metabase.exe", "metabase", "nginx.exe", "node.exe")
   or InitiatingProcessCommandLine has_any ("metabase.jar", "metabase")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "bash", "sh", "dash", "curl.exe", "curl", "wget", "certutil.exe", "bitsadmin.exe", "whoami.exe", "whoami", "net.exe", "net1.exe", "nltest.exe", "reg.exe", "schtasks.exe", "rundll32.exe")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Scope to hosts running Metabase or other Java web apps via a device group to cut noise; some Java apps legitimately shell out for health checks or backups — allowlist those exact command lines. Any whoami/net/reg/curl child of the Metabase JVM should be treated as a probable exploitation attempt and triaged against Metabase application logs.

## 11) Browser Spawning Script Host or LOLBin (ClearFake Drive-By / Fake Update)

**Tactic:** Execution  
**ATT&CK:** T1059  
**Severity:** Medium  
**Purpose:** ClearFake injects fake-update and ClickFix overlays into compromised sites; successful lures frequently result in the browser process itself launching a script interpreter or LOLBin to fetch the loader. Behavioural coverage that survives ClearFake domain shadowing rotation.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "opera_gx.exe", "vivaldi.exe", "iexplore.exe", "msedgewebview2.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "rundll32.exe", "regsvr32.exe", "msiexec.exe", "certutil.exe", "bitsadmin.exe", "curl.exe", "installutil.exe", "hh.exe")
| where not(FileName =~ "cmd.exe" and ProcessCommandLine has_any ("/c ver", "echo"))
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessSHA256, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Browser-integrated enterprise tools (SSO helpers, print/PDF handlers, update checkers) can spawn cmd or rundll32 — allowlist specific command lines. Escalate when the child command line contains download/encoding indicators or when a subsequent DeviceFileEvents shows an executable written to %TEMP%/%APPDATA% by the same chain.
