## 1) ClickFix: Run Dialog (RunMRU) Entry Containing Script/LOLBin Command

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClickFix / ClearFake social-engineering lures instruct victims to paste an attacker-supplied command into the Windows Run dialog. Every pasted command is recorded under Explorer\RunMRU, making this one of the most durable detections for the technique regardless of the delivery domain or payload.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl", "certutil", "bitsadmin", "msiexec", "rundll32", "regsvr32", "wscript", "cscript", "forfiles", "conhost", "FromBase64String", "iwr", "irm", "Invoke-", "http://", "https://", "\\\\", "DavWWWRoot", "-w h", "-enc", "hidden")
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Very low volume in most enterprises. Admins legitimately type mmc/cmd/powershell into Run — tighten by requiring a URL, encoded content, or a UNC path in RegistryValueData if noisy. Allowlist known IT admin accounts/jump hosts rather than removing keywords.

## 2) Interpreter or LOLBin Spawned Directly by explorer.exe With Download/Obfuscation Markers

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the post-paste execution stage of ClickFix/ClearFake and similar fake-CAPTCHA lures, where explorer.exe (Run dialog, or a pasted shortcut/double-click) directly launches a script host or LOLBin that fetches remote content or uses hidden/encoded execution.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "certutil.exe", "bitsadmin.exe", "installutil.exe", "conhost.exe")
| where ProcessCommandLine has_any ("http://", "https://", "-w hidden", "-windowstyle h", "-nop", "-noprofile", "-enc", "-e ", "frombase64string", "iex", "invoke-expression", "invoke-webrequest", "iwr ", "irm ", "downloadstring", "downloadfile", "bypass", "davwwwroot", "\\\\", "webclient", "start-process", "[char]", "-join")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Users double-clicking .ps1/.vbs/.hta helper scripts from Explorer will fire. Allowlist specific signed internal scripts by hash/path and known software-deployment shortcuts. Consider raising fidelity by requiring both a URL and an obfuscation marker.

## 3) Process Execution or Payload Retrieval From WebDAV / UNC Share

**Tactic:** Execution  
**ATT&CK:** T1105  
**Severity:** High  
**Purpose:** ClearFake campaigns tagged 'WebDav' stage payloads on remote WebDAV shares so the binary or DLL never touches local disk in an obvious way. Detects execution of images from UNC/DavWWWRoot paths or LOLBins referencing WebDAV paths on the command line.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FolderPath startswith "\\\\" or FolderPath has "DavWWWRoot"
    or ProcessCommandLine has_any ("DavWWWRoot", "@SSL\\DavWWWRoot", "@80\\", "@443\\")
    or (ProcessCommandLine has "\\\\" and FileName in~ ("rundll32.exe", "regsvr32.exe", "mshta.exe", "msiexec.exe", "cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "certutil.exe"))
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Environments that run software from internal file shares (SCCM, logon scripts, netlogon) will generate volume — allowlist known internal server names in FolderPath/ProcessCommandLine (e.g. \\\\corp.example.com\\netlogon). Executions from an internet-routable WebDAV host (DavWWWRoot, @SSL, @80) should stay unfiltered.

## 4) Potentially Suspicious Mofcomp Execution (Sigma translation)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218  
**Severity:** Medium  
**Purpose:** Translation of Sigma rule 1dd05363: detects mofcomp.exe spawned by a shell/script host or compiling a MOF from a user-writable/suspicious path, a technique used to install malicious WMI event-consumer persistence.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "mofcomp.exe" or ProcessVersionInfoOriginalFileName =~ "mofcomp.exe"
| where InitiatingProcessFileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wsl.exe", "wscript.exe", "cscript.exe")
    or ProcessCommandLine has_any (@"\AppData\Local\Temp", @"\Contacts\", @"\Favorites\", @"\Favourites\", @"\Music\", @"\Pictures\", @"\Users\Public\", @"\Videos\", @"\WINDOWS\Temp\", "%appdata%", "%temp%", "%tmp%")
| where not(InitiatingProcessFolderPath =~ @"C:\Windows\System32\wbem\WmiPrvSE.exe" and ProcessCommandLine has @"C:\Windows\TEMP\" and ProcessCommandLine endswith ".mof")
| where not(InitiatingProcessFileName =~ "InstallUtil.exe" and ProcessCommandLine has @"C:\Windows\TEMP" and ProcessCommandLine has ".tmp")
| where isnotempty(InitiatingProcessCommandLine)
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Preserved the Sigma WmiPrvSE and SCCM InstallUtil/Microsoft.ConfigurationManager.SVProvider exclusions; add your own management-agent parents (e.g. ccmexec.exe wrappers, vendor installers) if they compile MOFs from TEMP. Investigate the referenced .mof content for ActiveScriptEventConsumer/CommandLineEventConsumer classes.

## 5) Windows Firewall Allow Rule Added for Binary in Uncommon/User-Writable Path

**Tactic:** DefenseEvasion  
**ATT&CK:** T1562.004  
**Severity:** Medium  
**Purpose:** Defender-XDR equivalent of Sigma rule cde0a575 (firewall-as EventIDs 2004/2071/2097): detects creation of a Windows Firewall allow rule whose application path points to a temp/public/AppData location, as done by loaders and RATs to keep their C2 channel open.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"SharedAccess\Parameters\FirewallPolicy\FirewallRules"
| where RegistryValueData has "Action=Allow"
| where RegistryValueData has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\Users\Public\", @"C:\Temp\", @"C:\Tmp\", @"C:\PerfLogs\", @"C:\Windows\Temp\", @"C:\Windows\Tasks\", @"\Downloads\", @"C:\ProgramData\")
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RegistryKey, RegistryValueName, RegistryValueData, ReportId
| union (
    DeviceProcessEvents
    | where Timestamp > ago(1d)
    | where (FileName =~ "netsh.exe" and ProcessCommandLine has "firewall" and ProcessCommandLine has_any ("add rule", "add allowedprogram"))
        or (FileName in~ ("powershell.exe", "pwsh.exe") and ProcessCommandLine has "New-NetFirewallRule")
    | where ProcessCommandLine has_any (@"\AppData\", @"\Users\Public\", @"C:\Temp\", @"C:\Windows\Temp\", @"C:\ProgramData\", @"\Downloads\", @"C:\PerfLogs\", "action=allow", "-Action Allow")
    | project Timestamp, DeviceName, InitiatingProcessAccountName = AccountName, InitiatingProcessFileName = FileName, InitiatingProcessFolderPath = FolderPath, InitiatingProcessCommandLine = ProcessCommandLine, RegistryKey = "", RegistryValueName = "", RegistryValueData = ProcessCommandLine, ReportId
)
| order by Timestamp desc
```

**Tuning notes:** Sigma's filters for MsMpEng, TiWorker, svchost/dllhost System rules and Program Files/System32 paths are covered by the path allowlist logic — extend with your own agents that install rules from ProgramData (backup, RMM, AV). Software installers running from %TEMP% are the main FP source; allowlist by InitiatingProcessSHA256/signer.
