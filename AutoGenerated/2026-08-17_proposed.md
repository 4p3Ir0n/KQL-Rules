## 1) ClickFix / ClearFake: Malicious command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClickFix and ClearFake social-engineering lures instruct the victim to press Win+R and paste an attacker-supplied command (PowerShell, mshta, curl, msiexec, conhost --headless). Every pasted command is recorded under the Explorer RunMRU registry key, making this one of the highest-fidelity detections for the initial execution step regardless of the delivery domain.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl", "bitsadmin", "certutil", "msiexec", "rundll32", "regsvr32", "wscript", "cscript", "conhost", "cmd.exe /c", "cmd /c", "iwr", "irm", "Invoke-WebRequest", "Invoke-Expression", "IEX", "FromBase64String", "http://", "https://", "\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins and developers legitimately paste UNC paths and occasionally cmd/powershell into Run. Baseline per-user: allowlist known IT accounts or jump hosts. Consider raising severity when RegistryValueData contains both a hidden-window switch (-w h, -windowstyle hidden) and a download cmdlet, or contains '# verification'/'captcha'/emoji padding used to push the malicious portion off-screen. RunMRU entries are only written when the dialog is used interactively, so volume is naturally low.

## 2) ClickFix: Script interpreter spawned directly by Explorer with download-and-execute command line

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** After the victim pastes the fake 'verification' command, the interpreter is launched as a child of explorer.exe (Run dialog) rather than from a shell or scheduled task. Combining that lineage with download/execute or hidden-window indicators detects IClickFix/ClearFake execution without relying on the rotating delivery domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe", "conhost.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "bitsadmin.exe", "certutil.exe")
| extend cmd = tolower(ProcessCommandLine)
| where cmd has_any ("http://", "https://", "\\\\")
    or cmd has_any ("invoke-webrequest", "invoke-restmethod", "iwr ", "irm ", "downloadstring", "downloadfile", "frombase64string", "-enc", "-e jab", "iex", "invoke-expression", "start-process", "-w h", "-windowstyle hidden", "-nop", "-noprofile", "--headless")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, FolderPath, ProcessId, ReportId
```

**Tuning notes:** Explorer-parented cmd.exe with a UNC path is common in some environments; scope the UNC clause out if noisy. Software-deployment tooling that shells msiexec from Explorer double-clicks can fire — allowlist by signed MSI path or known packaging accounts. Watch for conhost.exe as parent, which indicates the 'conhost.exe --headless' ClickFix variant used to hide the console window.

## 3) mshta.exe or msiexec.exe executing a remote URL (ClearFake / EtherHiding payload stage)

**Tactic:** Execution  
**ATT&CK:** T1218.005  
**Severity:** High  
**Purpose:** ClearFake and its EtherHiding-hosted loaders frequently pivot to mshta.exe or msiexec.exe with an HTTP(S) argument to pull the next stage from a compromised site or Cloudflare worker. Remote-hosted HTA/MSI execution is rare in normal enterprise operation and is a durable behavioral marker across indicator churn.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("mshta.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe")
| extend cmd = tolower(ProcessCommandLine)
| where cmd matches regex @"https?://" or cmd has "javascript:" or cmd has "vbscript:" or cmd has ".hta"
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Some legacy line-of-business apps and vendor installers call msiexec with an internal HTTP path; allowlist by internal FQDN or by the initiating deployment agent (ccmexec.exe, intune management extension). Enrich by joining DeviceNetworkEvents on the resulting ProcessId to capture the remote host for blocking.

## 4) Script interpreter or LOLBin making outbound HTTP(S) to a rare external host

**Tactic:** CommandAndControl  
**ATT&CK:** T1071.001  
**Severity:** Medium  
**Purpose:** IClickFix/ClearFake C2 and payload retrieval is performed by the pasted interpreter itself (powershell, mshta, curl, bitsadmin) talking to short-lived domains, including Cloudflare workers.dev fronting and blockchain-gated (EtherHiding) endpoints. Detecting the process-to-network pattern survives domain rotation.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "bitsadmin.exe", "certutil.exe", "regsvr32.exe", "rundll32.exe", "msiexec.exe", "conhost.exe")
| where isnotempty(RemoteUrl) or RemotePort in (80, 443, 8080, 8443)
| where not(ipv4_is_private(RemoteIP)) and RemoteIP !startswith "127."
| summarize Attempts = count(), Urls = make_set(RemoteUrl, 10), RemoteIPs = make_set(RemoteIP, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, RemoteUrl
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, RemoteUrl, RemoteIPs, Attempts
```

**Tuning notes:** Highest volume source is legitimate PowerShell automation reaching update/telemetry endpoints — build an allowlist of approved destinations (aka.ms, *.microsoft.com, internal proxies, package repos) and of signed automation scripts. Prioritize results where the domain is newly observed org-wide (join against a 30-day RemoteUrl baseline) or where the initiating command line matches the ClickFix detection above.

## 5) Loader self-deletion via cmd timeout/ping chained to del (Vidar / ClickFix payload cleanup)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070.004  
**Severity:** Medium  
**Purpose:** Vidar and ClickFix-delivered loaders commonly clean up after exfiltration by spawning a shell that sleeps via timeout.exe or ping.exe and then deletes the parent executable, often with an rmdir of the staging folder. This chained pattern is a reliable post-execution artifact independent of any indicator.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe")
| extend cmd = tolower(ProcessCommandLine)
| where (cmd has_any ("timeout", "ping ", "choice", "start-sleep") and cmd has_any ("del ", "erase ", "rmdir", "rd /s", "remove-item"))
| where cmd has_any ("\\appdata\\local\\temp\\", "\\appdata\\roaming\\", "\\programdata\\", "\\users\\public\\", "\\windows\\temp\\", ".exe", ".scr", ".dll")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Legitimate installers and uninstallers (and some MSI custom actions) use the same sleep-then-delete idiom; allowlist by InitiatingProcessFolderPath for known setup tooling and by signed parent binaries. Correlate with the credential-store detection: a self-delete from a process that just touched browser secrets is a confirmed stealer.

## 6) Web server process spawning a command shell (PHP/WordPress web shell execution)

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** Critical  
**Purpose:** php.shin_webshell is dropped into WordPress installations (wp-admin/wp-content, often disguised as .gif) and reached through Cloudflare workers.dev fronting. On the host, exploitation manifests as the web server or PHP handler spawning a shell or discovery/download utility — the definitive behavioural signal of web shell use.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("php.exe", "php-cgi.exe", "httpd.exe", "nginx.exe", "w3wp.exe", "tomcat.exe", "caddy.exe", "node.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "net.exe", "net1.exe", "whoami.exe", "hostname.exe", "ipconfig.exe", "systeminfo.exe", "tasklist.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "nltest.exe", "reg.exe", "schtasks.exe", "bash.exe", "wmic.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ProcessId, ReportId
```

**Tuning notes:** Some CMS plugins, cron wrappers and monitoring checks shell out from PHP/w3wp legitimately — build a per-server allowlist keyed on the exact child command line. Never allowlist whoami/net/nltest/certutil. Consider splitting into two rules (interactive shells = Critical, discovery utilities = High) if the web tier is chatty.

## 7) Script or image-extension file written into a web root by the web server or an unusual process

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** High  
**Purpose:** Detects the drop of a PHP web shell (including .gif/.jpg-masquerading payloads referenced in the php.shin_webshell reporting) into WordPress or IIS content directories, which is the persistence step preceding remote command execution.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileModified", "FileRenamed")
| extend p = tolower(FolderPath)
| where p has_any ("\\wwwroot\\", "\\inetpub\\", "\\htdocs\\", "\\www\\", "\\wp-content\\", "\\wp-admin\\", "\\wp-includes\\", "\\uploads\\", "\\public_html\\")
| where p endswith ".php" or p endswith ".phtml" or p endswith ".php5" or p endswith ".asp" or p endswith ".aspx" or p endswith ".ashx" or p endswith ".jsp" or p endswith ".gif" or p endswith ".jpg" or p endswith ".png"
| where InitiatingProcessFileName in~ ("php.exe", "php-cgi.exe", "httpd.exe", "nginx.exe", "w3wp.exe", "cmd.exe", "powershell.exe", "pwsh.exe", "certutil.exe", "curl.exe", "bitsadmin.exe", "wscript.exe", "cscript.exe", "ftp.exe", "tar.exe")
| project Timestamp, DeviceId, DeviceName, FileName, FolderPath, SHA256, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Exclude legitimate deployment pipelines (msdeploy.exe, git, CI agents, WordPress auto-update writing to wp-content/upgrade) by initiating process and account. Image extensions in \uploads\ are high volume from normal CMS use — keep them only if written by php/w3wp outside the media upload path, or split image extensions into a separate lower-severity hunt.
