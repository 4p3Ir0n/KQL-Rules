## 1) ClickFix Paste-and-Run: Malicious Command Written to Explorer RunMRU

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake / IClickFix / "Unknown Loader" campaigns instruct victims to paste an attacker-supplied command into the Windows Run dialog (fake CAPTCHA / "verify you are human" / fake browser-update lures). Every such execution leaves the pasted string in HKCU\...\Explorer\RunMRU, which is a durable, high-fidelity artifact independent of rotating domains and hashes.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"CurrentVersion\Explorer\RunMRU"
| where isnotempty(RegistryValueData)
| extend Cmd = tolower(RegistryValueData)
| where Cmd has_any ("powershell", "pwsh", "mshta", "curl", "certutil", "bitsadmin", "msiexec", "rundll32", "regsvr32", "wscript", "cscript", "conhost", "forfiles", "ftp")
    or Cmd has_any ("iex", "invoke-expression", "invoke-webrequest", "iwr", "downloadstring", "frombase64string", "-enc", "-e ncod", "http://", "https://", "\\\\", ".hta", "webdav")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** RunMRU legitimately holds admin commands (cmd, mmc, \\fileserver shares). Baseline per-user: allowlist known admin accounts and internal UNC prefixes. Long single-line values (>150 chars) and values containing base64 or URLs are almost always malicious — consider splitting into a high-severity variant on strlen(RegistryValueData) > 150.

## 2) Browser or Explorer Spawning Script Interpreter with Remote Download (ClickFix Chain)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** After the ClickFix paste-and-run or a fake-update download from a compromised WordPress/ClearFake injection, the first stage is a script interpreter launched from explorer.exe (Run dialog) or directly from a browser process, pulling the next stage over HTTP. This lineage plus download/execute command-line combination is the core ClearFake / IClickFix / Unknown Loader delivery TTP.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe", "chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "iexplore.exe", "outlook.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "conhost.exe")
| extend Cmd = tolower(ProcessCommandLine)
| where Cmd has_any ("http://", "https://", "iex", "invoke-expression", "invoke-webrequest", "iwr", "downloadstring", "downloadfile", "frombase64string", "-enc", "-encodedcommand", "-w hidden", "-windowstyle hidden", "-nop", "bypass", "webdav", "\\\\")
| project Timestamp, DeviceName, DeviceId, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine, FolderPath, ProcessId, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Explorer -> cmd.exe with short benign command lines and browser -> msiexec for legitimate enterprise app installers are the main noise sources; allowlist by signed MSI path/publisher and by known IT automation URLs. Software-deployment tooling that launches from Outlook attachments should be excluded by sender/path baseline rather than removing the parent.

## 3) Ray Cluster Component Spawning Shell or Script Interpreter (CVE-2025-62593 Exploitation)

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** CVE-2025-62593 allows code injection into Ray, leading to remote code execution on Ray head/worker nodes. Successful exploitation manifests as the Ray daemon (raylet, gcs_server, dashboard) or its python host process spawning an interactive shell, downloader, or reverse-shell one-liner — a durable post-exploitation signal regardless of the injection vector.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("raylet", "gcs_server", "ray.exe", "ray_client", "plasma_store")
    or (InitiatingProcessFileName in~ ("python.exe", "python3.exe", "pythonw.exe", "python") and InitiatingProcessCommandLine has_any ("ray", "raylet", "ray.util", "ray dashboard", "serve run", "job_supervisor"))
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "bash", "sh", "dash", "curl.exe", "curl", "wget", "certutil.exe", "bitsadmin.exe", "whoami.exe", "whoami", "net.exe", "net1.exe", "nc", "ncat", "socat", "schtasks.exe", "reg.exe", "rundll32.exe", "mshta.exe")
| project Timestamp, DeviceName, DeviceId, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, FileName, ProcessCommandLine, FolderPath, ProcessId, ReportId
| order by Timestamp desc
```

**Tuning notes:** Ray workloads legitimately shell out (pip installs, nvidia-smi wrappers, entrypoint scripts). Baseline per-cluster over 7-14 days and allowlist recurring benign command lines; keep alerts on interactive shells with network/encoding keywords, whoami/net discovery, and schtasks/reg persistence. Restrict scope to known Ray head/worker device groups to cut volume.

## 4) mshta.exe or Signed LOLBin Executing Remote Content

**Tactic:** Execution  
**ATT&CK:** T1218.005  
**Severity:** Medium  
**Purpose:** ClickFix-delivered loaders and the Mythic/Supershell/Viper C2 families in this feed commonly bootstrap through signed Windows binaries that fetch and execute remote script content (mshta with a URL, rundll32 with a URL/javascript, regsvr32 scriptlet). This is a proxy-execution behavior that survives IOC rotation.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("mshta.exe", "rundll32.exe", "regsvr32.exe", "wmic.exe", "msiexec.exe", "installutil.exe", "msbuild.exe")
| extend Cmd = tolower(ProcessCommandLine)
| where Cmd has_any ("http://", "https://", "ftp://", "\\\\", "javascript:", "vbscript:", "scrobj.dll", "/i:http", "format:xml", ".hta")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Enterprise software distribution uses msiexec with internal HTTP(S) or UNC sources — allowlist by internal FQDN/UNC prefix. Legacy line-of-business apps may use mshta with local .hta files (excluded here since no scheme match). Elevate severity when the parent is a browser, Office app, or explorer.exe.

## 5) Shadow Copy and Recovery Destruction Prior to Encryption

**Tactic:** Impact  
**ATT&CK:** T1490  
**Severity:** Critical  
**Purpose:** The 'Unknown malware' cluster in this feed is tagged Ransomware alongside Mythic/Supershell/Viper C2 tooling. Regardless of family, pre-encryption inhibiting of system recovery (vssadmin/wmic shadow deletion, bcdedit recovery disablement, wbadmin catalog deletion) is a stable, high-confidence impact behavior.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| extend Cmd = tolower(ProcessCommandLine)
| where (FileName in~ ("vssadmin.exe", "wmic.exe", "diskshadow.exe") and Cmd has "shadow" and Cmd has_any ("delete", "resize", "/all"))
    or (FileName =~ "bcdedit.exe" and Cmd has_any ("recoveryenabled no", "bootstatuspolicy ignoreallfailures", "/set {default}"))
    or (FileName =~ "wbadmin.exe" and Cmd has_any ("delete catalog", "delete systemstatebackup", "delete backup"))
    or (FileName in~ ("powershell.exe", "pwsh.exe") and Cmd has_any ("win32_shadowcopy", "remove-computerrestorepoint", "disable-computerrestore"))
    or (FileName =~ "wevtutil.exe" and Cmd has_any (" cl ", "clear-log"))
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ProcessIntegrityLevel, ReportId
| order by Timestamp desc
```

**Tuning notes:** Backup agents and imaging tools legitimately resize or delete shadow copies — allowlist by initiating process path/signer (e.g., approved backup suites) and by scheduled maintenance windows. wevtutil clear-log is occasionally used by sysprep/imaging pipelines; scope those to build device groups. Treat any match whose parent is a browser, Office app, or a binary in Temp/AppData as Critical and auto-isolate candidate.

## 6) Outbound VNC / Apple Screen Sharing Traffic from Endpoint

**Tactic:** LateralMovement  
**ATT&CK:** T1021.005  
**Severity:** Medium  
**Purpose:** Following the Apple screen-sharing (VNC over TCP/5900, historically unencrypted with weak global-password auth) advisory, hunt for endpoints initiating VNC sessions. Unsanctioned outbound 5900/5901 from workstations indicates either shadow remote-access tooling or an attacker pivoting to macOS/embedded hosts using stolen screen-sharing credentials.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess", "ConnectionAttempt", "InboundConnectionAccepted")
| where RemotePort in (5900, 5901, 5902, 5800)
| summarize Connections = count(), Targets = make_set(RemoteIP, 50), Ports = make_set(RemotePort, 5), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, Connections, Targets, Ports
| order by LastSeen desc
```

**Tuning notes:** Allowlist sanctioned VNC/screen-sharing clients (RealVNC, TightVNC, TigerVNC, Remmina) used by IT support, plus known jump hosts and lab subnets. Flag connections from script interpreters or unsigned binaries, and internal fan-out (many distinct RemoteIPs from one source) as the higher-priority variant.
