## 1) AppLocker Policy Enumeration via Get-AppLockerPolicy

**Tactic:** Discovery  
**ATT&CK:** T1518.001  
**Severity:** Low  
**Purpose:** Detects PowerShell enumeration of effective, local, or LDAP-based AppLocker policies, commonly performed by adversaries to identify application-control gaps before deploying payloads (Sigma f14b1e99-5e53-4598-98dc-6f20ad7b35e0).

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe", "pwsh.exe") or ProcessVersionInfoOriginalFileName in~ ("PowerShell.EXE", "pwsh.dll")
| where ProcessCommandLine contains "Get-AppLockerPolicy"
| where ProcessCommandLine has_any ("-Effective", "/Effective", "–Effective", "—Effective", "-Ldap", "/Ldap", "–Ldap", "-Local", "/Local", "–Local")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Allowlist software-inventory / compliance tooling and admin jump hosts that legitimately export AppLocker policy (e.g., scheduled scripts run by SCCM or endpoint-management service accounts). Consider elevating severity when the invoking parent is not a management agent or when the same host also runs other discovery cmdlets within a short window.

## 2) ClickFix / ClearFake: Malicious Command Pasted into Windows Run Dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake and related 'ClickFix'/EtherHiding loaders instruct victims to paste an attacker-supplied command into the Win+R Run dialog. Windows records it under Explorer\RunMRU, giving a durable, infrastructure-independent detection of the social-engineering step.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl ", "certutil", "bitsadmin", "msiexec", "rundll32", "regsvr32", "wscript", "cscript", "conhost", "forfiles", "http://", "https://", "FromBase64String", "-enc", "iex", "Invoke-Expression", "Invoke-WebRequest", "\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountDomain, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins occasionally run legitimate UNC paths or powershell from the Run box; allowlist by account for known IT staff or by exact RegistryValueData strings used internally. Highest fidelity when RegistryValueData contains base64, a URL, or a comment/verification string such as '# I am not a robot'.

## 3) Script Interpreter Spawned Directly by Explorer with Download or Encoded Payload

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the second stage of ClickFix/ClearFake/OffLoader chains: explorer.exe launching a script host or download utility with hidden windows, encoded commands, or inline HTTP download-and-execute, indicating user-pasted execution rather than normal application launch.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "cmd.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "bitsadmin.exe", "certutil.exe")
| where ProcessCommandLine has_any ("-enc", "-ec ", "encodedcommand", "FromBase64String", "-w h", "-windowstyle h", "hidden", "iex", "Invoke-Expression", "Invoke-WebRequest", "Invoke-RestMethod", "DownloadString", "DownloadFile", "Net.WebClient", "http://", "https://", "-urlcache", "/transfer", "curl ", "| conhost", "Start-Process")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Explorer-launched shortcuts and some installers legitimately reference http URLs; allowlist specific known-good command lines and internal update scripts. Suppress helpdesk-driven activity by account or device group. Correlate with the following DeviceNetworkEvents from the spawned process to prioritize triage.

## 4) NetSupport RAT Client Executing from User-Writable Directory

**Tactic:** CommandAndControl  
**ATT&CK:** T1219  
**Severity:** High  
**Purpose:** ClearFake/ClickFix campaigns commonly deliver NetSupport Manager (NetSupport RAT) as client32.exe unpacked into user-writable folders and run for remote control. Detects the RAT binary or NetSupport-branded process executing outside legitimate install locations.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "client32.exe" or ProcessVersionInfoCompanyName has "NetSupport" or ProcessVersionInfoProductName has "NetSupport"
| where FolderPath has_any (@"\AppData\", @"\ProgramData\", @"\Users\Public\", @"\Temp\", @"\Downloads\", @"\Windows\Tasks\")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** If your organization licenses NetSupport Manager, allowlist its signed install path (typically Program Files) and the deploying management agent; the folder filter already excludes those. Extend FileName list with remsupp.exe/pcicl32.dll if seen. Pair with DeviceNetworkEvents on non-standard ports from the same process for confirmation.

## 5) macOS Stealer Behavior: osascript Password Prompt or Curl-Piped-to-Shell Install

**Tactic:** CredentialAccess  
**ATT&CK:** T1056.002  
**Severity:** High  
**Purpose:** MacSync Stealer and similar macOS infostealers rotate infrastructure but consistently use osascript fake password dialogs with hidden answers to harvest the login keychain password and a curl|bash one-liner for installation. Detects the behavior rather than the rotating domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("osascript", "bash", "sh", "zsh", "curl", "xattr", "security")
| where (ProcessCommandLine has "display dialog" and ProcessCommandLine has_any ("hidden answer", "default answer") and ProcessCommandLine has_any ("password", "Password", "credential", "System Preferences", "Keychain"))
    or (ProcessCommandLine has_any ("curl", "wget") and ProcessCommandLine has_any ("| bash", "| sh", "|bash", "|sh", "| zsh") and ProcessCommandLine has_any ("http://", "https://"))
    or (ProcessCommandLine has "xattr" and ProcessCommandLine has "-d" and ProcessCommandLine has "com.apple.quarantine")
    or (ProcessCommandLine has "security" and ProcessCommandLine has_any ("find-generic-password", "dump-keychain", "login.keychain"))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Requires Defender for Endpoint on macOS. Developer workstations legitimately use curl|bash (Homebrew, rustup) and xattr quarantine removal — allowlist known bootstrap URLs/hosts or exclude developer device groups, and keep the osascript password-dialog clause at higher severity since it is rarely benign. Pivot on the parent process (Terminal, browser-downloaded app bundle) to prioritize.

## 6) SharePoint w3wp.exe Spawning Command Shell or Recon Utility

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** Critical  
**Purpose:** Post-exploitation detection for SharePoint authentication-bypass/RCE chains (e.g., CVE-2026-55040): the IIS worker process hosting SharePoint spawning shells, script hosts, or discovery tools indicates successful web exploitation.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "w3wp.exe"
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe", "rundll32.exe", "regsvr32.exe", "certutil.exe", "bitsadmin.exe", "curl.exe", "net.exe", "net1.exe", "whoami.exe", "nltest.exe", "tasklist.exe", "schtasks.exe", "reg.exe", "vssadmin.exe", "wmic.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** SharePoint timer/health jobs and some solution deployments legitimately invoke powershell.exe from w3wp; allowlist specific command lines (e.g., SPTimerV4-related or vendor add-in scripts) after review. Scope to SharePoint servers via a device group to reduce noise from generic IIS applications.

## 7) Web Shell Written to SharePoint LAYOUTS or ASP.NET Temp Directory

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** Critical  
**Purpose:** Detects attacker-dropped .aspx/.ashx/.asmx payloads or DLLs written by the IIS worker process into SharePoint web-accessible directories — the standard persistence step after a SharePoint authentication bypass or RCE.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileModified", "FileRenamed")
| where FolderPath has_any (@"\TEMPLATE\LAYOUTS", @"\web server extensions\", @"\inetpub\wwwroot", @"\Microsoft.NET\Framework64\v4.0.30319\Temporary ASP.NET Files")
| where FileName endswith ".aspx" or FileName endswith ".ashx" or FileName endswith ".asmx" or FileName endswith ".asax" or FileName endswith ".dll"
| where InitiatingProcessFileName in~ ("w3wp.exe", "cmd.exe", "powershell.exe", "pwsh.exe", "mshta.exe", "rundll32.exe", "certutil.exe", "curl.exe")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Patch Tuesday / SharePoint cumulative updates and WSP solution deployments write to these paths — allowlist the update processes (TrustedInstaller.exe, msiexec.exe, psconfig) and suppress during approved maintenance windows. .dll writes to Temporary ASP.NET Files by w3wp are normal compilation artifacts; consider splitting that clause out or requiring an adjacent suspicious process event.

## 8) VMware vCenter Service Process Spawning Shell or Download Utility

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** Detects post-exploitation of vCenter path-traversal/RCE issues such as CVE-2026-59310, where the vCenter appliance's web/Java service processes spawn interactive shells, download tools, or reverse-shell interpreters.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("vmware-vpxd", "vsphere-ui", "vmware-envoy", "envoy", "java", "httpd", "nginx", "vmware-sts", "vmware-content-library")
| where FileName in~ ("sh", "bash", "dash", "csh", "python", "python3", "perl", "curl", "wget", "nc", "ncat", "socat", "chmod", "base64", "openssl", "crontab")
| where ProcessCommandLine has_any ("-c", "-i", "http://", "https://", "/tmp/", "/dev/tcp", "base64", "chmod +x", "| sh", "| bash")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Requires Defender for Endpoint on the Linux-based vCenter appliance (or on vCenter-adjacent Linux management hosts). vCenter internally invokes shell wrappers during service start, backup, and certificate operations — build a baseline over 7 days and allowlist recurring parent/child command-line pairs, especially those under /usr/lib/vmware and during patching windows.

## 9) Password Spray: Many Distinct Accounts Failing Authentication from One Source

**Tactic:** CredentialAccess  
**ATT&CK:** T1110.003  
**Severity:** Medium  
**Purpose:** Supports the large-scale credential-attack guidance by surfacing endpoint-visible spray/stuffing behavior — a single remote source or device failing authentication against many distinct accounts in a short window, often preceding successful Entra/AD credential abuse.

```kusto
DeviceLogonEvents
| where Timestamp > ago(1d)
| where ActionType == "LogonFailed"
| where isnotempty(AccountName)
| summarize FailedAccounts = dcount(AccountName), Attempts = count(), TargetedAccounts = make_set(AccountName, 40), LogonTypes = make_set(LogonType, 10), Devices = make_set(DeviceName, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by RemoteIP, RemoteDeviceName, bin(Timestamp, 1h)
| where FailedAccounts >= 10 and Attempts >= 20
| join kind=leftouter (
    DeviceLogonEvents
    | where Timestamp > ago(1d) and ActionType == "LogonSuccess"
    | summarize SuccessfulAccounts = make_set(AccountName, 20) by RemoteIP
) on RemoteIP
| project Timestamp, RemoteIP, RemoteDeviceName, FailedAccounts, Attempts, TargetedAccounts, SuccessfulAccounts, LogonTypes, Devices, FirstSeen, LastSeen
```

**Tuning notes:** Baseline thresholds per environment: vulnerability scanners, NAC appliances, backup agents, and misconfigured service accounts routinely generate high failed-logon counts — allowlist those RemoteIPs. Empty RemoteIP (local/interactive) rows can be excluded. A non-empty SuccessfulAccounts set on the same source should escalate to high severity, and pair with IdentityLogonEvents/AADSignInEventsBeta for tenant-side spray correlation.
