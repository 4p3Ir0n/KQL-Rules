## 1) AppLocker Policy Enumeration via Get-AppLockerPolicy

**Tactic:** Discovery  
**ATT&CK:** T1518.001  
**Severity:** Medium  
**Purpose:** Faithful Defender translation of Sigma rule f14b1e99 — detects PowerShell enumeration of AppLocker policies (Effective/LDAP/Local scope), typically performed by an adversary preparing application-control bypasses.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe","pwsh.exe") or ProcessVersionInfoOriginalFileName in~ ("PowerShell.EXE","pwsh.dll")
| where ProcessCommandLine contains "Get-AppLockerPolicy"
| where ProcessCommandLine has_any ("-Effective","/Effective","–Effective","—Effective","-Ldap","/Ldap","–Ldap","—Ldap","-Local","/Local","–Local","—Local")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Allowlist endpoint-management / compliance tooling accounts and scripted AppLocker audit jobs (SCCM, Intune remediation scripts, internal hardening baselines) by InitiatingProcessFileName or AccountName. Encoded commands will not match plaintext — pair with a companion rule for -EncodedCommand base64 containing 'Get-AppLockerPolicy'.

## 2) ClickFix / Fake-CAPTCHA Execution from Windows Run Dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClickFix, ClearFake, IClickFix and fake-Copilot lures instruct victims to paste a malicious command into the Win+R Run dialog. The pasted command is recorded in the RunMRU registry key, providing a high-fidelity behavioral signal independent of rotating C2 domains.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has "\\Explorer\\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","msiexec","conhost","wscript","cscript","rundll32","iwr","irm","Invoke-Expression","IEX","FromBase64String","http://","https://","\\u2705","verification","I am not a robot")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins and developers legitimately type powershell/cmd into Run. Reduce noise by scoping out IT/helpdesk accounts, or by requiring RegistryValueData length > 80 chars or presence of a URL / base64 blob. Pair with the explorer.exe-parent process rule for confirmation.

## 3) Explorer Spawning Scripting Host with Download/Clipboard Payload (ClickFix Chain)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the post-paste stage of ClickFix/ClearFake/EtherHiding lures: explorer.exe (Run dialog or clipboard paste) directly launching PowerShell, mshta, conhost --headless, or cmd with inline download-and-execute content leading to NetSupport, Vidar, Mythic or Covenant payloads.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","conhost.exe","curl.exe","msiexec.exe","rundll32.exe","regsvr32.exe")
| where ProcessCommandLine has_any ("http://","https://","iwr ","irm ","Invoke-WebRequest","Invoke-Expression","IEX","DownloadString","DownloadFile","FromBase64String","-enc","-EncodedCommand","-w hidden","-WindowStyle Hidden","--headless","Get-Clipboard","bitsadmin","certutil -urlcache","msiexec /i http")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Exclude signed internal deployment shortcuts launched from Explorer and known admin workstations. Consider raising severity when the command line contains a raw IP, a non-corporate TLD, or 'conhost.exe --headless'. Feed matched RemoteUrl values into DeviceNetworkEvents pivot for the follow-on C2.

## 4) MLflow / Python Web Service Spawning Shell or Network Tooling

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** Critical  
**Purpose:** Post-exploitation detection for CVE-2026-64849 and similar MLflow/AI-service exploitation: the MLflow server process (python/gunicorn/uvicorn) spawning interactive shells, download utilities or reconnaissance commands.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("python.exe","python3.exe","python","python3","pythonw.exe","mlflow.exe","mlflow","gunicorn","uvicorn","waitress-serve.exe")
    or InitiatingProcessCommandLine has_any ("mlflow server","mlflow ui","mlflow.server","-m mlflow")
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","bash","sh","dash","zsh","curl","curl.exe","wget","nc","ncat","whoami.exe","whoami","net.exe","net1.exe","certutil.exe","bitsadmin.exe","chmod","base64")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** ML pipelines legitimately shell out (conda, pip, git, chmod during package builds). Allowlist known training/build hosts or specific parent command lines rather than the whole FileName list, and exclude child processes whose command line references pip/conda/git. Prioritise alerts on internet-facing MLflow tracking servers.

## 5) Suspicious Child Process from IKEEXT Service Host (CVE-2026-33824)

**Tactic:** Execution  
**ATT&CK:** T1203  
**Severity:** High  
**Purpose:** Detects post-exploitation of the Microsoft IKE Service Extensions double-free RCE: the svchost.exe instance hosting IKEEXT spawning command interpreters or unusual binaries, which should never occur on a healthy host.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "svchost.exe"
| where InitiatingProcessCommandLine has_any ("IKEEXT","-k netsvcs", "PolicyAgent")
| where InitiatingProcessCommandLine has "IKEEXT" or InitiatingProcessCommandLine has "PolicyAgent"
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe","net.exe","net1.exe","whoami.exe","certutil.exe","bitsadmin.exe","curl.exe","msiexec.exe")
    or FolderPath has_any ("\\Users\\","\\ProgramData\\","\\Windows\\Temp\\","\\PerfLogs\\")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessId, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** On most hosts this rule should be silent; validate against your baseline for VPN/IPsec management scripts. Complement with monitoring of unexpected IKEEXT service crashes/restarts (Event ID 7031/7034 via a Sentinel Event table) and with DeviceNetworkEvents for inbound UDP/500 and UDP/4500 from untrusted sources on the same device.
