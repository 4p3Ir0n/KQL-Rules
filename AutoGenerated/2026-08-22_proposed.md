## 1) Zimbra (ZCS) mail service spawning shell or download utility — possible CVE-2026-73570 command injection

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** Detects post-exploitation command execution from the Zimbra Collaboration Suite mail stack (zmmailboxd, postfix/smtpd, amavis) as the 'zimbra' service account, which is the expected outcome of the unauthenticated SMTP-borne OS command injection in CVE-2026-73570.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFolderPath has "/opt/zimbra" or InitiatingProcessFileName in~ ("zmmailboxd","smtpd","postfix","master","amavisd","zmconfigd","httpd","nginx","java") or InitiatingProcessAccountName in~ ("zimbra","postfix")
| where FileName in~ ("sh","bash","dash","zsh","ksh","curl","wget","python","python3","perl","ruby","nc","ncat","socat","chmod","chattr","crontab","base64","openssl","id","whoami","useradd")
| where not(ProcessCommandLine has_any ("zmcontrol","zmprov","logrotate","zmlocalconfig"))
| project Timestamp, DeviceName, DeviceId, AccountName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, FileName, FolderPath, ProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Zimbra legitimately shells out for maintenance/cron tasks — baseline for a week and allowlist recurring parent+child+command-line triples (zmstat, zmlogswatch, backup scripts). Tighten by requiring outbound-capable children (curl/wget/nc/python) or reverse-shell patterns ('/dev/tcp/', 'bash -i', 'base64 -d') if volume is high. Requires Defender for Endpoint on Linux.

## 2) TrueConf Server process spawning interpreter or LOLBin — possible CVE-2026-72529/72530 exploitation

**Tactic:** Execution  
**ATT&CK:** T1059  
**Severity:** High  
**Purpose:** TrueConf Server exposes a scripting interface on 4307/TCP that is missing authentication (CVE-2026-72529) and allows sandbox escape into host code execution (CVE-2026-72530). Any command interpreter, script host, or download utility spawned by the TrueConf service is a strong exploitation signal.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has "trueconf" or InitiatingProcessFolderPath has "TrueConf"
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","curl.exe","wget.exe","net.exe","net1.exe","whoami.exe","sc.exe","schtasks.exe","bash.exe","sh","bash","python.exe","python3")
| project Timestamp, DeviceName, DeviceId, AccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessId, FileName, FolderPath, ProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Some TrueConf installer/updater workflows spawn cmd.exe or sc.exe; allowlist by matching InitiatingProcessCommandLine of the updater and a known child command line. Correlate with DeviceNetworkEvents inbound connections to LocalPort 4307 from external IPs on the same device to raise confidence.

## 3) Server-side process reaching cloud instance metadata service (MLflow SSRF CVE-2026-64849)

**Tactic:** Discovery  
**ATT&CK:** T1552.005  
**Severity:** Medium  
**Purpose:** Detects application/server processes (python, MLflow, gunicorn, java, node) connecting to cloud instance metadata endpoints (169.254.169.254, 100.100.100.200, metadata.google.internal), the classic SSRF outcome for CVE-2026-64849 leading to cloud credential theft.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteIP in ("169.254.169.254","169.254.170.2","100.100.100.200","fd00:ec2::254") or RemoteUrl has_any ("metadata.google.internal","169.254.169.254")
| where InitiatingProcessFileName has_any ("python","gunicorn","uvicorn","mlflow","java","node","ruby","php","nginx","httpd","w3wp")
| summarize Requests=count(), FirstSeen=min(Timestamp), LastSeen=max(Timestamp), Urls=make_set(RemoteUrl, 10), Ports=make_set(RemotePort, 5) by DeviceName, DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, RemoteIP
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RemoteIP, Ports, Urls, Requests
```

**Tuning notes:** Cloud SDKs inside app containers legitimately query IMDS for credentials — baseline which app processes normally do so and allowlist those (device + process + account). Prioritize hosts running MLflow (check for 'mlflow server'/'mlflow ui' in InitiatingProcessCommandLine) and cases where IMDS access is new for that host.

## 4) ClickFix / ClearFake: script interpreter launched from Explorer Run dialog (RunMRU paste-and-run)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake and IClickFix social-engineer victims into pasting a PowerShell/mshta/curl one-liner into the Windows Run dialog. This detects the resulting execution lineage (explorer.exe -> interpreter) combined with download/execution command-line markers.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","wscript.exe","cscript.exe","conhost.exe","msiexec.exe","rundll32.exe","forfiles.exe")
| where ProcessCommandLine has_any ("iex","invoke-expression","invoke-webrequest","invoke-restmethod","downloadstring","downloadfile","frombase64string","-enc","-encodedcommand","-w hidden","-windowstyle hidden","-nop","http://","https://","start-bitstransfer","curl ","certutil","mshta http","msiexec /i http","\\\\\\\\") 
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, FolderPath, ProcessCommandLine, ProcessId, InitiatingProcessFileName, InitiatingProcessId, ReportId
```

**Tuning notes:** Admins and IT staff also paste commands into Run; allowlist known admin accounts/jump hosts or exclude command lines that only reference internal UNC paths. Raise severity when the child process later contacts a newly-registered domain or writes to %APPDATA%/%TEMP%.

## 5) ClickFix paste-and-run artifact written to Explorer RunMRU registry key

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Records the forensic fingerprint of the ClickFix lure: the pasted command is written to HKCU\...\Explorer\RunMRU. Detecting interpreter/download strings in RunMRU values catches the technique even if the payload process is short-lived or blocked.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","cmd /c","cmd.exe /c","curl","certutil","bitsadmin","rundll32","msiexec","http://","https://","frombase64string","-enc","iex","wscript","cscript","\u2705","# ")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Helpdesk/admin usage of Run for cmd/powershell will fire; scope out known admin accounts or require URL/base64/verification-emoji markers in RegistryValueData. ClickFix lures frequently append a fake 'verification' string or emoji plus many spaces — a length check (strlen(RegistryValueData) > 120) is an effective additional filter.

## 6) Interpreter or LOLBin contacting attacker infrastructure shortly after ClickFix-style execution

**Tactic:** CommandAndControl  
**ATT&CK:** T1105  
**Severity:** Medium  
**Purpose:** Catches the ClearFake/IClickFix second stage: the pasted one-liner fetches a payload (Vidar, loaders) over HTTP from a low-reputation host. Detects script hosts and download LOLBins making outbound connections while running from user-writable folders or with hidden-window flags.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","certutil.exe","bitsadmin.exe","rundll32.exe","regsvr32.exe","msiexec.exe")
| where RemoteIPType == "Public"
| where InitiatingProcessCommandLine has_any ("hidden","-nop","-enc","iex","downloadstring","downloadfile","invoke-restmethod","invoke-webrequest","http") or InitiatingProcessParentFileName in~ ("explorer.exe","mshta.exe","wscript.exe")
| summarize Connections=count(), FirstSeen=min(Timestamp), LastSeen=max(Timestamp), Urls=make_set(RemoteUrl, 10), IPs=make_set(RemoteIP, 10), Ports=make_set(RemotePort, 5) by DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessId
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, IPs, Urls, Ports, Connections
```

**Tuning notes:** Allowlist enterprise automation (SCCM/Intune scripts, internal update servers) by RemoteUrl domain or signing/parent path. Enrich with DeviceInfo/PublicIP reputation or domain age; joining to DeviceFileEvents for a payload written to %TEMP%/%APPDATA% within 5 minutes greatly reduces false positives.

## 7) Sliver-style implant beaconing: regular outbound connections from binary in user-writable path

**Tactic:** CommandAndControl  
**ATT&CK:** T1571  
**Severity:** Medium  
**Purpose:** Sliver C2 indicators are ephemeral IP:port pairs, so this detects the durable behavior instead: an executable running from a temp/AppData/ProgramData/public path making repeated, evenly distributed outbound connections to the same public host over the day.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess","ConnectionAttempt")
| where RemoteIPType == "Public"
| where InitiatingProcessFolderPath has_any ("\\appdata\\local\\temp","\\appdata\\roaming","\\programdata","\\users\\public","\\downloads","\\perflogs","/tmp/","/dev/shm/","/var/tmp/")
| summarize Connections=count(), ActiveBuckets=dcount(bin(Timestamp, 5m)), Ports=make_set(RemotePort, 5), Urls=make_set(RemoteUrl, 5), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by DeviceName, DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName, RemoteIP
| where ActiveBuckets >= 12 and Connections >= 20
| extend SpanMinutes = datetime_diff('minute', LastSeen, FirstSeen)
| where SpanMinutes >= 60
| project FirstSeen, LastSeen, SpanMinutes, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, RemoteIP, Ports, Urls, Connections, ActiveBuckets
```

**Tuning notes:** Updaters and installers staged in %TEMP%/ProgramData (e.g., Chrome/Teams/AV updaters) beacon similarly — allowlist by InitiatingProcessSHA256 or signer. Tighten by requiring unsigned binaries (join DeviceFileCertificateInfo) or non-standard ports (RemotePort !in (80,443)); Sliver mTLS profiles commonly use 8888/31337/443 on raw IPs with no RemoteUrl.

## 10) Password spray against Entra ID / AD: many distinct accounts failing from one source

**Tactic:** CredentialAccess  
**ATT&CK:** T1110.003  
**Severity:** Medium  
**Purpose:** Operationalizes the Entra sign-in log review guidance: identifies a single source IP or device generating authentication failures across a large number of distinct accounts within an hour, the classic spray pattern that also reveals accounts missed by MFA rollout.

```kusto
IdentityLogonEvents
| where Timestamp > ago(1d)
| where ActionType == "LogonFailed"
| where isnotempty(AccountUpn) or isnotempty(AccountName)
| extend Principal = coalesce(AccountUpn, strcat(AccountDomain, "\\", AccountName))
| summarize FailedAccounts=dcount(Principal), Attempts=count(), Accounts=make_set(Principal, 25), Apps=make_set(Application, 10), Protocols=make_set(Protocol, 10), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by IPAddress, Location, bin(Timestamp, 1h)
| where FailedAccounts >= 10 and Attempts >= 20
| project FirstSeen, LastSeen, IPAddress, Location, FailedAccounts, Attempts, Accounts, Apps, Protocols
```

**Tuning notes:** Allowlist NAT egress IPs of on-prem gateways, MFA proxies, and legacy service accounts that cause bulk failures after password rotation. Tune FailedAccounts/Attempts thresholds to your tenant size; follow up by joining successful logons from the same IP within the window to identify compromised (likely MFA-less) accounts.
