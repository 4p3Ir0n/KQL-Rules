## 1) ClickFix: Run dialog (RunMRU) populated with script interpreter / download command

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste (ClickFix)  
**Severity:** High  
**Purpose:** ClearFake and IClickFix campaigns instruct victims to paste an attacker-supplied command into the Windows Run dialog. Every pasted command is recorded under Explorer\RunMRU, making this one of the most durable behavioral signals for the ClickFix lure chain regardless of rotating domains.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has "\\Explorer\\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl", "certutil", "bitsadmin", "msiexec", "rundll32", "wscript", "cscript", "conhost", "cmd /c", "cmd.exe /c", "iwr", "irm", "Invoke-WebRequest", "FromBase64String", "-enc", "-w h", "http://", "https://")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountUpn, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Allowlist admin/helpdesk workstations where operators routinely paste management one-liners into Run. Consider a second-stage join to DeviceProcessEvents within 5 minutes on the same DeviceId for higher fidelity. Sysadmin-typed 'cmd /c' with local paths only can be filtered by requiring a URL or encoding keyword.

## 2) Browser or Explorer spawning PowerShell/mshta with remote download-and-execute (ClearFake / EtherHiding)

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** ClearFake, IClickFix and the EtherHiding loaders deliver a fake-update or fake-CAPTCHA lure in the browser, then the user launches a shell that immediately fetches a stage from a compromised/shadowed domain. Detecting the browser/explorer -> shell -> remote fetch lineage catches the family independent of its 391 rotating indicators.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe", "chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "iexplore.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "cmd.exe", "wscript.exe", "cscript.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "msiexec.exe", "rundll32.exe", "node.exe")
| where ProcessCommandLine has_any ("http://", "https://", "FromBase64String", "-enc", "-EncodedCommand", "DownloadString", "DownloadFile", "Invoke-WebRequest", "Invoke-RestMethod", "iwr ", "irm ", "iex", "Start-BitsTransfer", "urlcache", "-urlcache", "WebClient")
| project Timestamp, DeviceId, DeviceName, AccountUpn, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine, FolderPath, SHA256, ReportId
```

**Tuning notes:** Corporate software-portal or intranet URLs can be excluded via `not(ProcessCommandLine has_any (<internal FQDNs>))`. Browser-spawned msiexec for legitimate signed installers is common — pivot on unsigned children or on FolderPath under %TEMP%/%APPDATA%. Raise severity when the child process is followed by an outbound connection from the same PID.

## 3) Hidden-window / headless console execution of PowerShell or MSHTA

**Tactic:** DefenseEvasion  
**ATT&CK:** T1564.003 - Hidden Window  
**Severity:** Medium  
**Purpose:** ClickFix-family pasted commands almost always add window-hiding (conhost.exe --headless, -w hidden, -WindowStyle Hidden, mshta with vbscript:close) so the victim never sees output. This is a compact, family-agnostic evasion signal for the ClearFake/IClickFix/Unknown Loader chains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (FileName =~ "conhost.exe" and ProcessCommandLine has "--headless")
    or (FileName in~ ("powershell.exe", "pwsh.exe") and ProcessCommandLine has_any ("-w hidden", "-w 1", "-windowstyle hidden", "-WindowStyle h", "-noni", "-NonInteractive -NoProfile -Hidden"))
    or (FileName =~ "mshta.exe" and ProcessCommandLine has_any ("vbscript:", "javascript:", "http://", "https://"))
| where InitiatingProcessFileName !in~ ("services.exe", "svchost.exe", "MsMpEng.exe")
| project Timestamp, DeviceId, DeviceName, AccountUpn, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine, FolderPath, SHA256, ReportId
```

**Tuning notes:** Endpoint management agents (SCCM, Intune, Tanium, RMM tools) launch hidden PowerShell constantly — allowlist by InitiatingProcessFileName / signer. conhost --headless is rare outside of ClickFix and Windows Terminal internals; keep that branch at higher severity than the -w hidden branch.

## 4) LNK file in user download/temp path launching a script interpreter

**Tactic:** Execution  
**ATT&CK:** T1204.002 - Malicious File (LNK)  
**Severity:** Medium  
**Purpose:** The fresh 'Unknown malware' cluster (LNK, PDF, FakeAdobe, Dropper, EFIMER tags) relies on shortcut files dropped from archives or fake document downloads that chain into cmd/PowerShell/wscript. Detects the LNK-to-interpreter handoff rather than the disposable payload hashes.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe", "7zfm.exe", "winrar.exe", "7zg.exe", "zipfldr.dll", "OUTLOOK.EXE", "AcroRd32.exe", "Acrobat.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe", "rundll32.exe", "regsvr32.exe", "node.exe", "msiexec.exe")
| where ProcessCommandLine has_any (".lnk", "\\Downloads\\", "\\AppData\\Local\\Temp\\", "Rar$", "7z", "\\AppData\\Roaming\\", "Temp\\Temp1_")
| project Timestamp, DeviceId, DeviceName, AccountUpn, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine, FolderPath, SHA256, ReportId
```

**Tuning notes:** Software packaging teams and installer extraction routinely hit Temp paths — allowlist known deployment shares and signed vendor installers. Consider joining to DeviceFileEvents for a .lnk written within the previous hour on the same device to reduce volume.

## 5) Node.js or script host running from user-writable directory (NodeJS loader / Mythic staging)

**Tactic:** Execution  
**ATT&CK:** T1059.007 - JavaScript  
**Severity:** Medium  
**Purpose:** Recent loader clusters (NodeJS, Mythic, OnyxC2, CTFLoaderService tags) ship a portable node.exe or script bundle into AppData/Temp/ProgramData and execute JS payloads from there. Legitimate Node development runs from Program Files or a project directory, so execution from user-writable staging paths is a strong loader signal.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("node.exe", "wscript.exe", "cscript.exe")
| where FolderPath has_any ("\\AppData\\Local\\Temp\\", "\\AppData\\Roaming\\", "\\ProgramData\\", "\\Users\\Public\\", "\\Downloads\\")
    or ProcessCommandLine has_any ("\\AppData\\Local\\Temp\\", "\\ProgramData\\", "\\Users\\Public\\", "-e require(", "--eval", "-p require(", "child_process")
| project Timestamp, DeviceId, DeviceName, AccountUpn, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, FolderPath, ProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Electron apps and some IDEs ship node.exe under %LOCALAPPDATA%\Programs — allowlist those specific folder paths and signers (e.g. Microsoft VS Code, Slack, Teams). Developers with nvm installs under %APPDATA%\nvm should be excluded per-host or per-group.

## 6) Service created with ImagePath in user-writable directory (CTFLoaderService-style persistence)

**Tactic:** Persistence  
**ATT&CK:** T1543.003 - Windows Service  
**Severity:** High  
**Purpose:** The current loader cluster registers masquerading services (e.g. CTFLoaderService) whose binaries live in Temp/AppData/ProgramData. Service registration pointing at a user-writable path is durable persistence tradecraft independent of the service name used.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has "\\CurrentControlSet\\Services\\"
| where RegistryValueName in~ ("ImagePath", "ServiceDll")
| where RegistryValueData has_any ("\\AppData\\", "\\Temp\\", "\\ProgramData\\", "\\Users\\Public\\", "\\Downloads\\", "powershell", "mshta", "rundll32", "cmd.exe /c", "node.exe", "-enc")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountUpn, InitiatingProcessFileName, InitiatingProcessCommandLine, RegistryKey, RegistryValueName, RegistryValueData, ReportId
```

**Tuning notes:** Some legitimate agents (backup, RMM, printer drivers) install services under %ProgramData% — build an allowlist of known-good ImagePath prefixes. Pair with DeviceProcessEvents for sc.exe/New-Service/PowerShell service creation on the same host for corroboration.

## 7) Zimbra Collaboration Suite mail process spawning shell or download tooling (CVE-2026-73570)

**Tactic:** InitialAccess  
**ATT&CK:** T1190 - Exploit Public-Facing Application  
**Severity:** Critical  
**Purpose:** CVE-2026-73570 lets an unauthenticated attacker inject OS commands via crafted SMTP traffic, executing as the zimbra service account. Any shell, downloader or reverse-shell child of the Zimbra/postfix process tree indicates successful exploitation.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessAccountName in~ ("zimbra", "postfix") 
    or InitiatingProcessFolderPath has "/opt/zimbra" 
    or InitiatingProcessCommandLine has_any ("zmmailboxd", "zmconfigd", "amavisd", "smtpd", "zimbra_")
| where FileName in~ ("sh", "bash", "dash", "zsh", "curl", "wget", "python", "python3", "perl", "php", "nc", "ncat", "netcat", "socat", "chmod", "chattr", "base64", "crontab", "whoami", "id", "openssl", "ssh")
| where ProcessCommandLine has_any ("-c ", "http://", "https://", "/dev/tcp/", "base64", "chmod +x", "| sh", "|sh", "bash -i", "nohup", "curl ", "wget ", "-e /bin/", "crontab -")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine, FolderPath, SHA256, ReportId
```

**Tuning notes:** Zimbra runs many legitimate shell wrappers (zmcontrol, logrotate, zmstat cron jobs) as the zimbra user — allowlist recurring scripts under /opt/zimbra/libexec and /opt/zimbra/bin by exact command line after a baselining period. Requires Defender for Endpoint on Linux with the Zimbra host onboarded.

## 10) Access to developer/CI secret material (.npmrc, .git-credentials, cloud and registry tokens)

**Tactic:** CredentialAccess  
**ATT&CK:** T1552.001 - Credentials In Files  
**Severity:** High  
**Purpose:** SDLC supply-chain intrusions pivot by stealing developer and pipeline credentials stored on disk (npm/registry tokens, git credentials, cloud and container registry configs, SSH keys). Command lines that read or exfiltrate these files are a high-signal credential-access behavior on dev and build endpoints.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "type.exe", "more.com", "findstr.exe", "curl.exe", "tar.exe", "7z.exe", "rar.exe", "certutil.exe", "node.exe", "python.exe", "sh", "bash", "cat", "grep")
| where ProcessCommandLine has_any (".npmrc", ".git-credentials", ".pypirc", ".netrc", ".docker\\config.json", ".docker/config.json", ".aws\\credentials", ".aws/credentials", ".kube\\config", ".kube/config", "id_rsa", "id_ed25519", "NPM_TOKEN", "GITHUB_TOKEN", "GH_TOKEN", "AZURE_CLIENT_SECRET", "gh auth token", "credentials.json", "terraform.tfstate")
| project Timestamp, DeviceId, DeviceName, AccountUpn, InitiatingProcessFileName, InitiatingProcessCommandLine, FileName, ProcessCommandLine, FolderPath, SHA256, ReportId
```

**Tuning notes:** Developers and CI scripts legitimately write .npmrc/.docker config during setup — filter on known provisioning scripts and on write-only operations. Highest fidelity when the same process also makes an external network connection (join DeviceNetworkEvents on InitiatingProcessId) or archives the files.

## 11) Entra ID password spray: single source IP failing against many distinct accounts

**Tactic:** CredentialAccess  
**ATT&CK:** T1110.003 - Password Spraying  
**Severity:** High  
**Purpose:** Operationalizes the SANS ISC guidance on reviewing Entra sign-in logs: identifies one source address generating failed authentications across a large number of distinct accounts within an hour, and flags any successes from that same source (likely the accounts missed by the MFA rollout).

```kusto
IdentityLogonEvents
| where Timestamp > ago(1d)
| where ActionType in ("LogonFailed", "LogonSuccess")
| where isnotempty(IPAddress)
| summarize FailedAccounts = dcountif(AccountUpn, ActionType == "LogonFailed"),
            Failures = countif(ActionType == "LogonFailed"),
            Successes = countif(ActionType == "LogonSuccess"),
            CompromisedCandidates = make_set_if(AccountUpn, ActionType == "LogonSuccess", 20),
            Apps = make_set(Application, 10),
            Countries = make_set(Country, 5)
        by IPAddress, bin(Timestamp, 1h)
| where FailedAccounts >= 15
| project Timestamp, IPAddress, FailedAccounts, Failures, Successes, CompromisedCandidates, Apps, Countries
| order by FailedAccounts desc
```

**Tuning notes:** Tune the FailedAccounts threshold to tenant size (start 15/hour for SMB, 30+ for large tenants). Allowlist NAT egress IPs of the corporate network and known VPN concentrators, or invert the logic to alert only when Successes > 0 from a spraying IP. Extend with legacy-auth Application values to prioritise non-MFA protocols.
