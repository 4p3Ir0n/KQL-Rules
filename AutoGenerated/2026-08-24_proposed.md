## 1) Zimbra service account spawning shell or downloader (CVE-2026-73570 exploitation)

**Tactic:** Execution  
**ATT&CK:** T1190 / T1059.004  
**Severity:** Critical  
**Purpose:** Detects post-exploitation command execution stemming from OS command injection in Zimbra Collaboration Suite, where mail-processing daemons (zmmailboxd/java, postfix/smtpd, amavisd) spawn shells, downloaders, or recon binaries as the 'zimbra' user.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFolderPath has "/opt/zimbra/" or InitiatingProcessAccountName in~ ("zimbra","zimbra-postfix") or InitiatingProcessFileName in~ ("zmmailboxd","amavisd","smtpd","cleanup","local","postfix","zmconfigd")
| where FileName in~ ("sh","bash","dash","zsh","curl","wget","python","python3","perl","nc","ncat","socat","chmod","chattr","base64","whoami","id","uname","crontab")
| where not(ProcessCommandLine has_any ("zmcontrol","zmprov","zmlocalconfig","logrotate"))
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Requires Defender for Endpoint on Linux mail servers. Zimbra legitimately spawns shells for maintenance/cron; baseline for 1-2 weeks and allowlist recurring parent+child+commandline triples (backup scripts, zmstat collectors, log rotation). Escalate immediately on curl/wget/nc/base64 children or any command line containing an external IP or /tmp path.

## 2) ClickFix / ClearFake: attacker-supplied command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClickFix and ClearFake fake-CAPTCHA / fake-update lures instruct victims to press Win+R and paste a malicious command. The pasted string is persisted in the Explorer RunMRU registry key, providing a high-fidelity, IOC-independent detection of the social-engineering step.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryValueCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl ","certutil","bitsadmin","wscript","cscript","rundll32","conhost --headless","cmd /c","cmd.exe /c","iwr","irm","invoke-webrequest","invoke-expression","iex","frombase64string","http://","https://","\\\\","-enc","-w hidden","hidden")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins/developers do type legitimate commands into Run. Allowlist by AccountName for known IT staff, or by exact RegistryValueData strings seen repeatedly across many hosts. The strings 'conhost --headless', 'frombase64string', and any http(s) URL are near-zero false positive and can be promoted to a separate Critical rule.

## 3) Explorer.exe spawning a script interpreter with remote download or obfuscation flags

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Catches the execution stage of ClickFix/ClearFake chains where the user-pasted Run-dialog or clipboard command is launched directly by explorer.exe, producing powershell/mshta/curl children that fetch a stage-2 payload.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","curl.exe","certutil.exe","bitsadmin.exe","msiexec.exe","conhost.exe","node.exe")
| where ProcessCommandLine has_any ("http://","https://","iwr ","irm ","invoke-webrequest","invoke-expression","iex(","iex ","downloadstring","downloadfile","frombase64string","-enc","-encodedcommand","-nop","-w hidden","-windowstyle hidden","--headless","start-process","bypass")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, ProcessId, InitiatingProcessFileName, InitiatingProcessId, ReportId
```

**Tuning notes:** Software deployment shortcuts and IT self-service portals launched from Explorer can match. Allowlist by exact command line or signed script paths under Program Files. Pair with the RunMRU rule on the same DeviceId within 5 minutes to raise confidence to Critical.

## 4) macOS ClickFix: curl/wget piped directly into a shell from Terminal or osascript

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** The macOS variant of ClickFix instructs users to paste a one-liner into Terminal that downloads and pipes a script straight into bash/zsh, or uses osascript to run it. Detects the download-and-execute pattern independent of the hosting domain.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("bash","sh","zsh","osascript","curl","python3")
| where ProcessCommandLine has_any ("curl","wget","nscurl")
| where ProcessCommandLine matches regex @"(?i)(curl|wget)[^|;]*(\||;|&&)\s*(sudo\s+)?(bash|sh|zsh|python3?|osascript)"
    or ProcessCommandLine has_all ("curl", "-o", "chmod")
| where InitiatingProcessFileName in~ ("Terminal","iTerm2","zsh","bash","login","osascript","Safari","Google Chrome","launchd","open")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Join to DeviceInfo on DeviceId to restrict to OSPlatform == 'macOS' if your Linux fleet generates noise. Homebrew, developer bootstrap scripts and MDM onboarding legitimately pipe curl into bash — allowlist by trusted host groups (developer devices) or by known-good domains present in the command line, not by removing the pattern.

## 5) EtherHiding: non-browser process contacting public blockchain RPC endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** High  
**Purpose:** ClearFake, IClickFix and the OffLoader chain use 'EtherHiding' — payload and C2 configuration stored in smart contracts and retrieved through public BNB/Ethereum RPC nodes. A script host or LOLBin (not a browser) resolving or connecting to blockchain RPC infrastructure indicates stage-2 retrieval.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("bsc-dataseed","binance.org","bscrpc","cloudflare-eth.com","infura.io","rpc.ankr.com","publicnode.com","llamarpc","drpc.org","eth.merkle.io","nodereal.io","quiknode.pro","alchemy.com","blastapi.io","chainstack","toncenter.com","ton.org")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","curl.exe","certutil.exe","node.exe","cmd.exe","python.exe","msbuild.exe","installutil.exe")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, RemoteUrl, RemoteIP, RemotePort, ReportId
```

**Tuning notes:** Extend the RPC domain list from your own threat intel; keep browsers out of the process list to avoid drowning in legitimate web3 site traffic. If your organization has legitimate blockchain/web3 development, scope by device group instead of removing the rule. Consider a companion hunt on browser processes writing script files to %TEMP% shortly after an RPC hit.

## 6) Node.js executing inline or temp-directory scripts (NodeJS loader / OnyxC2-style abuse)

**Tactic:** Execution  
**ATT&CK:** T1059.007  
**Severity:** Medium  
**Purpose:** Recent droppers ship a legitimate signed node.exe alongside an obfuscated .js payload, or invoke node with an inline '-e' expression, to defeat script-host blocking and AMSI. Detects node.exe executing code from user-writable staging locations or inline eval.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("node.exe","node")
| where ProcessCommandLine has_any (" -e "," --eval"," -p ","--experimental-network-imports") 
    or ProcessCommandLine has_any (@"\appdata\local\temp",@"\appdata\roaming",@"\programdata",@"\users\public",@"\downloads","/tmp/","/var/tmp/")
| where InitiatingProcessFileName !in~ ("code.exe","devenv.exe","webstorm64.exe","npm.cmd","yarn.cmd")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Developer workstations and Electron apps generate volume — scope to non-developer device groups first, or exclude node.exe instances whose FolderPath sits under Program Files / a signed vendor directory. High-value pivot: node.exe whose FolderPath is itself in %APPDATA% or %TEMP% (copied interpreter) should be Critical.

## 7) Package manager install lifecycle script spawning a shell or downloader (SDLC supply chain)

**Tactic:** Execution  
**ATT&CK:** T1195.002  
**Severity:** High  
**Purpose:** Malicious npm/pip/gem packages execute code through postinstall/setup.py hooks during dependency resolution on developer laptops and CI build agents. Detects package managers spawning shells, downloaders, or encoded PowerShell as a direct child of an install command.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("npm.cmd","npm","npx.cmd","yarn.cmd","pnpm.cmd","node.exe","pip.exe","pip3","python.exe","python3","gem","bundle","dotnet.exe","composer")
| where InitiatingProcessCommandLine has_any (" install"," ci"," add "," restore"," setup.py"," -m pip")
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","curl.exe","certutil.exe","bitsadmin.exe","bash","sh","curl","wget","nc","chmod")
| where ProcessCommandLine has_any ("http://","https://","-enc","-encodedcommand","frombase64string","iex","invoke-expression","downloadstring","/dev/tcp/","base64 -d","| bash","|bash","-w hidden","whoami","env","printenv")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Native module builds (node-gyp, cmake, MSVC) legitimately shell out — allowlist child command lines containing node-gyp/prebuild-install/cl.exe. Run first as a hunt on build agents to learn the baseline; on CI runners any outbound http(s) fetch inside an install hook warrants review. Consider excluding your internal artifact registry hostnames.

## 8) Access to developer and CI/CD secret files by scripting or archiving tools

**Tactic:** CredentialAccess  
**ATT&CK:** T1552.001  
**Severity:** Medium  
**Purpose:** Attackers pivoting through the SDLC harvest cloud, registry and VCS credentials from developer endpoints and build agents (.npmrc, .git-credentials, .aws/credentials, kube config, CI runner tokens). Detects interpreters and archivers reading or bundling these secret stores.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","wscript.exe","cscript.exe","curl.exe","tar.exe","7z.exe","rar.exe","node.exe","python.exe","bash","sh","cat","grep","tar","zip","scp","python3")
| where ProcessCommandLine has_any (".npmrc",".pypirc",".git-credentials",".gitconfig",".aws\\credentials",".aws/credentials",".azure\\accessTokens",".kube\\config",".kube/config",".docker\\config.json",".docker/config.json","id_rsa","id_ed25519",".ssh/config","gh_token","GITHUB_TOKEN","terraform.tfstate",".env.production","runner\\.credentials","secrets.yaml")
| where not(InitiatingProcessFileName in~ ("git.exe","code.exe","devenv.exe") and ProcessCommandLine has ".gitconfig")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Expect legitimate hits from CI bootstrap scripts and developer tooling that writes .npmrc/.docker config. Allowlist known automation accounts and specific pipeline script paths. Prioritize events where the same process also has outbound network activity (join DeviceNetworkEvents on InitiatingProcessId) or where multiple distinct secret paths appear in one command line.

## 9) Linux reverse shell via /dev/tcp or interpreter one-liner (Supershell / Mythic agent staging)

**Tactic:** CommandAndControl  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** Covers the reverse-shell and Socks5 staging behaviour associated with the Supershell/Mythic/OnyxC2 indicators in the feed, and is the most common follow-on from Zimbra-style command injection: a shell or interpreter opening a raw socket back to attacker infrastructure.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("/dev/tcp/","/dev/udp/")
    or (FileName in~ ("nc","ncat","netcat","socat") and ProcessCommandLine has_any (" -e ","exec:","-c ","/bin/sh","/bin/bash"))
    or (FileName in~ ("python","python3","perl","php","ruby") and ProcessCommandLine has_any ("socket.socket","SOCK_STREAM","pty.spawn","fsockopen","IO::Socket::INET"))
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Some monitoring/health-check scripts use /dev/tcp for port probes — allowlist by exact command line and parent script path. Correlate with DeviceNetworkEvents for the same InitiatingProcessId to confirm an external, non-RFC1918 destination; a service account such as 'zimbra', 'www-data' or 'jenkins' as AccountName should be treated as Critical.
