## 1) ClickFix / ClearFake: Run dialog (RunMRU) populated with script interpreter or download command

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClickFix and ClearFake social-engineering lures instruct the victim to paste an attacker-supplied command into the Windows Run dialog. Every pasted command is recorded under HKCU\...\Explorer\RunMRU, making this one of the most durable artifacts of the technique regardless of the payload or C2 infrastructure used.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl ", "certutil", "bitsadmin", "msiexec", "rundll32", "regsvr32", "wscript", "cscript", "conhost", "cmd /c", "cmd.exe /c", "FromBase64String", "iex", "Invoke-WebRequest", "iwr ", "http://", "https://", "\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountUpn, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins and helpdesk staff legitimately type cmd/powershell into Run. Reduce noise by requiring RegistryValueData to also contain a URL, base64 blob, or hidden-window switch, or by excluding known IT-admin accounts/workstations. Long RegistryValueData (strlen > 120) is a strong ClickFix signal since lures pad commands with spaces and fake verification text.

## 2) Script interpreter spawned directly by explorer.exe with remote download or hidden execution

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake/DOUBLECUP lures where the pasted Run-dialog or fake-CAPTCHA command causes explorer.exe to directly spawn PowerShell, mshta, curl, msiexec or similar with a URL, encoded blob, or hidden window.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "cmd.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "certutil.exe", "bitsadmin.exe", "conhost.exe", "node.exe")
| where ProcessCommandLine has_any ("http://", "https://", "-enc", "-ec ", "-e ", "FromBase64String", "Invoke-WebRequest", "iwr ", "Invoke-Expression", "iex ", "Net.WebClient", "DownloadString", "DownloadFile", "-w hidden", "-windowstyle hidden", "-nop", "-noprofile", "bypass", "Start-BitsTransfer", "\\\\")
| project Timestamp, DeviceId, DeviceName, AccountName, AccountUpn, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Allowlist internal software-deployment shortcuts and signed installer wrappers that users launch from the desktop. Some enterprise login scripts run via explorer; scope those out by AccountName or by CommandLine prefix. Consider raising fidelity by requiring both a URL and an execution-policy/hidden-window flag.

## 3) Fake CAPTCHA / 'verify you are human' text embedded in process command line

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClickFix, ClearFake and DOUBLECUP lures pad the pasted command with decoy strings such as a fake Cloudflare Ray ID, checkmark glyphs, or 'I am not a robot' comments so the victim believes they are completing a human-verification step. Detecting the lure text itself is payload-agnostic.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "conhost.exe", "msiexec.exe", "curl.exe")
| where ProcessCommandLine has_any ("I am not a robot", "not a robot", "human verification", "Verification ID", "Ray ID", "Cloudflare Verification", "verify you are human", "reCAPTCHA", "Captcha Verification", "✅", "✔", "# Windows Security", "Verification Code:")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, SHA256, ReportId
```

**Tuning notes:** Very low false-positive rate; treat any hit as high confidence. Extend the string list as new lure themes appear (fake Chrome update, fake Teams/Zoom meeting error, fake printer driver). Note that unicode glyph matching requires the sensor to preserve the original command line encoding.

## 4) PNG/image file used as payload carrier by script interpreter (DOUBLECUP loader pattern)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1027.003  
**Severity:** High  
**Purpose:** The DOUBLECUP loader and similar ClickFix-delivered stagers fetch a PNG/JPG/GIF that actually contains an appended or base64-encoded payload, then decode it in memory. Detects interpreters referencing image files together with download, decode, or pixel-extraction primitives.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "wscript.exe", "cscript.exe", "node.exe", "rundll32.exe", "cmd.exe", "curl.exe", "certutil.exe")
| where ProcessCommandLine has_any (".png", ".jpg", ".jpeg", ".gif", ".bmp", ".svg", ".webp")
| where ProcessCommandLine has_any ("FromBase64String", "DownloadData", "DownloadString", "DownloadFile", "Invoke-WebRequest", "iwr ", "WebClient", "GetPixel", "LockBits", "Drawing.Bitmap", "System.Drawing", "[Reflection.Assembly]", "Load(", "IEX", "Invoke-Expression", "-decode", "Convert]::", "Substring")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Legitimate image-processing or reporting scripts (SCCM, monitoring dashboards, PDF generators) can match on System.Drawing/Bitmap. Allowlist by signed script path or by InitiatingProcessFileName for known automation hosts. Pair with a follow-on check for a new executable/DLL written within 5 minutes on the same device to escalate priority.

## 5) Non-browser process contacting blockchain RPC or edge-worker infrastructure (EtherHiding)

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** Medium  
**Purpose:** ClearFake/IClickFix ('etherhiding', 'nochain') retrieve payload URLs from smart contracts via public blockchain RPC endpoints, and the shin_webshell cluster uses Cloudflare workers.dev/trycloudflare domains for C2. Script interpreters or LOLBins talking to these services is anomalous on endpoints.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "node.exe", "rundll32.exe", "regsvr32.exe", "msiexec.exe", "cmd.exe", "conhost.exe", "certutil.exe", "bitsadmin.exe")
| where RemoteUrl has_any ("bsc-dataseed", "binance.org", "cloudflare-eth", "publicnode.com", "llamarpc.com", "drpc.org", "ankr.com", "infura.io", "alchemy.com", "quiknode", "toncenter", "ton.org", "workers.dev", "trycloudflare.com", "pages.dev")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, RemoteUrl, RemoteIP, RemotePort, ReportId
```

**Tuning notes:** Exclude developer/blockchain workstations and CI agents where node.exe legitimately reaches RPC providers. workers.dev and pages.dev are also used by legitimate SaaS; consider splitting blockchain RPC (higher fidelity) from edge-worker domains (hunt only). RemoteUrl is only populated when the sensor sees the hostname — supplement with DeviceEvents DnsQuery data where available.

## 6) Web server process spawning a command shell (webshell execution)

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** Critical  
**Purpose:** Detects post-exploitation command execution through a webshell — including the php.shin_webshell WordPress/wp-admin cluster and exploitation of Oracle HTTP Server / WebLogic Proxy Plug-in improper access control (CVE-2026-21962) — by flagging shells or recon binaries whose parent is a web/application server process.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("w3wp.exe", "httpd.exe", "nginx.exe", "php.exe", "php-cgi.exe", "php-fpm.exe", "tomcat.exe", "tomcat9.exe", "java.exe", "javaw.exe", "beasvc.exe", "node.exe", "apache.exe", "ohs.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "bash.exe", "sh.exe", "wscript.exe", "cscript.exe", "net.exe", "net1.exe", "whoami.exe", "ipconfig.exe", "systeminfo.exe", "tasklist.exe", "nltest.exe", "certutil.exe", "bitsadmin.exe", "curl.exe", "reg.exe", "schtasks.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Some application stacks legitimately shell out (build servers, monitoring plugins, Java apps invoking cmd for maintenance). Baseline per-server: allowlist specific parent command lines or child command lines rather than whole hosts. For Oracle environments, confirm the java.exe parent is a WebLogic/OHS instance by checking InitiatingProcessCommandLine for 'weblogic.Server' or the Oracle middleware home path.

## 7) Web-executable file written into a web root by a web server or exploit process

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** High  
**Purpose:** Catches webshell drops (php.shin_webshell targeting wp-admin/WordPress paths, and post-exploitation of Oracle HTTP Server/WebLogic proxy plug-in) where the server process itself writes a new .php/.jsp/.aspx file into a content directory.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileModified", "FileRenamed")
| where FileName endswith ".php" or FileName endswith ".php5" or FileName endswith ".phtml" or FileName endswith ".jsp" or FileName endswith ".jspx" or FileName endswith ".aspx" or FileName endswith ".ashx" or FileName endswith ".asp"
| where InitiatingProcessFileName in~ ("w3wp.exe", "httpd.exe", "nginx.exe", "php.exe", "php-cgi.exe", "php-fpm.exe", "java.exe", "javaw.exe", "tomcat.exe", "beasvc.exe", "node.exe", "powershell.exe", "cmd.exe", "certutil.exe", "curl.exe", "bitsadmin.exe")
| where FolderPath has_any ("\\wwwroot", "\\htdocs", "\\www", "\\wp-content", "\\wp-admin", "\\wp-includes", "\\webapps", "\\servers\\", "\\public_html", "\\inetpub", "\\Oracle\\Middleware", "\\user_projects")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, RequestAccountName, ReportId
```

**Tuning notes:** CMS auto-updates, plugin installs, and CI/CD deployments will generate bursts of matches — allowlist deployment service accounts and correlate with change windows. Single-file writes outside maintenance windows, files with random names, or files dropped into wp-admin/wp-includes (which rarely change outside a core update) are the highest-value hits.
