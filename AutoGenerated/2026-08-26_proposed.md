## 1) Git hook script planted in repository (possible Gitea diffpatch code injection - CVE-2026-60004)

**Tactic:** Persistence  
**ATT&CK:** T1546  
**Severity:** High  
**Purpose:** CVE-2026-60004 lets an attacker with repo write access submit a malicious patch to the Gitea diffpatch API that writes an executable Git hook, which then runs shell commands as the Gitea service account. This detects hook-file writes inside repository/hook directories, especially those performed by the Gitea service process itself.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileModified", "FileRenamed")
| where FolderPath has_any ("hooks", "custom_hooks", "git-hooks")
| where FolderPath has_any (@"\.git\", "/.git/", ".git/hooks", "gitea-repositories", @"gitea\", "/gitea/")
| where FileName in~ ("pre-receive", "post-receive", "update", "post-update", "pre-commit", "pre-push", "post-merge", "proc-receive")
    or FileName endswith ".sh" or FileName endswith ".bat" or FileName endswith ".cmd" or FileName endswith ".ps1"
| extend GiteaWritten = InitiatingProcessFileName has "gitea" or InitiatingProcessParentFileName has "gitea"
| project Timestamp, DeviceName, ActionType, FileName, FolderPath, SHA256, GiteaWritten, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Legitimate CI/CD, repo-provisioning automation and Gitea upgrades also write hook files - baseline the accounts and parent processes that normally do this (e.g. deployment agents, Ansible/Chef, package managers) and exclude them. Where Gitea is containerized, hook paths may be under /data/gitea-repositories; extend the FolderPath list to match your deployment. Highest fidelity when GiteaWritten == true and the writing account is the Gitea service account.

## 2) Gitea service account spawning shell or download utility (CVE-2026-60004 exploitation)

**Tactic:** Execution  
**ATT&CK:** T1059  
**Severity:** Critical  
**Purpose:** Successful exploitation of the Gitea diffpatch code-injection flaw results in shell commands executing as the Gitea service account via a planted Git hook. This detects Gitea (or git invoked by Gitea) parenting interpreters, download tools, or reconnaissance commands.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("gitea", "git", "git.exe", "gitea.exe")
    or InitiatingProcessParentFileName has "gitea"
| where FileName in~ ("sh", "bash", "dash", "zsh", "cmd.exe", "powershell.exe", "pwsh.exe", "python", "python3", "perl", "ruby", "php", "curl", "curl.exe", "wget", "nc", "ncat", "socat", "base64", "chmod", "whoami", "id", "crontab", "certutil.exe", "bitsadmin.exe")
| where not(ProcessCommandLine has_any ("git-upload-pack", "git-receive-pack", "git-lfs", "hooks/update --"))
| project Timestamp, DeviceName, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Gitea legitimately spawns git and sometimes sh for hooks/LFS; baseline normal hook activity per server for a week and allowlist known hook script paths and command lines. Elevate severity when the child is a reverse-shell pattern (nc/socat/bash -i), when chmod +x is followed by execution from a repo path, or when outbound network activity from the same process is seen in DeviceNetworkEvents.

## 3) Oracle HTTP Server / WebLogic proxy plug-in spawning command interpreter

**Tactic:** InitialAccess  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** CVE-2026-21962 (improper access control in Oracle HTTP Server / WebLogic Proxy Plug-in) can give unauthorized read/write access to server data; post-exploitation typically manifests as the web tier executing OS commands or dropping web shells. Detects shell/LOLBin children of the HTTP server or WebLogic JVM.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("httpd", "httpd.exe", "ohs", "nodemanager", "java", "java.exe", "javaw.exe")
| where InitiatingProcessCommandLine has_any ("weblogic", "WebLogic", "ohs", "oracle_common", "Oracle_WT", "mod_wl", "DomainHome", "instances/ohs")
    or InitiatingProcessFileName in~ ("httpd", "httpd.exe", "ohs")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "sh", "bash", "ksh", "perl", "python", "python3", "curl", "curl.exe", "wget", "certutil.exe", "bitsadmin.exe", "whoami", "whoami.exe", "net.exe", "net1.exe", "nltest.exe", "nc", "ncat", "socat", "chmod", "tar", "base64")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessId, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Oracle middleware start/stop scripts legitimately spawn sh/cmd and java wrappers - allowlist known WLST/nodemanager command lines and scheduled maintenance windows. Consider pairing with DeviceFileEvents for new .jsp/.jspx/.war files under the OHS htdocs or WebLogic servers/*/tmp directories to catch web shell drops.

## 4) ClickFix / ClearFake: command pasted into Windows Run dialog (RunMRU) launching an interpreter

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClickFix and ClearFake lures instruct victims to paste a command into the Win+R Run dialog, which persists the command in the Explorer RunMRU registry key. Detects script-interpreter / download-utility strings written to RunMRU, a high-fidelity artifact of the paste-and-run social engineering chain.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "cmd /c", "cmd.exe /c", "curl ", "msiexec", "rundll32", "regsvr32", "forfiles", "conhost", "wscript", "cscript", "bitsadmin", "certutil", "iex", "invoke-expression", "invoke-webrequest", "downloadstring", "frombase64string", "-enc", "-w h", "-windowstyle hidden", "http://", "https://", "\\\\")
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins and helpdesk staff legitimately type cmd/powershell into Run - suppress bare values such as "cmd", "powershell", "mmc", "\\\\server\\share" and focus alerting on values containing URLs, encoded blobs, hidden-window flags, or unusual padding/whitespace used to hide the payload. Correlate with a matching DeviceProcessEvents child of explorer.exe within 60 seconds to confirm execution.

## 5) Explorer-parented interpreter with remote download or encoded payload (ClickFix paste-and-run execution)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Confirms the ClickFix/ClearFake execution stage: explorer.exe (Run dialog or clipboard paste in a terminal) directly spawning PowerShell, mshta, cmd, curl or msiexec with URL, encoded, or hidden-window arguments to stage the dropper.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe", "conhost.exe", "wt.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "cmd.exe", "curl.exe", "msiexec.exe", "wscript.exe", "cscript.exe", "rundll32.exe", "regsvr32.exe", "bitsadmin.exe", "certutil.exe", "forfiles.exe")
| where ProcessCommandLine has_any ("http://", "https://", "iex", "invoke-expression", "downloadstring", "downloadfile", "invoke-webrequest", "irm ", "iwr ", "frombase64string", "-enc", "-encodedcommand", "-w h", "windowstyle hidden", "-nop", "bypass", "start-process", "curl ", "\\\\")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, ProcessCreationTime, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Developer and IT workstations generate benign hits (manual PowerShell with -nop/bypass, curl testing). Scope to non-admin user populations first, or require two or more of: URL + hidden window + encoded command. Add allowlists for signed internal tooling launched from Explorer and for known software-install msiexec URLs.

## 6) Script interpreter contacting public blockchain RPC or CDN endpoints (ClearFake / EtherHiding staging)

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** Medium  
**Purpose:** ClearFake and related ClickFix clusters use EtherHiding - reading payloads from smart contracts through public blockchain RPC nodes - and pull second stages from public CDNs such as jsDelivr. Detects PowerShell/script hosts and LOLBins making these outbound requests, which is abnormal for endpoint interpreters.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "wscript.exe", "cscript.exe", "cmd.exe", "curl.exe", "rundll32.exe", "regsvr32.exe", "msiexec.exe", "node.exe")
| where RemoteUrl has_any ("bsc-dataseed", "binance.org", "bnbchain", "cloudflare-eth", "llamarpc", "publicnode.com", "drpc.org", "ankr.com", "infura.io", "alchemy.com", "quiknode", "jsdelivr.net", "statically.io", "raw.githack", "pages.dev", "workers.dev", "r2.dev")
| summarize ConnectionCount = count(), RemoteUrls = make_set(RemoteUrl, 20), RemoteIPs = make_set(RemoteIP, 20), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessId
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, ConnectionCount, RemoteUrls, RemoteIPs
```

**Tuning notes:** Crypto/web3 developers and node.exe build tooling legitimately reach RPC and CDN hosts - exclude engineering device groups or specific repos/build agents. jsDelivr is also used by legitimate software updaters; require the interpreter to be explorer-parented or short-lived for higher fidelity. Keep the RPC-provider list in a watchlist function rather than inline so it can be updated.

## 7) Autorun registry value pointing to a user-writable directory (RAT persistence, e.g. Overlord RAT)

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** Medium  
**Purpose:** Commodity RATs such as Overlord RAT persist by writing Run/RunOnce (or Winlogon shell) values that launch a payload staged in AppData, Temp, ProgramData or Public. Detects that behavior independent of the family's rotating hashes and C2 domains.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has_any (@"CurrentVersion\Run", @"CurrentVersion\RunOnce", @"CurrentVersion\Policies\Explorer\Run", @"Winlogon\Shell", @"Winlogon\Userinit")
| where RegistryValueData has_any (@"\AppData\", @"\Local\Temp\", @"\Roaming\", @"\ProgramData\", @"\Users\Public\", @"\Downloads\", @"\Windows\Temp\")
    or RegistryValueData has_any ("powershell", "mshta", "rundll32", "regsvr32", "wscript", "cscript", "-enc", "frombase64string", "http://", "https://")
| project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Legitimate per-user apps (Teams, OneDrive, Slack, Chrome updaters, some VPN clients) install Run values under AppData - build an allowlist of known-good value names plus signed publisher paths. Prioritize entries written by unsigned processes, by interpreters, or where the referenced file was created in the last 24 hours (join to DeviceFileEvents on SHA256/FolderPath).

## 8) Unexpected process querying cloud instance metadata service (169.254.169.254)

**Tactic:** CredentialAccess  
**ATT&CK:** T1552.005  
**Severity:** High  
**Purpose:** SSRF and post-exploitation credential theft frequently target the link-local instance metadata service to obtain cloud IAM tokens. Detects connections to 169.254.169.254 from interpreters, LOLBins or web/application server processes rather than the sanctioned cloud guest agents.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteIP in ("169.254.169.254", "fd00:ec2::254", "169.254.170.2") or RemoteUrl has_any ("metadata.google.internal", "169.254.169.254", "instance-data")
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "curl.exe", "wget.exe", "python.exe", "python3", "perl", "php", "java", "java.exe", "httpd", "httpd.exe", "nginx", "w3wp.exe", "node.exe", "sh", "bash", "mshta.exe", "rundll32.exe", "certutil.exe", "bitsadmin.exe")
| summarize Attempts = count(), RemoteUrls = make_set(RemoteUrl, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessId
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, Attempts, RemoteUrls
```

**Tuning notes:** Allowlist sanctioned cloud agents and SDK-based apps that legitimately fetch instance credentials (WindowsAzureGuestAgent, AWS SSM/CloudWatch agents, google_guest_agent, kubelet, application pools intentionally using instance roles). Web/app server processes (w3wp, java, httpd, php) hitting metadata are the highest-signal cases and suggest SSRF or web shell activity.

## 9) Android Debug Bridge (adb) used to connect to remote devices or push/install payloads

**Tactic:** LateralMovement  
**ATT&CK:** T1021  
**Severity:** Medium  
**Purpose:** Recent dropper activity tagged ADB/Android/IoT abuses exposed ADB (tcp/5555) to deploy payloads to Android and IoT devices. Detects adb.exe on managed endpoints performing remote connect, push, install or shell operations - rare outside mobile development.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("adb.exe", "adb") or ProcessCommandLine has_any (" adb connect", "adb.exe connect", "adb -s ", "adb tcpip")
| where ProcessCommandLine has_any ("connect ", "tcpip", " push ", " install ", " shell ", "forward", "reverse", ":5555", ":5037")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Exclude known mobile-development and QA device groups, and adb binaries shipped inside Android Studio/SDK platform-tools paths used by developer accounts. Treat adb executed from Temp/AppData/Downloads, launched by an interpreter or Office app, or targeting internet-routable IPs on port 5555 as high severity; correlate with DeviceNetworkEvents on RemotePort 5555.
