## 1) ClickFix: Run dialog (RunMRU) contains download/execution command

**Tactic:** Execution  
**ATT&CK:** T1204.004 - User Execution: Malicious Copy and Paste  
**Severity:** High  
**Purpose:** ClearFake / IClickFix and similar 'ClickFix' lures instruct the victim to paste a command into the Windows Run dialog. Windows records pasted commands in the Explorer RunMRU registry key, making this one of the most durable forensic signals of a ClickFix infection.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","rundll32","msiexec","cmd /c","cmd.exe /c","conhost","wscript","cscript","forfiles","http://","https://","iex","invoke-expression","invoke-webrequest","frombase64string","-enc","-w h","hidden","\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Very low volume in most environments. Allowlist admin/helpdesk accounts that legitimately paste UNC paths or 'cmd' into Run. Consider removing generic terms like '\\\\' and 'cmd /c' first if noisy. Correlate the same DeviceId with DeviceProcessEvents within +/-5 minutes to confirm execution.

## 2) ClickFix: Explorer spawning interpreter with download/hidden-execution flags

**Tactic:** Execution  
**ATT&CK:** T1059.001 - Command and Scripting Interpreter: PowerShell  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake social engineering where explorer.exe (Run dialog / File Explorer address bar) directly launches a script interpreter or LOLBin with staging flags.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","msiexec.exe","rundll32.exe","regsvr32.exe","bitsadmin.exe","certutil.exe")
| where ProcessCommandLine has_any ("-w hidden","-windowstyle hidden","-nop","-noprofile","-enc","-encodedcommand","frombase64string","iex","invoke-expression","invoke-webrequest","invoke-restmethod","downloadstring","downloadfile","http://","https://","\\\\", "start-process","webclient")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** Legitimate double-clicked .bat/.cmd/.msi files launched from Explorer will also parent from explorer.exe - allowlist known internal script paths and software-deployment MSIs by SHA256/FolderPath. Tighten by requiring ProcessCommandLine length > 150 characters, which is typical of pasted ClickFix payloads.

## 3) IClickFix: PowerShell fetching payload from public CDN / code-hosting service and piping to execution

**Tactic:** CommandAndControl  
**ATT&CK:** T1105 - Ingress Tool Transfer  
**Severity:** High  
**Purpose:** IClickFix/ClearFake droppers stage second-stage PowerShell from jsdelivr, raw.githubusercontent and similar CDNs (including EtherHiding-served scripts) and immediately execute it in memory.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe")
| where ProcessCommandLine has_any ("jsdelivr","raw.githubusercontent","gitcdn","statically.io","pastebin","paste.ee","bitbucket.org","gitlab.io","githubusercontent","workers.dev","r2.dev","pages.dev","blob.core.windows.net","ipfs")
| where ProcessCommandLine has_any ("iex","invoke-expression","downloadstring","invoke-restmethod","irm ","invoke-webrequest","iwr ","| powershell","frombase64string","start-process","-o ","-outfile")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
| order by Timestamp desc
```

**Tuning notes:** Developer workstations legitimately curl from jsdelivr/github - scope out engineering device groups or require the parent to be explorer.exe/browser/office process. Extend the CDN list as new abuse infrastructure appears; do not rely on the specific ThreatFox domains as they rotate daily.

## 4) Browser process spawning script interpreter or LOLBin (ClearFake / EtherHiding chain)

**Tactic:** Execution  
**ATT&CK:** T1059.003 - Command and Scripting Interpreter: Windows Command Shell  
**Severity:** Medium  
**Purpose:** ClearFake injects fake-update/fake-CAPTCHA overlays into compromised sites; the resulting execution frequently appears as a browser process spawning cmd/powershell/mshta or a dropped binary from the downloads folder.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","iexplore.exe","msedgewebview2.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","msiexec.exe","hh.exe")
   or (FolderPath has_any ("\\Downloads\\","\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\ProgramData\\") and FileName endswith ".exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** Browser self-updaters and enterprise SSO/PDF helpers will trigger; allowlist signed updater paths (e.g. GoogleUpdate, MicrosoftEdgeUpdate) and known internal .exe SHA256s. Consider dropping the Downloads-folder clause first if volume is high, keeping only interpreter children.

## 5) RAT persistence: autorun value pointing to user-writable directory

**Tactic:** Persistence  
**ATT&CK:** T1547.001 - Registry Run Keys / Startup Folder  
**Severity:** High  
**Purpose:** Commodity RATs such as Overlord RAT and ClickFix-delivered droppers persist by writing a Run/RunOnce value that references a binary or script staged in Temp, AppData, ProgramData or Public.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\Windows\CurrentVersion\Policies\Explorer\Run", @"\Winlogon\Shell", @"\Winlogon\Userinit")
| where RegistryValueData has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\AppData\\Local\\","\\ProgramData\\","\\Users\\Public\\","\\Windows\\Temp\\","powershell","mshta","wscript","cscript","rundll32","regsvr32","curl","cmd /c")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** Several legitimate apps (Teams, OneDrive, Slack, Zoom, Spotify) install into AppData - allowlist by InitiatingProcessFolderPath/RegistryValueData substring. Prioritise events whose InitiatingProcessFileName is a script host or an unsigned binary in a temp path.

## 6) Beaconing from binary in temp/user-writable path to external non-standard port

**Tactic:** CommandAndControl  
**ATT&CK:** T1571 - Non-Standard Port  
**Severity:** Medium  
**Purpose:** Behavioural detection of RAT C2 (Overlord RAT, HemiGate/Dumplings RAT style implants) that run from Temp/AppData/ProgramData and beacon repeatedly to an ip:port combination outside common web ports.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess","ConnectionAttempt")
| where RemoteIPType == "Public"
| where RemotePort !in (80, 443, 53, 123, 22, 25, 587, 993, 995, 8443)
| where InitiatingProcessFolderPath has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\ProgramData\\","\\Users\\Public\\","\\Windows\\Temp\\","\\Downloads\\")
| summarize ConnectionCount = count(), DistinctPorts = dcount(RemotePort), FirstSeen = min(Timestamp), LastSeen = max(Timestamp), SamplePorts = make_set(RemotePort, 10), RemoteIPs = make_set(RemoteIP, 10)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName
| where ConnectionCount >= 5
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, ConnectionCount, DistinctPorts, SamplePorts, RemoteIPs
| order by ConnectionCount desc
```

**Tuning notes:** Allowlist game launchers, updaters and conferencing clients that legitimately run from AppData and use high ports. Raise ConnectionCount or add regular-interval (beacon jitter) analysis with a stdev of inter-arrival times to reduce false positives.

## 7) IIS worker process (w3wp.exe) spawning command shell - .NET deserialization RCE

**Tactic:** InitialAccess  
**ATT&CK:** T1190 - Exploit Public-Facing Application  
**Severity:** Critical  
**Purpose:** Exploitation of .NET deserialization flaws such as CVE-2021-23758 in Ajax.NET Professional results in code execution inside the IIS worker process; the first observable is w3wp.exe spawning a shell or LOLBin.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("w3wp.exe","aspnet_wp.exe","httpd.exe","tomcat.exe")
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","net.exe","net1.exe","whoami.exe","nltest.exe","ipconfig.exe","systeminfo.exe","curl.exe","schtasks.exe","sc.exe","reg.exe","csc.exe")
```

**Tuning notes:** Some web apps legitimately shell out (report generation, csc.exe for runtime compilation of ASPX views). Baseline per-server: allowlist recurring benign command lines by hash of ProcessCommandLine, but never allowlist whoami/net/certutil. Pair with DeviceFileEvents for new .aspx/.ashx files written by w3wp for webshell follow-up.

## 8) AI gateway / Python web service spawning shell or download utility

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Command and Scripting Interpreter: Unix Shell  
**Severity:** High  
**Purpose:** Per Microsoft Threat Intelligence, exposed AI workloads (e.g. LiteLLM gateways) are exploited to run OS commands; the endpoint signal is the Python/Node service process spawning a shell, curl/wget or chmod.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("python","python3","uvicorn","gunicorn","litellm","node","ollama","vllm","streamlit","jupyter")
| where FileName in~ ("sh","bash","dash","zsh","curl","wget","chmod","chattr","nohup","nc","ncat","socat","base64","crontab","useradd","ssh-keygen")
   or ProcessCommandLine has_any ("/dev/tcp/","bash -i","sh -i","| base64 -d","curl -s http","wget -q http")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
| order by Timestamp desc
```

**Tuning notes:** ML/ops containers legitimately shell out during model pulls and pip installs - allowlist known deployment command lines and CI/CD hosts, or exclude events whose parent command line matches the pip/conda install pattern. Prioritise events on internet-facing gateway hosts.

## 9) Cryptomining execution on server workloads (stratum / miner arguments)

**Tactic:** Impact  
**ATT&CK:** T1496 - Resource Hijacking  
**Severity:** High  
**Purpose:** Follow-on stage of exposed AI-infrastructure and web-service compromise: attackers deploy XMRig-style miners. Detects mining pool arguments and miner binaries regardless of file name.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("stratum+tcp","stratum+ssl","stratum1+tcp","--donate-level","--cpu-priority","--nicehash","--coin=monero","randomx","xmrig","--rig-id","-o pool.","--algo=rx/0","minerd","ethminer","nbminer","cpuminer")
   or FileName in~ ("xmrig","xmrig.exe","minerd","nbminer","ethminer","t-rex","phoenixminer.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** Near-zero false positives outside sanctioned crypto research/GPU benchmarking hosts - allowlist those device groups. Complement with DeviceNetworkEvents on common pool ports (3333, 4444, 5555, 7777, 14444) for miners using config files instead of CLI arguments.

## 10) Enumeration of API keys and .env secrets on AI/application hosts

**Tactic:** CredentialAccess  
**ATT&CK:** T1552.001 - Credentials In Files  
**Severity:** Medium  
**Purpose:** Attackers exploiting AI gateways harvest provider API keys, .env files and cloud credentials before establishing persistence. Detects command-line access to secret stores from server processes.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cat","grep","egrep","find","strings","tar","zip","awk","sed","head","more","type","powershell.exe","pwsh.exe")
| where ProcessCommandLine has_any (".env","credentials.json","config.yaml","litellm_config","OPENAI_API_KEY","ANTHROPIC_API_KEY","AZURE_OPENAI","AWS_SECRET_ACCESS_KEY","/root/.aws/","/.aws/credentials","/.ssh/id_","/.kube/config","/.docker/config.json","master_key","api_key")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Developer and CI/CD activity is the main noise source; scope this rule to production/internet-facing AI gateway device groups and exclude known automation accounts. Escalate when the parent process is a web service (python/uvicorn/node) or a reverse shell.

## 11) Linux local privilege escalation: root process spawned by non-root parent or setuid bit set

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1548.001 - Abuse Elevation Control Mechanism: Setuid and Setgid  
**Severity:** High  
**Purpose:** Covers exploitation outcomes of local Linux privesc flaws such as CVE-2022-0995 (kernel OOB write), CVE-2015-5287 (ABRT symlink) and CVE-2015-3246 (libuser): an unprivileged user obtaining a root shell or dropping a setuid binary.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where isnotempty(InitiatingProcessAccountName)
| where (AccountName == "root" and InitiatingProcessAccountName !in ("root","") and FileName in~ ("bash","sh","dash","zsh","ksh","python","python3","perl"))
   or (ProcessCommandLine has_any ("chmod u+s","chmod 4755","chmod 4777","chown root") and ProcessCommandLine has_any ("/tmp/","/var/tmp/","/dev/shm/","/home/"))
| project Timestamp, DeviceId, DeviceName, AccountName, InitiatingProcessAccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** sudo/su, pkexec and configuration-management agents (ansible, puppet, chef) legitimately produce root children from non-root parents - allowlist those InitiatingProcessFileName values after baselining. Focus on cases where the parent is a web service, a binary in /tmp, or an unknown compiled file.

## 12) Unexpected modification of /etc/passwd, /etc/shadow or sudoers

**Tactic:** Persistence  
**ATT&CK:** T1098 - Account Manipulation  
**Severity:** High  
**Purpose:** Corruption or modification of /etc/passwd is the exploitation outcome of the libuser race condition (CVE-2015-3246) and a common post-exploitation persistence step on Linux hosts including compromised AI/application servers.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FolderPath has_any ("/etc/passwd","/etc/shadow","/etc/sudoers","/etc/sudoers.d/","/etc/gshadow","/etc/group")
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where InitiatingProcessFileName !in~ ("useradd","usermod","userdel","groupadd","groupmod","passwd","chpasswd","vipw","vigr","pwconv","systemd-sysusers","dpkg","rpm","yum","dnf","apt","apt-get")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, FolderPath, FileName, ActionType, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** Add your configuration-management tooling (ansible-tmp scripts, puppet, salt-minion, cloud-init) to the exclusion list after review. Editors such as vi/nano writing these files by an interactive non-admin session should be treated as high priority.
