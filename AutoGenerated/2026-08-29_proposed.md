## 1) ClickFix: Explorer-spawned script interpreter with download/exec command line

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** Detects the core ClickFix/ClearFake/IClickFix social-engineering pattern where a victim pastes an attacker-supplied command into the Windows Run dialog or terminal, causing explorer.exe to directly spawn a script host or download utility with remote-payload retrieval logic.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","certutil.exe","msiexec.exe","wscript.exe","cscript.exe","bitsadmin.exe","rundll32.exe","regsvr32.exe","conhost.exe","wt.exe")
| where ProcessCommandLine has_any ("iex","invoke-expression","downloadstring","downloadfile","frombase64string","-enc","-encodedcommand","hidden","webclient","iwr","invoke-webrequest","curl ","http://","https://","msiexec /i","start-process","-nop","bypass", @"\\")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, ReportId
| order by Timestamp desc
```

**Tuning notes:** explorer.exe spawning cmd.exe/wt.exe is normal for power users; consider dropping cmd.exe/conhost.exe from FileName list or requiring the network-download keywords only. Allowlist internal admin scripts run from Run dialog by IT staff accounts. Pair with the RunMRU registry detection for higher confidence.

## 2) ClickFix: Run dialog MRU history contains download or encoded payload command

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** ClickFix lures instruct victims to press Win+R and paste a command, which Windows records under Explorer\RunMRU. Detecting suspicious RunMRU values provides durable forensic evidence of the lure even if the payload process is short-lived.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl ","certutil","bitsadmin","msiexec","rundll32","regsvr32","wscript","cscript","frombase64string","iex","invoke-webrequest","downloadstring","http://","https://", @"\\")
| project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Legitimate admin usage (e.g. \\fileserver\share UNC paths, mmc, control panel) will surface; allowlist known internal UNC prefixes and hosts belonging to IT staff. Values ending in a long run of spaces before a fake 'verification ID' comment are a strong ClickFix signal worth promoting to Critical.

## 3) EtherHiding: script host or browser child process contacting blockchain RPC endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** Medium  
**Purpose:** ClearFake/Unknown Loader campaigns use EtherHiding, storing loader stages in smart contracts on BSC/Ethereum/Sepolia and fetching them through public RPC gateways. Non-browser processes talking to blockchain RPC endpoints is a strong C2/stager indicator.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","curl.exe","node.exe","msbuild.exe","cmd.exe")
| where RemoteUrl has_any ("bsc-dataseed","binance.org","sepolia","infura.io","alchemy.com","cloudflare-eth","drpc.org","publicnode.com","ankr.com","llamarpc","quicknode","web3")
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, RemoteUrl, RemoteIP, RemotePort, ReportId
| order by Timestamp desc
```

**Tuning notes:** Exclude developer or blockchain-engineering workstations where node.exe/curl legitimately reach RPC providers. If RemoteUrl is frequently empty in your tenant, join to DeviceNetworkEvents RemoteIP reputation or add the provider IP ranges. Keep the provider keyword list in a watchlist for easy updates.

## 4) TerminalFix: DLL sideloaded from user-writable directory alongside the host binary

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.002  
**Severity:** High  
**Purpose:** The TerminalFix campaign drops a legitimate signed executable together with a malicious DLL in a user-writable folder so the DLL is loaded via search-order hijacking. This detects image loads where the loading binary and the DLL reside in the same non-system, user-writable directory.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FolderPath endswith ".dll"
| extend DllDir = tolower(extract(@"^(.*)\\[^\\]+$", 1, FolderPath))
| extend ProcDir = tolower(extract(@"^(.*)\\[^\\]+$", 1, InitiatingProcessFolderPath))
| where isnotempty(DllDir) and DllDir == ProcDir
| where DllDir has_any (@"\appdata\local\temp", @"\appdata\roaming", @"\appdata\local\", @"\downloads", @"\public", @"\programdata", @"\users\", @"\windows\temp")
| where InitiatingProcessFolderPath !startswith "C:\\Windows\\" and InitiatingProcessFolderPath !startswith "C:\\Program Files"
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, FileName, FolderPath, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Portable apps, installers, Electron/updater frameworks and self-extracting archives in %TEMP% generate benign hits; allowlist by InitiatingProcessFileName + SHA256 pairs. Enrich by joining DeviceFileEvents to see whether the exe and dll were written within minutes of each other by an archive/browser process (much stronger signal).

## 5) Web server process spawning command shell or recon utility (webshell execution)

**Tactic:** Execution  
**ATT&CK:** T1505.003  
**Severity:** Critical  
**Purpose:** Detects PHP/IIS/Apache/Nginx worker processes launching shells or discovery tools, the canonical execution trace of a webshell such as php.shin_webshell dropped on a compromised WordPress or ownCloud host.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("php.exe","php-cgi.exe","php-fpm","httpd","httpd.exe","apache2","nginx","nginx.exe","w3wp.exe","tomcat.exe","node.exe")
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","net.exe","net1.exe","whoami.exe","certutil.exe","bitsadmin.exe","curl.exe","nltest.exe","reg.exe","sh","bash","dash","nc","ncat","wget","curl","python3","perl","whoami","id","uname")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** Some CMS/plugin maintenance jobs legitimately shell out (image processing, backup, composer, cron wrappers) — allowlist by exact child command line, not by parent. node.exe is noisy on build servers; remove it if needed. Escalate immediately when the child is an encoded PowerShell or reaches the network.

## 6) Web-accessible script or binary written by web server or CMS process

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** High  
**Purpose:** Detects webshell drops (including .php files disguised in upload/wp-admin paths, and .aspx/.ashx shells written by w3wp) which is the persistence step for php.shin_webshell and for post-exploitation of ownCloud (CVE-2023-49105) and AjaxPro (CVE-2021-23758) style flaws.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where InitiatingProcessFileName in~ ("php.exe","php-cgi.exe","php-fpm","httpd","httpd.exe","apache2","nginx","nginx.exe","w3wp.exe","tomcat.exe","java.exe","occ")
| where FileName endswith ".php" or FileName endswith ".phtml" or FileName endswith ".php5" or FileName endswith ".aspx" or FileName endswith ".ashx" or FileName endswith ".asmx" or FileName endswith ".jsp" or FileName endswith ".jspx" or FileName endswith ".exe" or FileName endswith ".dll" or FileName endswith ".sh" or FileName endswith ".ps1"
| where FolderPath has_any ("wp-content","wp-admin","wp-includes","/uploads/", @"\uploads\", "owncloud","nextcloud","inetpub","htdocs","www","webroot","public_html","/data/")
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, ActionType, FileName, FolderPath, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** CMS/plugin auto-updates, composer/npm deployments and CI agents legitimately write .php/.dll under webroots — allowlist update service accounts, maintenance windows and deployment tool parent processes. Consider suppressing paths under vendor/ or node_modules/. Very high fidelity for single .php writes into uploads/ directories.

## 7) JFrog Artifactory (java) writing files outside repository cache paths

**Tactic:** Persistence  
**ATT&CK:** T1546  
**Severity:** Medium  
**Purpose:** CVE-2026-66384 lets an authenticated user write data outside the intended Docker cache directory. This hunts for the Artifactory JVM writing to OS persistence, cron, ssh or web-serving locations, or writing script/executable files — the exploitation outcome of the traversal.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where InitiatingProcessFileName in~ ("java","java.exe","artifactory","artifactory.exe","tomcat.exe") 
| where InitiatingProcessCommandLine has_any ("artifactory","jfrog")
| where FolderPath has_any ("/etc/cron", "/etc/systemd", "/root/.ssh", "/home/", "/usr/local/bin", "/var/spool/cron", "/etc/init.d", "/tmp/", @"\Start Menu\Programs\Startup", @"\Windows\System32", @"\Tasks\", @"\inetpub")
    or FolderPath has ".."
    or FileName endswith ".sh" or FileName endswith ".jsp" or FileName endswith ".war" or FileName endswith ".ps1" or FileName endswith ".bat"
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, ActionType, FileName, FolderPath, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Artifactory legitimately uses /tmp and its own data/cache directories for staging — allowlist the configured $JFROG_HOME data, cache and logs paths and the temp subdirectories it uses on your build hosts. Tighten to only the persistence paths if /tmp noise is high. Pair with a follow-up query for java.exe spawning shells.

## 8) Linux root shell spawned from an unprivileged parent without sudo/su

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1068  
**Severity:** High  
**Purpose:** Provides post-exploitation coverage for local kernel privilege-escalation bugs such as CVE-2026-53362 (IPv6 subsystem) by detecting a root-owned shell or interpreter whose parent process ran as a non-root user and was not a legitimate privilege-escalation helper.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FolderPath startswith "/"
| where AccountName == "root"
| where isnotempty(InitiatingProcessAccountName) and InitiatingProcessAccountName != "root"
| where FileName in~ ("bash","sh","dash","zsh","ksh","busybox","python3","python","perl","ruby","nc","ncat","socat","id","whoami")
| where InitiatingProcessFileName !in~ ("sudo","su","pkexec","doas","systemd","init","sshd","cron","crond","login","runc","containerd-shim","dockerd","kubelet","agetty","salt-minion","puppet","ansible-runner")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, ReportId
| order by Timestamp desc
```

**Tuning notes:** Configuration-management, backup and monitoring agents that use setuid helpers will produce benign hits — allowlist by InitiatingProcessFileName/FolderPath per server role. Add gcc/cc/make execution by the same user shortly before the root shell as a strong corroborating signal of on-host exploit compilation. Tune away containers if runtime parents differ in your fleet.
