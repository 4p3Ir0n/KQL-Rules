## 1) ClickFix / TerminalFix: Explorer-spawned scripting host with download-and-run command line

**Tactic:** Execution  
**ATT&CK:** T1204.004 - User Execution: Malicious Copy and Paste  
**Severity:** High  
**Purpose:** Detects the core ClickFix/ClearFake/TerminalFix pattern where a fake CAPTCHA or "fix" page instructs the user to paste a command into the Run dialog or terminal, resulting in explorer.exe directly spawning a scripting or download utility with remote-payload arguments.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","msiexec.exe","rundll32.exe","regsvr32.exe","bitsadmin.exe","certutil.exe","conhost.exe","wt.exe")
| where ProcessCommandLine has_any ("-enc","-ec ","frombase64string","iex","invoke-expression","invoke-webrequest","iwr ","downloadstring","downloadfile","start-process","webclient","-w hidden","-windowstyle hidden","-nop","http://","https://","\\\\","curl ","certutil -urlcache","bitsadmin /transfer","mshta ")
| extend LureHint = ProcessCommandLine has_any ("captcha","verify","verification","robot","human","fix","ray id","cloudflare","i am not a")
| project Timestamp, DeviceName, AccountUpn, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, LureHint, ProcessId, ReportId
```

**Tuning notes:** explorer.exe rarely launches encoded/remote-fetching command lines in normal use. Allowlist internal IT self-service scripts and software-center launchers by hash/command-line substring. Consider raising severity when LureHint is true or when the parent chain includes a browser. Tighten by removing plain "http://"/"https://" matches if noisy in environments where users launch UNC/web shortcuts from Run.

## 2) ClickFix pasted command recorded in Explorer RunMRU registry key

**Tactic:** Execution  
**ATT&CK:** T1059.001 - Command and Scripting Interpreter: PowerShell  
**Severity:** High  
**Purpose:** Detects the forensic artifact left when a victim pastes an attacker-supplied command into the Windows Run dialog (ClickFix / ClearFake / TerminalFix lures), which writes the full command into HKCU RunMRU.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where isnotempty(RegistryValueData)
| where RegistryValueData has_any ("powershell","pwsh","cmd","mshta","msiexec","curl","certutil","bitsadmin","wscript","cscript","rundll32","conhost","wt.exe","http","iex","frombase64string","-enc","hidden","\\\\")
| project Timestamp, DeviceName, AccountName, AccountSid, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins legitimately type cmd/powershell into Run; consider suppressing single-token values (RegistryValueData length < 25) and allowlisting IT/admin accounts or jump hosts. High-fidelity signals are long values containing base64, http(s), or hidden-window flags.

## 3) MSI loader: msiexec installing a package from a remote URL or user-writable path

**Tactic:** Execution  
**ATT&CK:** T1218.007 - System Binary Proxy Execution: Msiexec  
**Severity:** High  
**Purpose:** Detects the MSI-loader delivery technique tagged in the fresh 'Unknown Loader' / OffLoader indicator set, where msiexec.exe silently installs a payload from an internet URL or a temp/AppData location.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "msiexec.exe"
| where ProcessCommandLine has_any ("http://","https://","\\\\") or ProcessCommandLine has_any (@"\appdata\", @"\temp\", @"\programdata\", @"\users\public\", @"\downloads\")
| where ProcessCommandLine has_any ("/i","-i","/package","/a") 
| extend Silent = ProcessCommandLine has_any ("/qn","/quiet","/qb","/q ")
| where Silent or InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","explorer.exe","node.exe","chrome.exe","msedge.exe","firefox.exe")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, Silent, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Allowlist software-distribution agents (SCCM/Intune/ccmexec.exe, Chocolatey, Winget, PatchMyPC) and internal package repository URLs/UNC shares. Remote-URL MSI installs are the strongest signal; consider splitting URL-based and temp-path-based logic into separate severities.

## 4) Signed-looking binary side-loading a DLL from the same user-writable directory

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.002 - Hijack Execution Flow: DLL Side-Loading  
**Severity:** High  
**Purpose:** Detects the DLL sideloading stage of the TerminalFix campaign: a legitimate executable copied into a user-writable folder loads an attacker DLL colocated in that same folder.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FileName endswith ".dll"
| where FolderPath has_any (@"\users\", @"\appdata\", @"\programdata\", @"\temp\", @"\downloads\", @"\public\")
| where InitiatingProcessFolderPath has_any (@"\users\", @"\appdata\", @"\programdata\", @"\temp\", @"\downloads\", @"\public\")
| extend DllDir = tolower(substring(FolderPath, 0, strlen(FolderPath) - strlen(FileName)))
| extend ProcDir = tolower(substring(InitiatingProcessFolderPath, 0, strlen(InitiatingProcessFolderPath) - strlen(InitiatingProcessFileName)))
| where DllDir == ProcDir
| where InitiatingProcessFileName !in~ ("node.exe","python.exe","code.exe","msedgewebview2.exe","teams.exe","onedrive.exe")
| summarize LoadedDlls = make_set(FileName, 20), Loads = count(), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ProcDir
| project FirstSeen, LastSeen, DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, LoadedDlls, Loads
```

**Tuning notes:** Portable apps, Electron apps, installers and game launchers legitimately do this - build an allowlist of known-good (InitiatingProcessFileName, DLL name) pairs and of software distribution folders. Pivot to DeviceFileEvents to confirm the DLL was written minutes before first load, which is the strongest sideloading indicator.

## 5) Reverse tunnel / remote-access tunnel utility execution

**Tactic:** CommandAndControl  
**ATT&CK:** T1572 - Protocol Tunneling  
**Severity:** High  
**Purpose:** Detects the reverse tunnel stage of the TerminalFix intrusion and generic adversary tunneling via cloudflared, ngrok, devtunnel, chisel, frp, or SSH remote port forwarding.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (FileName in~ ("cloudflared.exe","ngrok.exe","devtunnel.exe","chisel.exe","frpc.exe","frps.exe","gost.exe","lt.exe","pagekite.exe","plink.exe","nps.exe","npc.exe"))
    or (FileName in~ ("ssh.exe","plink.exe") and ProcessCommandLine has_any (" -R "," -N "," -f ","0.0.0.0:","StrictHostKeyChecking=no"))
    or ProcessCommandLine has_any ("tunnel run","tunnel --url","trycloudflare","ngrok tcp","ngrok http","devtunnel host","localtunnel","chisel client","frpc -c","-R 3389","-R 445")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ProcessId, ReportId
```

**Tuning notes:** Allowlist sanctioned tunneling in dev/IT environments by device group, service account, or full command line (e.g., an approved cloudflared service install). Renamed binaries are common: complement with DeviceNetworkEvents to trycloudflare.com / *.ngrok*.io / *.devtunnels.ms from unexpected processes.

## 6) Web server or PHP interpreter spawning a command shell (webshell execution)

**Tactic:** Persistence  
**ATT&CK:** T1505.003 - Server Software Component: Web Shell  
**Severity:** Critical  
**Purpose:** Detects php.shin_webshell-style webshell activity on Windows web servers, where httpd/php-cgi/w3wp spawns command interpreters or discovery utilities.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("php.exe","php-cgi.exe","httpd.exe","apache.exe","nginx.exe","w3wp.exe","tomcat9.exe","java.exe","caddy.exe")
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","certutil.exe","bitsadmin.exe","curl.exe","whoami.exe","net.exe","net1.exe","ipconfig.exe","systeminfo.exe","tasklist.exe","nltest.exe","reg.exe","schtasks.exe","rundll32.exe")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ProcessId, ReportId
```

**Tuning notes:** Some web apps legitimately shell out (backup scripts, image tooling, java build agents). Allowlist specific parent+child+command-line triplets per application server rather than disabling the rule. java.exe is the noisiest parent - consider splitting it out for app-server estates.

## 7) Script file written into web content directory by web server or unexpected process

**Tactic:** Persistence  
**ATT&CK:** T1505.003 - Server Software Component: Web Shell  
**Severity:** High  
**Purpose:** Detects webshell drops (including .php disguised as .gif or planted under wp-admin/uploads) matching the php.shin_webshell WordPress targeting.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where FolderPath has_any (@"\inetpub\", @"\wwwroot\", @"\htdocs\", @"\www\", @"\wp-content\", @"\wp-admin\", @"\wp-includes\", @"\uploads\", @"\public_html\")
| where FileName has_any (".php",".phtml",".php5",".php7",".asp",".aspx",".ashx",".jsp",".jspx") or FileName endswith ".gif.php" or FileName endswith ".php.gif"
| where InitiatingProcessFileName in~ ("php.exe","php-cgi.exe","httpd.exe","apache.exe","nginx.exe","w3wp.exe","java.exe","tomcat9.exe","cmd.exe","powershell.exe","pwsh.exe","certutil.exe","curl.exe","bitsadmin.exe","wscript.exe","cscript.exe","7z.exe","tar.exe")
| project Timestamp, DeviceName, FileName, FolderPath, ActionType, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Filter out CI/CD deployment agents, WordPress auto-update flows (writes by php with wp-admin/includes update paths), and known plugin update processes. Baseline per web server for a week; genuine deployments come from a small set of accounts/processes.

## 8) Non-browser process accessing browser credential and cookie stores (Vidar-style stealer)

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003 - Credentials from Web Browsers  
**Severity:** High  
**Purpose:** Detects infostealer collection behavior (Vidar and similar) where a non-browser process copies or reads Chromium/Firefox credential databases, cookies, and Local State key material.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FileName in~ ("Login Data","Login Data For Account","Cookies","Web Data","Local State","key4.db","key3.db","logins.json","cert9.db","places.sqlite","formhistory.sqlite")
    or FolderPath has_any (@"\Local Extension Settings\", @"\Network\Cookies")
| where ActionType in ("FileCreated","FileCopied","FileModified","FileRenamed")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","vivaldi.exe","msedgewebview2.exe","chrome_proxy.exe","backgroundtaskhost.exe","searchprotocolhost.exe","msmpeng.exe")
| summarize TargetFiles = make_set(FileName, 25), Hits = count(), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256
| where Hits >= 2
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, TargetFiles, Hits
```

**Tuning notes:** Allowlist backup/sync agents, endpoint DLP, browser migration tools and IT inventory scanners. Prioritize initiating processes running from Temp/AppData or unsigned binaries; a process touching stores across multiple browser profiles in one minute is near-certain stealer activity.

## 10) Loader persistence written from user-writable staging directory

**Tactic:** Persistence  
**ATT&CK:** T1547.001 - Registry Run Keys / Startup Folder  
**Severity:** Medium  
**Purpose:** Catches the persistence step common to MSI-loader, ClearFake and Vidar loader chains: a Run key or scheduled task pointing at a binary or script located in AppData/Temp/ProgramData, created by a scripting host or recently dropped executable.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\Windows\CurrentVersion\Policies\Explorer\Run", @"\CurrentVersion\Explorer\Shell Folders")
| where RegistryValueData has_any (@"\appdata\", @"\temp\", @"\programdata\", @"\users\public\", @"\downloads\", "powershell", "mshta", "wscript", "cscript", "rundll32", "msiexec", "node.exe", "frombase64string", "-enc", "http")
| where InitiatingProcessFileName !in~ ("msiexec.exe") or InitiatingProcessCommandLine has_any ("http://","https://",@"\temp\",@"\appdata\")
| project Timestamp, DeviceName, AccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Many legitimate user-scope apps (Teams, OneDrive, Zoom, Slack, Electron updaters) persist from AppData - allowlist by RegistryValueName and the signed binary path. Highest fidelity when the value data contains a scripting host, encoded content, or a URL.

## 11) Artifactory/Java service writing files outside its data directory (CVE-2026-66384 path traversal)

**Tactic:** Persistence  
**ATT&CK:** T1574 - Hijack Execution Flow  
**Severity:** Medium  
**Purpose:** Provides post-exploitation visibility for the JFrog Artifactory Docker-cache path traversal, where the Artifactory JVM writes attacker-controlled content outside the intended cache path (e.g., into system, startup, web, or plugin directories).

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("java.exe","javaw.exe","artifactory.exe","jf.exe")
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where FolderPath has_any (@"\Windows\System32\", @"\Windows\Temp\", @"\Start Menu\Programs\Startup\", @"\System32\Tasks\", @"\inetpub\", @"\wwwroot\", @"\.ssh\", @"\var\etc\plugins\", @"\etc\plugins\", @"\bin\")
    or FileName has_any (".groovy",".jsp",".ps1",".bat",".cmd",".sh",".dll",".exe","authorized_keys")
| where not(FolderPath has_any (@"\artifactory\var\data\artifactory\cache\", @"\artifactory\var\data\artifactory\filestore\", @"\artifactory\var\log\", @"\artifactory\var\work\"))
| project Timestamp, DeviceName, FileName, FolderPath, ActionType, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Tune the excluded legitimate Artifactory data paths to your install layout (JFROG_HOME) before enabling; also allowlist upgrade/installer windows and plugin deployment by change ticket. Pair with the web-shell-execution rule to catch follow-on execution by the Artifactory service account.
