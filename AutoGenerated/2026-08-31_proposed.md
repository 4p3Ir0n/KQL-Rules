## 1) ClickFix: Suspicious command staged via Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake/IClickFix/TerminalFix ClickFix lures instruct users to paste an attacker-supplied command into the Win+R Run dialog. Windows records pasted/typed Run entries in the Explorer RunMRU registry key, giving a durable, IOC-independent signal of the social-engineering step regardless of the delivery domain.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| extend cmd = tolower(tostring(RegistryValueData))
| where cmd has_any ("powershell", "pwsh", "cmd.exe", "cmd /c", "mshta", "msiexec", "curl", "certutil", "bitsadmin", "rundll32", "regsvr32", "wscript", "cscript", "conhost", "iwr", "invoke-webrequest", "invoke-expression", "iex", "frombase64string", "downloadstring", "http://", "https://", "-w hidden", "-windowstyle", "-enc", "captcha", "verify", "not a robot", "ray id")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** RunMRU is normally used for short entries like 'cmd', 'mmc', '\\server\share'. Expect very low volume; if admins routinely paste long PowerShell into Run, allowlist by InitiatingProcessAccountName or specific device groups. Consider dropping the broad 'cmd.exe'/'powershell' keywords alone and requiring a second indicator (URL, hidden window, encoding) in noisy admin environments.

## 2) Script interpreter or LOLBin spawned directly by explorer.exe with download/exec markers

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** After a ClickFix paste (Run dialog, Explorer address bar, or file double-click), the first stage is launched as a direct child of explorer.exe. Detecting explorer.exe -> powershell/mshta/msiexec/curl with download or obfuscation markers catches ClearFake, IClickFix and the TerminalFix loader chain behaviorally.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "msiexec.exe", "curl.exe", "rundll32.exe", "regsvr32.exe", "forfiles.exe", "conhost.exe", "bitsadmin.exe", "certutil.exe")
| extend cl = tolower(ProcessCommandLine)
| where cl has_any ("-w hidden", "-windowstyle h", "-nop", "-noprofile", "-enc", "-encodedcommand", "frombase64string", "iex", "invoke-expression", "invoke-webrequest", "iwr", "downloadstring", "downloadfile", "start-bitstransfer", "curl ", "http://", "https://", "conhost --headless", ".hta", "urlmon", "webclient", "-urlcache", "/i http")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Explorer-parented interpreters are normal when users double-click .bat/.ps1 scripts or shortcuts; allowlist known internal script paths and software-deployment shortcuts. Tighten by requiring FolderPath of the payload under \Users\ or \ProgramData\, or by excluding signed corporate scripts. 'conhost --headless' is a strong standalone signal and can be promoted to its own high-fidelity rule.

## 3) msiexec installing a package from a remote URL or UNC path (MSI-loader)

**Tactic:** Execution  
**ATT&CK:** T1218.007  
**Severity:** High  
**Purpose:** The 'MSI-loader' component seen in the Unknown Loader / ClickFix clusters uses msiexec.exe to fetch and silently install a remotely hosted MSI, which then sideloads or drops the next stage. Remote-source msiexec execution is rare outside managed deployment.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "msiexec.exe"
| extend cl = tolower(ProcessCommandLine)
| where cl has_any ("http://", "https://", "\\\\")
| where cl has_any (" /i", " -i", "/package", "/quiet", " /qn", " /qb", " /q ")
| project Timestamp, DeviceId, DeviceName, AccountName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Allowlist internal software-distribution servers (Intune/SCCM content hosts, internal UNC repositories) by URL/host substring, and allowlist InitiatingProcessFileName of ccmexec.exe / IntuneManagementExtension.exe. Alert priority should rise when the parent is explorer.exe, a browser, mshta.exe, or a script host.

## 4) EtherHiding: non-browser process contacting public blockchain RPC endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** High  
**Purpose:** ClearFake and related loaders use 'EtherHiding' / on-chain C2 (Polygon, BSC, Sepolia testnet) to retrieve payload URLs and commands from smart contracts via public RPC gateways. Script hosts, node.exe, or unsigned binaries querying blockchain RPC infrastructure is a strong C2 indicator.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess", "ConnectionRequest", "HttpConnectionInspected")
| where RemoteUrl has_any ("bsc-dataseed", "polygon-rpc", "rpc.ankr.com", "infura.io", "alchemy.com", "alchemyapi.io", "cloudflare-eth.com", "sepolia", "quicknode", "llamarpc", "publicnode.com", "drpc.org", "bscrpc", "binance.org", "blastapi.io", "nodereal.io", "etherscan.io", "bscscan.com", "polygonscan.com")
    or RemoteUrl matches regex @"(?i)(rpc|mainnet|testnet)[-.][a-z0-9-]*\.(io|com|org|network|xyz)"
| where InitiatingProcessFileName !in~ ("chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "iexplore.exe", "msedgewebview2.exe")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RemoteUrl, RemoteIP, RemotePort, ReportId
| order by Timestamp desc
```

**Tuning notes:** Allowlist legitimate crypto wallets, blockchain developer tooling and node clients per device/user; in dev environments scope this rule to non-developer device groups. Browsers are excluded because ClearFake's on-chain lookup normally happens inside browser JS - run a separate variant that keeps browsers but correlates with a subsequent explorer/script-host child process within 5 minutes.

## 5) Reverse tunnel / port-forward utility execution (TerminalFix)

**Tactic:** CommandAndControl  
**ATT&CK:** T1572  
**Severity:** High  
**Purpose:** The TerminalFix campaign establishes a reverse tunnel for persistent interactive access. This detects execution of SSH reverse forwarding and common tunneling agents (cloudflared, ngrok, frp, chisel, gost, devtunnel) which give attackers inbound access through egress-only firewalls.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| extend cl = tolower(ProcessCommandLine)
| where (FileName in~ ("ssh.exe", "plink.exe", "putty.exe") and cl matches regex @"(^|\s)-[a-z]*r(\s|$)|-r\s*\d{1,5}:|0\.0\.0\.0:\d+")
    or FileName in~ ("cloudflared.exe", "ngrok.exe", "frpc.exe", "frps.exe", "chisel.exe", "gost.exe", "nps.exe", "npc.exe", "localtonet.exe", "pinggy.exe", "devtunnel.exe", "loophole.exe", "bore.exe", "tailscaled.exe")
    or cl has_any ("tunnel --url", "tunnel run --token", "--edge-ip-version", "client -tunnel", "chisel client", "-l :socks", "tcp 3389", "tcp 22", "stcp", "remote_port")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Allowlist sanctioned use: Cloudflare Tunnel/Tailscale on approved servers (by DeviceName and installed service path), and admin SSH port-forwarding accounts. Treat execution from \Users\, \ProgramData\ or \Temp\, or a renamed binary (FileName not matching the tool's expected SHA/signer), as critical. Pair with DeviceNetworkEvents for long-lived outbound sessions from the same process.

## 6) DLL sideloading: image loaded from same user-writable directory as its host executable

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.001  
**Severity:** Medium  
**Purpose:** TerminalFix and similar multistage intrusions drop a legitimately signed executable plus a malicious DLL into a user-writable folder so the DLL is loaded via search-order hijacking. Matching the loaded DLL's directory to the initiating executable's directory under user-writable paths surfaces this pattern without relying on hashes.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FileName endswith ".dll"
| extend dllDir = tolower(tostring(parse_path(FolderPath).DirectoryPath)), exeDir = tolower(tostring(parse_path(InitiatingProcessFolderPath).DirectoryPath))
| where isnotempty(dllDir) and dllDir == exeDir
| where dllDir has_any (@"\appdata\local\temp", @"\appdata\roaming", @"\appdata\local\", @"\users\public", @"\programdata", @"\downloads", @"\music", @"\pictures", @"\documents", @"\windows\temp")
| summarize LoadCount = count(), DllList = make_set(FileName, 20), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, dllDir
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, dllDir, DllList, LoadCount
```

**Tuning notes:** Installers, self-extracting updaters, Electron/Teams/Zoom-style apps and portable dev tools legitimately load DLLs beside themselves in AppData - allowlist by InitiatingProcessFileName plus directory pattern. Enrich by joining to DeviceFileEvents to confirm the exe and DLL were created within minutes of each other by an archive tool, browser, or msiexec.

## 7) Web server or PHP process spawning a command shell (webshell execution)

**Tactic:** Execution  
**ATT&CK:** T1505.003  
**Severity:** Critical  
**Purpose:** php.shin_webshell targets WordPress (wp-admin, wp-content) and proxies C2 through Cloudflare workers.dev. Regardless of the shell's code or C2 domain, exploitation is visible when the web server/PHP interpreter spawns OS commands - the core webshell behavior.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("w3wp.exe", "php.exe", "php-cgi.exe", "php-fpm.exe", "httpd.exe", "nginx.exe", "apache.exe", "tomcat.exe", "java.exe", "node.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "net.exe", "net1.exe", "whoami.exe", "hostname.exe", "systeminfo.exe", "ipconfig.exe", "tasklist.exe", "reg.exe", "sc.exe", "schtasks.exe", "certutil.exe", "bitsadmin.exe", "curl.exe", "wget.exe", "nltest.exe", "quser.exe", "wmic.exe", "rundll32.exe", "attrib.exe", "icacls.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Some web apps legitimately shell out (backup jobs, ImageMagick wrappers, monitoring scripts) - baseline per server and allowlist specific parent+child+command-line triples. On Java-heavy servers java.exe/node.exe parents may be noisy; consider splitting them into a lower-severity variant. Escalate immediately when the command line contains encoded PowerShell, download cmdlets, or account/lateral-movement commands.

## 8) Server-side script file written into a web root by a web server or PHP process

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** High  
**Purpose:** Webshell installation is visible as the web server or interpreter writing new .php/.phtml/.aspx files - or PHP code disguised with image extensions (the shin_webshell 'gif' tag) - into web content directories such as wp-content/uploads or wp-admin.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileModified", "FileRenamed")
| extend p = tolower(FolderPath)
| where InitiatingProcessFileName in~ ("w3wp.exe", "php.exe", "php-cgi.exe", "php-fpm.exe", "httpd.exe", "nginx.exe", "apache.exe", "tomcat.exe", "java.exe")
    or p has_any (@"\wp-content\uploads\", @"\wp-content\plugins\", @"\wp-content\themes\", @"\wp-admin\", @"\wp-includes\", @"\inetpub\wwwroot\", @"\htdocs\", @"\public_html\", @"\www\")
| where FileName has_any (".php", ".phtml", ".php5", ".php7", ".pht", ".phar", ".asp", ".aspx", ".ashx", ".jsp", ".jspx")
    or (p has_any (@"\wp-content\uploads\", @"\htdocs\", @"\public_html\", @"\inetpub\wwwroot\") and FileName has_any (".gif", ".jpg", ".png", ".ico", ".txt", ".log") and InitiatingProcessFileName in~ ("w3wp.exe", "php.exe", "php-cgi.exe", "php-fpm.exe", "httpd.exe", "nginx.exe"))
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, RequestSourceIP, ReportId
| order by Timestamp desc
```

**Tuning notes:** Filter out legitimate deployment paths: CI/CD agents, WordPress/plugin auto-updates (allowlist InitiatingProcessFileName of the updater plus cache/upgrade directories), and caching plugins that write .php cache files. Baseline over 7-14 days and alert on first-seen filenames only; use summarize by FolderPath to spot bulk plugin updates versus single anomalous file drops.
