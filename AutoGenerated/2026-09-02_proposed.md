## 1) PaperCut NG/MF Server Process Spawning Command Shell or Script Interpreter

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** Detects post-exploitation of CVE-2026-81578 / CVE-2026-82078 chains in PaperCut NG/MF, where the unauthenticated config modification plus unsafe reflection leads to arbitrary code execution under the PaperCut Java service. Any shell, script host, or LOLBin child of the PaperCut application/service process is highly anomalous.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("pc-app.exe", "pc-service.exe", "pc-web-print.exe", "pc-client.exe", "java.exe", "javaw.exe")
| where InitiatingProcessFolderPath has_any ("papercut", "pc-app", "PaperCut MF", "PaperCut NG")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe", "rundll32.exe", "regsvr32.exe", "certutil.exe", "bitsadmin.exe", "curl.exe", "net.exe", "net1.exe", "whoami.exe", "bash.exe", "sh.exe", "msiexec.exe", "schtasks.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** PaperCut legitimately shells out for some print/scan integrations and scheduled maintenance scripts — baseline normal children per server for 7-14 days and allowlist known integration scripts by full command line, not just image name. If the deployment uses a bundled JRE outside a folder named 'papercut', extend the InitiatingProcessFolderPath filter to that install path. Pair with DeviceFileEvents for new .jar/.class/.war files written under the PaperCut classpath, which is the primary artifact of the unsafe-reflection abuse.

## 2) Browser Credential and Cookie Store Copied to Staging Directory (Vidar-style Stealer)

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003  
**Severity:** High  
**Purpose:** Vidar and similar loader-delivered infostealers copy Chromium/Gecko credential, cookie, and autofill databases out of browser profiles into a temporary staging folder before archiving and exfiltrating them to C2. This behavioral pattern survives IOC rotation of Vidar's C&C domains and hashes.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileRenamed", "FileModified")
| where FileName in~ ("Login Data", "Login Data For Account", "Web Data", "Cookies", "Network Cookies", "key4.db", "key3.db", "logins.json", "cookies.sqlite", "formhistory.sqlite", "places.sqlite")
| where FolderPath has_any ("\\AppData\\Local\\Temp\\", "\\ProgramData\\", "\\Users\\Public\\", "\\Windows\\Temp\\", "\\AppData\\Roaming\\")
| where not(FolderPath has_any ("\\Google\\Chrome\\User Data\\", "\\Microsoft\\Edge\\User Data\\", "\\Mozilla\\Firefox\\Profiles\\", "\\BraveSoftware\\", "\\Opera Software\\"))
| summarize FileCount = dcount(FileName), Files = make_set(FileName, 20), Paths = make_set(FolderPath, 20), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName
| where FileCount >= 2
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, FileCount, Files, Paths
```

**Tuning notes:** Allowlist browser-profile migration tools, enterprise backup/DLP agents, and IT imaging scripts by InitiatingProcessSHA256 or signer. Lower FileCount to 1 for high-value hosts to increase sensitivity. Enrich by joining DeviceNetworkEvents from the same InitiatingProcessId for outbound HTTP POSTs to newly-registered domains or Telegram/Steam dead-drop resolvers, which Vidar uses for C2 discovery.

## 3) CMSTP App Paths Registry Key Modification (CmstpExtensionDll Hijack)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218.003  
**Severity:** Medium  
**Purpose:** Faithful translation of Sigma rule b6d235fc-1d38-4b12-adbe-325f06728f37. Detects writes to the cmmgr32.exe App Paths key — notably CmstpExtensionDll — which attackers (e.g. G0069/MuddyWater) use to load arbitrary DLLs via CMSTP for code execution and UAC bypass.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has "\\SOFTWARE\\Microsoft\\Windows\\CurrentVersion\\App Paths\\cmmgr32.exe"
| where isnotempty(RegistryValueData)
| where not(RegistryValueName =~ "CmstpExtensionDll" and RegistryValueData in~ ("C:\\Windows\\System32\\cmcfg32.dll", "C:\\Windows\\SysWOW64\\cmcfg32.dll"))
| project Timestamp, DeviceId, DeviceName, ActionType, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Legitimate writers are essentially only Windows servicing (TrustedInstaller/TiWorker.exe) and Connection Manager profile installs (cmstp.exe run by an admin); allowlist those InitiatingProcessFileName values if noisy. Any DLL path outside System32/SysWOW64 — especially in user-writable directories such as %TEMP%, %APPDATA%, or ProgramData — should be treated as High and triaged immediately alongside DeviceImageLoadEvents for that DLL.

## 4) Shell Open Command Registry Hijack (ms-settings / exefile UAC Bypass)

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1548.002  
**Severity:** High  
**Purpose:** Faithful translation of Sigma rule 152f3630-77c1-4284-bcc0-4cc68ab2f6e7. Detects manipulation of HKCU Classes shell\open\command keys for ms-settings (fodhelper/computerdefaults UAC bypass) and exefile (file-association hijack persistence), excluding known benign COM CLSID defaults.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has_any ("Classes\\ms-settings\\shell\\open\\command", "Classes\\exefile\\shell\\open\\command")
| extend ValueName = iff(isempty(RegistryValueName), "(Default)", RegistryValueName)
| where (ValueName =~ "SymbolicLinkValue" and RegistryValueData has "\\Software\\Classes\\{")
     or ValueName =~ "DelegateExecute"
     or ValueName in~ ("(Default)", "Default")
| where isnotempty(RegistryValueData)
| where RegistryValueData !in~ ("{4813071a-41ad-44a2-9835-886d2f63ca30}", "{A56A841F-E974-45C1-8001-7E3F8A085917}", "{4ED3A719-CEA8-4BD9-910D-E252F997AFC2}", "{BFEC0C93-0B7D-4F2C-B09C-AFFFC4BDAE78}")
| project Timestamp, DeviceId, DeviceName, ActionType, RegistryKey, ValueName, RegistryValueData, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Note the Sigma rule allows an empty DelegateExecute value only as part of the 'empty details' filter; this query drops empty data entirely — if you want the classic fodhelper chain (empty DelegateExecute followed immediately by a (Default) write) remove the isnotempty filter and correlate the two events within 60 seconds on DeviceId+InitiatingProcessId. Some software (uninstallers, shell extension installers) legitimately writes exefile associations; allowlist by signed InitiatingProcess. Escalate when RegistryValueData references powershell, cmd, mshta, rundll32, or a path in %TEMP%/%APPDATA%.

## 5) Counterfeit Software Installer from Download/Archive Path Spawning Script Host or Downloader

**Tactic:** Execution  
**ATT&CK:** T1204.002  
**Severity:** High  
**Purpose:** Targets the deceptive software download campaign reported by Microsoft Defender Experts, where look-alike vendor pages deliver regenerated installer archives. Legitimate installers rarely spawn PowerShell/mshta/curl with download-and-execute command lines; this detects the trojanized-installer-to-loader handoff independent of specific hashes or domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFolderPath has_any ("\\Downloads\\", "\\AppData\\Local\\Temp\\", "\\Users\\Public\\", "\\ProgramData\\", "\\7zO", "\\Rar$", "\\Temp1_", "\\AppData\\Local\\Microsoft\\Windows\\INetCache\\")
| where InitiatingProcessFileName matches regex @"(?i)^(setup|install|installer|update|updater|launcher|activator|crack|keygen|.*(setup|install|x64|win64|full)).*\.(exe|msi)$"
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "rundll32.exe", "regsvr32.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "msiexec.exe", "conhost.exe", "node.exe", "AutoIt3.exe")
| where ProcessCommandLine has_any ("http://", "https://", "-enc", "-EncodedCommand", "FromBase64String", "Invoke-Expression", "iex ", "IWR", "Invoke-WebRequest", "DownloadString", "DownloadFile", "-w hidden", "-windowstyle hidden", "-nop", "bypass", "Add-MpPreference", "ExclusionPath", "urlcache", "/transfer", "javascript:", "vbscript:")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessSignerType, ReportId
```

**Tuning notes:** Many genuine installers (Chrome, Zoom, driver bundles) run from Downloads and may call msiexec or curl — allowlist by InitiatingProcessSHA256 plus a valid, non-revoked authenticode signer (InitiatingProcessSignerType == 'Microsoft' or trusted vendor). Prioritize alerts where the parent is unsigned or signed by a certificate first seen in the last 30 days, or where the process was written to disk by a browser (join DeviceFileEvents FileOriginUrl for the download referrer to identify the look-alike site).

## 6) ClickFix / Fake CAPTCHA Paste-and-Run Execution from Explorer Run Dialog

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** ClearFake and related FakeCaptcha/ClickFix lures instruct victims to paste an attacker-supplied command into the Windows Run dialog or terminal. This yields a script interpreter spawned directly by explorer.exe with download-and-execute or clipboard-marker content — a durable behavioral signature that outlives the campaign's rotating domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe", "wt.exe", "OpenWith.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "rundll32.exe", "conhost.exe", "node.exe")
| where ProcessCommandLine has_any ("Invoke-Expression", "iex(", "iex ", "IWR", "Invoke-WebRequest", "Invoke-RestMethod", "irm ", "DownloadString", "DownloadFile", "FromBase64String", "-enc", "-EncodedCommand", "curl ", "mshta http", "msiexec /i http", "start-process", "Get-Clipboard", "\u2705", "I am not a robot", "verification", "captcha", "Ray ID", "human")
| where ProcessCommandLine has_any ("http", "-enc", "FromBase64String", "captcha", "verification", "Ray ID")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Admin/helpdesk staff occasionally paste one-liners into Run; scope out known IT accounts or require a second signal. Strengthen by correlating with DeviceRegistryEvents writes to HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU within 5 minutes (the pasted string is recorded there verbatim), and with DeviceNetworkEvents to newly-observed or Cloudflare workers.dev / *.dpdns.org style domains. Emoji and phrases like 'I am not a robot' are strong true-positive indicators used by ClickFix lures.

## 7) Web Server Process Spawning Shell or Recon Commands (PHP/WordPress Webshell)

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** Critical  
**Purpose:** php.shin_webshell and similar WordPress/PHP webshells execute OS commands through the web server or PHP CGI process. Any cmd/powershell/recon child of w3wp.exe, php-cgi.exe, httpd.exe, or nginx worker processes indicates webshell command execution.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("w3wp.exe", "php-cgi.exe", "php.exe", "httpd.exe", "nginx.exe", "caddy.exe", "tomcat9.exe", "tomcat10.exe", "node.exe")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "whoami.exe", "net.exe", "net1.exe", "ipconfig.exe", "systeminfo.exe", "tasklist.exe", "nltest.exe", "quser.exe", "certutil.exe", "bitsadmin.exe", "curl.exe", "wget.exe", "schtasks.exe", "reg.exe", "wmic.exe", "rundll32.exe", "vssadmin.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Some CMS/plugin functionality (image processing, scheduled cron via wp-cron, backup plugins) legitimately shells out — baseline per web server and allowlist specific full command lines rather than image names. Pair with a companion DeviceFileEvents hunt for .php/.phtml/.gif files written into wwwroot, wp-content/uploads, or wp-admin by the web server or an unexpected process, which catches shell drop before execution. Treat any hit on internet-facing hosts as Critical and pivot on the source IPs of preceding inbound connections.

## 8) Script or Disguised-Image File Written to Web Root by Web Server Process

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** High  
**Purpose:** Detects webshell deployment (php.shin_webshell campaign artifacts include .php and .gif-disguised shells dropped into WordPress paths such as wp-admin and wp-content/uploads) by flagging server-side script files created in web-accessible directories by the web server or PHP process itself.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileRenamed", "FileModified")
| where FolderPath has_any ("\\wwwroot\\", "\\inetpub\\", "\\htdocs\\", "\\www\\", "\\wp-content\\", "\\wp-admin\\", "\\wp-includes\\", "\\public_html\\", "\\webapps\\")
| where FileName endswith ".php" or FileName endswith ".phtml" or FileName endswith ".php7" or FileName endswith ".phar" or FileName endswith ".asp" or FileName endswith ".aspx" or FileName endswith ".jsp" or FileName endswith ".gif" or FileName endswith ".ico"
| where InitiatingProcessFileName in~ ("w3wp.exe", "php-cgi.exe", "php.exe", "httpd.exe", "nginx.exe", "node.exe", "cmd.exe", "powershell.exe", "certutil.exe", "curl.exe", "wget.exe", "7z.exe", "tar.exe")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, FileSize, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, RequestAccountName, ReportId
```

**Tuning notes:** WordPress/plugin auto-updates and CI/CD deployment agents write .php files legitimately — allowlist deployment service accounts, msdeploy/WebDeploy, and update processes, or exclude scheduled maintenance windows. The .gif/.ico extensions are included because this family disguises shells as images; expect noise from media uploads, so consider restricting image extensions to files created under wp-admin/wp-includes or files whose content is later loaded by the PHP interpreter. Correlate with the web-server-spawns-shell detection for confirmation.
