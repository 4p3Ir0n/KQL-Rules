## 1) ClickFix / ClearFake: Malicious command pasted into Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake and related ClickFix lures instruct victims to paste an attacker-supplied command into the Win+R Run dialog. Every pasted command is recorded in the Explorer RunMRU registry key, giving a durable, high-fidelity signal of the social-engineering step regardless of the delivery domain or payload hash.

```kusto
DeviceRegistryEvents | where Timestamp > ago(1d) | where RegistryKey has @"\Explorer\RunMRU" | where RegistryValueData has_any ("powershell","pwsh","mshta","curl","cmd /c","cmd.exe /c","conhost","msiexec","bitsadmin","certutil","rundll32","regsvr32","wscript","cscript","forfiles","FromBase64String","iex","Invoke-WebRequest","Invoke-Expression","http://","https://","\\\\") | project Timestamp, DeviceName, InitiatingProcessAccountDomain, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Very low volume in most estates. Allowlist admin workstations and known helpdesk one-liners by RegistryValueData prefix. Note RunMRU values end with '\1' and are written when the dialog is used, so absence of a matching process event does not mean the command failed - correlate with DeviceProcessEvents on the same device within +/- 5 minutes.

## 2) ClickFix chain: Explorer or headless conhost spawning script interpreter with download/eval flags

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClearFake / ClickFix / fake-CAPTCHA lures where explorer.exe (Run dialog or clipboard paste) or 'conhost.exe --headless' launches a hidden PowerShell/mshta/curl command that fetches and evaluates remote content.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where InitiatingProcessFileName in~ ("explorer.exe","conhost.exe") | where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","msiexec.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe") | where ProcessCommandLine has_any ("iex","invoke-expression","invoke-webrequest"," irm "," iwr ","downloadstring","downloadfile","frombase64string","-enc","-ec ","-encodedcommand","windowstyle hidden","-w h","http://","https://","start-bitstransfer","--headless") | project Timestamp, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Explorer-parented cmd.exe with a UNC path is common in some environments - split cmd.exe into its own tier if noisy. Allowlist software-deployment scripts and IT self-service tools by command-line substring. Tighten by requiring a DeviceNetworkEvents hit from the same ProcessId within 2 minutes for higher precision.

## 3) Browser renderer process spawning LOLBin (possible Chromium V8 exploitation)

**Tactic:** Execution  
**ATT&CK:** T1203  
**Severity:** High  
**Purpose:** Post-exploitation of CVE-2026-87491 style V8 out-of-bounds write bugs requires a sandbox escape or in-renderer command execution; a renderer-type browser process creating a shell or scripting host is anomalous and indicates successful drive-by code execution.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where InitiatingProcessFileName in~ ("chrome.exe","msedge.exe","opera.exe","brave.exe","vivaldi.exe","chromium.exe") | where InitiatingProcessCommandLine has_any ("--type=renderer","--type=utility","--type=gpu-process") | where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","curl.exe","schtasks.exe","msiexec.exe","wmic.exe","installutil.exe","reg.exe") | project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessId, ReportId
```

**Tuning notes:** Legitimate exceptions: crashpad/updater helpers (exclude FileName endswith 'setup.exe' for the browser vendor path), enterprise browser management extensions using native messaging hosts. Verify InitiatingProcessCommandLine really contains a renderer sandbox type; browser-broker-parented cmd.exe from user-initiated 'open with' actions should be excluded.

## 4) VShell-style Linux payload staging: remote script piped to shell or chmod+exec from world-writable path

**Tactic:** CommandAndControl  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** VShell (and Mythic/Supershell-style Go implants seen in the same feed) is typically dropped by a one-liner that curls a hosted script (e.g. whack.sh) into a shell, or writes a binary to /tmp and marks it executable before launching it. Detects the delivery/execution TTP rather than perishable URLs or hashes.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where ProcessCommandLine matches regex @"(?i)(curl|wget)\s+[^|;]{4,}\|\s*(ba|z|d)?sh" or ProcessCommandLine matches regex @"(?i)chmod\s+(\+x|[0-7]{3,4})\s+/(tmp|dev/shm|var/tmp|run)/" or ProcessCommandLine matches regex @"(?i)\b(nohup|setsid)\b.*/(tmp|dev/shm|var/tmp)/" | where ProcessCommandLine !contains "apt-get" | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Build/CI hosts and container images legitimately pipe installers to shell - allowlist by DeviceName or by trusted domains inside the command line (e.g. get.docker.com, packages.microsoft.com). Correlate with DeviceNetworkEvents to a raw IP:high-port from the newly created binary to confirm implant beaconing.

## 5) SEO-poisoning / PPI campaign: user runs executable from archive-extraction or Downloads path with lure filename

**Tactic:** Execution  
**ATT&CK:** T1204.002  
**Severity:** Medium  
**Purpose:** The Unit 42 PPI campaign delivers multi-payload malware through YouTube gaming lures and SEO poisoning, where victims extract and run a cracked-game/cheat/installer binary. Detects execution of freshly extracted binaries from temp archive paths and download folders with typical lure naming.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FolderPath has_any (@"\Temp\Rar$", @"\Temp\7z", @"\AppData\Local\Temp\Temp1_", @"\Downloads\", @"\AppData\Local\Temp\.zip") | where InitiatingProcessFileName in~ ("winrar.exe","7zg.exe","7zfm.exe","7z.exe","winzip32.exe","peazip.exe","explorer.exe","chrome.exe","msedge.exe","firefox.exe","opera.exe") | where FileName endswith ".exe" or FileName endswith ".scr" or FileName endswith ".com" or FileName endswith ".pif" | where FileName has_any ("setup","install","crack","keygen","patch","activator","cheat","loader","launcher","mod","hack","unlock","free","v3","update") or ProcessCommandLine has_any ("password","pass:","pw:") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Expect noise from legitimate vendor installers run out of Downloads - allowlist signed publishers by joining on DeviceFileEvents/file signer data or excluding known-good SHA256s. Prioritise alerts where the child process later spawns powershell.exe, writes to a Run key, or contacts a raw IP. Consider restricting to non-admin users.

## 6) Defender exclusion or real-time protection tampering from command line

**Tactic:** DefenseEvasion  
**ATT&CK:** T1562.001  
**Severity:** High  
**Purpose:** Both the commodity PPI/loader campaigns and ClearFake follow-on payloads persistently add Defender exclusions for their staging directory or disable real-time monitoring before dropping the next stage. This is a durable, payload-agnostic post-execution behaviour.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where (ProcessCommandLine has_any ("Add-MpPreference","Set-MpPreference") and ProcessCommandLine has_any ("ExclusionPath","ExclusionExtension","ExclusionProcess","DisableRealtimeMonitoring","DisableScriptScanning","DisableBehaviorMonitoring","DisableIOAVProtection","MAPSReporting","SubmitSamplesConsent")) or (FileName =~ "reg.exe" and ProcessCommandLine has @"Windows Defender\Exclusions") or (ProcessCommandLine has "mpcmdrun" and ProcessCommandLine has_any ("-RemoveDefinitions","-DisableService")) | project Timestamp, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Allowlist endpoint-management tooling (SCCM/Intune remediation scripts, backup and EDR-vendor installers) by InitiatingProcessFileName and known script paths. Exclusions added for user-writable paths (AppData, Temp, ProgramData, Downloads, C:\Users\Public) should be treated as Critical.

## 7) Proxy/tunnel client execution associated with loader C2 (clash, v2ray/xray, frp, ngrok)

**Tactic:** CommandAndControl  
**ATT&CK:** T1572  
**Severity:** Medium  
**Purpose:** The 'Unknown Loader' cluster tags (clash-verge, OffLoader, CDN-poison) and Supershell/Mythic infrastructure frequently pair with user-mode proxy or reverse-tunnel clients used to relay C2 traffic and bypass egress controls. Detects execution of these tunnelling binaries from non-standard locations.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName has_any ("clash","clash-verge","mihomo","v2ray","xray","sing-box","frpc","frps","ngrok","cloudflared","gost","chisel","nps","npc") or ProcessCommandLine has_any (" -config ","tunnel --url","tcp --remote","server_addr","vmess://","vless://","trojan://","ss://") | where FolderPath has_any (@"\AppData\", @"\Temp\", @"\ProgramData\", @"\Users\Public\", "/tmp/", "/dev/shm/", "/var/tmp/") or isempty(FolderPath) | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** cloudflared and ngrok have legitimate developer use - scope to non-developer device groups or allowlist specific SHA256/publisher plus expected config paths. Pair with DeviceNetworkEvents from the same ProcessId to a non-corporate ASN/high port to raise confidence.

## 8) Microsoft Graph / Entra ID tenant reconnaissance from an endpoint

**Tactic:** Discovery  
**ATT&CK:** T1087.004  
**Severity:** Medium  
**Purpose:** After passkey-themed social engineering and MFA persistence, actors pivot to Microsoft Graph for directory, mailbox and SharePoint reconnaissance. Detects Graph/Entra enumeration tooling executed interactively on a managed endpoint - the on-device footprint of that cloud recon stage.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","python.exe","python3.exe","dotnet.exe") | where ProcessCommandLine has_any ("Connect-MgGraph","Invoke-MgGraphRequest","Get-MgUser","Get-MgGroup","Get-MgApplication","Get-MgServicePrincipal","Get-MgDirectoryRole","Get-MgUserAuthenticationMethod","Connect-AzureAD","Get-AzureADUser","AADInternals","GraphRunner","roadrecon","roadtx","graph.microsoft.com/v1.0/users","graph.microsoft.com/beta/me/drive") | project Timestamp, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Allowlist identity administrators' jump hosts and scheduled reporting/automation accounts by DeviceName + AccountName. Treat execution by a standard user, from a browser/Office parent, or referencing AADInternals/GraphRunner/roadrecon as High. Correlate with cloud sign-in and Graph audit logs for the same UPN.
