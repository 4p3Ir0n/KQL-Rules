## 1) AsyncRAT-style persistence: Run key / Startup / scheduled task pointing at user-writable payload

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** High  
**Purpose:** AsyncRAT and its loaders persist by copying a small .NET payload into %AppData%, %ProgramData%, %TEMP% or C:\Users\Public and registering it via a Run key, Startup folder shortcut, or a minute-interval scheduled task. This detects the registration behavior rather than the rotating hashes/C2 IPs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("schtasks.exe","reg.exe","powershell.exe","pwsh.exe","cmd.exe","wscript.exe","cscript.exe")
| where (ProcessCommandLine has "schtasks" and ProcessCommandLine has "/create" and ProcessCommandLine has_any ("/sc minute","/sc onlogon","/sc onstart","/rl highest"))
    or (ProcessCommandLine has_any (@"CurrentVersion\Run", @"CurrentVersion\RunOnce", @"Start Menu\Programs\Startup", "shell:startup"))
| where ProcessCommandLine has_any (@"\appdata\", @"\local\temp\", @"\programdata\", @"\users\public\", @"\roaming\")
| where ProcessCommandLine has_any (".exe",".vbs",".js",".bat",".cmd",".ps1",".lnk",".scr")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Allowlist software-deployment tooling (SCCM/Intune agents, known installer parents) and internal packaging scripts that legitimately register ProgramData tasks. Consider raising fidelity by requiring InitiatingProcessFileName in script hosts (wscript/cscript/powershell/mshta) or a parent in a browser download path.

## 2) AsyncRAT injection host beaconing: .NET LOLBin making direct outbound connections on non-standard ports

**Tactic:** CommandAndControl  
**ATT&CK:** T1071.001  
**Severity:** High  
**Purpose:** AsyncRAT payloads are commonly injected into or launched via .NET utilities (RegSvcs, RegAsm, InstallUtil, MSBuild, aspnet_compiler) or run from user-writable folders, then beacon to attacker ip:port pairs on non-web ports. Detects the beacon behavior independent of the specific C2 IP list.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType == "ConnectionSuccess"
| where isnotempty(RemoteIP) and not(ipv4_is_private(RemoteIP))
| where InitiatingProcessFileName in~ ("regsvcs.exe","regasm.exe","installutil.exe","msbuild.exe","aspnet_compiler.exe","csc.exe","cvtres.exe","jsc.exe")
    or InitiatingProcessFolderPath has_any (@"\appdata\roaming\", @"\appdata\local\temp\", @"\programdata\", @"\users\public\")
| where RemotePort !in (80, 443, 53, 123, 25, 587)
| summarize ConnCount = count(), DistinctPorts = dcount(RemotePort), Ports = make_set(RemotePort, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RemoteIP, InitiatingProcessAccountName
| where ConnCount >= 3
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RemoteIP, Ports, ConnCount
```

**Tuning notes:** Baseline legitimate developer machines (MSBuild/csc outbound to NuGet-like endpoints) and business apps installed under %LOCALAPPDATA% (Teams, Slack, Zoom, Chrome updaters) — allowlist by InitiatingProcessFolderPath or signer. Lower the ConnCount threshold for high-value hosts; raise it in dev-heavy environments.

## 3) ClickFix / ClearFake: attacker command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake's ClickFix lure instructs victims to copy a command from a compromised website and paste it into Win+R. The pasted command is recorded in the Explorer RunMRU registry key, making it a durable, high-fidelity artifact of the social-engineering execution step.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl ","certutil","bitsadmin","msiexec","conhost","rundll32","wscript","cscript","cmd /c","cmd.exe /c","iex","invoke-expression","invoke-webrequest","iwr ","downloadstring","frombase64string","-enc","-w hidden","-windowstyle hidden","ms-appinstaller","http://","https://")
| project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins occasionally paste legitimate UNC paths or mmc/cmd invocations; allowlist by AccountName for known IT staff or by exact RegistryValueData patterns used in internal runbooks. Pair with a follow-on check of child processes of explorer.exe within 5 minutes on the same device to confirm execution.

## 4) ClickFix follow-on: explorer.exe spawning hidden/remote-fetching script interpreter

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** After the victim pastes the ClickFix command, Explorer launches the interpreter directly. Detects explorer.exe (or the Run dialog path) spawning powershell/mshta/cmd/curl with hidden windows, encoded payloads, or remote URLs — the execution stage of ClearFake, EtherHiding and similar fake-CAPTCHA chains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","wscript.exe","cscript.exe","rundll32.exe","msiexec.exe","conhost.exe","certutil.exe","bitsadmin.exe")
| where ProcessCommandLine has_any ("http://","https://","-enc","-encodedcommand","frombase64string","iex","invoke-expression","downloadstring","downloadfile","invoke-webrequest","iwr ","-w hidden","-windowstyle hidden","--headless","ms-appinstaller","webclient","start-process")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Users double-clicking internal .bat/.ps1 shortcuts from Explorer will fire; allowlist specific script paths or signed internal tooling. mshta.exe and conhost --headless from explorer.exe should be treated as near-zero-false-positive and can be promoted to Critical.

## 5) App Installer (ms-appinstaller) protocol abuse for payload delivery

**Tactic:** Execution  
**ATT&CK:** T1218  
**Severity:** Medium  
**Purpose:** The 'Unknown Loader' cluster (Amadey-dropped, DonutLoader/OffLoader variants) uses the ms-appinstaller: URI handler to make AppInstaller.exe fetch and install an attacker-controlled .appinstaller/.msix package from a remote domain, bypassing browser mark-of-the-web and SmartScreen.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("appinstaller.exe","desktopappinstaller.exe","winget.exe")
    or ProcessCommandLine has "ms-appinstaller:"
| where ProcessCommandLine has_any ("ms-appinstaller:","http://","https://",".appinstaller",".msix",".appx")
| where InitiatingProcessFileName in~ ("msedge.exe","chrome.exe","firefox.exe","brave.exe","explorer.exe","outlook.exe","powershell.exe","cmd.exe","mshta.exe","winword.exe","excel.exe")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Allowlist internal MSIX distribution URLs/domains used by your packaging team and winget invocations against the official Microsoft store source. Enrich by joining DeviceNetworkEvents for the remote host contacted by AppInstaller.exe within +/- 2 minutes.

## 6) Unauthorized ScreenConnect/ConnectWise RMM client installed from user-writable path

**Tactic:** Persistence  
**ATT&CK:** T1219  
**Severity:** High  
**Purpose:** The 'Unknown RAT' cluster abuses ConnectWise ScreenConnect as a RAT: a signed client is dropped from a 7zip SFX or download folder and installed as a service for persistent remote access. Detects RMM client installation/execution originating from temp/download/appdata locations or spawned by browsers, mail clients and script hosts.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName has_any ("screenconnect","connectwise","anydesk","atera","syncro","splashtop","rustdesk","remoteutilities","supremo","tightvnc")
    or ProcessCommandLine has_any ("screenconnect.client","e=Access&y=Guest","connectwisecontrol","&p=443&s=")
| where FolderPath has_any (@"\appdata\local\temp\", @"\downloads\", @"\appdata\roaming\", @"\users\public\", @"\programdata\", @"\perflogs\")
    or InitiatingProcessFileName in~ ("msedge.exe","chrome.exe","firefox.exe","outlook.exe","winrar.exe","7z.exe","powershell.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessIntegrityLevel, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Critical to allowlist the RMM tool your own IT/MSP legitimately uses (by installer path, signer, and relay hostname). Everything else in this list should be treated as unapproved remote access. Consider a companion DeviceNetworkEvents query for ScreenConnect relay domains not matching your tenant's instance.

## 7) DLL sideloading: signed EXE in temp/archive-extraction path loading unsigned DLL from same folder

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.001  
**Severity:** High  
**Purpose:** The 7zip-SFX / DLL-sideloading delivery chain used by the Unknown RAT cluster drops a legitimately signed executable alongside a malicious DLL into a temp or user folder. Detects a process running from a user-writable directory loading a valid-name DLL from that same directory that is unsigned or untrusted.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\downloads\", @"\users\public\", @"\programdata\", @"\perflogs\")
| where FileName endswith ".dll"
| where InitiatingProcessFolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\downloads\", @"\users\public\", @"\programdata\", @"\perflogs\")
| extend DllDir = tolower(substring(FolderPath, 0, strlen(FolderPath) - strlen(FileName)))
| extend ExeDir = tolower(replace_string(tolower(InitiatingProcessFolderPath), tolower(InitiatingProcessFileName), ""))
| where DllDir == ExeDir
| where isempty(Signer) or SignatureStatus !in~ ("Valid","Signed")
| project Timestamp, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, FileName, FolderPath, SHA256, Signer, SignatureStatus, ReportId
```

**Tuning notes:** Portable apps and self-extracting installers (setup bootstrappers, Teams/Chrome updaters staging in %TEMP%) generate noise — allowlist by InitiatingProcessFileName + Signer of the parent EXE. Prioritize cases where the parent EXE is signed by a major vendor but the co-located DLL is unsigned (classic sideload).
