## 1) ScreenConnect Client Spawning Suspicious Child Processes (CVE-2026-84869 Exploitation)

**Tactic:** Execution  
**ATT&CK:** T1219 - Remote Access Software  
**Severity:** High  
**Purpose:** Detects abuse of ConnectWise ScreenConnect remote sessions to transfer and execute payloads without host confirmation, as enabled by CVE-2026-84869. The ScreenConnect client service spawning script interpreters, LOLBins or archive/installer tooling is a strong signal of unauthorized remote execution.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("ScreenConnect.ClientService.exe", "ScreenConnect.WindowsClient.exe", "ScreenConnect.Client.exe", "ConnectWiseControl.Client.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "wscript.exe", "cscript.exe", "mshta.exe", "rundll32.exe", "regsvr32.exe", "msiexec.exe", "bitsadmin.exe", "certutil.exe", "curl.exe", "net.exe", "net1.exe", "whoami.exe", "nltest.exe", "schtasks.exe", "reg.exe", "installutil.exe", "7z.exe", "winrar.exe")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Legitimate helpdesk staff routinely run cmd.exe/powershell.exe via ScreenConnect. Baseline by technician account, device group and command-line content; allowlist known support scripts and maintenance windows. Consider restricting FileName list to the LOLBin subset (mshta, regsvr32, certutil, bitsadmin, installutil) for a higher-fidelity variant, and correlate with DeviceFileEvents writes under ScreenConnect temp folders.

## 2) ClickFix / FakeCaptcha: Script Interpreter Launched from Windows Run Dialog (explorer.exe parent)

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** Detects the ClearFake / IClickFix social-engineering chain where the victim pastes an attacker-supplied command into the Run dialog or terminal. explorer.exe directly spawning powershell/mshta/curl with obfuscated or download-oriented arguments is the core durable behavior of these families.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "conhost.exe", "rundll32.exe")
| where ProcessCommandLine has_any ("-enc", "-EncodedCommand", "FromBase64String", "IEX", "Invoke-Expression", "Invoke-WebRequest", "Invoke-RestMethod", "DownloadString", "DownloadFile", "Net.WebClient", "-w hidden", "-WindowStyle Hidden", "-nop", "-NoProfile", "http://", "https://", "curl ", "bitsadmin", "start-process", "msiexec /i http", "\\\\")
    or ProcessCommandLine matches regex @"(?i)\s#\s*[A-Za-z0-9 ]{10,}"
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins and developers legitimately launch PowerShell from Explorer; scope out IT/engineering device groups or require two or more matching keywords. The regex clause targets the ClickFix trailing-comment 'verification ID' padding used to hide the command in the Run dialog - drop it if noisy. Correlate with DeviceNetworkEvents from the spawned process for follow-on payload retrieval.

## 3) ClickFix Artifact: RunMRU Registry Entry Containing Script or Download Command

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** Medium  
**Purpose:** Detects persistence of the ClickFix lure in the Run dialog MRU key. ClearFake/IClickFix victims paste a copied command into Win+R, which writes the full attacker command line into HKCU\...\RunMRU - a high-fidelity forensic artifact independent of any specific domain.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl", "certutil", "bitsadmin", "wscript", "cscript", "rundll32", "msiexec", "FromBase64String", "IEX", "Invoke-", "http://", "https://", "\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountDomain, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Power users and admins may legitimately type powershell/cmd into Run - filter simple values like 'powershell\\1' or 'cmd\\1' and require a URL, base64 or an encoding keyword. Exclude known admin accounts/jump hosts.

## 4) AsyncRAT Loader Chain: Script Interpreter Spawning Trusted .NET Host for Injection

**Tactic:** DefenseEvasion  
**ATT&CK:** T1055.012 - Process Hollowing  
**Severity:** High  
**Purpose:** Detects the typical AsyncRAT/DonutLoader delivery chain where a script host (wscript/mshta/powershell) launches a signed .NET or Windows binary (aspnet_compiler.exe, RegAsm.exe, InstallUtil.exe, MSBuild.exe, caspol.exe, jsc.exe) used as an injection target for the RAT payload.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("aspnet_compiler.exe", "RegAsm.exe", "RegSvcs.exe", "InstallUtil.exe", "MSBuild.exe", "caspol.exe", "jsc.exe", "AddInProcess.exe", "vbc.exe", "csc.exe", "AppLaunch.exe")
| where InitiatingProcessFileName in~ ("wscript.exe", "cscript.exe", "mshta.exe", "powershell.exe", "pwsh.exe", "cmd.exe", "rundll32.exe", "regsvr32.exe", "explorer.exe", "winrar.exe", "7zfm.exe", "outlook.exe", "chrome.exe", "msedge.exe", "firefox.exe")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Developer and CI/CD workstations legitimately invoke MSBuild/csc/vbc from cmd and powershell - exclude build-server device groups or filter ProcessCommandLine containing known solution/project paths. aspnet_compiler.exe and AppLaunch.exe spawned by script hosts are almost always malicious and can be alerted at higher severity.

## 5) Commodity RAT Beaconing: User-Directory Binary Connecting to Non-Standard Port

**Tactic:** CommandAndControl  
**ATT&CK:** T1571 - Non-Standard Port  
**Severity:** Medium  
**Purpose:** Behavioral detection for AsyncRAT/loader C2 (commonly ip:port on non-standard high ports) without relying on perishable IP indicators: an unsigned executable running from AppData/Temp/ProgramData making repeated outbound connections to an external IP on an uncommon port.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType == "ConnectionSuccess"
| where isnotempty(RemoteIP) and RemoteIPType == "Public"
| where RemotePort !in (80, 443, 53, 123, 25, 587, 993, 995, 22, 3389, 8443)
| where InitiatingProcessFolderPath has_any (@"\AppData\Roaming\", @"\AppData\Local\Temp\", @"\ProgramData\", @"\Users\Public\", @"\Downloads\")
| summarize ConnCount = count(), DistinctPorts = dcount(RemotePort), FirstSeen = min(Timestamp), LastSeen = max(Timestamp), Ports = make_set(RemotePort, 20), RemoteIPs = make_set(RemoteIP, 20)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName
| where ConnCount >= 5
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName, ConnCount, DistinctPorts, Ports, RemoteIPs
```

**Tuning notes:** Game launchers, updaters, torrent clients and some collaboration tools run from user directories on odd ports - allowlist by InitiatingProcessSHA256 or file name. Tighten by adding a beaconing-regularity check (stdev of inter-arrival time) or by requiring the binary to be recently written (join DeviceFileEvents). Adjust ConnCount threshold to environment volume.

## 6) Local Harvesting of AI/LLM API Keys and Provider Credential Files

**Tactic:** Discovery  
**ATT&CK:** T1552.001 - Credentials In Files  
**Severity:** Medium  
**Purpose:** Inspired by the stolen-inference supply chain report: detects processes enumerating or reading files and environment variables that hold LLM provider API keys (OPENAI_API_KEY, ANTHROPIC_API_KEY, .env, provider config directories) - the endpoint-side precursor to reselling stolen inference capacity.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "bash.exe", "sh.exe", "python.exe", "python3.exe", "node.exe", "findstr.exe", "select-string.exe", "grep", "rg.exe", "curl.exe", "wget.exe", "tar.exe")
| where ProcessCommandLine has_any ("OPENAI_API_KEY", "ANTHROPIC_API_KEY", "AZURE_OPENAI", "GEMINI_API_KEY", "GOOGLE_API_KEY", "HUGGINGFACE", "HF_TOKEN", "GROQ_API_KEY", "MISTRAL_API_KEY", "sk-proj-", "sk-ant-", ".openai", ".anthropic", ".aws/credentials", ".env", "credentials.json", "config.json")
| where ProcessCommandLine has_any ("cat ", "type ", "Get-Content", "findstr", "Select-String", "grep", "printenv", "Get-ChildItem Env:", "dir /s", "ls -R", "curl", "Invoke-WebRequest", "Compress-Archive", "tar ", "copy ", "cp ")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Developer workstations and AI coding agents legitimately read .env and API key variables - scope to non-engineering device groups first, or require the command line to also contain exfil verbs (curl/Invoke-WebRequest/Compress-Archive). Extend the keyword list with your organisation's internal AI gateway variable names.

## 7) Clipboard-Sourced Obfuscated PowerShell Execution (ClickFix Paste Chain)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1027 - Obfuscated Files or Information  
**Severity:** Medium  
**Purpose:** Detects ClearFake/IClickFix follow-on stages where a heavily obfuscated or base64-encoded PowerShell command runs with hidden window and bypassed execution policy, typically launched via the pasted Run-dialog or terminal command.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe", "pwsh.exe")
| where ProcessCommandLine has_any ("-enc", "-EncodedCommand", "-e ", "FromBase64String", "[char[]]", "-join", "Invoke-Expression", "IEX", "iwr ", "irm ", "DownloadString", "Get-Clipboard")
| where ProcessCommandLine has_any ("-w hidden", "-WindowStyle Hidden", "-nop", "-NoProfile", "-ep bypass", "-ExecutionPolicy Bypass", "-noni", "-NonInteractive")
| extend CmdLen = strlen(ProcessCommandLine)
| where CmdLen > 180 or ProcessCommandLine has_any ("FromBase64String", "Get-Clipboard", "-EncodedCommand")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, CmdLen, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Management tooling (SCCM, Intune, RMM agents, backup software) frequently uses encoded PowerShell - allowlist by InitiatingProcessFileName/FolderPath of known agents rather than by command content. Adjust the CmdLen threshold to your baseline; consider pairing with DeviceNetworkEvents from the same ProcessId for external connections.
