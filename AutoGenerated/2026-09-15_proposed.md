## 1) ClickFix / ClearFake: Malicious command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake and IClickFix social-engineering lures instruct victims to press Win+R and paste an attacker-supplied command. Every such paste is recorded in the Explorer RunMRU registry key, making this one of the most durable detections for the ClickFix delivery chain regardless of the rotating domains and payload hashes.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in~ ("RegistryValueSet", "RegistryValueCreated")
| where RegistryKey has @"Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl", "certutil", "bitsadmin", "rundll32", "regsvr32", "wscript", "cscript", "msiexec", "conhost", "cmd /c", "cmd.exe /c", "iwr", "Invoke-WebRequest", "IEX", "FromBase64String", "-enc", "-e ", "hidden", "http://", "https://", "\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins and helpdesk staff legitimately type \\server\share, cmd, and powershell into Run. Allowlist by account for known IT staff or drop the bare "cmd /c"/"powershell" keywords if noisy, keeping the download/encoding indicators. Pay attention to RegistryValueData containing long strings, unicode padding, or trailing spaces used to hide the real command off-screen.

## 2) Script interpreter spawned directly by explorer.exe with download or encoded payload arguments

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Captures the execution stage of ClickFix/ClearFake/EtherHiding chains: the user pastes the command so the interpreter (powershell, mshta, curl, msiexec, conhost) is launched as a direct child of explorer.exe with remote-fetch or obfuscation arguments — behavior that virtually never occurs from legitimate user interaction.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "cmd.exe", "curl.exe", "wscript.exe", "cscript.exe", "msiexec.exe", "conhost.exe", "rundll32.exe", "regsvr32.exe", "certutil.exe", "bitsadmin.exe")
| where ProcessCommandLine has_any ("http://", "https://", "IEX", "Invoke-Expression", "Invoke-WebRequest", "iwr ", "DownloadString", "DownloadFile", "FromBase64String", "-enc", "-EncodedCommand", "-w hidden", "-windowstyle hidden", "-nop", "Start-BitsTransfer", "curl ", "msiexec /i http", "\\AppData\\", "\\Temp\\")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Software deployment or admin scripts launched from a desktop shortcut can match; allowlist by signed script path or by specific hash. Consider raising severity when the command line length exceeds ~300 characters or contains base64 blobs. Correlate with the RunMRU detection on the same DeviceId within 5 minutes for very high confidence.

## 3) EtherHiding: script host or LOLBIN connecting to public blockchain RPC endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** Medium  
**Purpose:** ClearFake and related loaders use EtherHiding — storing the next-stage payload/C2 configuration in smart contracts on BNB Chain or the Sepolia testnet — and retrieve it through public RPC providers. Non-browser processes talking to blockchain RPC infrastructure is a strong, IOC-independent signal.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("bsc-dataseed", "binance.org", "sepolia", "infura.io", "alchemyapi.io", "g.alchemy.com", "cloudflare-eth.com", "publicnode.com", "rpc.ankr.com", "drpc.org", "quiknode.pro", "nodereal.io", "llamarpc.com", "blastapi.io")
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "wscript.exe", "cscript.exe", "cmd.exe", "curl.exe", "rundll32.exe", "regsvr32.exe", "node.exe", "certutil.exe", "bitsadmin.exe")
   or InitiatingProcessFolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\Users\Public\", @"\ProgramData\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RemoteUrl, RemoteIP, RemotePort, ReportId
```

**Tuning notes:** Exclude developer and blockchain-engineering workstations and legitimate node.exe projects by device group or by initiating process path. Browser processes are deliberately excluded (the injected JS runs in-browser and is expected); hunt the browser child process instead. Extend the RPC domain list as new providers appear.

## 4) Run key or Startup persistence pointing to a user-writable directory

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** High  
**Purpose:** AsyncRAT, Amadey-dropped loaders and PavinLoader/OffLoader payloads commonly persist via HKCU/HKLM Run values or Startup shortcuts that reference an executable or script staged in AppData, Temp, ProgramData or Public — a behavior stable across all of their rotating hashes.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in~ ("RegistryValueSet", "RegistryValueCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Explorer\Shell Folders", @"\Windows\CurrentVersion\Policies\Explorer\Run")
| where RegistryValueData has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| where RegistryValueData has_any (".exe", ".dll", ".js", ".vbs", ".bat", ".cmd", ".ps1", ".scr", ".hta", "powershell", "mshta", "rundll32", "wscript", "cscript")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Legitimate per-user apps (Teams, OneDrive, Slack, Zoom updaters, Discord) install into AppData and will match — allowlist on RegistryValueData path prefixes or on signed InitiatingProcessFileName. Prioritize entries whose value data contains a random-looking filename or whose initiating process is a script host.

## 5) Scheduled task created for a binary or script in a user-writable path

**Tactic:** Persistence  
**ATT&CK:** T1053.005  
**Severity:** High  
**Purpose:** AsyncRAT and Amadey/OffLoader-style loaders create scheduled tasks (often with /sc minute or ONLOGON and highest privileges) that re-launch a payload dropped into Temp/AppData/ProgramData, providing resilient persistence independent of the sample hash.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("schtasks.exe", "powershell.exe", "pwsh.exe")
| where ProcessCommandLine has_any ("/create", "-create", "Register-ScheduledTask", "New-ScheduledTask")
| where ProcessCommandLine has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
   or ProcessCommandLine has_any ("/sc minute", "/sc MINUTE", "/ru system", "/RL HIGHEST", "mshta", "powershell -w hidden", "-enc")
| where ProcessCommandLine has_any (".exe", ".dll", ".js", ".vbs", ".bat", ".cmd", ".ps1", ".hta", "powershell", "mshta", "rundll32", "wscript")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Software installers and management agents (SCCM, Intune, backup tools) create tasks from ProgramData — allowlist by initiating process signer/path. Tasks created by a process that itself lives in Temp/AppData are the highest-fidelity subset; consider splitting that into a separate Critical rule.

## 6) rundll32/regsvr32 executing a module from a user-writable directory

**Tactic:** Execution  
**ATT&CK:** T1218.011  
**Severity:** Medium  
**Purpose:** Loader families such as the Amadey-dropped 'Unknown Loader'/PavinLoader/OffLoader cluster stage a DLL in %AppData%, %Temp%, %ProgramData% or %Public% and execute it with rundll32 or regsvr32 to evade image-path based controls. Detecting the execution location rather than the hash survives payload rotation.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("rundll32.exe", "regsvr32.exe", "installutil.exe", "msbuild.exe", "regasm.exe", "regsvcs.exe", "aspnet_compiler.exe")
| where ProcessCommandLine has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\", "http://", "https://")
| where not(ProgramFileName == "")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Remove the placeholder 'not(ProgramFileName == \"\")' line if the column is unavailable in your schema. Some installers call rundll32 against Temp-staged DLLs; allowlist by parent installer path/signer. MSBuild/InstallUtil/RegAsm entries here overlap with AsyncRAT .NET in-memory loading and should be treated as high priority when the parent is a script host.

## 7) Executable running from AppData/Temp making repeated outbound connections on non-standard ports

**Tactic:** CommandAndControl  
**ATT&CK:** T1571  
**Severity:** Medium  
**Purpose:** AsyncRAT payloads execute from user-writable directories and beacon to attacker C2 on arbitrary high ports (commonly 6606/7707/8808 and randomized ports). Clustering outbound connections by the initiating process path and port surfaces this beaconing without relying on the 1000+ perishable ip:port IOCs.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType == "ConnectionSuccess"
| where InitiatingProcessFolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| where RemotePort !in (80, 443, 53, 123, 445, 8443)
| where not(ipv4_is_private(RemoteIP))
| summarize ConnCount = count(), DistinctRemotes = dcount(RemoteIP), Ports = make_set(RemotePort, 10), Remotes = make_set(RemoteIP, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName
| where ConnCount >= 5
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, ConnCount, DistinctRemotes, Ports, Remotes
```

**Tuning notes:** Legitimate per-user apps in AppData (Teams, Discord, Spotify, game launchers, updaters) generate non-standard port traffic — allowlist by InitiatingProcessSHA256 or folder path. Tighten by adding a beaconing check (low standard deviation of inter-connection delta) or by requiring a single RemoteIP with a high connection count over many hours.

## 8) LOLBIN download of an executable payload into a user-writable staging directory

**Tactic:** InitialAccess  
**ATT&CK:** T1105  
**Severity:** Medium  
**Purpose:** Both the ClickFix/ClearFake chains and the Amadey-dropped loader cluster fetch their next stage with curl, certutil, bitsadmin or PowerShell and write it into Temp/AppData before execution. Detecting the download-to-disk behavior catches delivery before the payload runs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("curl.exe", "certutil.exe", "bitsadmin.exe", "powershell.exe", "pwsh.exe", "mshta.exe", "wscript.exe", "cscript.exe")
| where ProcessCommandLine has_any ("http://", "https://", "ftp://")
| where ProcessCommandLine has_any ("-o ", "--output", "-OutFile", "DownloadFile", "Start-BitsTransfer", "urlcache", "-urlcache", "/transfer", "-split", "WebClient")
| where ProcessCommandLine has_any (@"\AppData\", @"\Temp\", @"\Users\Public\", @"\ProgramData\", @"\Downloads\", ".exe", ".dll", ".msi", ".scr", ".ps1", ".bat", ".hta")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, SHA256, ReportId
```

**Tuning notes:** Developer tooling, package managers (choco, winget, pip) and patch scripts use curl/BITS heavily — allowlist by parent process, signer or destination domain. Highest fidelity when the parent is explorer.exe, an Office application, or a browser, or when the URL host is a bare IP or newly-registered domain.
