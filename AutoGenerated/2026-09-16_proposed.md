## 1) ClickFix: Suspicious Command Recorded in Explorer RunMRU (Win+R Paste)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake and IClickFix campaigns socially engineer victims into pasting a malicious command into the Windows Run dialog. Every Run-dialog execution is persisted to HKCU\...\Explorer\RunMRU, which makes this registry key a high-fidelity, durable detection point for the ClickFix lure regardless of the rotating delivery domains.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has "Explorer\\RunMRU"
| where isnotempty(RegistryValueData)
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","msiexec","rundll32","regsvr32","wscript","cscript","conhost","forfiles","ftp ","http://","https://","FromBase64String","-enc","-w hidden","iex","Invoke-","\\\\")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessAccountUpn, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins and developers legitimately type cmd/powershell into Run; the value filter focuses on download/encode/UNC patterns rather than bare shell names. Allowlist known IT-admin accounts or jump hosts if noisy. RunMRU value names are single letters plus '\1' suffix - keep RegistryValueData as the primary triage field. Pair with a 5-minute lookaround of DeviceProcessEvents for the same DeviceId to confirm execution.

## 2) Script Interpreter or LOLBin Spawned Directly by explorer.exe With Remote/Encoded Payload

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake and similar paste-and-run lures: because the command is launched from the Run dialog, Explorer becomes the direct parent of powershell/mshta/cmd/curl carrying a remote URL, base64 blob, or hidden-window flag. This is behaviorally stable across the constantly rotating ClearFake and IClickFix infrastructure.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","wscript.exe","cscript.exe","curl.exe","certutil.exe","msiexec.exe","rundll32.exe","regsvr32.exe","bitsadmin.exe","conhost.exe","forfiles.exe")
| where ProcessCommandLine has_any ("http://","https://","FromBase64String","-enc","-EncodedCommand","-e ","-w hidden","-windowstyle hidden","-nop","-noprofile","Invoke-WebRequest","Invoke-Expression","iwr ","iex ","DownloadString","DownloadFile","Start-BitsTransfer","-urlcache","javascript:","vbscript:","\\\\")
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Explorer-parented shells are normal when users double-click .bat/.cmd/.lnk files from shares - allowlist by known internal UNC prefixes or signed script paths. Software deployment tools that surface a UI can also trigger msiexec from Explorer; allowlist specific MSI paths. Tighten by requiring two or more matched keywords if volume is high.

## 3) mshta.exe Executing Remote or Inline Script Content

**Tactic:** Execution  
**ATT&CK:** T1218.005  
**Severity:** High  
**Purpose:** ClearFake and related ClickFix chains commonly use mshta.exe to retrieve and execute HTA/JS staged on compromised or shadowed domains (including payloads served with decoy media extensions). mshta fetching remote content or running inline script protocol handlers is almost never legitimate in enterprise environments.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "mshta.exe"
| where ProcessCommandLine has_any ("http://","https://","javascript:","vbscript:","\\\\",".mp4",".mp3",".png",".jpg",".txt",".log")
| project Timestamp, DeviceName, DeviceId, AccountName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** A handful of legacy line-of-business apps still ship local .hta files - those are excluded already since local .hta paths without the listed keywords will not match. If an internal web app uses mshta with an intranet URL, allowlist that exact FQDN. Investigate the child processes of matching mshta PIDs for the follow-on loader.

## 4) Scheduled Task Created to Run a Binary From a User-Writable Directory

**Tactic:** Persistence  
**ATT&CK:** T1053.005  
**Severity:** Medium  
**Purpose:** AsyncRAT and Amadey-style loaders (OffLoader/PavinLoader) routinely establish persistence with schtasks.exe pointing at a dropped executable in %AppData%, %LocalAppData%\Temp or %ProgramData%, often with /rl HIGHEST and an onlogon/minute trigger. This targets the persistence TTP rather than perishable hashes.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("schtasks.exe") and ProcessCommandLine has "/create"
| where ProcessCommandLine has_any ("appdata","\\temp\\","programdata","\\public\\","\\users\\","%tmp%","%temp%")
| extend HighPriv = ProcessCommandLine has_any ("/rl highest","/ru system")
| extend FastTrigger = ProcessCommandLine has_any ("/sc minute","/sc onlogon","/sc onstart","/mo 1","/sc once")
| project Timestamp, DeviceName, DeviceId, AccountName, ProcessCommandLine, HighPriv, FastTrigger, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Software updaters (Chrome, Edge, Teams, Zoom) create tasks referencing user profile paths - allowlist by InitiatingProcessFolderPath of the signed installer or by task name prefix. Raise severity when HighPriv and FastTrigger are both true or when InitiatingProcessFileName is a script host (powershell/wscript/mshta).

## 5) Run/RunOnce Autostart Value Pointing at AppData, Temp or ProgramData

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** Medium  
**Purpose:** Loaders in this feed (Amadey droppers, PavinLoader/OffLoader) and AsyncRAT builds set HKCU/HKLM Run values to a copied payload in a user-writable folder. Monitoring the registry write catches persistence even when the dropper itself is unknown and packed with UPX.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any ("CurrentVersion\\Run","CurrentVersion\\RunOnce","Windows\\CurrentVersion\\Policies\\Explorer\\Run")
| where RegistryValueData has_any ("AppData","\\Temp\\","ProgramData","\\Public\\","%temp%","%appdata%")
| where RegistryValueData has_any (".exe",".dll",".scr",".bat",".cmd",".vbs",".js",".ps1","powershell","mshta","rundll32","wscript")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Expect benign hits from OneDrive, Teams, Slack, Spotify and Squirrel-based installers that live in %LocalAppData% - allowlist those specific value names/paths. Prioritise events where InitiatingProcessFileName is cmd.exe, reg.exe, powershell.exe, wscript.exe or an unsigned binary in Temp.

## 6) Repeated Outbound Beacons on Non-Standard Ports From a Binary in a User-Writable Path

**Tactic:** CommandAndControl  
**ATT&CK:** T1571  
**Severity:** High  
**Purpose:** AsyncRAT C2 is predominantly raw TCP to ip:port pairs on non-web ports (e.g. 6606/7707/8808 and random high ports) from an executable dropped into AppData/Temp/ProgramData. Detecting the beacon pattern by process location and port profile survives the daily churn of AsyncRAT C2 addresses.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess","ConnectionAttempt","ConnectionFailed")
| where RemoteIPType == "Public"
| where InitiatingProcessFolderPath has_any ("\\appdata\\","\\temp\\","\\programdata\\","\\users\\public\\")
| where RemotePort !in (80, 443, 53, 8443, 123, 22)
| summarize Attempts = count(), DistinctPorts = dcount(RemotePort), FirstSeen = min(Timestamp), LastSeen = max(Timestamp), Ports = make_set(RemotePort, 10), Remotes = make_set(strcat(RemoteIP, ":", tostring(RemotePort)), 10), URLs = make_set(RemoteUrl, 5) by DeviceName, DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName
| where Attempts >= 5
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, Attempts, DistinctPorts, Ports, Remotes, URLs
```

**Tuning notes:** Game launchers, chat clients and P2P/update agents installed per-user will surface here - allowlist by InitiatingProcessSHA256 or folder path after review. Lower the Attempts threshold for hunting, raise it for alerting. Cross-reference InitiatingProcessSHA256 against DeviceFileEvents to find the dropper that wrote it.

## 7) Microsoft Defender Exclusion or Feature Disabled via Command Line

**Tactic:** DefenseEvasion  
**ATT&CK:** T1562.001  
**Severity:** High  
**Purpose:** Amadey-dropped loaders and RAT installers commonly carve out Defender exclusions for their staging folder or disable real-time monitoring before dropping the second stage. This is a compact, high-signal defense-evasion behaviour independent of the payload hashes.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (ProcessCommandLine has_any ("Add-MpPreference","Set-MpPreference") and ProcessCommandLine has_any ("ExclusionPath","ExclusionExtension","ExclusionProcess","DisableRealtimeMonitoring","DisableBehaviorMonitoring","DisableIOAVProtection","DisableScriptScanning","MAPSReporting","SubmitSamplesConsent"))
    or (FileName in~ ("reg.exe","powershell.exe","pwsh.exe","cmd.exe") and ProcessCommandLine has "Windows Defender" and ProcessCommandLine has_any ("Exclusions","DisableAntiSpyware","DisableRealtimeMonitoring","TamperProtection"))
    or (FileName =~ "sc.exe" and ProcessCommandLine has_any ("windefend","sense","wdnissvc") and ProcessCommandLine has_any ("stop","delete","config","disabled"))
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Legitimate exclusions are usually pushed by GPO/Intune rather than an interactive command line; allowlist your endpoint-management agent (e.g. ccmexec.exe, IntuneManagementExtension) as InitiatingProcessFileName. Treat any match whose parent is a script host or a binary under Temp/AppData as Critical.

## 8) macOS osascript Displaying a Password Prompt (AMOS/ClickFix Credential Phish)

**Tactic:** CredentialAccess  
**ATT&CK:** T1056.002  
**Severity:** High  
**Purpose:** The IClickFix cluster delivers Atomic macOS Stealer (AMOS) through fake-verification pages on compromised education and government sites. AMOS uses osascript to render a fake system dialog with a hidden-answer field to harvest the user's login keychain password. This detects the credential-prompt behaviour on Defender for Endpoint macOS agents.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("osascript","osascript.bin")
| where ProcessCommandLine has_any ("display dialog","display alert")
| where ProcessCommandLine has_any ("hidden answer","password","Passwort","credentials","administrator","System Preferences","System Settings","unlock","Touch ID","keychain")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Some enterprise Mac management scripts (Jamf/Munki self-service prompts) legitimately use osascript password dialogs - allowlist by InitiatingProcessFolderPath (e.g. /Library/Application Support/JAMF) or by the exact dialog text. Any match whose parent is Terminal, bash/zsh, curl or a binary under /tmp, /var/folders or ~/Downloads should be escalated immediately.

## 9) macOS/Linux Remote Script Piped Directly Into a Shell or Decoded Inline

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** The macOS ClickFix variant instructs victims to paste a one-liner into Terminal that curls a staged payload and pipes it into sh/bash, frequently combined with base64 decoding and quarantine-attribute stripping. This is the core execution behaviour of the IClickFix/AMOS delivery chain and is independent of the rotating payload URLs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("bash","sh","zsh","dash","curl","xattr","chmod","osascript")
| where (ProcessCommandLine has_any ("curl","wget") and ProcessCommandLine has_any ("| sh","|sh","| bash","|bash","| zsh","|zsh","| osascript","|osascript"))
    or (ProcessCommandLine has_any ("base64 -d","base64 --decode","openssl enc -d") and ProcessCommandLine has_any ("| sh","| bash","eval"))
    or (ProcessCommandLine has "xattr" and ProcessCommandLine has_any ("-c","-d com.apple.quarantine","-r -d"))
    or (ProcessCommandLine has "chmod" and ProcessCommandLine has_any ("777","+x") and ProcessCommandLine has_any ("/tmp/","/var/folders/","/Users/Shared/","Downloads/"))
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Developer workstations generate legitimate curl|bash (homebrew, rustup, nvm installers) - allowlist by known installer domains present in the command line or by developer device group. xattr quarantine removal by signed management tooling can be allowlisted via InitiatingProcessFolderPath. Highest confidence when the parent is Terminal.app/iTerm and the same device also shows an osascript password dialog within minutes.
