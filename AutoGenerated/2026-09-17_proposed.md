## 1) ClickFix / FakeUpdate: Run dialog (RunMRU) entry launching a script interpreter

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** ClearFake and related ClickFix lures instruct victims to paste a malicious command into the Windows Run dialog. Every pasted command is persisted under Explorer\RunMRU, giving a high-fidelity, IOC-independent artifact of the social-engineering step.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl ","certutil","bitsadmin","rundll32","wscript","cscript","msiexec","conhost","-enc","iwr ","Invoke-","cmd /c","cmd.exe /c","forfiles","\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins and helpdesk staff legitimately paste UNC paths or 'cmd /c' commands; allowlist known IT accounts/devices or tighten to RegistryValueData containing base64/http/hidden markers. Consider joining to DeviceProcessEvents within 5 minutes on the same DeviceId to confirm the command actually executed.

## 2) Script interpreter spawned directly by explorer.exe with download/hidden-execution flags

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake and similar paste-and-run lures, where explorer.exe (Run dialog, Win+R, or double-clicked shortcut) directly spawns PowerShell/mshta/curl with remote fetch or hidden-window arguments.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","cmd.exe","curl.exe","certutil.exe","bitsadmin.exe","rundll32.exe","msiexec.exe")
| where ProcessCommandLine has_any ("http://","https://","-enc","-EncodedCommand","FromBase64String","-w hidden","-windowstyle hidden","-nop","-NoProfile","IEX","Invoke-Expression","Invoke-WebRequest","DownloadString","DownloadFile","iwr ","curl ","javascript:","mshta ")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Software deployment or admin scripts launched from Explorer can match; allowlist specific signed script paths and known internal URLs/shares. Raise severity when the command line also contains clipboard references, '✅'/'I am not a robot' style comment padding, or very long base64 blobs.

## 3) EtherHiding: scripting engine or LOLBin contacting public blockchain RPC endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** High  
**Purpose:** ClearFake and the tagged 'Unknown Loader' cluster use EtherHiding - retrieving next-stage payloads/C2 configuration from smart contracts on BSC/Ethereum/Sepolia via public RPC nodes. Interpreter processes talking to Web3 RPC infrastructure is highly anomalous on enterprise endpoints.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
```

**Tuning notes:** Developer workstations running node.exe against Web3 endpoints are a legitimate source - scope out dev device groups or the node.exe entry. 'rpc.' is broad; drop it if noisy and rely on the named providers. Browser-initiated Web3 traffic is intentionally excluded.

## 4) Run key or Startup persistence pointing at a binary in user-writable directories

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** High  
**Purpose:** AsyncRAT, Amadey-dropped loaders and most commodity stealers persist by writing an autorun value referencing an executable or script staged in %TEMP%, %APPDATA%, %PROGRAMDATA% or Public. This is a durable behavioral signal independent of the current IOC set.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Explorer\Shell Folders", @"\Windows\CurrentVersion\Policies\Explorer\Run")
| where RegistryValueData has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\ProgramData\\","\\Users\\Public\\","\\Windows\\Temp\\","\\Downloads\\")
| where RegistryValueData has_any (".exe",".scr",".vbs",".js",".bat",".cmd",".ps1",".hta",".dll")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Some legitimate installers (Teams, Zoom updaters, Chrome updater) write AppData paths - allowlist by RegistryValueData publisher path or by InitiatingProcessFileName of known updaters. Pair with DeviceFileEvents to confirm the referenced file was recently created.

## 5) Scheduled task created to run a payload from Temp/AppData with hidden or frequent trigger

**Tactic:** Persistence  
**ATT&CK:** T1053.005  
**Severity:** Medium  
**Purpose:** AsyncRAT and loader families commonly register a scheduled task (often with /rl highest or a minute-interval trigger) pointing to a dropped binary in a user-writable folder, providing persistence and privilege continuity.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "schtasks.exe"
| where ProcessCommandLine has "/create" or ProcessCommandLine has "/CREATE"
| where ProcessCommandLine has_any ("\\AppData\\","\\Temp\\","\\ProgramData\\","\\Users\\Public\\","\\Downloads\\","powershell","mshta","wscript","cscript","rundll32")
| project Timestamp, DeviceId, DeviceName, AccountName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Software installers and management agents create tasks referencing ProgramData; allowlist by InitiatingProcessFileName (e.g., msiexec.exe launched from a signed installer) or by task name prefix. Higher confidence when the parent is explorer.exe, a browser, or an unsigned binary in Temp.

## 6) Unsigned binary in user-writable folder beaconing to a public IP on a non-standard port

**Tactic:** CommandAndControl  
**ATT&CK:** T1571  
**Severity:** High  
**Purpose:** AsyncRAT and similar .NET RATs execute from %AppData%/%Temp%/%ProgramData% and beacon to attacker infrastructure on non-web ports (e.g., 6606/7707/8808 and randomized high ports). Detecting the behavior avoids reliance on the ~2000 perishable ThreatFox IOCs.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess","ConnectionAttempt")
| where RemoteIPType == "Public"
| where InitiatingProcessFolderPath has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\ProgramData\\","\\Users\\Public\\","\\Windows\\Temp\\","\\Downloads\\")
| where RemotePort !in (80, 443, 53, 8080, 123)
| summarize Connections = count(), Ports = make_set(RemotePort, 10), Destinations = make_set(RemoteIP, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName
| where Connections >= 3
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, Connections, Ports, Destinations
```

**Tuning notes:** Game launchers, chat clients and some updaters run from AppData and use odd ports - allowlist by InitiatingProcessFolderPath/SHA. Lower the Connections threshold for low-noise environments; add a join to DeviceFileEvents to prioritise binaries created in the last 7 days.

## 7) Microsoft Defender exclusion or protection disabled via command line

**Tactic:** DefenseEvasion  
**ATT&CK:** T1562.001  
**Severity:** High  
**Purpose:** Loaders (Amadey-style droppers, ClickFix payload chains) and RATs routinely add Defender exclusions for their staging folder or disable real-time monitoring before dropping the final payload.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("Add-MpPreference","Set-MpPreference","MpCmdRun.exe -RemoveDefinitions","DisableRealtimeMonitoring","DisableBehaviorMonitoring","DisableIOAVProtection","DisableScriptScanning","ExclusionPath","ExclusionExtension","ExclusionProcess","sc stop WinDefend","sc config WinDefend")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Security/IT tooling and imaging scripts legitimately set exclusions - allowlist by initiating process path, signing status, or SCCM/Intune management accounts. Treat exclusions for AppData/Temp/root drive ('C:\\') as critical regardless of actor.

**ATT&CK:** T1218  
**Severity:** Medium  
**Purpose:** AsyncRAT loaders and many commodity .NET RATs abuse trusted Microsoft .NET utilities to compile or host the payload in memory, evading file-based detection. Execution of these binaries outside a build/dev context is anomalous.

## 10) macOS: osascript credential-harvesting dialog (AMOS stealer pattern)

**Tactic:** CredentialAccess  
**ATT&CK:** T1059.002  
**Severity:** High  
**Purpose:** Atomic macOS Stealer's fake 'setup guide' chain uses AppleScript to display a password prompt ('with hidden answer') and then validates/uses the captured credential to unlock the keychain. This is the core credential-theft behaviour of AMOS regardless of the delivery domain.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("osascript","osacompile") or ProcessCommandLine has "osascript"
| where ProcessCommandLine has_any ("display dialog","with hidden answer","default answer","System Preferences","System Settings","administrator privileges","do shell script","password","security find-generic-password","login.keychain")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Some legitimate Mac admin tooling and installers prompt via AppleScript - allowlist by InitiatingProcessFolderPath (e.g., /Applications/<approved app>) or by known management agents (Jamf, Munki). Highest confidence when combined with 'with hidden answer' plus 'do shell script ... with administrator privileges'.

## 11) macOS: curl/wget piped directly to a shell, or quarantine attribute stripped from a downloaded payload

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** AMOS deceptive install guides instruct users to paste a one-liner that downloads and executes the stealer, and the loader strips com.apple.quarantine / chmod +x's the payload in /tmp or /Users/Shared to bypass Gatekeeper.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (ProcessCommandLine matches regex @"(curl|wget)[^|]{0,200}\|\s*(sudo\s+)?(ba)?sh"
    or (FileName =~ "xattr" and ProcessCommandLine has_any ("-d com.apple.quarantine","-c ","-r -d com.apple.quarantine"))
    or (FileName =~ "chmod" and ProcessCommandLine has_any ("+x /tmp/","+x /Users/Shared/","777 /tmp/","+x /var/tmp/"))
    or ProcessCommandLine has_any ("spctl --master-disable","launchctl load -w /Users/","ditto -xk"))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Developer and Homebrew workflows legitimately pipe curl to bash and chmod +x in /tmp - scope out engineering device groups or Homebrew's parent process. Prioritise events whose parent is Terminal.app/iTerm launched shortly after a browser download, or where the target path is /Users/Shared.

## 12) PowerSploit/offensive PowerShell tradecraft in command line or script block

**Tactic:** Discovery  
**ATT&CK:** T1059.001  
**Severity:** Medium  
**Purpose:** The tagged 'Unknown malware' cluster includes PowerSploit and Mythic tooling. Detects hands-on-keyboard use of well-known offensive PowerShell function names and in-memory loading cradles, which remain stable across infrastructure churn.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe","pwsh.exe","powershell_ise.exe") or InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe")
| where ProcessCommandLine has_any ("Invoke-Mimikatz","Invoke-DllInjection","Invoke-Shellcode","Invoke-ReflectivePEInjection","Get-KeyStrokes","Get-GPPPassword","Invoke-TokenManipulation","PowerView","Invoke-BloodHound","Get-NetDomainController","Invoke-Kerberoast","Out-EncryptedScript","Add-Persistence","Invoke-WmiCommand","[Reflection.Assembly]::Load","System.Reflection.AssemblyName","VirtualAlloc","memcpy","-enc ")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Red team and authorised pentest windows will trigger this - maintain an exception list of engagement devices/timeframes. '-enc ' and 'VirtualAlloc' are the noisiest terms; if needed, require two or more matching terms or restrict encoded commands to those exceeding 500 characters.
