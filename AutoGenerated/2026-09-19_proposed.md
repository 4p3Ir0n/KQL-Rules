## 1) ClickFix: Run dialog (RunMRU) populated with script/downloader command

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste  
**Severity:** High  
**Purpose:** ClearFake and other ClickFix/EtherHiding campaigns socially engineer victims into pasting a malicious command into the Windows Run dialog. Every pasted command is recorded under HKCU\...\Explorer\RunMRU, giving a durable, high-fidelity artifact of the initial execution regardless of the changing C2 domains.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl ","certutil","bitsadmin","msiexec","rundll32","regsvr32","wscript","cscript","conhost","cmd /c","cmd.exe /c","forfiles","node ")
    or RegistryValueData has_any ("http://","https://","FromBase64String","-enc","-ec ","iwr ","Invoke-WebRequest","Invoke-Expression","IEX","-w hidden","-nop","DownloadString","\\\\")
| project Timestamp, DeviceName, DeviceId, AccountName=InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins and developers legitimately paste UNC paths and cmd commands; allowlist by AccountName for known IT staff or exclude RegistryValueData that resolves only to internal file shares. Consider raising severity when the value contains base64, 'hidden', or an external URL. Tune out software deployment tooling that writes RunMRU indirectly.

## 2) Script interpreter or LOLBin spawned directly by explorer.exe with remote-download arguments

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** Follow-on detection for ClickFix/ClearFake and fake-update lures: after the user pastes the command, explorer.exe (the Run dialog / shell) becomes the parent of powershell, mshta, curl, msiexec or cmd invoking a remote payload. Catches the execution behavior rather than the rotating ClearFake domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","certutil.exe","bitsadmin.exe","msiexec.exe","rundll32.exe","regsvr32.exe","wscript.exe","cscript.exe","node.exe")
| where ProcessCommandLine has_any ("http://","https://","FromBase64String","-enc","-ec ","-e ","iwr","Invoke-WebRequest","Invoke-Expression","IEX","DownloadString","DownloadFile","-w hidden","-windowstyle hidden","-nop","-noprofile","Start-BitsTransfer","/i ")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Exclude internal software portals / package managers that legitimately launch msiexec with an intranet URL. Some help-desk workflows use 'curl.exe' from Run; scope those by device group. If noisy, restrict to commands longer than 120 characters or containing base64-like tokens.

## 3) AsyncRAT-style injection into .NET utility binaries (aspnet_compiler, RegSvcs, InstallUtil, MSBuild, AppLaunch)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218 - System Binary Proxy Execution / Process Injection  
**Severity:** High  
**Purpose:** AsyncRAT and other commodity .NET RATs are typically delivered by a loader that starts a signed Microsoft .NET utility in a suspended state and hollows the RAT into it. Detecting these binaries launched with no/odd arguments from a script host or user-writable path finds the family independent of the 961 rotating hashes/C2s.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("aspnet_compiler.exe","RegAsm.exe","RegSvcs.exe","InstallUtil.exe","MSBuild.exe","AppLaunch.exe","jsc.exe","csc.exe","vbc.exe")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","cmd.exe","rundll32.exe","winword.exe","excel.exe","explorer.exe","node.exe")
    or InitiatingProcessFolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\users\public\", @"\programdata\", @"\downloads\")
| where not(ProcessCommandLine has_any (".csproj",".sln",".vbproj","/target:","msbuild.rsp"))
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, ProcessIntegrityLevel, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Developer workstations and CI agents legitimately run MSBuild/csc/vbc from scripts — exclude build-server device groups and paths under source-control roots. aspnet_compiler.exe and AppLaunch.exe from non-IIS/non-ClickOnce hosts are almost always malicious; keep those at high severity.

## 4) Executable in user-writable directory beaconing to external host on a non-standard port

**Tactic:** CommandAndControl  
**ATT&CK:** T1571 - Non-Standard Port  
**Severity:** Medium  
**Purpose:** AsyncRAT and similar commodity RATs drop into %AppData%/%Temp%/ProgramData and beacon repeatedly to an ip:port C2 on uncommon high ports. Aggregating repeated outbound connections from non-installed binaries detects the family without relying on the 961 short-lived IOCs.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType == "ConnectionSuccess"
| where InitiatingProcessFolderPath has_any (@"\appdata\roaming\", @"\appdata\local\temp\", @"\programdata\", @"\users\public\", @"\downloads\")
| where RemoteIPType == "Public"
| where RemotePort !in (80, 443, 8443, 53, 123)
| summarize ConnCount=count(), DistinctPorts=dcount(RemotePort), FirstSeen=min(Timestamp), LastSeen=max(Timestamp), Ports=make_set(RemotePort, 10), Remotes=make_set(RemoteIP, 10)
    by DeviceName, DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessSHA256
| where ConnCount >= 5
| extend DurationMin = datetime_diff('minute', LastSeen, FirstSeen)
| project FirstSeen, LastSeen, DurationMin, DeviceName, DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessSHA256, ConnCount, DistinctPorts, Ports, Remotes
```

**Tuning notes:** Per-user installed apps (Teams, Spotify, Discord, game launchers, some VPN clients) live in AppData and use odd ports — allowlist by SHA256/signer. Beacon-like regularity (low variance in inter-connection delta) is a strong escalation signal; add a stddev calculation if you need fewer alerts.

## 5) Node.js / script host executing inline or user-path script with network access

**Tactic:** Execution  
**ATT&CK:** T1059.007 - JavaScript  
**Severity:** Medium  
**Purpose:** The feed's downloader cluster is tagged NodeJS — actors ship a portable node.exe (often EV-signed) and run inline JavaScript loaders, or abuse wscript/cscript from user directories. Detects the loader stage regardless of payload hash.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (FileName =~ "node.exe" and (ProcessCommandLine has_any (" -e "," --eval","-p ","--input-type=module","require('child_process')","require(\"child_process\")","http://","https://") or FolderPath has_any (@"\appdata\", @"\temp\", @"\users\public\", @"\downloads\")))
    or (FileName in~ ("wscript.exe","cscript.exe") and ProcessCommandLine has_any (@"\appdata\", @"\temp\", @"\users\public\", @"\downloads\", ".js", ".jse", ".vbe", ".wsf"))
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Developer machines run node.exe constantly — exclude device groups of engineers or exclude node processes whose parent is a known IDE/terminal and whose working directory is a source repo. Legacy line-of-business VBS logon scripts under \\NETLOGON should be excluded by path.

## 6) Linux: root shell or privileged process spawned from an unprivileged non-setuid parent

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1068 - Exploitation for Privilege Escalation  
**Severity:** Medium  
**Purpose:** Generic post-exploitation signal for the actively-exploited Linux kernel flaws in this feed (CVE-2025-39964 AF_ALG race, CVE-2026-53266 ebtables OOB write, CVE-2025-39682 TLS recvmsg). Successful local kernel exploitation typically manifests as a shell or interpreter running as root whose parent ran as a normal user.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("bash","sh","dash","zsh","ksh","python","python3","perl","ruby","nc","ncat","socat","busybox")
| where AccountName == "root"
| where isnotempty(InitiatingProcessAccountName) and InitiatingProcessAccountName !in~ ("root","system")
| where InitiatingProcessFileName !in~ ("sudo","su","pkexec","doas","systemd","sshd","cron","crond","runc","containerd-shim","dockerd")
| project Timestamp, DeviceName, DeviceId, AccountName, ProcessId, FileName, FolderPath, ProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessId, ReportId
```

**Tuning notes:** Container runtimes, orchestration agents and CI runners legitimately transition UIDs — allowlist those parent binaries and container host device groups. Correlate with recent kernel-module loads, unusual /tmp binaries, or a preceding compiler invocation to raise confidence. Only meaningful on Defender for Endpoint Linux onboarded hosts.
