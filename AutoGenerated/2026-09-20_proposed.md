## 1) ClickFix: Attacker-Supplied Command Pasted Into the Windows Run Dialog

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste (ClickFix)  
**Severity:** High  
**Purpose:** ClearFake/ClickFix lures instruct victims to paste a crafted command into the Win+R Run dialog. Every such execution leaves the command string in the Explorer RunMRU registry value, giving a high-fidelity, IOC-independent detection of the social-engineering step.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","msiexec","rundll32","regsvr32","wscript","cscript","conhost","cmd /c","cmd.exe /c","http://","https://","iwr","irm","invoke-expression","iex","frombase64string","-enc","-ec ","hidden")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Administrators legitimately type 'cmd', 'powershell' or UNC paths into Run; filter on RegistryValueData length (> 80 chars is strongly suspicious) or require a URL/base64/hidden-window token. Allowlist known IT admin accounts and jump hosts. Pair hits with the follow-on process created by explorer.exe within 60 seconds for confirmation.

## 2) Explorer-Spawned Interpreter Performing Download-and-Execute (ClickFix / ClearFake chain)

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake and similar fake-CAPTCHA / fake-Wordfence lures: explorer.exe directly spawning a script interpreter or LOLBin whose command line contains remote-download and in-memory execution primitives.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","wscript.exe","cscript.exe","msiexec.exe","rundll32.exe","regsvr32.exe","conhost.exe","node.exe","bitsadmin.exe","certutil.exe")
| where ProcessCommandLine has_any ("iex","invoke-expression","invoke-webrequest","iwr ","irm ","downloadstring","downloadfile","webclient","frombase64string","-enc","-ec ","-nop","-w hidden","-windowstyle hidden","--headless","http://","https://","start-bitstransfer","urlcache","scriptblock")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Legitimate helpdesk scripts and software installers launched from Explorer can match; allowlist by signed parent installer path, specific script share UNC paths, or admin accounts. 'conhost.exe --headless' plus a URL is almost always malicious. Consider raising severity when the command line contains both a URL and an execution primitive (iex/Start-Process).

## 3) Script Host or LOLBin Contacting Public Blockchain RPC Endpoint (EtherHiding)

**Tactic:** CommandAndControl  
**ATT&CK:** T1102 - Web Service  
**Severity:** High  
**Purpose:** ClearFake and the tagged 'etherhiding'/'sepolia' stealer campaigns retrieve their next-stage payload and C2 configuration from smart contracts via public blockchain RPC nodes. Non-browser interpreters talking to those RPC services is anomalous and durable across infrastructure rotation.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("bsc-dataseed","binance.org","sepolia","infura.io","alchemy.com","ankr.com","publicnode.com","quiknode","cloudflare-eth","drpc.org","llamarpc","nodereal.io","blockpi.network","rpc." )
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","mshta.exe","wscript.exe","cscript.exe","node.exe","curl.exe","rundll32.exe","regsvr32.exe","cmd.exe","msiexec.exe","certutil.exe")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RemoteUrl, RemoteIP, RemotePort, ReportId
```

**Tuning notes:** The generic 'rpc.' token is broad — drop it if it produces noise from internal services. Allowlist legitimate developer/blockchain workstations and CI agents. Browsers are deliberately excluded because the injected page itself makes RPC calls; if you want the browser-side view, run a separate lower-severity hunt scoped to chrome/edge/firefox with a first-seen-domain filter.

## 4) Browser Credential Store Copied or Written by Non-Browser Process

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003 - Credentials from Web Browsers  
**Severity:** High  
**Purpose:** RustyStealer and Amadey-dropped stealers harvest Chromium/Firefox credential databases. Detects a non-browser process creating, renaming or copying browser secret stores (Login Data, Local State, key4.db, cookies) — the core behaviour regardless of hash or C2 domain.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FileName in~ ("Login Data","Login Data For Account","Web Data","Cookies","Local State","key4.db","key3.db","logins.json","cert9.db","places.sqlite","formhistory.sqlite")
| where ActionType in ("FileCreated","FileRenamed","FileModified")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","vivaldi.exe","msedgewebview2.exe","iexplore.exe","svchost.exe","MsMpEng.exe","backup.exe")
| where not(FolderPath has_any ("\\User Data\\Default\\","\\User Data\\Profile","\\Mozilla\\Firefox\\Profiles\\")) or FolderPath has_any ("\\Temp\\","\\AppData\\Local\\Temp","\\ProgramData\\","\\Users\\Public\\","\\Downloads\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ActionType, FileName, FolderPath, SHA256, ReportId
```

**Tuning notes:** Backup, EDR/DLP, browser-migration and profile-sync tools legitimately touch these files — allowlist them by InitiatingProcessFolderPath/signer. Also consider joining to a DeviceNetworkEvents lookup for the same InitiatingProcessId to confirm exfiltration.

## 5) Run Key Persistence Pointing at Temp / AppData / ProgramData Binary

**Tactic:** Persistence  
**ATT&CK:** T1547.001 - Registry Run Keys / Startup Folder  
**Severity:** Medium  
**Purpose:** Amadey-style loaders, ClickFix second stages and commodity stealers persist by writing an autorun value that references a payload dropped into a user-writable directory. This is the durable persistence TTP behind the fresh 'Downloader'/'dropped-by-amadey' indicator sets.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Policies\Explorer\Run", @"\Windows\CurrentVersion\Winlogon")
| where RegistryValueData has_any ("\\AppData\\Local\\Temp","\\AppData\\Roaming","\\ProgramData\\","\\Users\\Public\\","\\Downloads\\","\\Windows\\Temp","powershell","mshta","rundll32","wscript","cscript","curl","node.exe")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Some legitimate per-user apps (Teams, Zoom updaters, Slack, OneDrive) install into AppData — allowlist by exact RegistryValueData prefix and publisher. Enrich by joining DeviceFileEvents for the creation of the referenced binary within the previous hour; new-file + new-Run-value is the strong signal.

## 6) Linux Pipe-to-Shell Download Execution (VShell / Mexals / Supershell Staging)

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Unix Shell  
**Severity:** High  
**Purpose:** VShell, Supershell, Mythic ELF agents and the Mexals crypto-mining crew all stage via 'curl|wget ... | bash' one-liners. Detects remote-content execution without relying on rotating download URLs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("bash","sh","dash","zsh","curl","wget","python3","perl")
| where ProcessCommandLine matches regex @"(?i)(curl|wget)[^|;]{0,200}\|\s*(sudo\s+)?(ba|z|da)?sh"
    or ProcessCommandLine has_any ("wget -q -O- ","curl -fsSL","--no-check-certificate","-O /tmp/","-O /dev/shm/")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Build/CI hosts and container images legitimately use install.sh one-liners — scope out known build agents or allowlist trusted domains (get.docker.com, packages vendor domains) by adding a RemoteUrl exclusion list. Escalate when the parent is a web server, cron, or an SSH session from an unusual source.

## 7) Execution From World-Writable Linux Directory (/tmp, /dev/shm, /var/tmp)

**Tactic:** Execution  
**ATT&CK:** T1059 - Command and Scripting Interpreter  
**Severity:** High  
**Purpose:** VShell and Mythic implants, and Mexals miner droppers, are chmod'ed and launched from world-writable paths. Execution of any binary from these directories with a shell/cron/web parent is a strong post-compromise signal.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FolderPath has_any ("/tmp/","/dev/shm/","/var/tmp/","/run/user/","/var/www/")
| where FileName !in~ ("sh","bash","dash","sed","awk","grep","cat")
| where InitiatingProcessFileName in~ ("bash","sh","dash","zsh","cron","crond","systemd","sshd","python3","perl","httpd","apache2","nginx","php-fpm","curl","wget","chmod","nohup","setsid")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Package managers, configuration-management agents (Ansible remote modules run from ~/.ansible/tmp), and some installers execute from /tmp — allowlist those specific paths/filename patterns. Correlate with an outbound DeviceNetworkEvents connection from the same ProcessId to raise confidence (implant check-in).

## 8) Web Server or PHP Worker Spawning a Shell / Recon Command

**Tactic:** Persistence  
**ATT&CK:** T1505.003 - Web Shell  
**Severity:** Critical  
**Purpose:** The 'fake-wordfence' WordPress mu-plugin campaign drops PHP backdoors that execute OS commands. Any web server or PHP-FPM worker spawning an interactive shell, downloader or recon binary indicates active web-shell use.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("httpd","apache2","nginx","php-fpm","php-cgi","php","w3wp.exe","tomcat","node")
| where FileName in~ ("bash","sh","dash","zsh","python3","perl","curl","wget","whoami","id","uname","nc","ncat","socat","chmod","crontab","cmd.exe","powershell.exe","net.exe","net1.exe","systeminfo.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Some PHP applications shell out legitimately (image conversion, backup plugins, WP-Cron via sh). Baseline per-server for 7 days and allowlist the recurring parent+child+command-line triples. Commands containing base64, curl to an IP literal, or reverse-shell syntax should page immediately.

## 9) PHP File Written to WordPress mu-plugins / Plugin Directory by Web Process

**Tactic:** Persistence  
**ATT&CK:** T1505.003 - Web Shell  
**Severity:** High  
**Purpose:** Detects the file-drop stage of the fake-Wordfence WordPress compromise, where attackers place a must-use plugin (auto-loaded, hidden from the plugin list) to maintain persistence and deliver stealer payloads.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where FileName endswith ".php"
| where FolderPath has_any ("mu-plugins","/wp-content/plugins/","/wp-includes/","/wp-admin/","\\wp-content\\plugins\\")
| where InitiatingProcessFileName has_any ("httpd","apache2","nginx","php-fpm","php-cgi","php","w3wp.exe","node","curl","wget","sh","bash")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Legitimate plugin installs and auto-updates performed by the web user will match — allowlist scheduled maintenance windows or the update process lineage (wp-cron/WP-CLI). Files written directly into mu-plugins are rare in most deployments and should be treated as high confidence.

## 10) Shadow Copy Deletion / Recovery Tampering Prior to Ransomware Encryption

**Tactic:** Impact  
**ATT&CK:** T1490 - Inhibit System Recovery  
**Severity:** Critical  
**Purpose:** The fresh indicator set is tagged 'Ransomware'. Regardless of family or hash, pre-encryption recovery destruction (vssadmin/wmic shadow deletion, bcdedit recovery disable, wbadmin catalog delete) is a durable, high-severity behaviour.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (FileName in~ ("vssadmin.exe","wmic.exe","diskshadow.exe") and ProcessCommandLine has_any ("delete shadows","shadowcopy delete","resize shadowstorage","delete shadowstorage"))
    or (FileName =~ "bcdedit.exe" and ProcessCommandLine has_any ("recoveryenabled no","bootstatuspolicy ignoreallfailures","safeboot"))
    or (FileName =~ "wbadmin.exe" and ProcessCommandLine has_any ("delete catalog","delete systemstatebackup","delete backup"))
    or (FileName in~ ("powershell.exe","pwsh.exe") and ProcessCommandLine has_any ("Win32_ShadowCopy","Remove-CimInstance -Query","Delete()") and ProcessCommandLine has "ShadowCopy")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Backup software and sysprep/imaging jobs can legitimately resize or delete shadow storage — allowlist by InitiatingProcessFolderPath of the backup agent and by service account. Anything parented by Office apps, script hosts, or a binary in Temp/AppData should trigger automatic isolation.

## 11) Linux Root Shell Spawned by Non-Root Process From User-Writable Path (Kernel LPE Post-Exploitation)

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1068 - Exploitation for Privilege Escalation  
**Severity:** High  
**Purpose:** Kernel bugs such as the AF_ALG race (CVE-2025-39964), the ebtables SNAT OOB write (CVE-2026-53266) and the TLS recvmsg flaw (CVE-2025-39682) are exploited by unprivileged local binaries that then return a root shell. Detects the observable post-exploitation outcome rather than the unlogged kernel memory corruption.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("bash","sh","dash","zsh","python3","perl")
| where AccountName =~ "root"
| where isnotempty(InitiatingProcessAccountName) and InitiatingProcessAccountName !~ "root"
| where InitiatingProcessFolderPath has_any ("/tmp/","/dev/shm/","/var/tmp/","/home/","/run/user/","/var/www/")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessIntegrityLevel, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** sudo/pkexec/su invocations normally show root child with a non-root parent — exclude InitiatingProcessFileName in (sudo, su, pkexec, systemd-run, doas) if you only want implicit escalation, or keep them and instead require the parent path to be under /tmp, /dev/shm or /var/www as above. Validate patch level of the host from vulnerability management data to prioritise triage.
