## 1) ClickFix / ClearFake: Malicious Command Pasted into Windows Run Dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake and related ClickFix campaigns instruct victims to paste an attacker-supplied command into the Windows Run dialog. Every pasted command is recorded in the Explorer RunMRU registry key, making it a high-fidelity artifact of this social-engineering execution chain.

```kusto
DeviceRegistryEvents | where Timestamp > ago(1d) | where ActionType in ("RegistryValueSet", "RegistryKeyCreated") | where RegistryKey has @"\Explorer\RunMRU" | where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl ", "certutil", "bitsadmin", "rundll32", "regsvr32", "wscript", "cscript", "msiexec", "conhost", "forfiles", "iwr", "Invoke-WebRequest", "Invoke-Expression", "IEX", "FromBase64String", "http://", "https://", "-enc", "-w h", "hidden") | project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** RunMRU entries are user-driven and normally contain simple strings (cmd, mmc, \\fileserver\share). Allowlist known admin workstations and internal UNC paths. Consider splitting into two severities: presence of any base64/http string = high, plain 'powershell' = medium. Pair with a follow-up hunt for child processes of explorer.exe within 60 seconds of the registry write.

## 2) Script Interpreter Spawned Directly by explorer.exe with Download or Obfuscation Flags

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake and fake-CAPTCHA lures where the user pastes a command that Explorer launches directly (Run dialog, Win+R, or shell:), producing powershell/mshta/curl children of explorer.exe carrying download or encoding arguments.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where InitiatingProcessFileName =~ "explorer.exe" | where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "rundll32.exe", "regsvr32.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "msiexec.exe", "conhost.exe") | where ProcessCommandLine has_any ("http://", "https://", "-enc", "-e ", "EncodedCommand", "FromBase64String", "IEX", "Invoke-Expression", "Invoke-WebRequest", "iwr ", "DownloadString", "DownloadFile", "-w hidden", "-windowstyle hidden", "-nop", "bypass", "Start-BitsTransfer", "/transfer", "urlcache", "\\AppData\\", "\\ProgramData\\") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Legitimate admin use of Win+R powershell is common in IT teams; allowlist by AccountName/DeviceName groups. Software deployment tools that shell out via explorer.exe (rare) may need exclusion. Reduce noise by requiring at least two of the keyword groups (network + obfuscation).

## 3) AsyncRAT-Style Injection into Trusted .NET Utilities from Script or Office Parents

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218.011  
**Severity:** High  
**Purpose:** AsyncRAT and similar .NET RATs are commonly staged by loaders that spawn signed Microsoft .NET utilities (aspnet_compiler, RegAsm, RegSvcs, InstallUtil, MSBuild) in a suspended state and hollow them with the RAT payload. The parent/child pairing is durable across IOC rotation.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName in~ ("aspnet_compiler.exe", "RegAsm.exe", "RegSvcs.exe", "InstallUtil.exe", "MSBuild.exe", "jsc.exe", "csc.exe", "vbc.exe", "AddInProcess32.exe", "AppLaunch.exe") | where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "wscript.exe", "cscript.exe", "mshta.exe", "winword.exe", "excel.exe", "outlook.exe", "wmiprvse.exe", "explorer.exe", "rundll32.exe", "regsvr32.exe", "msiexec.exe") or InitiatingProcessFolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\users\public\", @"\programdata\", @"\downloads\") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Developer machines and CI agents legitimately invoke MSBuild/csc/vbc from cmd or PowerShell — scope out build servers and dev device groups, or exclude MSBuild when the command line references a .sln/.csproj under a source-control path. aspnet_compiler.exe spawned by anything other than IIS deployment tooling is almost always malicious.

## 4) Repeated Outbound Beaconing from Binaries in User-Writable Directories on Non-Standard Ports

**Tactic:** CommandAndControl  
**ATT&CK:** T1571  
**Severity:** Medium  
**Purpose:** AsyncRAT, VShell and Mythic agents typically execute from AppData/Temp/ProgramData and beacon to hard-coded ip:port pairs on non-web ports. This behavioral view survives the daily rotation of the 1,200+ fresh C2 indicators in the feed.

```kusto
DeviceNetworkEvents | where Timestamp > ago(1d) | where ActionType == "ConnectionSuccess" | where InitiatingProcessFolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\users\public\", @"\programdata\", @"\downloads\", "/tmp/", "/dev/shm/", "/var/tmp/") | where not(ipv4_is_private(RemoteIP)) | where RemotePort !in (80, 443, 53, 123, 445) | summarize ConnCount = count(), DistinctPorts = make_set(RemotePort, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, RemoteIP | where ConnCount >= 10 | project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, RemoteIP, DistinctPorts, ConnCount
```

**Tuning notes:** Game launchers, messaging clients and some updaters installed per-user in AppData will trigger; allowlist by InitiatingProcessFileName + signer. Tune ConnCount threshold to environment (raise to 30+ in noisy estates) and consider adding an interval-regularity check (stdev of time deltas) to isolate true beacons.

## 5) Remote Payload Piped Directly to a Shell on Linux (curl|wget to bash)

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** VShell, Supershell, Mexals cryptomining and Mythic Linux agents are overwhelmingly delivered via one-liner installers that curl/wget a script and pipe it straight into sh/bash, avoiding disk-based detection.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName in~ ("bash", "sh", "dash", "zsh", "ksh", "python", "python3", "perl") or InitiatingProcessFileName in~ ("bash", "sh", "dash", "zsh") | where ProcessCommandLine has_any ("curl", "wget", "fetch") | where ProcessCommandLine has_any ("| bash", "|bash", "| sh", "|sh", "| python", "|python", "| perl", "bash -c", "sh -c") | where ProcessCommandLine has_any ("http://", "https://", "ftp://") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Container build steps, Ansible/Chef bootstraps and legitimate vendor install scripts (e.g. get.docker.com, rustup) use this pattern. Allowlist by trusted destination hostname substring and by service-account name on build hosts. Highest confidence when the download host is a raw IP or the parent is a web/app server process (nginx, php-fpm, tomcat).

## 6) Interactive Reverse Shell via /dev/tcp or Network-Redirected Shell

**Tactic:** CommandAndControl  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** Supershell, VShell and Mythic operators frequently upgrade access with classic reverse-shell one-liners. Detects bash /dev/tcp redirection, nc -e, socat exec and python socket-to-shell payloads on Linux/macOS endpoints.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where ProcessCommandLine has_any ("/dev/tcp/", "/dev/udp/", "nc -e", "nc -c", "ncat -e", "socat exec", "socat tcp", "EXEC:'/bin/sh", "EXEC:'/bin/bash", "pty.spawn", "socket.SOCK_STREAM", "os.dup2", "rm /tmp/f;mkfifo", "mkfifo /tmp/") | where FileName in~ ("bash", "sh", "dash", "zsh", "ksh", "nc", "ncat", "netcat", "socat", "python", "python3", "perl", "ruby", "php") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Very low false-positive rate outside of pentest/red-team activity and some legacy health-check scripts that use /dev/tcp for port probing — allowlist those specific script paths by InitiatingProcessCommandLine. Escalate severity when the parent is a web server or database process (indicates web-shell driven access).

## 8) Silent Install or Execution of RMM Tooling (ConnectWise ScreenConnect) from Temp/Download Paths

**Tactic:** Persistence  
**ATT&CK:** T1219  
**Severity:** Medium  
**Purpose:** Threat actors in the ClickFix/EV-signed cluster abuse ConnectWise ScreenConnect and similar RMM agents for persistent remote access, dropping signed installers into user-writable paths and installing them unattended with an attacker-controlled relay URL.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName has_any ("ScreenConnect", "ConnectWise", "AnyDesk", "TeamViewer", "atera", "splashtop", "SimpleHelp", "RemoteUtilities", "rustdesk", "MeshAgent", "syncro", "LogMeIn", "GoToAssist") or ProcessCommandLine has_any ("e=Access&y=Guest", "&p=&s=", "ScreenConnect.ClientService", "--silent-install", "/silent /install", "--install --silent", "&c=") | where FolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\users\public\", @"\programdata\", @"\downloads\", @"\perflogs\") or InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "msiexec.exe", "rundll32.exe", "winword.exe", "excel.exe") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
```

## 9) Shadow Copy Deletion and Recovery Sabotage Prior to Encryption

**Tactic:** Impact  
**ATT&CK:** T1490  
**Severity:** Critical  
**Purpose:** The feed includes a ransomware-tagged cluster; deletion of volume shadow copies, disabling of Windows recovery and clearing of backup catalogs is the near-universal pre-encryption step and is high-fidelity on endpoints.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where (FileName in~ ("vssadmin.exe", "wmic.exe", "diskshadow.exe") and ProcessCommandLine has_any ("delete shadows", "shadowcopy delete", "delete shadowstorage", "resize shadowstorage")) or (FileName =~ "wbadmin.exe" and ProcessCommandLine has_any ("delete catalog", "delete systemstatebackup", "delete backup")) or (FileName =~ "bcdedit.exe" and ProcessCommandLine has_any ("recoveryenabled no", "ignoreallfailures", "bootstatuspolicy")) or (FileName in~ ("powershell.exe", "pwsh.exe") and ProcessCommandLine has_any ("Win32_ShadowCopy", "Remove-WmiObject -Class Win32_Shadowcopy", "Disable-ComputerRestore")) | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Backup software and imaging tools occasionally resize shadow storage — allowlist those specific parent binaries and command lines. Any 'delete shadows /all /quiet' should page immediately regardless of parent. Consider correlating with high-volume DeviceFileEvents rename activity on the same device within 30 minutes.

## 10) Linux: Root-Privileged Shell Spawned from an Unprivileged, Non-Interactive Parent

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1068  
**Severity:** High  
**Purpose:** Generic post-exploitation signal for the actively-exploited Linux kernel flaws in the feed (CVE-2025-39964, CVE-2026-53266, CVE-2025-39682). Successful local kernel exploitation nearly always manifests as a root shell or root command spawned by a process running as a non-root user or by an internet-facing service account.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName in~ ("bash", "sh", "dash", "zsh", "ksh", "id", "whoami", "chattr", "useradd", "usermod", "passwd") | where AccountName =~ "root" | where isnotempty(InitiatingProcessAccountName) and InitiatingProcessAccountName !~ "root" | where InitiatingProcessFileName !in~ ("sudo", "su", "pkexec", "systemd", "sshd", "login", "cron", "crond", "gdm-session-worker", "polkitd") | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Setuid helpers and container runtimes (docker, containerd-shim, runc) legitimately transition UID — extend the parent allowlist to match your container and orchestration stack. Elevate to critical when the initiating process is a web/app server (nginx, httpd, php-fpm, java, node) or when the child executable resides in /tmp, /dev/shm or /var/tmp. Requires Defender for Endpoint on Linux with full process telemetry.
