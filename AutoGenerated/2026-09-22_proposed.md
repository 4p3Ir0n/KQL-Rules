## 1) ClickFix / ClearFake: Interpreter spawned from Explorer Run dialog with download-and-execute pattern

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste (ClickFix)  
**Severity:** High  
**Purpose:** ClearFake and related fake-CAPTCHA/"ErrTraffic" lures instruct victims to paste a command into the Windows Run dialog or a terminal. The pasted command is executed by explorer.exe (or a terminal host) and typically fetches a second stage. This detects the lineage plus download/execution keywords rather than the rotating ClearFake domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe","wt.exe","OpenConsole.exe","mshta.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","curl.exe","wscript.exe","cscript.exe","msiexec.exe","rundll32.exe","bitsadmin.exe","certutil.exe")
| where ProcessCommandLine has_any ("-w hidden","-windowstyle hidden","-nop","-noprofile","-enc","frombase64string","iwr ","invoke-webrequest","invoke-restmethod","iex(","invoke-expression","downloadstring","downloadfile","curl ","certutil -urlcache","bitsadmin /transfer","mshta http","msiexec /i http","start-bitstransfer","conhost --headless")
| project Timestamp, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Allowlist internal helpdesk one-liners and software-deployment scripts users are told to paste. If explorer.exe parentage is too noisy in your estate, restrict to FileName in (powershell.exe,pwsh.exe,mshta.exe,curl.exe) first. Pair with the RunMRU registry detection for higher confidence; a hit on both within minutes is near-certain ClickFix.

## 2) ClickFix artifact: Script interpreter command written to Explorer RunMRU history

**Tactic:** Execution  
**ATT&CK:** T1059.001 - Command and Scripting Interpreter: PowerShell  
**Severity:** High  
**Purpose:** When a victim pastes a ClearFake/ClickFix command into Win+R, Windows records it under HKCU\...\Explorer\RunMRU. This is a durable forensic artifact of the social-engineering step and survives even if the payload fetch fails.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","cmd.exe","cmd /c","mshta","curl","certutil","bitsadmin","msiexec","rundll32","wscript","cscript","conhost","http://","https://","frombase64string","iex","\\\\")
| project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins and power users legitimately type cmd/powershell in Run; consider excluding bare values matching ^(cmd|powershell|pwsh)(\.exe)?\\1$ and focus on values longer than ~40 chars or containing URLs/base64. Scope out IT/admin accounts if needed, or raise severity when the value contains hidden-window or base64 markers.

## 3) AsyncRAT-style scheduled task persistence for payload in user-writable path

**Tactic:** Persistence  
**ATT&CK:** T1053.005 - Scheduled Task/Job: Scheduled Task  
**Severity:** Medium  
**Purpose:** AsyncRAT loaders routinely copy the .NET payload into %AppData%/%Temp%/%ProgramData% and register a scheduled task (often with /rl highest and /sc minute or onlogon) created from a script interpreter. Detects the persistence TTP independent of the 987 rotating hashes/C2s.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "schtasks.exe"
| where ProcessCommandLine has_any ("/create","-create")
| where ProcessCommandLine has_any (@"\appdata\", @"\local\temp\", @"\programdata\", @"\users\public\", @"\roaming\", ".vbs", ".js", ".bat", ".ps1", ".cmd", ".scr", ".pif")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","wscript.exe","cscript.exe","mshta.exe","explorer.exe","winrar.exe","7zfm.exe","msiexec.exe")
| project Timestamp, DeviceName, AccountName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Exclude known software updaters and packaging tools that stage tasks from ProgramData (e.g., specific vendor installer paths). Tasks created by SYSTEM-run deployment agents (SCCM/Intune) are common false positives - filter on InitiatingProcessAccountName != 'system' if your deployment tooling triggers this.

## 4) Managed-code LOLBin (aspnet_compiler / MSBuild / InstallUtil / RegAsm) making external network connections

**Tactic:** CommandAndControl  
**ATT&CK:** T1218 - System Binary Proxy Execution / .NET LOLBin beaconing  
**Severity:** High  
**Purpose:** AsyncRAT and similar .NET RATs are frequently injected into or executed via aspnet_compiler.exe, MSBuild.exe, InstallUtil.exe, RegAsm.exe/RegSvcs.exe to proxy execution and inherit trust. These binaries almost never talk to the internet on a workstation, so outbound public connections are a strong beacon indicator.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("aspnet_compiler.exe","msbuild.exe","installutil.exe","regasm.exe","regsvcs.exe","csc.exe","jsc.exe","cvtres.exe")
| where RemoteIPType == "Public"
| summarize Connections = count(), Ports = make_set(RemotePort, 20), Remotes = make_set(strcat(RemoteIP, iff(isempty(RemoteUrl), "", strcat(" | ", RemoteUrl))), 20), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, Connections, Ports, Remotes
```

**Tuning notes:** Build servers and developer workstations legitimately run MSBuild/csc with NuGet restore traffic - exclude by device group or allowlist nuget.org/pkgs.dev.azure.com destinations. On standard user endpoints treat any hit as high fidelity.

## 5) Cobalt Strike default named pipe patterns observed on endpoint

**Tactic:** DefenseEvasion  
**ATT&CK:** T1055 - Process Injection (Cobalt Strike SMB/post-ex named pipes)  
**Severity:** Critical  
**Purpose:** Cobalt Strike beacons create predictable named pipes for post-exploitation jobs and SMB peer-to-peer links (msagent_, postex_/postex_ssh_, status_, MSSE-*-server, mojo-like decoys). Detecting the pipe names catches the framework regardless of the 153 rotating C2 IPs/hashes and watermarks.

```kusto
DeviceEvents
| where Timestamp > ago(1d)
| where ActionType in ("NamedPipeEvent","CreateRemoteThreadApiCall")
| extend PipeName = tostring(coalesce(column_ifexists("AdditionalFields", "") , ""))
| extend PipeCandidate = strcat(FileName, " ", PipeName)
| where PipeCandidate matches regex @"(?i)(msagent_[0-9a-f]{2,4}|postex_[0-9a-f]{4}|postex_ssh_[0-9a-f]{4}|status_[0-9a-f]{2,6}|MSSE-[0-9a-z]+-server|\\\\pipe\\\\[0-9a-f]{8}$|mypipe-(f|h)|ntsvcs_[0-9a-f]{2,4}|win_svc|wkssvc_[0-9a-f]{2,4})"
| project Timestamp, DeviceName, ActionType, FileName, PipeCandidate, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Named pipe telemetry requires the NamedPipeEvent ActionType to be present in your tenant; validate coverage first. Legitimate software occasionally uses random hex pipe names - pivot on the initiating process (rundll32/dllhost/werfault/spoolsv with no command line is highly suspicious). Update the regex as operators customise Malleable C2 pipe names; keep the postex_/msagent_ prefixes as the core.

## 6) TerminalFix-style script reading image files and reflectively loading code

**Tactic:** DefenseEvasion  
**ATT&CK:** T1027.003 - Steganography  
**Severity:** High  
**Purpose:** The TerminalFix campaign hid stages inside PNG files and extracted them at runtime. Detects PowerShell/script interpreters that reference image files together with pixel-extraction or in-memory assembly loading APIs - a durable signature of steganographic loaders.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","cmd.exe")
| where ProcessCommandLine has_any (".png",".jpg",".jpeg",".bmp",".gif",".ico",".webp")
| where ProcessCommandLine has_any ("System.Drawing","Bitmap","GetPixel","LockBits","[Reflection.Assembly]::Load","Reflection.Assembly","FromBase64String","DeflateStream","GZipStream","Marshal.Copy","VirtualAlloc","[byte[]]","ReadAllBytes","WebClient","Invoke-Expression","iex")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Image-processing automation and some installer scripts use System.Drawing legitimately - allowlist by signed script paths or known internal automation accounts. Extend to DeviceFileEvents/DeviceImageLoadEvents follow-up: a .png written to %TEMP%/%APPDATA% immediately before this process start is strong corroboration. Very long encoded command lines should be escalated automatically.

## 7) Reverse tunnel / port-forwarding utility execution (TerminalFix-style egress)

**Tactic:** CommandAndControl  
**ATT&CK:** T1572 - Protocol Tunneling  
**Severity:** High  
**Purpose:** The TerminalFix intrusion chain established a reverse tunnel for persistent remote access. Detects execution of common tunnelling utilities and native SSH reverse port-forwarding, which are rarely legitimate on user endpoints.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where (FileName in~ ("ngrok.exe","cloudflared.exe","frpc.exe","frps.exe","gost.exe","chisel.exe","plink.exe","nps.exe","npc.exe","rathole.exe","localtonet.exe","pinggy.exe","bore.exe","iox.exe"))
    or (FileName in~ ("ssh.exe","plink.exe") and ProcessCommandLine matches regex @"(?i)\s-[a-z]*(R|D|L)\s*\d")
    or (FileName =~ "netsh.exe" and ProcessCommandLine has "portproxy" and ProcessCommandLine has_any ("add","v4tov4","v4tov6"))
    or (ProcessCommandLine has_any ("tunnel run","tunnel --url","authtoken","tcp 3389","tcp 445","-remote_port","server_addr"))
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessIntegrityLevel, ReportId
```

**Tuning notes:** Cloudflared/ngrok may be sanctioned for specific dev teams - allowlist by device group and signed install path (Program Files). Unsigned copies running from %TEMP%, %APPDATA% or Downloads should always alert. netsh portproxy is occasionally used by admins for legacy app access; require non-admin account or unusual device to reduce noise.

## 8) Defender exclusion or AMSI/real-time protection tampering from a script interpreter

**Tactic:** DefenseEvasion  
**ATT&CK:** T1562.001 - Impair Defenses: Disable or Modify Tools  
**Severity:** High  
**Purpose:** AsyncRAT, VShell and ClickFix-delivered loaders commonly add a Defender exclusion for their staging directory or disable real-time monitoring/AMSI before dropping the payload. This is a high-signal pre-execution step shared across all three families.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("Add-MpPreference","Set-MpPreference","MpCmdRun","amsiInitFailed","AmsiUtils","DisableRealtimeMonitoring","DisableBehaviorMonitoring","DisableIOAVProtection","DisableScriptScanning","ExclusionPath","ExclusionExtension","ExclusionProcess","sc stop windefend","net stop windefend")
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","wscript.exe","cscript.exe","mshta.exe","reg.exe","sc.exe","net.exe","MpCmdRun.exe")
| project Timestamp, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessIntegrityLevel, ReportId
```

**Tuning notes:** Security/IT baseline scripts and EDR deployment tooling legitimately set exclusions - allowlist specific SCCM/Intune/Ansible initiating process paths and service accounts. Exclusions covering %TEMP%, %APPDATA%, whole drives (C:\) or wildcard extensions should always be escalated, as should any hit whose parent is explorer.exe or a browser.
