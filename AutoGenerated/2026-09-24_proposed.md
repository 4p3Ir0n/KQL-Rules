## 1) ClickFix: Malicious Command Pasted into the Windows Run Dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste (ClickFix)  
**Severity:** High  
**Purpose:** ClearFake / IClickFix / MacFinger-style ClickFix lures instruct victims to paste an attacker-supplied command into the Win+R Run dialog. Windows records this in the Explorer RunMRU registry key, giving a durable, high-fidelity artifact of the social-engineering step regardless of the rotating DGA/C2 domains reported for these families.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where isnotempty(RegistryValueData)
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","bitsadmin","certutil","msiexec","rundll32","regsvr32","wscript","cscript","conhost","cmd /c","cmd.exe /c","iex","Invoke-Expression","Invoke-WebRequest","DownloadString","FromBase64String","-enc","-ep bypass","http://","https://","\\\\")
| extend PastedCommand = RegistryValueData
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, PastedCommand, InitiatingProcessFileName, ReportId
```

**Tuning notes:** RunMRU legitimately contains entries like cmd, mmc, \\fileserver\share. Allowlist known admin jump-hosts and specific internal UNC paths by InitiatingProcessAccountName or DeviceName. Consider raising severity when the value also contains base64 or a raw URL. Very long values (>200 chars) are almost always malicious - add `| where strlen(PastedCommand) > 120` for a high-precision variant.

## 2) ClickFix Lineage: explorer.exe Spawning a Scripting Host with Download/Obfuscation Flags

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** When a victim pastes a ClickFix command into Run (or an mshta/ms-search lure fires), the resulting interpreter is a direct child of explorer.exe. Detects the execution stage of ClearFake, IClickFix and Unknown Loader delivery chains independent of specific domains.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","wscript.exe","cscript.exe","curl.exe","msiexec.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","conhost.exe")
| where ProcessCommandLine has_any ("-enc","-EncodedCommand","-e ","FromBase64String","iex","Invoke-Expression","Invoke-WebRequest","Invoke-RestMethod","DownloadString","DownloadFile","Net.WebClient","-w hidden","-windowstyle hidden","-nop","-ep bypass","-ExecutionPolicy Bypass","http://","https://","--headless","/transfer","urlcache")
| project Timestamp, DeviceName, DeviceId, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, ProcessId, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Interactive admins launching PowerShell from Explorer with -nop are common; scope out IT/helpdesk accounts or known scripts by hashing ProcessCommandLine patterns. Software deployment tools that shell out via Explorer (rare) should be allowlisted by InitiatingProcessCommandLine. Pair with the RunMRU detection for correlation and auto-escalation.

## 3) ClearFake/ClickFix Padded or Decoy-Text Command Line (conhost --headless, whitespace padding, fake CAPTCHA strings)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1140 - Deobfuscate/Decode Files or Information  
**Severity:** High  
**Purpose:** ClearFake and related ClickFix kits pad the pasted command with hundreds of spaces and append decoy text (fake Cloudflare/'Ray ID'/'I am not a robot' verification strings) so the malicious portion scrolls out of view in the Run dialog, and frequently launch via 'conhost.exe --headless' to suppress a visible window.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","mshta.exe","conhost.exe","wscript.exe","cscript.exe")
| where ProcessCommandLine matches regex @"\s{40,}"
    or ProcessCommandLine has_any ("--headless","I am not a robot","not a robot","Ray ID","ray-id","Verification ID","verify you are human","Cloudflare Verification","reCAPTCHA Verification","\u2705","\u274c")
| where ProcessCommandLine has_any ("http","iex","Invoke-","mshta","curl","powershell","msiexec","FromBase64String","-enc","\\\\")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Whitespace padding of 40+ characters is rare in legitimate command lines but can appear in badly quoted installer/MSI wrappers - allowlist by InitiatingProcessFileName (e.g. setup bootstrappers). 'conhost.exe --headless' alone is used by some legitimate terminal tooling; the second has_any clause keeps precision. Tune the emoji literals if your ingestion normalizes unicode.

## 4) Loader Drop: Randomly-Named Executable Launched from Temp/AppData by a Browser or Script Host

**Tactic:** Execution  
**ATT&CK:** T1105 - Ingress Tool Transfer  
**Severity:** Medium  
**Purpose:** Amadey/gcleaner-dropped 'Unknown Loader' samples and ClearFake payloads land in %TEMP%, %APPDATA% or C:\ProgramData with pseudo-random file names and are executed by the delivery script or browser. Detects the payload-execution stage independent of the 350 rotating hashes/URLs reported.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\ProgramData\", @"\Users\Public\", @"\Windows\Temp\")
| where FileName endswith ".exe" or FileName endswith ".scr" or FileName endswith ".com" or FileName endswith ".pif"
| where FileName matches regex @"^[a-zA-Z0-9]{6,20}\.(exe|scr|com|pif)$"
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","msiexec.exe","curl.exe","certutil.exe","bitsadmin.exe","chrome.exe","msedge.exe","firefox.exe","explorer.exe","7zFM.exe","WinRAR.exe")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Installers and updaters routinely stage randomly-named binaries in Temp. Reduce noise by joining to DeviceFileEvents for a recent download (FileOriginUrl present) or by filtering on unsigned binaries where signature data is available in your environment. Allowlist known deployment agents (SCCM/Intune/Chocolatey) by InitiatingProcessFolderPath and common vendor-named temp subfolders.

## 5) Mirai/Gafgyt IoT Loader Pattern: Remote ELF Fetch + chmod + Execute from World-Writable Path

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Unix Shell  
**Severity:** High  
**Purpose:** Mirai/Gafgyt infection one-liners fetch an ELF via wget/curl/tftp/busybox into /tmp, /dev/shm or /var/run, chmod it executable and run it, often iterating over multiple architecture builds. Detects the behavior on Defender-for-Linux endpoints regardless of the 318 rotating IP:port indicators.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("sh","bash","dash","busybox","ash","wget","curl","tftp","ftpget","chmod")
| where ProcessCommandLine has_any ("/tmp/","/dev/shm/","/var/run/","/var/tmp/","/mnt/")
| where (ProcessCommandLine has_any ("wget","curl","tftp","ftpget","busybox") and ProcessCommandLine has_any ("chmod","777","+x"))
    or ProcessCommandLine matches regex @"chmod\s+(777|\+x)\s+\S+\s*;\s*\./"
    or ProcessCommandLine has_any ("mips","mipsel","arm7","armv6l","x86_64 ; ./","jackmymips","/bin/busybox wget")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, ProcessId, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Build servers, container image builds and configuration management (Ansible, cloud-init) legitimately download and chmod binaries in /tmp. Allowlist by device group (CI/CD fleet) or by InitiatingProcessCommandLine containing known automation paths. The architecture-name clause is the highest-fidelity portion; split it into its own higher-severity rule if noise is high.

## 6) Network Appliance/Web Service Process Spawning a Shell or Recon Command (Check Point, F5 BIG-IP APM, Arista VCO)

**Tactic:** InitialAccess  
**ATT&CK:** T1190 - Exploit Public-Facing Application  
**Severity:** Critical  
**Purpose:** CVE-2026-93616 (Check Point path traversal to arbitrary script execution), CVE-2026-85102 (Check Point gateway RCE) and CVE-2026-94127 (F5 BIG-IP APM heap overflow RCE) and CVE-2026-93952 (Arista VCO) all end in code execution as the appliance's web/service account. Any shell, recon or download child of those daemons on a Defender-onboarded management/orchestrator host is a strong post-exploitation signal.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("httpd","httpd2","apache2","nginx","lighttpd","java","tomcat","node","python","python3","php-fpm","cpd","fwm","cpm","httpd_admin","tmm","restjavad","icrd","w3svc","vco","velocloud")
| where FileName in~ ("sh","bash","dash","zsh","ksh","csh","perl","python","python3","ruby","nc","ncat","netcat","socat","curl","wget","whoami","id","uname","ifconfig","ip","chmod","chattr","crontab","useradd","adduser","ssh-keygen","base64","openssl")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, ProcessId, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessId, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Appliance management daemons do legitimately shell out for health checks and backups - baseline for 7 days and allowlist recurring parent/child command-line pairs per device. Highest priority when the child is a reverse-shell pattern (nc/socat with an IP, bash -i), when chmod/crontab/useradd appear, or when the host is internet-facing. Only fires on hosts with a Defender agent; for pure appliances, complement with syslog-based analytics.

## 7) Script or Web Shell Written into Web-Accessible / Upload Directory by a Server Process

**Tactic:** Persistence  
**ATT&CK:** T1505.003 - Web Shell  
**Severity:** High  
**Purpose:** The Check Point path traversal (CVE-2026-93616) lets an unauthenticated attacker upload and execute arbitrary scripts; similar post-exploitation of F5/Arista management interfaces drops web shells. Detects a server/web daemon creating executable script content in web or upload paths, including traversal artifacts in the path.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where FileName endswith ".sh" or FileName endswith ".php" or FileName endswith ".jsp" or FileName endswith ".jspx" or FileName endswith ".aspx" or FileName endswith ".py" or FileName endswith ".pl" or FileName endswith ".cgi" or FileName endswith ".war"
| where FolderPath has_any ("/var/www","/opt/CPsuite","/opt/CPshrd","/web/","/htdocs/","/upload","/tmp/","/var/tmp/","/usr/local/tomcat","/usr/share/nginx","inetpub\\wwwroot","\\webapps\\")
    or FolderPath has_any ("../","..%2f","%2e%2e")
| where InitiatingProcessFileName in~ ("httpd","httpd2","apache2","nginx","java","tomcat","node","python","python3","php-fpm","cpd","fwm","cpm","httpd_admin","restjavad","w3wp.exe","tmm")
| project Timestamp, DeviceName, DeviceId, ActionType, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, RequestAccountName, ReportId
```

**Tuning notes:** Legitimate appliance upgrades, hotfix installs and app deployments write scripts into these paths - allowlist maintenance windows and known package-manager parents. Correlate with the appliance-shell-spawn rule: a script write followed within minutes by execution of the same path is near-certain exploitation. Add your own web roots to the FolderPath list.
