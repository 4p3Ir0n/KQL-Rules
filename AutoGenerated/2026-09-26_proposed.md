## 1) ClickFix Social Engineering: Browser-Spawned Run-Dialog Style PowerShell/mshta Execution

**Tactic:** Execution  
**ATT&CK:** T1204.004 / T1059.001 - Malicious Copy-Paste (ClickFix)  
**Severity:** High  
**Purpose:** Detects the ClickFix / MacFinger pattern where a user is tricked into pasting an attacker-supplied command into the Windows Run dialog or terminal, resulting in a browser or explorer parent spawning powershell/mshta/curl with remote payload retrieval and hidden window flags.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe","chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","iexplore.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","bitsadmin.exe","wscript.exe","cscript.exe","conhost.exe")
| where ProcessCommandLine has_any ("http://","https://","FromBase64String","IEX","Invoke-Expression","Invoke-WebRequest","DownloadString","DownloadFile","-enc","-EncodedCommand","Start-BitsTransfer","irm ","iwr ")
    or ProcessCommandLine has_all ("-w","hidden")
| where ProcessCommandLine has_any ("-w hidden","-WindowStyle Hidden","-nop","-NoProfile","-ep bypass","-ExecutionPolicy Bypass","mshta","curl","certutil","FromBase64String","IEX","iex(","irm ","iwr ")
| project Timestamp, DeviceId, DeviceName, AccountName, AccountDomain, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, FolderPath, ProcessId, ReportId
```

**Tuning notes:** Allowlist internal helpdesk scripts and software-deployment tooling that legitimately launch PowerShell from explorer.exe. Consider joining to DeviceEvents for clipboard/Run-dialog MRU (RunMRU registry writes in DeviceRegistryEvents under \Explorer\RunMRU) to raise confidence. Tighten by requiring an outbound DeviceNetworkEvents connection from the same ProcessId within 60s.

## 2) Suspicious RunMRU Registry Entry Containing Script or Download Command

**Tactic:** Execution  
**ATT&CK:** T1204.004 - ClickFix Run Dialog Abuse (RunMRU artifact)  
**Severity:** Medium  
**Purpose:** ClickFix campaigns (including MacFinger/GeoGated variants) instruct victims to press Win+R and paste a command. Windows records this in HKCU\...\Explorer\RunMRU, producing a durable forensic artifact independent of the payload domain.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has "\\Explorer\\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","cmd /c","cmd.exe /c","http://","https://","FromBase64String","IEX","Invoke-Expression","wscript","cscript","msiexec","rundll32","\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessAccountDomain, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admin workstations commonly see cmd/powershell in RunMRU; scope out known IT staff accounts or require the value to also contain a URL/base64 indicator. Very low volume on standard user endpoints — good candidate for high-fidelity alerting after account-based allowlisting.

## 3) Arbitrary File Download Using Microsoft Office Application (Sigma 4ae3e30b)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1202 - Indirect Command Execution  
**Severity:** Medium  
**Purpose:** Translation of Sigma rule 'Potential Arbitrary File Download Using Office Application': Office binaries (WINWORD, EXCEL, POWERPNT, MSOXMLED) invoked with a URL on the command line can be abused as a LOLBIN to fetch remote content.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("EXCEL.EXE","MSOXMLED.EXE","POWERPNT.EXE","WINWORD.EXE")
| where ProcessCommandLine has_any ("http://","https://")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** SharePoint/OneDrive document opens legitimately pass https:// URLs to Office apps when launched from a browser or Teams — allowlist InitiatingProcessFileName of browsers/Teams combined with your corporate tenant hostnames (*.sharepoint.com, internal SP FQDNs). Focus on cases where the parent is a script host (wscript/cscript/powershell/cmd) or where the URL points to a non-corporate domain.

## 4) PowerShell Obfuscation Using Set-Alias / New-Alias (Sigma 96cd126d)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1027 / T1059.001 - Obfuscated PowerShell via Alias Cmdlets  
**Severity:** Low  
**Purpose:** Translation of the Sigma ps_script rule: attackers define aliases with Set-Alias/New-Alias to hide the real cmdlets invoked by a script. Known benign CIM alias definitions are filtered out.

```kusto
DeviceEvents
| where Timestamp > ago(1d)
| where ActionType == "PowerShellCommand"
| extend ScriptBlockText = tostring(parse_json(AdditionalFields).Command)
| where isnotempty(ScriptBlockText)
| where ScriptBlockText has "Set-Alias " or ScriptBlockText has "New-Alias "
| where not(ScriptBlockText matches regex @"(?i)Set-Alias\s+-Name\s+(ncms|gcls|ncso|gcms|rcms|rcie|gcai|gcim|scim|ncim|rcim|icim)\s+-Value\s+\S+\s+-Option\s+ReadOnly,\s*AllScope\s+-ErrorAction\s+SilentlyContinue")
| project Timestamp, DeviceId, DeviceName, AccountName = InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ScriptBlockText, ReportId
```

**Tuning notes:** Requires PowerShell script block / command logging forwarded to Defender. Extremely noisy on its own — profile and allowlist internal module and profile scripts (e.g., corporate PowerShell profiles, Exchange/AzureAD module loaders) by hash or by InitiatingProcessCommandLine. Best used as an enrichment signal combined with encoded-command or download activity from the same process.

## 5) SharePoint / IIS Worker Process Spawning Command or Script Interpreter

**Tactic:** Execution  
**ATT&CK:** T1505.003 / T1059 - Web Shell and Server-Side Exploitation  
**Severity:** Critical  
**Purpose:** Detects post-exploitation of SharePoint code-injection RCE (e.g., CVE-2026-65660) and similar web-app RCE where w3wp.exe or the SharePoint timer/service process spawns a shell, script host, or LOLBIN.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("w3wp.exe","owstimer.exe","httpd.exe","nginx.exe","php-cgi.exe","php.exe","tomcat.exe")
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","curl.exe","net.exe","net1.exe","whoami.exe","nltest.exe","schtasks.exe","bcdedit.exe","vssadmin.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, AccountDomain, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Some SharePoint farm maintenance and deployment jobs legitimately launch PowerShell from owstimer.exe — baseline over 30 days and allowlist specific scheduled maintenance command lines and service accounts. Treat any w3wp.exe -> cmd.exe/powershell.exe as critical on internet-facing servers.

## 6) Web Shell File Written to Web-Server Content Directory

**Tactic:** Persistence  
**ATT&CK:** T1505.003 - Web Shell  
**Severity:** High  
**Purpose:** Detects post-exploitation web shell drops following web application RCE such as SharePoint code injection (CVE-2026-65660) or WordPress remote file inclusion (CVE-2026-87902), where the server process writes executable script content into a web root.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where FolderPath has_any ("\\inetpub\\wwwroot","\\Web Server Extensions\\","\\_layouts\\","\\TEMPLATE\\LAYOUTS","\\wp-content\\","\\wp-includes\\","\\htdocs\\","\\httpdocs\\","/var/www/","/usr/share/nginx/html/")
| where FileName endswith ".aspx" or FileName endswith ".asmx" or FileName endswith ".ashx" or FileName endswith ".asp" or FileName endswith ".php" or FileName endswith ".jsp" or FileName endswith ".jspx"
| where InitiatingProcessFileName in~ ("w3wp.exe","owstimer.exe","httpd.exe","nginx.exe","php-cgi.exe","php.exe","cmd.exe","powershell.exe","pwsh.exe","python3","sh","bash")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Exclude legitimate deployment pipelines (msdeploy.exe, WordPress auto-update run by the site user, CI/CD agents) by initiating process and folder. WordPress plugin/theme updates write .php files under wp-content regularly — allowlist the update path or require the writing process to be a shell. Triage by reviewing file content and any subsequent child process from w3wp.exe.

## 7) Mirai/Gafgyt-Style Dropper: Shell Fetch-Chmod-Execute Chain on Linux Hosts

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Unix Shell / IoT Botnet Deployment  
**Severity:** High  
**Purpose:** Detects the canonical Mirai/Gafgyt infection chain on Linux/IoT endpoints — wget/curl/tftp retrieval of an ELF binary into a writable temp path followed by chmod +x and execution — independent of the current C2 IPs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("wget","curl","tftp","busybox","chmod","sh","bash","ftpget")
| where ProcessCommandLine has_any ("chmod 777","chmod +x","chmod 755","wget http","curl -O","curl http","tftp -g","busybox wget","busybox tftp")
| where ProcessCommandLine has_any ("/tmp/","/var/tmp/","/dev/shm/","/var/run/","/mnt/","./")
| summarize Cmds = make_set(ProcessCommandLine, 20), Procs = make_set(FileName, 10), Events = count(), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine, AccountName
| where Events >= 2
| project FirstSeen, LastSeen, DeviceId, DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, Procs, Cmds, Events
```

**Tuning notes:** Linux servers with configuration management (Ansible, Chef, Puppet) and container build steps trigger fetch+chmod patterns — allowlist by AccountName (root via CM agent) and known InitiatingProcessFileName. Raise severity when the parent is a network service daemon (e.g., dropbear, httpd, telnetd) indicating exploitation of an exposed device.

## 8) EtherHiding: Endpoint Process Contacting Public Blockchain RPC / Web3 Gateway Endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102 - Web Service (EtherHiding / Blockchain C2)  
**Severity:** Medium  
**Purpose:** IClickFix and Unknown Loader campaigns are tagged 'etherhiding' — payload stages are retrieved from smart contracts via public blockchain RPC gateways. Detects non-browser or script-host processes reaching such gateways, a strong signal of blockchain-based C2 retrieval.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("bsc-dataseed","binance.org","infura.io","alchemy.com","ankr.com","quicknode","publicnode.com","llamarpc","polygon-rpc","drpc.org","blockpi","1rpc.io","cloudflare-eth","nodereal.io")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","certutil.exe","rundll32.exe","regsvr32.exe","msiexec.exe","node.exe")
    or InitiatingProcessFolderPath has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\Users\\Public\\","\\ProgramData\\")
| project Timestamp, DeviceId, DeviceName, RemoteUrl, RemoteIP, RemotePort, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Legitimate blockchain developers, crypto wallets and node.exe-based dev tooling will hit these endpoints — allowlist by device group (dev workstations) or by signed wallet application paths. Extend the gateway list as new public RPC providers appear. Browser traffic is deliberately excluded to reduce noise; add browser-child-process correlation if ClickFix lures via the browser are in scope.

## 9) Azure Reconnaissance Tooling Executed from Endpoint (Storm-3168 Service Principal Abuse)

**Tactic:** Discovery  
**ATT&CK:** T1526 / T1087 - Cloud Service and Account Discovery  
**Severity:** Medium  
**Purpose:** Detects endpoint-side precursors to Storm-3168 style cloud attacks: bulk Azure/Entra enumeration and service-principal credential handling via Az/Graph PowerShell, az CLI, or offensive tooling, which precedes resource deletion and credential access in the tenant.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe","pwsh.exe","az.cmd","az.exe","python.exe","cmd.exe")
| where ProcessCommandLine has_any (
    "Connect-AzAccount","Connect-MgGraph","Get-AzResource","Get-AzRoleAssignment","Get-AzADServicePrincipal",
    "Get-MgServicePrincipal","New-AzADSpCredential","Add-AzADAppCredential","New-MgServicePrincipalPassword",
    "Get-AzKeyVaultSecret","az ad sp","az role assignment list","az keyvault secret","az account list",
    "Get-AzSubscription","roadrecon","AzureHound","Invoke-AzureHound","MicroBurst","Get-AzPasswordss","Get-AzPasswords")
| where ProcessCommandLine has_any ("-ServicePrincipal","--service-principal","ApplicationId","-CertificateThumbprint","ClientSecret","-p ","secret","AzureHound","roadrecon","MicroBurst","Get-AzPasswords")
    or ProcessCommandLine has_any ("Get-AzADServicePrincipal","Get-MgServicePrincipal","New-AzADSpCredential","Add-AzADAppCredential","New-MgServicePrincipalPassword","az ad sp")
| project Timestamp, DeviceId, DeviceName, AccountName, AccountDomain, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, FolderPath, ReportId
```

**Tuning notes:** Cloud engineers and CI/CD build agents run these cmdlets routinely — scope to non-admin devices or exclude known automation hosts and service accounts. Highest fidelity signals are credential-adding cmdlets (New-AzADSpCredential, Add-AzADAppCredential, New-MgServicePrincipalPassword) and offensive tool names. Correlate with CloudAppEvents/AADServicePrincipalSignInLogs in Sentinel for full tenant-side context; endpoint coverage here is only the operator workstation.
