## 1) SharePoint / IIS Worker Process (w3wp.exe) Spawning Command Interpreter

**Tactic:** Execution  
**ATT&CK:** T1190 / T1059  
**Severity:** High  
**Purpose:** Detects post-exploitation of SharePoint code injection flaws such as CVE-2026-65660, where the IIS worker process hosting SharePoint spawns a shell, script interpreter, or recon utility - a reliable behavioral signal of server-side code execution regardless of the specific exploit used.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "w3wp.exe"
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe","certutil.exe","bitsadmin.exe","curl.exe","net.exe","net1.exe","whoami.exe","nltest.exe","tasklist.exe","schtasks.exe","bcdedit.exe","vssadmin.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, AccountDomain, FileName, ProcessCommandLine, FolderPath, InitiatingProcessCommandLine, InitiatingProcessId, ReportId
```

**Tuning notes:** SharePoint servers legitimately invoke cmd.exe/powershell.exe during timer jobs, PSConfig upgrades, and some third-party web parts. Baseline per-server for 7-14 days and allowlist known admin/deployment accounts and scheduled maintenance windows. Prioritize alerts where the command line contains encoded commands, download cmdlets, or where the child process is whoami/nltest (recon immediately after exploitation).

## 2) Web Shell Dropped by IIS or PHP Web Server Process

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** High  
**Purpose:** Detects web shell persistence following exploitation of server-side RCE such as SharePoint code injection (CVE-2026-65660) or the WordPress Core remote file inclusion flaw (CVE-2026-87902), by alerting on script files written into web-served directories by the web server process itself.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where InitiatingProcessFileName in~ ("w3wp.exe","httpd.exe","httpd","apache2","nginx","php-fpm","php-cgi.exe","php.exe","node.exe","tomcat.exe","java.exe")
| where FileName endswith ".aspx" or FileName endswith ".asmx" or FileName endswith ".ashx" or FileName endswith ".asp" or FileName endswith ".php" or FileName endswith ".phtml" or FileName endswith ".jsp" or FileName endswith ".jspx"
| where FolderPath has_any ("inetpub", "wwwroot", "TEMPLATE\\LAYOUTS", "wp-content", "wp-includes", "html", "htdocs", "webapps", "/var/www")
| project Timestamp, DeviceId, DeviceName, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Exclude legitimate CMS/plugin update paths (e.g. wp-content/upgrade, WordPress auto-update temp dirs) and SharePoint solution deployment directories, plus CI/CD or WebDeploy service accounts. Files written into uploads/cache directories or with randomized 8-12 char names are the highest-fidelity subset. Consider joining to DeviceNetworkEvents for subsequent inbound requests to the new file.

## 3) Linux/Unix Web Server Process Spawning Shell (Web Exploitation Follow-On)

**Tactic:** Execution  
**ATT&CK:** T1059  
**Severity:** High  
**Purpose:** Detects exploitation of WordPress Core remote file inclusion (CVE-2026-87902) and similar PHP RCE issues where the PHP/web server process spawns an interactive shell or download utility on Linux hosts onboarded to Defender for Endpoint.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("php-fpm","php","php-cgi","httpd","apache2","nginx","lighttpd","caddy")
| where FileName in~ ("sh","bash","dash","zsh","python","python3","perl","curl","wget","nc","ncat","socat","chmod","crontab","base64")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Some PHP applications legitimately shell out (image processing via ImageMagick, sendmail wrappers, backup plugins). Baseline command lines per web host and allowlist known wrappers. Reverse-shell indicators (`sh -i`, `/dev/tcp/`, `nc -e`, base64 -d piped to sh) should be escalated immediately.

## 4) Potential Arbitrary File Download Using Office Application (Sigma 4ae3e30b)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1202  
**Severity:** Medium  
**Purpose:** Faithful translation of the Sigma rule: Microsoft Office binaries (Excel, PowerPoint, Word, MSOXMLED) launched with an http/https URL on the command line, which abuses the Office application as an indirect downloader/proxy execution utility.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("EXCEL.EXE","MSOXMLED.EXE","POWERPNT.EXE","WINWORD.EXE")
    or ProcessVersionInfoOriginalFileName in~ ("Excel.exe","msoxmled.exe","POWERPNT.EXE","WinWord.exe")
| where ProcessCommandLine has_any ("http://","https://")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessVersionInfoOriginalFileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Opening documents from SharePoint/OneDrive/Teams links legitimately produces http(s) command lines, usually with the tenant's own *.sharepoint.com or *-my.sharepoint.com hosts and launched by explorer.exe/browser/Teams. Allowlist your tenant's SharePoint/OneDrive hostnames and internal intranet FQDNs, then focus on external domains, IP-literal URLs, and parents such as wscript.exe, powershell.exe, mshta.exe or Office apps launched non-interactively.

## 5) LSASS Memory Access by WerFault.exe (Sigma e5b33f7d)

**Tactic:** CredentialAccess  
**ATT&CK:** T1003.001  
**Severity:** High  
**Purpose:** Translation of the Sigma process_access rule detecting credential dumping tools (Mimikatz, NanoDump, Procdump, Taskmgr-based dumps) that masquerade as or proxy through WerFault.exe to open lsass.exe with full access rights.

```kusto
DeviceEvents
| where Timestamp > ago(1d)
| where ActionType in ("OpenProcessApiCall","ReadProcessMemoryApiCall")
| where FileName =~ "lsass.exe"
| where InitiatingProcessFileName =~ "WerFault.exe"
| extend GrantedAccess = tostring(parse_json(AdditionalFields).GrantedAccess)
| where isempty(GrantedAccess) or GrantedAccess in ("0x1FFFFF","0x1fffff","2097151")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, GrantedAccess, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Genuine WER crash handling of lsass.exe is rare but possible; validate that InitiatingProcessFolderPath is System32/SysWOW64, the parent is svchost.exe/wermgr.exe, and the command line carries a legitimate -p/-s crash-reporting argument. WerFault.exe running from a non-system directory or with no crash arguments is almost always malicious. Pair with DeviceFileEvents for .dmp files written shortly after.

## 6) Potential PowerShell Obfuscation Using Alias Cmdlets (Sigma 96cd126d)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1027  
**Severity:** Low  
**Purpose:** Translation of the Sigma ps_script rule: Set-Alias/New-Alias usage inside script blocks, a common technique for obfuscating PowerShell tooling by remapping cmdlet names, excluding the benign CIM alias definitions shipped by Microsoft modules.

```kusto
DeviceEvents
| where Timestamp > ago(1d)
| where ActionType == "PowerShellCommand"
| extend ScriptBlockText = tostring(parse_json(AdditionalFields).Command)
| where ScriptBlockText has_any ("Set-Alias ","New-Alias ")
| where not(ScriptBlockText matches regex @"(?i)Set-Alias\s+-Name\s+(ncms|gcls|ncso|gcms|rcms|rcie|gcai|gcim|scim|ncim|rcim|icim)\s+-Value\s+\w+\s+-Option ReadOnly, AllScope -ErrorAction SilentlyContinue")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, ScriptBlockText, ReportId
```

**Tuning notes:** Requires Script Block Logging / Defender PowerShell command telemetry. Many admin profiles and modules define aliases legitimately - allowlist known internal module names and signed profile paths, and hunt on aliases pointing to Invoke-Expression, IEX, Invoke-WebRequest, Add-Type, or obviously random/short alias names. Best used as a hunt or correlation enrichment rather than a standalone alert.

## 7) ClickFix / ClearFake Fake-CAPTCHA Execution via Windows Run Dialog

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** Detects the ClickFix/ClearFake/IClickFix social-engineering chain (EtherHiding-delivered lures) in which a victim pastes an attacker-supplied command into the Windows Run dialog, leaving a RunMRU registry artifact containing a downloader command.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has @"Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","msiexec","rundll32","conhost","wscript","cscript","cmd.exe /c","cmd /c","iex","invoke-webrequest","invoke-expression","frombase64string","-enc","-w h","hidden","http://","https://",".hta",".ps1")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins occasionally type powershell/cmd into Run - allowlist known IT staff accounts or require the value data to contain a URL, encoding, or hidden-window flag. Note attackers pad commands with whitespace and fake text like 'I am not a robot'; a long RunMRU value (>200 chars) is a strong indicator. Correlate with the follow-on DeviceProcessEvents detection on explorer.exe parentage.

## 8) Explorer-Spawned Script Interpreter Performing Remote Payload Retrieval (ClickFix Follow-On)

**Tactic:** CommandAndControl  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake campaigns where explorer.exe (Run dialog or clipboard paste) launches a hidden interpreter that downloads and executes a loader payload, covering the same behavior regardless of the rapidly-rotating domains reported for IClickFix/ClearFake.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe","mshta.exe","conhost.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","certutil.exe","bitsadmin.exe","msiexec.exe","rundll32.exe")
| where ProcessCommandLine has_any ("http://","https://","iex","Invoke-Expression","Invoke-WebRequest","IWR","DownloadString","DownloadFile","FromBase64String","-enc","-EncodedCommand","-nop","-w hidden","-windowstyle hidden","Start-BitsTransfer")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Allowlist internal software-deployment scripts and helpdesk one-liners by command-line hash or signing account. Suppress URLs pointing to approved internal update servers. Very long single-line commands, base64 blobs, and clipboard-style padding are the highest-fidelity subset; combine with the RunMRU detection for near-zero false positives.

## 9) Loader Staged in User-Writable Directory Establishing Persistence or AV Exclusions

**Tactic:** Persistence  
**ATT&CK:** T1053.005  
**Severity:** Medium  
**Purpose:** Detects the core TTPs of Amadey-style droppers and the 'Unknown Loader' family: an executable running from Temp/AppData/ProgramData/Public that immediately creates a scheduled task, Run key, or Defender exclusion to persist the next-stage payload.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\users\public\", @"\programdata\", @"\downloads\")
| where (FileName =~ "schtasks.exe" and ProcessCommandLine has "/create")
    or (FileName =~ "reg.exe" and ProcessCommandLine has_any (@"\CurrentVersion\Run", "RunOnce", "Image File Execution Options"))
    or (FileName in~ ("powershell.exe","pwsh.exe") and ProcessCommandLine has_any ("Add-MpPreference","-ExclusionPath","-ExclusionExtension","Set-MpPreference","New-ScheduledTask","Register-ScheduledTask"))
    or (FileName =~ "attrib.exe" and ProcessCommandLine has "+h")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Software installers and updaters routinely run from Temp and create tasks/Run keys - allowlist signed installers by InitiatingProcessSignerType/SignatureStatus or by known vendor certificate, and exclude your patch-management agent's staging paths. Unsigned parents with randomized filenames plus Defender exclusion creation should be treated as Critical.

## 10) macOS ClickFix: Curl Piped to Shell / osascript Downloader

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** Medium  
**Purpose:** Detects the macOS variant of the IClickFix / MacFinger ClickFix campaign where victims are instructed to paste a Terminal command that curls a payload and pipes it directly into a shell or executes it via osascript.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("bash","sh","zsh","osascript","curl")
| where ProcessCommandLine has_any ("curl","wget")
| where ProcessCommandLine matches regex @"(?i)(curl|wget)[^|;]*\|\s*(sudo\s+)?(ba|z)?sh"
    or ProcessCommandLine has_any ("| osascript","-o /tmp/","-o ~/Library/","&& chmod +x","; chmod +x","nohup")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Developer workstations legitimately use curl|bash for tool installers (Homebrew, rustup, nvm). Allowlist known installer domains in the command line and/or exclude engineering device groups, or require the parent to be Terminal/iTerm launched shortly after browser activity. Escalate when the URL is an IP literal, a newly-registered domain, or the payload is written to a hidden path under ~/Library.

## 11) Access to Azure CLI / Cloud SDK Credential Stores by Non-Standard Process

**Tactic:** CredentialAccess  
**ATT&CK:** T1552.001  
**Severity:** Medium  
**Purpose:** Provides endpoint visibility into the credential-theft precursor of Storm-3168 style attacks, where service principal secrets and cached cloud tokens are harvested from developer/admin workstations and then reused for Azure reconnaissance and resource deletion.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FolderPath has_any (@"\.azure\", @"\.aws\", "/.azure/", "/.aws/", @"\AppData\Roaming\Microsoft\Azure", "AzureRmContext.json")
    or FileName in~ ("msal_token_cache.bin","msal_token_cache.json","accessTokens.json","azureProfile.json","service_principal_entries.json","credentials","TokenCache.dat","ServicePrincipalSecret")
| where ActionType in ("FileCreated","FileModified","FileRenamed","FileCopied")
| where InitiatingProcessFileName !in~ ("az.exe","azd.exe","python.exe","pwsh.exe","powershell.exe","code.exe","devenv.exe","AzureCliProxy.exe","aws.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, ActionType, FileName, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Backup agents, sync clients (OneDrive), and IDE extensions touch these paths - build an allowlist of approved initiating processes for your developer fleet rather than hardcoding. Highest fidelity when the initiating process is a script interpreter with archiving/exfil behavior, an unsigned binary, or a remote-management tool. Pair with cloud-side sign-in telemetry for the affected service principal.
