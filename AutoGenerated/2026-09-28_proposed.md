## 1) SharePoint IIS worker process (w3wp.exe) spawning command interpreters or recon tooling

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** Detects post-exploitation of SharePoint code-injection/RCE flaws such as CVE-2026-65660, where attacker-supplied code executes inside the IIS worker process and spawns shells, LOLBins, or discovery commands.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "w3wp.exe"
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","cscript.exe","wscript.exe","mshta.exe","certutil.exe","bitsadmin.exe","curl.exe","net.exe","net1.exe","whoami.exe","nltest.exe","reg.exe","rundll32.exe","regsvr32.exe","wmic.exe","schtasks.exe","7z.exe")
| project Timestamp, DeviceName, AccountName, AccountDomain, FileName, FolderPath, ProcessCommandLine, InitiatingProcessCommandLine, InitiatingProcessAccountName, ProcessId, ReportId
```

**Tuning notes:** csc.exe/vbc.exe compilation by w3wp is normal for SharePoint and is intentionally excluded. Allowlist known SharePoint health/maintenance scripts and monitoring agents that legitimately run under the app pool identity. On dedicated SharePoint farms nearly any shell child of w3wp is worth alerting; on shared IIS hosts, scope by DeviceName to SharePoint servers first.

## 2) Web shell or unexpected script file written into SharePoint/IIS web content directories

**Tactic:** Persistence  
**ATT&CK:** T1505.003  
**Severity:** Critical  
**Purpose:** Detects web shell drops following exploitation of SharePoint code injection (CVE-2026-65660) or other IIS-facing RCE, where w3wp.exe or a shell child writes .aspx/.ashx/.asmx content into served directories.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified","FileRenamed")
| where FolderPath has_any (@"\TEMPLATE\LAYOUTS", @"\inetpub\wwwroot", @"\Web Server Extensions", @"\_layouts", @"\App_Data\Temp")
| where FileName endswith ".aspx" or FileName endswith ".ashx" or FileName endswith ".asmx" or FileName endswith ".asax" or FileName endswith ".soap" or FileName endswith ".dll"
| where InitiatingProcessFileName in~ ("w3wp.exe","cmd.exe","powershell.exe","pwsh.exe","mshta.exe","certutil.exe","curl.exe","rundll32.exe")
| project Timestamp, DeviceName, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, RequestAccountName, ReportId
```

**Tuning notes:** Exclude patch/upgrade windows (psconfig.exe, Windows Installer, SharePoint CU deployment) and approved WSP solution deployments, which legitimately write DLLs and pages. Consider suppressing temporary ASP.NET compilation artifacts under Temporary ASP.NET Files by adding a FolderPath !has filter.

## 3) ClickFix / ClearFake: malicious command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** Detects the ClickFix / IClickFix / ClearFake social-engineering chain in which the victim is instructed to paste an attacker-supplied command into Win+R; the command is recorded in the RunMRU registry key before execution.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl ","certutil","bitsadmin","msiexec","rundll32","regsvr32","wscript","cscript","conhost","cmd /c","cmd.exe /c","iwr ","irm ","iex","FromBase64String","-enc","-ec ","hidden","http://","https://","\\\\")
| project Timestamp, DeviceName, AccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Admins and helpdesk legitimately type cmd/powershell into Run; tighten by requiring a URL, encoded-command flag, or download cmdlet in RegistryValueData if volume is high. Exclude known IT jump/admin workstations by DeviceName or AccountName. Note that the trailing \1 marker in RunMRU data is normal.

## 4) Explorer or browser spawning a hidden downloader shell (ClickFix/ClearFake paste-and-run)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClickFix/ClearFake fake-CAPTCHA and fake-update lures: explorer.exe (Run dialog) or a browser spawning powershell/mshta/conhost --headless/curl with remote-download and in-memory execution flags.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("explorer.exe","chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe")
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","conhost.exe","curl.exe","msiexec.exe","rundll32.exe","wscript.exe","cscript.exe","forfiles.exe")
| where ProcessCommandLine has_any ("iex","invoke-expression","invoke-webrequest","iwr ","irm ","downloadstring","downloadfile","frombase64string","-enc","-ec ","-encodedcommand","--headless","-w hidden","-windowstyle hidden","bypass","http://","https://","mshta http","start-process")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ProcessId, ReportId
```

**Tuning notes:** Software deployment or self-service portals launched from Explorer may match; allowlist by signed script paths or specific command-line prefixes. Browser-parented msiexec can be a legitimate downloaded installer double-click — require a URL or encoded command for higher fidelity. conhost.exe --headless as a child of explorer.exe is almost always malicious.

## 5) Run/RunOnce autostart value pointing to a user-writable path created by a script host

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** Medium  
**Purpose:** Detects AsyncRAT and generic loader persistence where a script interpreter or shell writes an autorun value referencing a payload in AppData, Temp, ProgramData, or Public.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Policies\Explorer\Run", @"\Winlogon\Shell", @"\Winlogon\Userinit")
| where RegistryValueData has_any ("AppData","Temp","ProgramData","Users\\Public","Downloads","Roaming")
| where RegistryValueData has_any (".exe",".bat",".cmd",".vbs",".js",".jse",".ps1",".lnk",".scr",".hta")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","wscript.exe","cscript.exe","mshta.exe","cmd.exe","reg.exe","rundll32.exe","regsvr32.exe","msbuild.exe","installutil.exe")
| project Timestamp, DeviceName, AccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Some legitimate per-user apps (Teams, Slack, updaters) install Run values under AppData but are normally written by their own signed installer, not by a script host — the InitiatingProcessFileName filter handles most of this. Allowlist internal logon-script tooling and packaging agents by value name or hash.

## 6) .NET LOLBin (MSBuild/InstallUtil/RegAsm/aspnet_compiler) launched by a script host or from a user directory

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218  
**Severity:** High  
**Purpose:** Detects the AsyncRAT / loader tradecraft of executing or injecting .NET payloads through trusted Microsoft binaries to evade application control and AV.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("msbuild.exe","installutil.exe","regasm.exe","regsvcs.exe","aspnet_compiler.exe","csc.exe","jsc.exe","microsoft.workflow.compiler.exe")
| where InitiatingProcessFileName in~ ("wscript.exe","cscript.exe","mshta.exe","powershell.exe","pwsh.exe","cmd.exe","explorer.exe","winword.exe","excel.exe","outlook.exe","rundll32.exe","regsvr32.exe","7zfm.exe","winrar.exe")
```

**Tuning notes:** Developer workstations and build agents legitimately run MSBuild/csc from Temp — allowlist by DeviceName group or by parent devenv.exe/dotnet.exe/agent processes. aspnet_compiler and Microsoft.Workflow.Compiler almost never run interactively and should stay high severity.

## 7) Repeated outbound C2 from a binary running in AppData/Temp/ProgramData on a non-standard port

**Tactic:** CommandAndControl  
**ATT&CK:** T1571  
**Severity:** Medium  
**Purpose:** Detects AsyncRAT and loader beaconing: payloads staged in user-writable directories that repeatedly connect to external infrastructure on uncommon high ports (AsyncRAT commonly uses 6606/7707/8808 and randomized ports).

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType == "ConnectionSuccess"
| where InitiatingProcessFolderPath has_any (@"\appdata\local\temp", @"\appdata\roaming", @"\programdata", @"\users\public", @"\downloads")
| where isnotempty(RemoteIP) and not(ipv4_is_private(RemoteIP))
| where RemotePort !in (80, 443, 53, 445)
| summarize Connections=count(), DistinctRemotes=dcount(RemoteIP), Ports=make_set(RemotePort, 10), Remotes=make_set(RemoteIP, 10), Urls=make_set(RemoteUrl, 5), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName
| where Connections >= 5
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, Connections, DistinctRemotes, Ports, Remotes, Urls
```

**Tuning notes:** Allowlist known auto-updating apps that install into AppData (browsers, Teams, Zoom, Dropbox) by SHA256 or file name, and game/VoIP clients that use high UDP ports. Lower the Connections threshold when hunting; raise it for alerting. Consider adding a signer check (InitiatingProcessSHA256 joined to known-good) rather than hardcoding names.

## 8) Executable or script launched directly from an archive extraction or Downloads path

**Tactic:** Execution  
**ATT&CK:** T1204.002  
**Severity:** Medium  
**Purpose:** Detects the delivery stage used by 'Unknown Loader' / dropper campaigns distributing zip and exe payloads from open directories: user opens an archive and runs the contained binary, LNK, or script.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("winrar.exe","7zfm.exe","7zg.exe","bandizip.exe","peazip.exe","explorer.exe","zipfldr.dll","msedge.exe","chrome.exe","firefox.exe","outlook.exe")
| where FolderPath has_any (@"\Downloads\", @"\AppData\Local\Temp\Rar$", @"\AppData\Local\Temp\7z", @"\AppData\Local\Temp\Temp1_", @"\AppData\Local\Temp\BNZ.", @"\Users\Public", @"\AppData\Local\Temp\")
| where FileName endswith ".exe" or FileName endswith ".scr" or FileName endswith ".js" or FileName endswith ".jse" or FileName endswith ".vbs" or FileName endswith ".wsf" or FileName endswith ".bat" or FileName endswith ".cmd" or FileName endswith ".hta" or FileName endswith ".msi" or FileName endswith ".ps1"
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, SHA256, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** High-volume on developer and IT devices; scope to non-privileged user populations first or require the file to be unsigned (join to DeviceFileCertificateInfo). Allowlist common installer names and internally distributed tools by SHA256. Script/LNK/HTA hits from archives are far higher fidelity than .exe and can be split into a separate higher-severity rule.

## 9) Scheduled task created that executes a payload from a user-writable directory

**Tactic:** Persistence  
**ATT&CK:** T1053.005  
**Severity:** Medium  
**Purpose:** Detects RAT/loader persistence (AsyncRAT, ClickFix follow-on payloads) that registers a scheduled task pointing at AppData, Temp, ProgramData, or Public, frequently with high-frequency or logon triggers.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("schtasks.exe","powershell.exe","pwsh.exe")
| where ProcessCommandLine has_any ("/create", "Register-ScheduledTask", "New-ScheduledTask")
| where ProcessCommandLine has_any ("AppData", "\\Temp\\", "ProgramData", "Users\\Public", "Downloads", "mshta", "powershell -", "-enc", "FromBase64String", "wscript", "cscript", "rundll32", "regsvr32", "curl ", "bitsadmin")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Exclude software deployment tooling (SCCM/Intune/Chocolatey/PDQ) and vendor updaters that legitimately register tasks from ProgramData. Task creation running as SYSTEM from an interactive user session, or with /sc minute, deserves escalation.

## 10) Azure service-principal authentication followed by broad cloud resource enumeration from an endpoint

**Tactic:** Discovery  
**ATT&CK:** T1580  
**Severity:** Medium  
**Purpose:** Detects Storm-3168 style tradecraft where compromised service principal credentials are used from an operator endpoint to authenticate non-interactively and rapidly enumerate tenant resources, roles, and identities via az CLI or Az PowerShell.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("az.cmd","az.exe","powershell.exe","pwsh.exe","cmd.exe","python.exe")
| where ProcessCommandLine has_any ("az login","Connect-AzAccount","Connect-MgGraph","Connect-AzureAD","az account get-access-token","az resource list","az group list","az role assignment list","az ad sp list","az ad app list","az keyvault list","az keyvault secret list","az storage account list","Get-AzResource","Get-AzRoleAssignment","Get-MgServicePrincipal","Get-AzKeyVaultSecret")
| extend ServicePrincipalAuth = ProcessCommandLine has_any ("--service-principal","-ServicePrincipal","--federated-token","ClientSecretCredential","-ApplicationId","--password","--certificate")
| summarize Commands=make_set(ProcessCommandLine, 20), CommandCount=count(), SpAuth=max(ServicePrincipalAuth), FirstSeen=min(Timestamp), LastSeen=max(Timestamp) by DeviceName, AccountName, InitiatingProcessFileName
| where SpAuth == true or CommandCount >= 5
| project FirstSeen, LastSeen, DeviceName, AccountName, InitiatingProcessFileName, CommandCount, SpAuth, Commands
```

**Tuning notes:** Cloud/DevOps engineer workstations and self-hosted CI agents will match; allowlist by DeviceName/AccountName for approved automation hosts and by known pipeline service accounts. Plain-text secrets or certificate paths on the command line are always worth investigating regardless of volume. Correlate with CloudAppEvents/AADSignInEventsBeta for the matching service principal sign-in.

## 11) Bulk Azure resource deletion issued from an endpoint

**Tactic:** Impact  
**ATT&CK:** T1485  
**Severity:** High  
**Purpose:** Detects the destructive phase of Storm-3168 activity where compromised service principals are used to delete resource groups, resources, backups, or key vaults from an operator-controlled host.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("az.cmd","az.exe","powershell.exe","pwsh.exe","cmd.exe","python.exe")
| where ProcessCommandLine has_any ("az group delete","az resource delete","az vm delete","az storage account delete","az keyvault delete","az keyvault purge","az backup","Remove-AzResourceGroup","Remove-AzResource","Remove-AzVM","Remove-AzStorageAccount","Remove-AzKeyVault","Remove-AzRecoveryServicesVault","Remove-MgServicePrincipal")
| where ProcessCommandLine has_any ("--yes","-y ","-Force","--no-wait","-Confirm:$false") or ProcessCommandLine has "foreach"
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Legitimate teardown of ephemeral lab/CI resource groups is common — allowlist by resource-group naming convention appearing in the command line, by approved automation accounts, or by CI agent device groups. Pair with the service-principal discovery rule; deletions preceded by SP authentication and enumeration within the same hour should be treated as critical.
