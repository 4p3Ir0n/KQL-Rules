## 1) Inbound authentication or remote execution originating from NetScaler appliance IPs (CVE-2026-88771/88772 post-exploitation)

**Tactic:** LateralMovement  
**ATT&CK:** T1078 - Valid Accounts  
**Severity:** High  
**Purpose:** Citrix NetScaler ADC/Gateway appliances (FreeBSD-based) cannot run Defender for Endpoint, so exploitation of CVE-2026-88771 (command injection) and CVE-2026-88772 (memory buffer RCE) is only visible on the Windows estate when the attacker pivots off the appliance. This detection surfaces any logon, SMB/WinRM/RDP session, or remote service creation whose source IP is a NetScaler NSIP/SNIP/MIP, which should almost never initiate authentication to workstations or member servers.

```kusto
DeviceLogonEvents
| where Timestamp > ago(1d)
| where isnotempty(RemoteIP)
| where RemoteIP in (dynamic(["<NETSCALER_NSIP>","<NETSCALER_SNIP_1>","<NETSCALER_SNIP_2>"]))
| where LogonType in ("Network","RemoteInteractive","Interactive","Batch","Service")
| where ActionType in ("LogonSuccess","LogonFailed")
| summarize LogonCount = count(), Accounts = make_set(AccountName, 25), LogonTypes = make_set(LogonType, 10), Results = make_set(ActionType, 5), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, RemoteIP
| project FirstSeen, LastSeen, DeviceName, DeviceId, RemoteIP, Accounts, LogonTypes, Results, LogonCount
| order by LastSeen desc
```

**Tuning notes:** Replace the placeholder values with the actual NSIP/SNIP/MIP addresses of every NetScaler ADC and Gateway in the environment (maintain as an external watchlist or custom function rather than inline). Legitimate traffic from these IPs is usually limited to LDAP/Kerberos binds to domain controllers from a single service account — allowlist that specific account+DC pair and alert on anything else. Pair with a companion hunt for the same source IPs in DeviceNetworkEvents (inbound 445/5985/3389) if you ingest NetFlow-equivalent telemetry.

## 2) AsyncRAT-style .NET LOLBin (RegAsm/RegSvcs/aspnet_compiler/MSBuild) spawned by a script host

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218.009 - System Binary Proxy Execution: Regsvcs/Regasm  
**Severity:** High  
**Purpose:** AsyncRAT loaders routinely stage the RAT by process-hollowing a Microsoft .NET utility (aspnet_compiler.exe, RegAsm.exe, RegSvcs.exe, InstallUtil.exe, MSBuild.exe, jsc.exe, AddInProcess.exe) launched from PowerShell, WScript, MSHTA or cmd. Detecting this lineage catches the family independent of the 3,794 rotating hashes/C2 IPs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("aspnet_compiler.exe","RegAsm.exe","RegSvcs.exe","InstallUtil.exe","MSBuild.exe","jsc.exe","AddInProcess.exe","AppLaunch.exe","csc.exe")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe","explorer.exe","winword.exe","excel.exe","outlook.exe","msiexec.exe")
| where not(ProcessCommandLine has_any (".csproj",".sln",".vbproj",".targets","/nologo /noconfig"))
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessParentFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Developer workstations and build agents legitimately spawn MSBuild/csc from cmd or PowerShell — scope out build-server device groups and allowlist MSBuild command lines that reference a project/solution file. aspnet_compiler.exe and AddInProcess.exe with no arguments are near-zero-false-positive in enterprise environments and can be promoted to a higher-severity alert on their own.

## 3) Run/RunOnce autostart value pointing to an executable in a user-writable directory

**Tactic:** Persistence  
**ATT&CK:** T1547.001 - Registry Run Keys / Startup Folder  
**Severity:** Medium  
**Purpose:** AsyncRAT, ClearFake-delivered loaders and generic commodity droppers persist by writing a Run/RunOnce value that references a payload dropped in AppData, Temp, ProgramData or C:\Users\Public. This is a durable persistence behavior common to all three IOC-family items in the feed.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Policies\Explorer\Run", @"\Windows\CurrentVersion\RunServices")
| where RegistryValueData has_any (@"\AppData\Roaming\", @"\AppData\Local\Temp\", @"\ProgramData\", @"\Users\Public\", @"\Windows\Temp\", "powershell", "mshta", "wscript", "cscript", "rundll32", "curl ", "certutil")
| where RegistryValueData has_any (".exe",".scr",".bat",".cmd",".vbs",".js",".ps1",".dll",".lnk")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessSHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Common benign writers include Teams/OneDrive/Slack/Zoom updaters and vendor agents that legitimately live under %LocalAppData%; allowlist by InitiatingProcessSHA256 or by exact RegistryValueData prefix rather than by folder. Consider a sibling rule for schtasks.exe /create command lines referencing the same user-writable paths and for Startup-folder file drops in DeviceFileEvents.

## 4) Repeated outbound connections on non-standard ports from a binary in a user-writable directory

**Tactic:** CommandAndControl  
**ATT&CK:** T1571 - Non-Standard Port  
**Severity:** High  
**Purpose:** AsyncRAT and similar commodity RATs beacon from a payload copied into %AppData%\Roaming, %Temp%, ProgramData or C:\Users\Public to attacker ip:port pairs on high/non-standard ports (the dominant IOC type in the AsyncRAT feed). This detects the beaconing behavior rather than the ephemeral C2 addresses.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess","ConnectionAttempt")
| where InitiatingProcessFolderPath has_any (@"\AppData\Roaming\", @"\AppData\Local\Temp\", @"\ProgramData\", @"\Users\Public\", @"\Windows\Temp\")
| where RemotePort !in (80, 443, 53, 123, 445, 389, 636, 88)
| where not(ipv4_is_private(RemoteIP)) or isnotempty(RemoteUrl)
| summarize ConnCount = count(), DistinctRemotes = dcount(RemoteIP), Ports = make_set(RemotePort, 15), Remotes = make_set(RemoteIP, 15), Urls = make_set(RemoteUrl, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256
| where ConnCount >= 10
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, ConnCount, DistinctRemotes, Ports, Remotes, Urls
| order by LastSeen desc
```

**Tuning notes:** Game launchers, Electron apps, updaters and VPN clients installed under %LocalAppData% generate non-standard-port traffic — allowlist by InitiatingProcessSHA256 / signer after review. Tighten by requiring a single repeated RemotePort (classic AsyncRAT ports 6606/7707/8808/4449/1177 etc.) or low jitter between connections if you want alert-grade fidelity; keep it broad for hunting.

## 5) ClickFix: command interpreter spawned directly by explorer.exe with download or encoded payload

**Tactic:** Execution  
**ATT&CK:** T1059.001 - Command and Scripting Interpreter: PowerShell  
**Severity:** High  
**Purpose:** ClearFake and the tagged 'ClickFix' loaders trick users into pasting a command into the Win+R Run dialog or a terminal, producing powershell.exe/mshta.exe/curl.exe/msiexec.exe as a direct child of explorer.exe with a download or base64 payload. This lineage is the highest-signal endpoint artifact of the ClickFix social-engineering chain.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","curl.exe","bitsadmin.exe","certutil.exe","msiexec.exe","rundll32.exe","regsvr32.exe","conhost.exe")
| where ProcessCommandLine has_any ("http://","https://","FromBase64String","-enc","-ec ","-e ","EncodedCommand","Invoke-Expression","iex","Invoke-WebRequest","iwr ","DownloadString","DownloadFile","Start-BitsTransfer","-w h","-windowstyle hidden","-nop","-noprofile","curl ","msiexec","\\\\")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessId, ReportId
| order by Timestamp desc
```

**Tuning notes:** Power users and IT staff occasionally launch PowerShell one-liners from Run; baseline by AccountName and exclude known admin workstations. Very few legitimate cases combine explorer.exe parentage with hidden window style or base64 — consider splitting those conditions into a higher-severity alert and leaving plain 'http://' matches as a hunt.

## 6) ClickFix artifact: RunMRU registry value containing a scripting or download command

**Tactic:** Execution  
**ATT&CK:** T1204.004 - User Execution: Malicious Copy and Paste  
**Severity:** High  
**Purpose:** When a victim pastes a ClickFix/ClearFake command into the Windows Run dialog, Explorer records it under HKCU\...\Explorer\RunMRU. This registry residue persists even if the process telemetry is missed or the payload fails, making it a reliable retroactive indicator of ClickFix victimization.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","cmd.exe","cmd /","mshta","rundll32","regsvr32","wscript","cscript","curl","certutil","bitsadmin","msiexec","conhost","http://","https://","FromBase64String","-enc","iex","\u2705","captcha","verification","robot")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Admins typing 'cmd' or 'powershell' with no arguments will match the bare interpreter keywords — require the value to be longer than ~40 characters or to contain a URL/base64/flag token to cut that noise. The checkmark/'verification'/'robot' strings are lure text appended by ClickFix pages and are effectively zero-false-positive; alert on those immediately.

## 7) DLL side-loading: application in a user-writable folder loads a DLL from the same folder

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.002 - Hijack Execution Flow: DLL Side-Loading  
**Severity:** High  
**Purpose:** The 'Unknown Loader' cluster (tagged DLL-sideloading) and the NeedyMantis modular framework both stage a renamed or legitimately signed host executable next to a malicious DLL under AppData/ProgramData/Temp/Public. Flagging co-located exe+dll execution out of user-writable paths catches the loader stage regardless of the specific binaries used.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FileName endswith ".dll"
| where FolderPath has_any (@"\AppData\Local\", @"\AppData\Roaming\", @"\ProgramData\", @"\Users\Public\", @"\Windows\Temp\", @"\Downloads\", @"\PerfLogs\")
| where InitiatingProcessFolderPath has_any (@"\AppData\Local\", @"\AppData\Roaming\", @"\ProgramData\", @"\Users\Public\", @"\Windows\Temp\", @"\Downloads\", @"\PerfLogs\")
| extend DllDir = tolower(substring(FolderPath, 0, strlen(FolderPath) - strlen(FileName)))
| extend ExeDir = tolower(substring(InitiatingProcessFolderPath, 0, strlen(InitiatingProcessFolderPath) - strlen(InitiatingProcessFileName)))
| where DllDir == ExeDir
| where InitiatingProcessFileName !endswith "setup.exe" and InitiatingProcessFileName !has "updater" and InitiatingProcessFileName !has "installer"
| summarize LoadCount = count(), Dlls = make_set(FileName, 20), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine, Dlls, LoadCount
| order by LastSeen desc
```

**Tuning notes:** Portable apps, Electron/Chromium-based tools, self-extracting installers and per-user software (Teams, Zoom, Dropbox, Nvidia) legitimately load DLLs from their own AppData folder — build an allowlist of InitiatingProcessSHA256 or of top-level folder prefixes after a one-week baseline. High-value tightening: restrict InitiatingProcessFileName to known side-load hosts (e.g. OneDriveStandaloneUpdater.exe, vlc.exe, iTunesHelper.exe, dbghelp-loading utilities) or require the DLL name to match a known system DLL (version.dll, dbghelp.dll, winhttp.dll, msvcp140.dll, secur32.dll).

## 8) EtherHiding: non-browser process contacting public blockchain RPC endpoints

**Tactic:** CommandAndControl  
**ATT&CK:** T1102 - Web Service  
**Severity:** High  
**Purpose:** ClearFake and related loaders use 'EtherHiding' — retrieving next-stage payloads/C2 configuration from smart contracts via public BNB Smart Chain / Ethereum RPC endpoints. Browsers hitting these hosts are expected when a user visits a compromised site, but a script host, LOLBin or binary in a user-writable path doing so is strong evidence of the loader stage.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("bsc-dataseed","binance.org","bscrpc","rpc.ankr.com","cloudflare-eth.com","publicnode.com","llamarpc.com","infura.io","alchemy.com","drpc.org","nodereal.io","blastapi.io","quiknode.pro","1rpc.io","etherscan.io","bscscan.com")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","mshta.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","curl.exe","certutil.exe","bitsadmin.exe","msiexec.exe","node.exe","conhost.exe")
    or InitiatingProcessFolderPath has_any (@"\AppData\Roaming\", @"\AppData\Local\Temp\", @"\ProgramData\", @"\Users\Public\", @"\Windows\Temp\")
| project Timestamp, DeviceName, DeviceId, InitiatingProcessAccountName, RemoteUrl, RemoteIP, RemotePort, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, ReportId
| order by Timestamp desc
```

**Tuning notes:** Exclude legitimate crypto/dev tooling (MetaMask-adjacent desktop wallets, hardhat/truffle node.exe on developer machines, blockchain analytics agents) by device group or process hash. Extend the domain list as new public RPC providers appear; keep browser processes out of scope deliberately since their traffic to these hosts is the normal victim-side pattern, not the C2 channel.

## 9) msiexec installing a package directly from a remote URL

**Tactic:** Execution  
**ATT&CK:** T1218.007 - System Binary Proxy Execution: Msiexec  
**Severity:** Medium  
**Purpose:** The 'Unknown Loader' feed is tagged msi/exe/ClickFix; remote-MSI installation (msiexec /i https://... /qn) is a recurring delivery mechanism for these loaders and for ConnectWise/RMM abuse, bypassing many application-control policies.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "msiexec.exe"
| where ProcessCommandLine has_any ("http://","https://","\\\\")
| where ProcessCommandLine has_any ("/i","-i","/package","/quiet","/qn","/qb","/norestart")
| project Timestamp, DeviceName, DeviceId, AccountName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessParentFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Software-distribution platforms (Intune Win32 wrappers, SCCM, Chocolatey, PDQ) may invoke remote MSIs — allowlist by InitiatingProcessFileName/parent (ccmexec.exe, IntuneManagementExtension.exe, agent services) and by approved vendor hostnames maintained externally. Escalate severity when the parent is a browser, Office app, explorer.exe or a script host.

## 10) Microsoft Defender exclusion added for a user-writable path or tampering with AV settings

**Tactic:** DefenseEvasion  
**ATT&CK:** T1562.001 - Impair Defenses: Disable or Modify Tools  
**Severity:** High  
**Purpose:** Loaders in the ClickFix/ClearFake/AsyncRAT ecosystem and post-compromise frameworks such as NeedyMantis commonly precede payload staging with Add-MpPreference exclusions, Set-MpPreference disabling of real-time monitoring, or direct writes to the Defender Exclusions registry hive so their AppData/ProgramData payload is never scanned.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("Add-MpPreference","Set-MpPreference","MpCmdRun","DisableRealtimeMonitoring","DisableBehaviorMonitoring","DisableIOAVProtection","DisableScriptScanning","ExclusionPath","ExclusionExtension","ExclusionProcess","RemoveDefinitions")
    or (FileName =~ "reg.exe" and ProcessCommandLine has @"Windows Defender\Exclusions")
| where not(InitiatingProcessFileName in~ ("MsMpEng.exe","MpCmdRun.exe") and InitiatingProcessFolderPath has @"\Windows Defender\")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessParentFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Legitimate exclusion management usually comes from Group Policy/Intune/Defender policy channels rather than interactive command lines — allowlist your endpoint-management agents (IntuneManagementExtension.exe, ccmexec.exe, specific SCCM/Ansible/Chef parents) by hash or parent process. Treat exclusions naming %AppData%, %Temp%, %ProgramData%, C:\Users\Public or a whole drive letter as critical and page on them; complement with DeviceRegistryEvents on HKLM\SOFTWARE\Microsoft\Windows Defender\Exclusions\*.
