## 1) AsyncRAT-style .NET LOLBin host beaconing to non-standard port

**Tactic:** CommandAndControl  
**ATT&CK:** T1071.001  
**Severity:** High  
**Purpose:** AsyncRAT payloads are commonly injected into or hosted by .NET utilities (aspnet_compiler.exe, RegAsm.exe, RegSvcs.exe, InstallUtil.exe, MSBuild.exe) which then beacon to attacker ip:port combinations on non-web ports. Detects the durable behavior rather than the 3789 perishable indicators.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("aspnet_compiler.exe","RegAsm.exe","RegSvcs.exe","InstallUtil.exe","MSBuild.exe","jsc.exe","csc.exe")
| where RemoteIPType == "Public"
| where not(RemotePort in (80, 443))
| summarize ConnCount = count(), Ports = make_set(RemotePort, 10), RemoteIPs = make_set(RemoteIP, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessParentFileName
| where ConnCount >= 3
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, RemoteIPs, Ports, ConnCount
```

**Tuning notes:** Legitimate .NET compilation rarely makes outbound sockets; if developer build agents trigger this, allowlist by DeviceId or by InitiatingProcessParentFileName (devenv.exe, dotnet.exe, MSBuild pipelines). Lower ConnCount threshold to 1 for high-confidence environments, or add RemotePort in (6606,7707,8808,1177,4444,2404) for classic AsyncRAT ports.

## 2) Scheduled task or Run key persistence pointing to user-writable payload path

**Tactic:** Persistence  
**ATT&CK:** T1053.005  
**Severity:** Medium  
**Purpose:** AsyncRAT and most commodity loaders copy themselves into AppData/Temp/ProgramData and persist with a scheduled task (/rl HIGHEST, ONLOGON, /sc MINUTE) or an HKCU Run value. Detects the persistence step independent of hash/IP indicators.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("schtasks.exe","reg.exe")
| where (FileName =~ "schtasks.exe" and ProcessCommandLine has "/create") or (FileName =~ "reg.exe" and ProcessCommandLine has_any ("\\CurrentVersion\\Run","\\CurrentVersion\\RunOnce"))
| where ProcessCommandLine has_any ("\\AppData\\", "\\Temp\\", "\\ProgramData\\", "\\Users\\Public\\", "\\Downloads\\", "%appdata%", "%temp%", "%localappdata%")
| where ProcessCommandLine has_any (".exe", ".vbs", ".js", ".bat", ".cmd", ".ps1", ".hta", ".scr", ".pif")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Software updaters (Google, Edge, Adobe, Teams) create AppData-based tasks; allowlist on InitiatingProcessFolderPath / signed updater names rather than removing path patterns. Consider raising severity when InitiatingProcessFileName is a script host (wscript.exe, mshta.exe, powershell.exe).

## 3) ClickFix / ClearFake: Run dialog (RunMRU) used to launch download-and-execute command

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** ClearFake/ClickFix social engineering instructs victims to paste a clipboard command into the Windows Run dialog. The pasted command is recorded in the Explorer RunMRU registry key, giving a high-fidelity, infrastructure-independent detection.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has "\\Explorer\\RunMRU"
| where RegistryValueData has_any ("powershell","pwsh","mshta","curl","certutil","bitsadmin","msiexec","rundll32","wscript","cscript","conhost","cmd /c","cmd.exe /c","forfiles","iex","irm","iwr","http","\\\\")
| project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, ReportId
```

**Tuning notes:** Admins legitimately use the Run box for cmd/powershell; the download verbs (http, iwr, irm, curl, certutil, mshta) are the high-signal terms — split the list into a strict tier for alerting and a broad tier for hunting. Allowlist known IT admin accounts/devices if noisy.

## 4) Hidden script interpreter spawned by Explorer or browser with remote fetch (ClickFix chain)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the ClickFix/ClearFake execution chain where the pasted or browser-delivered command runs a hidden/encoded PowerShell or mshta that pulls an on-device payload from attacker infrastructure.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","wscript.exe","cscript.exe","curl.exe","conhost.exe")
| where InitiatingProcessFileName in~ ("explorer.exe","msedge.exe","chrome.exe","firefox.exe","brave.exe","opera.exe","iexplore.exe")
| where ProcessCommandLine has_any ("http://","https://","FromBase64String","-enc","-EncodedCommand","IEX","Invoke-Expression","Invoke-WebRequest","irm ","iwr ","DownloadString","DownloadFile","--headless","Start-BitsTransfer")
    or ProcessCommandLine has_any ("-w hidden","-windowstyle hidden","-nop","-noprofile","-ep bypass","-executionpolicy bypass")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Browser-spawned cmd.exe is occasionally used by enterprise SSO/agent helpers — allowlist specific command lines. Managed deployment scripts launched from Explorer by admins are the main FP source; scope to non-admin users first.

## 5) DLL side-loading: binary in user-writable directory loads co-located DLL

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.002  
**Severity:** High  
**Purpose:** The 'Unknown Loader' cluster (ClickFix / DLL-sideloading / MSI dropper tags) stages a legitimate signed EXE plus a malicious DLL in the same user-writable folder. Detects the side-load regardless of file hash.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FileName endswith ".dll"
| where InitiatingProcessFolderPath has_any ("\\AppData\\Local\\Temp\\", "\\AppData\\Roaming\\", "\\ProgramData\\", "\\Users\\Public\\", "\\Downloads\\", "\\Windows\\Temp\\")
| extend DllDir = tolower(substring(FolderPath, 0, strlen(FolderPath) - strlen(FileName)))
| extend ExeDir = tolower(substring(InitiatingProcessFolderPath, 0, strlen(InitiatingProcessFolderPath) - strlen(InitiatingProcessFileName)))
| where DllDir == ExeDir
| where InitiatingProcessFileName !endswith "setup.exe" and InitiatingProcessFileName !endswith "installer.exe"
| summarize LoadedDlls = make_set(FileName, 20), Loads = count(), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessParentFileName
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, LoadedDlls, Loads
```

**Tuning notes:** Portable apps, game launchers, installer bootstrappers and Electron apps legitimately load co-located DLLs from AppData — allowlist by InitiatingProcessFileName/folder after baselining a week. Enrich by joining DeviceFileEvents to check whether the DLL was written within minutes of load, or DeviceProcessEvents for unsigned/invalid signature status of the initiating image.

## 6) Msiexec installing package from remote URL or user-writable staging path

**Tactic:** Execution  
**ATT&CK:** T1218.007  
**Severity:** Medium  
**Purpose:** The loader cluster uses MSI droppers (msi tag) delivered via ClickFix pages; msiexec with an http(s) argument or a package in Temp/Downloads followed by child process execution is a durable loader behavior.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "msiexec.exe"
| where ProcessCommandLine has_any ("http://","https://","\\AppData\\","\\Temp\\","\\Downloads\\","\\ProgramData\\","\\Users\\Public\\")
| where ProcessCommandLine has_any ("/i","-i","/package","/quiet","/qn","/norestart")
| project Timestamp, DeviceName, AccountName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Software distribution tooling (SCCM/Intune/ccmexec.exe, winget, Chocolatey) commonly stages MSIs in temp paths — allowlist by InitiatingProcessFileName. Remote-URL installs (/i http...) should stay as a separate, higher-severity branch since they are rarely legitimate.

## 7) Unauthorized RMM tool installation or chained RMM deployment

**Tactic:** Persistence  
**ATT&CK:** T1219  
**Severity:** High  
**Purpose:** Detects the reported campaign where phishing leads to MSP360 RMM installation which then deploys ScreenConnect, creating redundant remote-access channels. Alerts on RMM binaries running from user-writable paths and on one RMM agent spawning another installer.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName has_any ("screenconnect","connectwisecontrol","msp360","cbbackup","onlinebackup","atera","splashtop","anydesk","teamviewer","syncro","pcmonitor","gotoassist","logmein","ninjarmm","ninjaone","action1","rustdesk","dwagent","supremo","tacticalrmm")
    or ProcessCommandLine has_any ("screenconnect","connectwisecontrol","e=Access&y=Guest","msp360","tacticalrmm","atera","ninjarmm")
| where FolderPath has_any ("\\AppData\\","\\Downloads\\","\\Temp\\","\\ProgramData\\","\\Users\\Public\\")
    or InitiatingProcessFileName in~ ("outlook.exe","msedge.exe","chrome.exe","firefox.exe","winrar.exe","7zFM.exe","explorer.exe","powershell.exe","mshta.exe","msiexec.exe")
    or InitiatingProcessFileName has_any ("msp360","cbbackup","screenconnect","atera","ninja")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Critical: allowlist the RMM product(s) your IT/MSP legitimately uses by exact FolderPath and installer parent process, and alert on every other product in the list (unauthorized-RMM policy). Pay special attention to hits where one RMM agent is the initiating process for a different vendor's installer — that is the campaign's signature chain.

## 8) Script host or LOLBin launched from archive/download path (RedFlick-style delivery)

**Tactic:** Execution  
**ATT&CK:** T1204.002  
**Severity:** High  
**Purpose:** Star Blizzard's RedFlick delivery relies on user-opened lures (archives, LNK/URL/HTA files from compromised websites) that launch script interpreters or rundll32 from Downloads/Temp/archive extraction paths. Detects the user-execution hand-off step.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("mshta.exe","wscript.exe","cscript.exe","powershell.exe","pwsh.exe","rundll32.exe","regsvr32.exe","cmd.exe","msbuild.exe","installutil.exe")
| where InitiatingProcessFileName in~ ("explorer.exe","winrar.exe","7zFM.exe","7zG.exe","WinZip.exe","Bandizip.exe","peazip.exe","outlook.exe","msedge.exe","chrome.exe","firefox.exe")
| where ProcessCommandLine has_any ("\\Downloads\\","\\Temp\\","\\AppData\\Local\\Temp\\","\\Rar$","\\7z","\\Temp1_",".lnk",".url",".hta",".js",".jse",".vbs",".wsf",".iso",".img",".lz")
    or ProcessCommandLine has_any ("http://","https://","FromBase64String","-enc","DownloadString")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Users opening legitimate scripted installers from Downloads will fire; prioritise hits where the child is mshta/wscript/cscript, where the command line references a .lnk/.url, or where the process subsequently makes an external network connection (join DeviceNetworkEvents on InitiatingProcessId). Allowlist known internal tooling archives.

## 9) Linux shell download-chmod-execute chain (Mirai/Gafgyt loader behavior)

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** Medium  
**Purpose:** Mirai/Gafgyt infections on Linux endpoints (including Defender for Endpoint on Linux servers and IoT gateways) drop ELF payloads via wget/curl/tftp/busybox, chmod them executable and run them, often deleting the file afterwards.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("sh","bash","dash","ash","busybox","zsh") or FileName in~ ("sh","bash","busybox")
| where ProcessCommandLine has_any ("wget","curl","tftp","ftpget","busybox wget")
| where ProcessCommandLine has_any ("chmod 777","chmod +x","chmod 755")
| where ProcessCommandLine has_any ("/tmp/","/dev/shm/","/var/tmp/","/var/run/","./")
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Container build scripts and CI runners legitimately chain curl+chmod — allowlist build hosts by DeviceId or exclude InitiatingProcessParentFileName of known CI agents (runner, dockerd, containerd). Splitting on ProcessCommandLine containing multiple architecture names (arm, mips, x86, sh4) yields near-zero-FP Mirai dropper detection.

## 10) Cloud, CI and source-control credential files accessed via command line

**Tactic:** CredentialAccess  
**ATT&CK:** T1552.001  
**Severity:** High  
**Purpose:** Mirrors the Storm-3068 path from a compromised developer identity to cloud control-plane access: harvesting local cloud CLI tokens, CI secrets, git credentials and .env files from developer endpoints.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","findstr.exe","more.com","type.exe","tar.exe","7z.exe","rar.exe","certutil.exe","curl.exe","bash.exe","sh","bash","cat","grep")
| where ProcessCommandLine has_any (".aws\\credentials",".aws/credentials",".azure\\azureProfile.json",".azure/accessTokens.json","msal_token_cache",".kube\\config",".kube/config",".git-credentials",".npmrc",".pypirc","credentials.json","service-account","id_rsa",".ssh/id_",".env","gcloud\\credentials","terraform.tfstate","secrets.yaml")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Developer workstations will generate benign hits (editors, build scripts, terraform runs). Reduce noise by excluding InitiatingProcessFileName of known IDEs/build tools, by alerting only when several distinct secret paths are touched by one process tree within minutes, or when the same process later contacts an external IP (join DeviceNetworkEvents). Scope tightly to non-developer devices for high-confidence alerting.
