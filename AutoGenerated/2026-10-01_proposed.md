## 1) ClickFix/ClearFake: Malicious Command Pasted into Windows Run Dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake/ClickFix lures instruct victims to paste an attacker-supplied command into the Windows Run dialog. Each pasted command is persisted in the Explorer RunMRU registry key, giving a durable, high-fidelity artifact of the social-engineering step independent of the rotating domains/URLs in the IOC feed.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where isnotempty(RegistryValueData)
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl ", "certutil", "bitsadmin", "msiexec", "rundll32", "regsvr32", "wscript", "cscript", "cmd /c", "cmd.exe /c", "conhost", "iex", "invoke-expression", "invoke-webrequest", "frombase64string", "-enc", "-ec ", "http://", "https://", "ftp://", "\\\\")
| extend CmdLength = strlen(RegistryValueData)
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, CmdLength, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** RunMRU entries ending in '\1' are normal format artifacts, not noise indicators. Allowlist internal admin habits (e.g. 'cmd', 'mmc', '\\fileserver\share') by RegistryValueData prefix or by account for IT staff. Consider raising severity when CmdLength > 120 or when the value contains both an http(s) URL and an interpreter. Pair with the companion explorer.exe child-process rule for confirmation of execution.

## 2) ClickFix: explorer.exe Spawning Script Interpreter with Download/Encoded Payload

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Detects the execution stage of ClearFake/ClickFix 'fake CAPTCHA / fix-it' lures where the user pastes a command into Run or Win+R, resulting in explorer.exe directly spawning powershell/mshta/curl/msiexec with a remote payload or encoded blob.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "conhost.exe")
| where ProcessCommandLine has_any ("iex", "invoke-expression", "invoke-webrequest", "iwr ", "downloadstring", "downloadfile", "frombase64string", "-enc", "-ec ", "-e ", "windowstyle hidden", "-w h", "bypass", "http://", "https://", "get-clipboard", "[char]", "start-process", "urlcache", "/transfer")
| extend CmdLength = strlen(ProcessCommandLine)
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, CmdLength, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Legitimate user-launched scripts from Explorer (double-clicked .ps1/.bat, software deployment helpers) will surface; allowlist by signed script path, specific command-line prefixes, or known admin accounts. Shortcut (.lnk) launches also show explorer.exe as parent — correlate with the RunMRU rule or a preceding browser process to confirm the ClickFix chain. Suppress enterprise tools that legitimately use msiexec with an http URL.

## 3) ScreenConnect/ConnectWise Client Executed From User-Writable or Browser/Script-Delivered Path

**Tactic:** CommandAndControl  
**ATT&CK:** T1219  
**Severity:** Medium  
**Purpose:** Threat actors deploy legitimate ScreenConnect (ConnectWise Control) clients as a cheap RAT. Detects ScreenConnect binaries running from temp/download/public paths or launched by a browser, mail client, Office app, or script interpreter — rather than from a managed installation directory.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName has_any ("ScreenConnect", "ConnectWiseControl", "Connectwise")
    or ProcessVersionInfoProductName has_any ("ScreenConnect", "ConnectWise Control")
    or ProcessVersionInfoFileDescription has "ScreenConnect"
    or ProcessCommandLine has_any ("ScreenConnect.ClientSetup", "e=Access&y=Guest", "&p=&c=", "ScreenConnect.WindowsClient.exe")
| where FolderPath has_any (@"\AppData\Local\Temp", @"\AppData\Roaming", @"\Downloads", @"\Users\Public", @"\ProgramData", @"\Windows\Temp", @"\Desktop")
    or InitiatingProcessFileName in~ ("chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "outlook.exe", "winword.exe", "excel.exe", "powerpnt.exe", "powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "rundll32.exe", "regsvr32.exe", "msiexec.exe", "explorer.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessVersionInfoProductName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** If your MSP/helpdesk legitimately uses ScreenConnect, allowlist the organization's instance by the client URL/instance ID embedded in ProcessCommandLine or FolderPath, and exclude the managed install path (C:\Program Files (x86)\ScreenConnect Client (<instanceid>)). Keep the browser/Office/script-parent branch enabled even for sanctioned deployments — self-installs delivered via email or web are the abuse pattern. Correlate with DeviceNetworkEvents to any ScreenConnect relay domain not matching the sanctioned instance.

```kusto

    or InitiatingProcessVersionInfoProductName has_any ("ScreenConnect", "ConnectWise Control")

Build a baseline of normal RMM-initiated scripts over 14 days before enabling.

## 5) DLL Sideloading: Signed Application Loading DLL From Its Own User-Writable Folder

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.001  
**Severity:** Medium  
**Purpose:** The 'Unknown Loader' cluster (ContagiousInterview/ClickFix droppers) relies on DLL sideloading: a legitimate signed EXE is copied into a user-writable directory alongside a malicious DLL of a hijackable name. Detects image loads where both the loading process and the DLL reside in AppData/Temp/Public/ProgramData.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FileName endswith ".dll"
| where FolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| where InitiatingProcessFolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\AppData\Local\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| extend DllDir = tostring(parse_path(FolderPath).DirectoryPath), ExeDir = tostring(parse_path(InitiatingProcessFolderPath).DirectoryPath)
| where tolower(DllDir) == tolower(ExeDir)
| where InitiatingProcessFileName !in~ ("msedgewebview2.exe", "teams.exe", "ms-teams.exe", "slack.exe", "code.exe", "onedrive.exe", "squirrel.exe", "setup.exe", "update.exe", "node.exe", "python.exe")
| summarize LoadCount = count(), DllNames = make_set(FileName, 20), AnyDllSha = any(SHA256) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ExeDir, bin(Timestamp, 1h)
| project Timestamp, DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ExeDir, DllNames, LoadCount, AnyDllSha
```

**Tuning notes:** Electron/Chromium apps, installers, and developer toolchains legitimately load DLLs from per-user install directories — the exclusion list above is a starting point and must be extended with your own software inventory. Increase fidelity by joining the DLL SHA256 to DeviceFileEvents to require the DLL was written within the previous hour, and by requiring the initiating EXE to be a valid-signed Microsoft/third-party binary (join DeviceProcessEvents on InitiatingProcessSHA256 where SignatureStatus == 'Valid').

## 6) Node.js/npm Spawning Shell, Downloader, or Script Interpreter (ContagiousInterview-style Loader)

**Tactic:** Execution  
**ATT&CK:** T1059  
**Severity:** High  
**Purpose:** Fake-recruiter / trojanized-repo campaigns (ContagiousInterview, NodeJS loaders in the Unknown Loader cluster) execute malicious postinstall or project scripts under node/npm, which then spawn shells, curl, or PowerShell to fetch second-stage payloads.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("node.exe", "node", "npm.cmd", "npx.cmd", "yarn.cmd", "pnpm.cmd", "bun.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "rundll32.exe", "regsvr32.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "schtasks.exe", "sh", "bash", "zsh", "osascript", "python", "python3")
| where ProcessCommandLine has_any ("http://", "https://", "iex", "invoke-expression", "invoke-webrequest", "downloadstring", "frombase64string", "-enc", "base64 -d", "atob", "curl ", "wget ", "chmod +x", "/tmp/", "\\AppData\\", "Add-MpPreference", "schtasks /create", "reg add")

```

**Tuning notes:** Developer workstations generate legitimate node->shell chains during builds (webpack, husky, node-gyp, electron-builder). The highest-signal subset is node spawning powershell with -enc/IEX, or node spawning curl to a bare IP — consider a stricter variant for alerting and the broad version for hunting.

## 7) Linux IoT Dropper Pattern: Shell Download + chmod + Execute From /tmp (Mirai/Gafgyt)

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** Mirai/Gafgyt infection chains on Linux endpoints and IoT-adjacent hosts use a shell one-liner that fetches an ELF via wget/curl/tftp/busybox into /tmp, /dev/shm, or /var/tmp, makes it executable, and runs it. This behavior survives IOC rotation of payload URLs and C2 ip:port pairs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("sh", "bash", "dash", "ash", "busybox", "wget", "curl", "tftp", "ftpget", "chmod", "perl")
| where ProcessCommandLine has_any ("/tmp/", "/dev/shm/", "/var/tmp/", "/var/run/", "/mnt/", "/dev/null")
| where ProcessCommandLine matches regex @"(?i)\b(wget|curl|tftp|ftpget)\b"
    or ProcessCommandLine matches regex @"(?i)chmod\s+(\+x|777|755)"
    or ProcessCommandLine matches regex @"(?i)\|\s*(sh|bash)\b"
| extend SuspiciousChain = iff(ProcessCommandLine matches regex @"(?i)(wget|curl|tftp)" and ProcessCommandLine matches regex @"(?i)chmod", "DownloadAndExec", "Partial")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SuspiciousChain, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Configuration-management agents (Ansible, Puppet, cloud-init), container build steps, and package mirrors produce similar patterns — allowlist by initiating process (ansible, salt-minion, dockerd, containerd-shim) and by known repository hostnames in the command line. Prioritize events where SuspiciousChain == 'DownloadAndExec', where the URL contains a bare IP address, or where the parent is a network-facing daemon (dropbear, sshd, telnetd, httpd).

## 8) Mail/Web Service Daemon Spawning Shell or Downloader (Zimbra CVE-2026-73570 Command Injection)

**Tactic:** InitialAccess  
**ATT&CK:** T1190  
**Severity:** Critical  
**Purpose:** Unauthenticated command injection against internet-facing mail servers (Zimbra CVE-2026-73570) manifests as the mail/web service account spawning a shell, downloader, or recon command. This parent-child anomaly is the durable detection regardless of the specific injection payload.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("zmmailboxd", "mailboxd", "java", "nginx", "httpd", "apache2", "postfix", "smtpd", "master", "amavisd", "clamd", "opendkim", "convertd", "zmconfigd", "w3wp.exe", "tomcat", "catalina.sh")
| where FileName in~ ("sh", "bash", "dash", "zsh", "curl", "wget", "python", "python3", "perl", "ruby", "php", "nc", "ncat", "netcat", "socat", "base64", "chmod", "chattr", "crontab", "whoami", "id", "uname", "hostname", "ssh-keygen", "useradd", "openssl", "cmd.exe", "powershell.exe")
| where not(InitiatingProcessFileName in~ ("java", "tomcat") and FileName in~ ("sh", "bash") and ProcessCommandLine has_any ("zmlocalconfig", "zmprov", "logrotate", "zmcontrol"))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Zimbra and Tomcat legitimately shell out for maintenance scripts (zmprov, zmlocalconfig, logrotate, backup jobs) — extend the exclusion clause with your server's cron/maintenance command lines after a one-week baseline. Treat any outbound fetch (curl/wget), reverse-shell tooling (nc/socat/python -c), or webshell file write under the mail server's web root as immediate escalation; pair with DeviceFileEvents for .jsp/.php creations under the Zimbra/Tomcat webapps directories.

## 9) macOS Image/Preview Renderer Spawning Shell or Downloader (CoreGraphics Exploitation Follow-On)

**Tactic:** Execution  
**ATT&CK:** T1203  
**Severity:** Medium  
**Purpose:** CVE-2026-86950 is an out-of-bounds write in CoreGraphics reachable via image parsing in Preview, QuickLook, Messages, and WebKit. Successful exploitation is observable when these renderer/helper processes spawn shells, scripting hosts, or downloaders — behavior they never exhibit normally.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("Preview", "quicklookd", "QuickLookUIService", "com.apple.quicklook", "com.apple.WebKit.WebContent", "WebContent", "Safari", "imagent", "Messages", "Photos", "mdworker", "mdworker_shared", "thumbnailExtension", "PreviewShell")
| where FileName in~ ("sh", "bash", "zsh", "curl", "wget", "nscurl", "osascript", "python3", "python", "perl", "ruby", "launchctl", "chmod", "xattr", "base64", "nc", "socat", "open", "defaults", "security")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** macOS-only; expect very low volume, so most hits warrant triage. Some QuickLook plugins and Safari extensions legitimately invoke 'open' or 'defaults' — allowlist specific command lines after review. Strengthen by correlating with a DeviceFileEvents write of an image/PDF to ~/Downloads or the Messages attachment directory in the preceding 5 minutes, and with any new LaunchAgent plist creation under ~/Library/LaunchAgents.
