## 1) Uncommon Child Process Spawned From XBootMgrSleep.exe

**Tactic:** DefenseEvasion  
**ATT&CK:** T1202 - Indirect Command Execution  
**Severity:** Medium  
**Purpose:** Detects any process other than the legitimate Windows Performance Toolkit xbootmgr.exe being spawned by the Microsoft-signed XBootMgrSleep.exe, which can be abused as a delayed-execution LOLBIN proxy to run arbitrary executables and break process lineage.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "xbootmgrsleep.exe"
| where tolower(FolderPath) != @"c:\program files (x86)\windows kits\10\windows performance toolkit\xbootmgr.exe"
| project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Only hosts with the Windows ADK / Windows Performance Toolkit installed will generate events at all, so volume should be near zero. If your organization installs the WPT to a non-default path (e.g. a D:\ drive or a 64-bit Program Files location), add that xbootmgr.exe path to the exclusion. Legitimate performance-tracing automation that chains xbootmgrsleep.exe to a wrapper script should be allowlisted by SHA256 of the child process, not by file name.

## 2) Renamed Schtasks.exe Execution

**Tactic:** Persistence  
**ATT&CK:** T1053.005 - Scheduled Task/Job: Scheduled Task  
**Severity:** High  
**Purpose:** Detects execution of a renamed copy of schtasks.exe - either via the PE OriginalFileName metadata not matching the on-disk name, or via schtasks-specific command-line switch combinations invoked by a binary whose name/command line does not reference schtasks. Threat actors rename schtasks.exe to evade name-based monitoring while creating persistence tasks.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| extend CmdLower = tolower(ProcessCommandLine)
| extend NormCmd = replace_string(replace_string(CmdLower, " \u2013", " /"), " -", " /")
| extend OFN = tolower(tostring(ProcessVersionInfoOriginalFileName))
| where (
        NormCmd has_any (" /create ", " /delete ", " /query ", " /change ", " /run ", " /end ")
        and NormCmd has_any (" /tn ", " /tr ", " /sc ", " /st ", " /ru ", " /fo ")
        and NormCmd !contains "schtasks"
        and not(NormCmd contains "openfiles" and NormCmd contains " /query " and NormCmd contains " /fo")
    )
    or (OFN == "schtasks.exe" and tolower(FileName) != "schtasks.exe")
| project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessVersionInfoOriginalFileName, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** The dash-to-slash normalization emulates Sigma's 'windash' modifier and can create false positives for unrelated tools that use -tn/-sc style flags; validate hits by checking ProcessVersionInfoOriginalFileName. Expect benign noise from backup/RMM agents that ship their own renamed task utilities - allowlist by signer and SHA256. Note ProcessVersionInfoOriginalFileName is empty for some packed/edited binaries, so the command-line branch is the primary coverage.

## 3) ClickFix: Malicious Command Pasted Into the Windows Run Dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004 - User Execution: Malicious Copy and Paste  
**Severity:** High  
**Purpose:** IClickFix campaigns instruct victims to paste an attacker-supplied command into the Win+R Run dialog. Every pasted entry is written to the Explorer RunMRU registry key, making it a high-fidelity artifact of the social-engineering step that precedes payload download (mshta/msiexec/powershell/curl).

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueName != "MRUList"
| extend Pasted = tolower(tostring(RegistryValueData))
| where Pasted has_any ("powershell", "pwsh", "cmd.exe", "cmd /c", "mshta", "msiexec", "curl", "certutil", "bitsadmin", "rundll32", "wscript", "cscript", "conhost", "iex", "invoke-expression", "invoke-webrequest", "downloadstring", "frombase64string", "http://", "https://", "\\\\")
| project Timestamp, DeviceName, InitiatingProcessAccountDomain, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins and developers legitimately type cmd/powershell into Run - reduce noise by requiring the value length to exceed ~60 characters, or by requiring a URL/base64/encoded indicator. The trailing '\1' suffix Explorer appends to each RunMRU value is normal. Pair with a follow-up hunt for child processes of explorer.exe within 2 minutes of the hit. Many ClickFix lures pad the command with whitespace to hide it in the Run box - inspect the full RegistryValueData, not just the prefix.

## 4) Msiexec Installing a Package From a Remote URL

**Tactic:** CommandAndControl  
**ATT&CK:** T1218.007 - System Binary Proxy Execution: Msiexec  
**Severity:** High  
**Purpose:** IClickFix and similar loader chains abuse 'msiexec /i https://<host>/x.msi /qn' to pull and execute a remote payload with a signed Microsoft binary, bypassing download-reputation controls. Detects msiexec invoked with an http(s) source, especially when spawned by a browser, shell, or script host.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "msiexec.exe"
| extend Cmd = tolower(ProcessCommandLine)
| where Cmd has_any ("http://", "https://", "\\\\")
| where Cmd has_any (" /i", " -i", " /package", " /a ", " /y ", " /z ")
| project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Allowlist known internal software-distribution URLs/UNC shares (SCCM/Intune content hosts, internal artifact repositories) by hostname substring. Prioritize events where InitiatingProcessFileName is explorer.exe, a browser, mshta.exe, powershell.exe, wscript.exe or cscript.exe, or where the URL host is a raw IP or a recently registered domain. Follow up with DeviceNetworkEvents for the same InitiatingProcessId to capture the download destination.

## 5) AsyncRAT-Style Injection Into .NET Framework LOLBINs

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218.009 - System Binary Proxy Execution: Regsvcs/Regasm  
**Severity:** High  
**Purpose:** AsyncRAT and related .NET RATs are typically loaded by a script-host stager that spawns a signed .NET utility (RegAsm, RegSvcs, InstallUtil, MSBuild, AppLaunch, aspnet_compiler) as a hollowing/injection host. Detects these binaries launched by script hosts, Office, or from user-writable directories, independent of the campaign's rotating C2 indicators.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("regasm.exe", "regsvcs.exe", "installutil.exe", "msbuild.exe", "aspnet_compiler.exe", "applaunch.exe", "caspol.exe", "jsc.exe", "csc.exe")
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe", "cmd.exe", "wmiprvse.exe", "rundll32.exe", "regsvr32.exe", "winword.exe", "excel.exe", "outlook.exe", "explorer.exe", "curl.exe", "forfiles.exe")
    or FolderPath has_any (@"\AppData\", @"\Temp\", @"\Users\Public\", @"\ProgramData\", @"\Downloads\")
| project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Developer workstations and build agents legitimately run msbuild.exe/csc.exe from cmd.exe or explorer.exe - scope those devices out by device group, or require an empty/odd command line (AsyncRAT injection hosts are usually launched with no arguments or a nonexistent project path). Combine with the companion network detection for the same process to raise confidence. aspnet_compiler.exe and applaunch.exe with no arguments are rarely benign anywhere.

## 6) Outbound C2 From .NET Utility or User-Directory Binary (AsyncRAT Beaconing)

**Tactic:** CommandAndControl  
**ATT&CK:** T1571 - Non-Standard Port  
**Severity:** Medium  
**Purpose:** AsyncRAT implants hosted in injected .NET LOLBINs or in binaries dropped under AppData/Temp beacon to attacker infrastructure, frequently on non-standard TLS ports. Detects public-internet connections initiated by processes that should never talk to the internet directly, or by executables running from user-writable paths.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteIPType == "Public"
| where ActionType in ("ConnectionSuccess", "ConnectionRequest")
| where InitiatingProcessFileName in~ ("regasm.exe", "regsvcs.exe", "installutil.exe", "aspnet_compiler.exe", "applaunch.exe", "caspol.exe", "jsc.exe", "msbuild.exe")
    or (InitiatingProcessFolderPath has_any (@"\AppData\Roaming\", @"\AppData\Local\Temp\", @"\Users\Public\", @"\ProgramData\") and RemotePort !in (80, 443))
| summarize Connections = count(), DistinctPorts = dcount(RemotePort), Ports = make_set(RemotePort, 10), Destinations = make_set(strcat(RemoteIP, ":", tostring(RemotePort)), 15), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, Connections, DistinctPorts, Ports, Destinations
```

**Tuning notes:** Allowlist legitimate updaters and collaboration apps that install into %LocalAppData% (Teams, Slack, Zoom, Chrome/Edge updaters, Dropbox) by SHA256 or publisher. MSBuild on developer machines contacting NuGet/package CDNs is expected - exclude build-agent device groups. Low connection counts to a single rare IP on ports like 4444/5050/6606/7707/8808 are the strongest AsyncRAT signal; enrich destinations against your own rare-external-IP baseline instead of static IOC lists.

## 7) Mirai/Gafgyt-Style Shell Dropper: Remote ELF Download, chmod, Execute

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Command and Scripting Interpreter: Unix Shell  
**Severity:** High  
**Purpose:** Mirai and Gafgyt variants propagate by piping a shell one-liner into exploited Linux/IoT devices that downloads an architecture-specific ELF via wget/curl/tftp/busybox into a world-writable directory, chmods it executable, and runs it. Detects the download+chmod+exec chain regardless of the rotating payload URLs and hashes.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| extend Cmd = tolower(ProcessCommandLine)
| where InitiatingProcessFileName in~ ("sh", "bash", "dash", "ash", "busybox", "sshd", "dropbear", "telnetd", "httpd", "nginx", "python3", "perl")
    or FileName in~ ("sh", "bash", "busybox", "wget", "curl", "tftp", "ftpget")
| where (Cmd has_any ("wget", "curl ", "tftp", "ftpget") and Cmd has_any ("chmod", "/tmp/", "/dev/shm/", "/var/tmp/", "/var/run/", "|sh", "| sh", "|bash", "| bash"))
    or Cmd matches regex @"chmod\s+(\+x|777|755)\s+[^\s]*(/tmp/|/var/tmp/|/dev/shm/|\./)"
    or Cmd matches regex @"busybox\s+(wget|tftp)"
| project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessIntegrityLevel, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Requires Defender for Endpoint on Linux. Baseline CI/CD runners, container build hosts, and configuration-management agents (Ansible, Chef, Puppet, cloud-init) which legitimately curl-and-chmod install scripts - exclude by device group or by InitiatingProcessAccountName. Highest fidelity when the parent is sshd/telnetd/httpd (post-exploitation) or when the URL host is a bare IP address. Follow up with DeviceFileEvents for new executable files in /tmp and /dev/shm on the same host.

## 8) Zammad Application Service Spawning a Shell or Privilege-Escalation Utility

**Tactic:** Execution  
**ATT&CK:** T1190 - Exploit Public-Facing Application  
**Severity:** High  
**Purpose:** CVE-2026-102489 (session fixation to RCE as the zammad user) chained with CVE-2026-102490 (local privilege escalation to root) results in the Zammad web/worker processes spawning interactive shells, network tools, or setuid/privilege-changing utilities. Detects post-exploitation command execution from the application service context rather than the exploit traffic itself.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName has_any ("ruby", "puma", "rails", "sidekiq", "zammad", "unicorn", "passenger", "node", "nginx")
    or InitiatingProcessAccountName =~ "zammad"
| where FileName in~ ("sh", "bash", "dash", "zsh", "nc", "ncat", "netcat", "socat", "curl", "wget", "python", "python3", "perl", "ruby", "sudo", "su", "chmod", "chown", "usermod", "useradd", "passwd", "crontab", "systemctl", "ssh-keygen", "base64")
| project Timestamp, DeviceName, AccountName, ProcessIntegrityLevel, FileName, FolderPath, ProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessId, ReportId
```

**Tuning notes:** Requires Defender for Endpoint on the Linux host running Zammad. Zammad legitimately shells out for Elasticsearch indexing, backup/restore scripts (zammad run rake ...), and logrotate - baseline those command lines for a week and allowlist exact patterns. Treat any event where AccountName resolves to root while InitiatingProcessAccountName is zammad as a confirmed privilege-escalation attempt (CVE-2026-102490). Also hunt for reverse-shell patterns ('>& /dev/tcp/', 'bash -i', 'socat ... exec:') and for new SSH authorized_keys writes via DeviceFileEvents on the same host.
