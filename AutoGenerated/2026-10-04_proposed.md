## 1) Uncommon Child Process Spawned From XBootMgrSleep.exe

**Tactic:** DefenseEvasion  
**ATT&CK:** T1202 - Indirect Command Execution  
**Severity:** High  
**Purpose:** Detects abuse of the Microsoft-signed Windows Performance Toolkit binary XBootMgrSleep.exe as a proxy/delayed launcher for arbitrary executables, bypassing parent-child based detections and application control heuristics.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where InitiatingProcessFileName =~ 'xbootmgrsleep.exe' | where FolderPath !~ @'C:\Program Files (x86)\Windows Kits\10\Windows Performance Toolkit\xbootmgr.exe' | project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Legitimate usage is nearly always xbootmgr.exe from the Windows Kits path; if your org installs WPT to a non-default location (e.g. D:\ or a portable ADK deployment) add that FolderPath to the allowlist. Expect near-zero volume outside performance-engineering workstations.

## 2) Renamed Schtasks.exe Execution

**Tactic:** Persistence  
**ATT&CK:** T1053.005 - Scheduled Task/Job: Scheduled Task  
**Severity:** High  
**Purpose:** Detects execution of a renamed copy of schtasks.exe (binary metadata still reports schtasks.exe, or schtasks-style command-line switches used by a process whose name/command line does not reference schtasks), a common evasion for scheduled-task persistence.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | extend CmdLower = tolower(ProcessCommandLine) | where (ProcessVersionInfoOriginalFileName =~ 'schtasks.exe' and FileName !~ 'schtasks.exe') or (CmdLower matches regex @'\s[-/](create|delete|query|change|run|end)\s' and CmdLower matches regex @'\s[-/](tn|tr|sc|st|ru|fo)\s' and CmdLower !has 'schtasks' and not(CmdLower has 'openfiles' and CmdLower matches regex @'\s[-/]query\s' and CmdLower matches regex @'\s[-/]fo')) | project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessVersionInfoOriginalFileName, ProcessVersionInfoCompanyName, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** The command-line branch can match other CLI tools that use /tn /tr style switches (some backup/RMM agents, custom wrappers). Allowlist by FolderPath/SHA256 after review. The OriginalFileName branch is high fidelity - any hit where FileName != schtasks.exe should be escalated. Note OriginalFileName is only populated when signed version info exists.

## 3) Kerberos Service Ticket Request via KerberosRequestorSecurityToken (PowerShell)

**Tactic:** CredentialAccess  
**ATT&CK:** T1558.003 - Kerberoasting  
**Severity:** High  
**Purpose:** Detects PowerShell script blocks or command lines using the System.IdentityModel.Tokens.KerberosRequestorSecurityToken constructor to request TGS tickets for SPNs - the core primitive of Kerberoasting and silver-ticket preparation.

```kusto
DeviceEvents | where Timestamp > ago(1d) | where ActionType in ('PowerShellCommand','ScriptContent','ScriptBlockLogged') or isnotempty(AdditionalFields) | where AdditionalFields has 'KerberosRequestorSecurityToken' or ProcessCommandLine has 'KerberosRequestorSecurityToken' | extend ScriptText = tostring(parse_json(AdditionalFields).Command) | project Timestamp, DeviceName, AccountDomain, AccountName, ActionType, ScriptText, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Requires PowerShell Script Block Logging to be forwarded to Defender (ActionType PowerShellCommand). Add a parallel hunt on DeviceProcessEvents where ProcessCommandLine has 'KerberosRequestorSecurityToken' to catch one-liners. Legitimate hits are rare - occasional red-team/pentest tooling or SPN health scripts; allowlist by specific script path or signing user, not by host.

## 4) ClickFix/FileFix: Interpreter Spawned Directly From Explorer With Download or Encoded Payload

**Tactic:** Execution  
**ATT&CK:** T1059.001 - Command and Scripting Interpreter: PowerShell  
**Severity:** High  
**Purpose:** Detects the ClickFix/FileFix social-engineering chain (tracked for IClickFix and Unknown Loader) where the victim pastes an attacker-supplied command into the Run dialog or Explorer address bar, causing explorer.exe to spawn a scripting host that downloads or decodes a second stage.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where InitiatingProcessFileName =~ 'explorer.exe' | where FileName in~ ('powershell.exe','pwsh.exe','cmd.exe','mshta.exe','wscript.exe','cscript.exe','msiexec.exe','curl.exe','certutil.exe','conhost.exe','rundll32.exe','bitsadmin.exe','deno.exe','node.exe') | where ProcessCommandLine has_any ('http://','https://','iwr ','irm ','iex','Invoke-WebRequest','Invoke-RestMethod','Invoke-Expression','DownloadString','DownloadFile','FromBase64String','-enc','-ec ','-e ','hidden','Start-BitsTransfer','\\\\','curl ','certutil -urlcache','mshta ') | project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins legitimately paste commands into Run; baseline per-user and allowlist known IT one-liners or internal file-share UNC paths. ClickFix lures typically include long padded whitespace, unicode check marks, or a trailing '# verification' style comment - add those as a scoring boost. Consider restricting FileName to script hosts only if cmd.exe volume is high.

## 5) Suspicious Command Written to Explorer RunMRU (ClickFix Paste Artifact)

**Tactic:** Execution  
**ATT&CK:** T1204.004 - User Execution: Malicious Copy and Paste  
**Severity:** Medium  
**Purpose:** Detects the forensic artifact left by ClickFix campaigns: a scripting/download command recorded in the Explorer RunMRU registry key after the victim pastes attacker content into the Win+R Run dialog.

```kusto
DeviceRegistryEvents | where Timestamp > ago(1d) | where RegistryKey has @'Explorer\RunMRU' | where RegistryValueData has_any ('powershell','pwsh','mshta','msiexec','curl','certutil','bitsadmin','rundll32','wscript','cscript','cmd /c','cmd.exe /c','iex','irm','iwr','FromBase64String','http://','https://','-enc','.hta','deno ') | project Timestamp, DeviceName, AccountDomain, AccountName, ActionType, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** RunMRU entries for internal UNC paths, mmc consoles and common admin tools are normal - allowlist by RegistryValueData prefix. Correlate within a few minutes against DeviceProcessEvents for the matching child of explorer.exe to confirm execution. Low severity alone, high when paired with the explorer-spawned-interpreter detection.

## 6) Msiexec Installing a Package From a Remote URL

**Tactic:** CommandAndControl  
**ATT&CK:** T1218.007 - System Binary Proxy Execution: Msiexec  
**Severity:** High  
**Purpose:** Detects the msiexec-based delivery pattern reported for IClickFix and Unknown Loader, where msiexec.exe is used to fetch and execute a remotely hosted MSI payload, proxying download and execution through a trusted signed binary.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName =~ 'msiexec.exe' | where ProcessCommandLine matches regex @'(?i)[-/](i|package|a|y)\s*"?(http|ftp)' | project Timestamp, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Some software distribution and vendor update workflows legitimately install MSIs from HTTPS URLs - allowlist by the specific FQDN in the command line or by InitiatingProcessFileName of the trusted deployment agent. Pivot on DeviceNetworkEvents for the msiexec.exe RemoteUrl to confirm destination reputation.

## 7) Download Piped Directly Into a Shell on Linux (Mirai/Gafgyt Dropper Pattern)

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Command and Scripting Interpreter: Unix Shell  
**Severity:** High  
**Purpose:** Detects the canonical Mirai/Gafgyt and ELF loader staging technique where wget/curl/tftp output is piped straight into a shell interpreter, executing a bot installer without touching disk persistently.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where ProcessCommandLine matches regex @'(?i)\b(wget|curl|tftp|ftpget|busybox\s+wget)\b[^|;]{0,300}\|\s*(/bin/)?(sh|bash|ash|dash|zsh|python[0-9.]*|perl)\b' | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Developer and CI/CD hosts run installer one-liners (rustup, nvm, docker get.docker.com) this way - allowlist by the specific trusted domain in ProcessCommandLine or by device group (build servers). On IoT/appliance-like Linux endpoints treat any hit as critical. Requires Defender for Endpoint on Linux.

## 8) ELF Payload Staged in World-Writable Directory and Made Executable

**Tactic:** Execution  
**ATT&CK:** T1222.002 - File and Directory Permissions Modification: Linux  
**Severity:** Medium  
**Purpose:** Detects Mirai/Gafgyt-style dropper behavior: fetching a binary into /tmp, /dev/shm or /var/tmp, chmod'ing it executable (often 777) and running it, frequently across multiple CPU-architecture variants.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where FileName in~ ('chmod','busybox') or ProcessCommandLine startswith 'chmod' | where ProcessCommandLine has_any ('777','+x','0777','755') | where ProcessCommandLine has_any ('/tmp/','/dev/shm','/var/tmp','/var/run','/mnt/','/run/user','./') | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Package managers, container entrypoints and build pipelines chmod files in /tmp routinely - scope out known build/CI device groups and allowlist InitiatingProcessFileName values like dpkg, rpm, docker-containerd. Strongest signal when the same device shows several chmod events within a minute against files with architecture-suffixed names (arm7, mips, x86) or when followed by an execution of the same path.

## 9) Web Application Service Account Spawning a Shell or Network Tool (Zammad RCE Chain)

**Tactic:** Execution  
**ATT&CK:** T1505.003 - Server Software Component: Web Shell  
**Severity:** High  
**Purpose:** Detects post-exploitation of web-application RCE such as the Zammad session fixation chain (CVE-2026-102489), where the application runtime (ruby/puma/rails/nginx/node) spawns an interactive shell, downloader or reconnaissance utility under the service account.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where InitiatingProcessFileName has_any ('ruby','puma','rails','unicorn','passenger','nginx','node','zammad','rake','bundle') | where FileName in~ ('sh','bash','dash','zsh','nc','ncat','netcat','socat','curl','wget','python','python3','perl','whoami','id','uname','crontab','ssh','base64','chmod') | project Timestamp, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Rails/Zammad legitimately shells out for background jobs (image processing, LDAP sync, backup scripts) - baseline the normal child commands per host for a week and allowlist exact ProcessCommandLine patterns. Any reverse-shell style command (nc with -e, bash -i >& /dev/tcp) should be promoted to critical immediately.

## 10) Zammad Service Account Attempting Local Privilege Escalation

**Tactic:** PrivilegeEscalation  
**ATT&CK:** T1068 - Exploitation for Privilege Escalation  
**Severity:** High  
**Purpose:** Detects the local escalation half of the Zammad chain (CVE-2026-102490), where the low-privileged zammad (or similar application) account invokes sudo/su/pkexec, modifies setuid permissions, or edits accounts and cron to reach root.

```kusto
DeviceProcessEvents | where Timestamp > ago(1d) | where AccountName in~ ('zammad','www-data','nginx','apache','rails') or InitiatingProcessAccountName in~ ('zammad','www-data','nginx','apache','rails') | where FileName in~ ('sudo','su','pkexec','doas','passwd','usermod','useradd','chown','visudo','crontab','systemctl','setcap') or ProcessCommandLine has_any ('chmod u+s','chmod 4755','/etc/sudoers','/etc/shadow','/etc/passwd','authorized_keys') | project Timestamp, DeviceName, AccountName, InitiatingProcessAccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Zammad's own installer/upgrade scripts call systemctl and chown as part of maintenance windows - allowlist by parent command line (e.g. zammad-upgrade, apt/dpkg maintainer scripts) and by change-window timestamps. Extend the account list to match your application service accounts; do not hardcode hostnames.
