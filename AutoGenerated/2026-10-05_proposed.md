## 1) Uncommon Child Process Spawned From XBootMgrSleep.exe

**Tactic:** DefenseEvasion  
**ATT&CK:** T1202 - Indirect Command Execution  
**Severity:** High  
**Purpose:** Detects any process other than the legitimate xbootmgr.exe being spawned by the Microsoft-signed Windows Performance Toolkit binary XBootMgrSleep.exe, which can be abused to execute an arbitrary executable after a delay (indirect command execution / proxy execution).

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "xbootmgrsleep.exe"
| where not(FolderPath =~ @"C:\Program Files (x86)\Windows Kits\10\Windows Performance Toolkit\xbootmgr.exe")
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** XBootMgrSleep.exe is rare outside performance-engineering workstations; any hit should be investigated. If your organization runs WPT from a non-default path (e.g., x64 Program Files or a portable ADK copy), extend the allowlist with those full paths of xbootmgr.exe rather than allowlisting by file name only. Consider also alerting on the presence of xbootmgrsleep.exe outside of the Windows Kits directory (copied LOLBIN).

## 2) Renamed Schtasks.exe Execution

**Tactic:** Persistence  
**ATT&CK:** T1036.003 - Rename System Utility / T1053.005 - Scheduled Task  
**Severity:** High  
**Purpose:** Detects execution of a renamed copy of schtasks.exe, identified either by scheduled-task command-line syntax appearing in a process whose command line does not reference schtasks, or by the PE OriginalFileName being schtasks.exe while the on-disk image name differs. Common masquerading technique to evade task-creation monitoring.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| extend cl = tolower(ProcessCommandLine)
| extend clNorm = replace_string(replace_string(cl, " -", " /"), "\u2013", "/")
| extend origName = tolower(tostring(ProcessVersionInfoOriginalFileName))
| extend hasOp = clNorm has_any (" /create ", " /delete ", " /query ", " /change ", " /run ", " /end ")
| extend hasFlag = clNorm has_any (" /tn ", " /tr ", " /sc ", " /st ", " /ru ", " /fo ")
| extend isOpenFiles = cl has "openfiles" and clNorm has " /query " and clNorm has " /fo"
| where (hasOp and hasFlag and not(cl has "schtasks") and not(isOpenFiles))
    or (origName == "schtasks.exe" and not(FileName =~ "schtasks.exe"))
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, FolderPath, ProcessVersionInfoOriginalFileName, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** The dash-to-slash normalization can produce false positives for unrelated tools that use ' -tn'/' -run' style switches; if noisy, restrict the first branch to processes where ProcessVersionInfoOriginalFileName is empty or non-Microsoft, or require at least two matching flags. Allowlist known management/backup agents (e.g., RMM wrappers that embed schtasks syntax) by InitiatingProcessFolderPath or signer. The OriginalFileName branch is very low noise and should rarely be tuned.

## 3) Run Key Persistence Pointing to User-Writable Payload Path

**Tactic:** Persistence  
**ATT&CK:** T1547.001 - Registry Run Keys / Startup Folder  
**Severity:** Medium  
**Purpose:** Detects commodity RAT/loader persistence (AsyncRAT, Unknown Loader droppers) that writes an autorun value referencing an executable or script staged in AppData, Temp or ProgramData, optionally wrapped in a script interpreter.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has_any (@"CurrentVersion\Run", @"CurrentVersion\RunOnce", @"CurrentVersion\Explorer\Shell Folders", @"CurrentVersion\Policies\Explorer\Run")
| extend data = tolower(tostring(RegistryValueData))
| where data has_any ("\\appdata\\", "\\local\\temp\\", "\\programdata\\", "\\public\\", "\\users\\public")
| where data has_any (".exe", ".scr", ".vbs", ".js", ".bat", ".cmd", ".ps1", "powershell", "mshta", "wscript", "cscript", "rundll32")
| project Timestamp, DeviceId, DeviceName, ActionType, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Legitimate per-user apps (Teams, OneDrive, Slack, Zoom updaters, some VPN clients) write Run values under AppData\Local — allowlist by RegistryValueName or by the signed InitiatingProcessFolderPath. Highest fidelity when InitiatingProcessFileName is a script host (powershell/wscript/mshta) or an unsigned binary in the same user-writable path.

## 4) RunMRU Registry Entry Containing Script Interpreter or Remote Payload (ClickFix Artifact)

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste  
**Severity:** Medium  
**Purpose:** Detects the forensic artifact left by ClickFix-style lures: a pasted command recorded in the Explorer RunMRU key that invokes PowerShell, mshta, curl or a remote/UNC path, indicating the user executed attacker-supplied text from the Run dialog.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType == "RegistryValueSet"
| where RegistryKey has @"Explorer\RunMRU"
| extend data = tolower(tostring(RegistryValueData))
| where data has_any ("powershell", "pwsh", "mshta", "cmd.exe /c", "cmd /c", "curl ", "certutil", "bitsadmin", "msiexec", "rundll32", "http://", "https://", "frombase64string", "iex", "\\\\")
| project Timestamp, DeviceId, DeviceName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessAccountName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Power users and helpdesk staff legitimately type cmd/powershell into the Run dialog — bare 'powershell' or 'cmd' with no arguments can be filtered out (require a URL, encoded blob, or more than ~40 characters of command text). Correlate with child-process activity of explorer.exe in the following minute for confirmation.
