## 1) Mirai/Gafgyt-style IoT dropper: download + chmod + execute chain on Linux

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Unix Shell  
**Severity:** High  
**Purpose:** Detects the canonical Mirai/Gafgyt loader behavior where a shell one-liner retrieves an ELF payload with wget/curl/tftp/busybox, makes it executable with chmod, and runs it from a world-writable directory. This is durable across the 2735 rotating ThreatFox indicators because it targets the dropper TTP rather than specific hosts.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where ProcessCommandLine has_any ("wget", "curl", "tftp", "ftpget", "busybox")
| where ProcessCommandLine matches regex @"chmod\s+(\+x|[0-7]{3})"
| where ProcessCommandLine has_any ("/tmp/", "/dev/shm/", "/var/tmp/", "/var/run/", "/mnt/", "/root/", "./")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Allowlist container build agents, package-install automation (Ansible/Chef/Puppet), and CI runners that legitimately curl+chmod install scripts. Consider excluding known SRE service accounts. If noisy, require the command line to also reference multiple architecture suffixes (arm, mips, x86, mpsl) which is highly specific to Mirai multi-arch loaders.

## 2) Linux binary executed from world-writable path with shell/downloader parent

**Tactic:** Execution  
**ATT&CK:** T1204.002 - Malicious File  
**Severity:** High  
**Purpose:** Detects execution of payloads staged in /tmp, /dev/shm or /var/tmp by a shell or downloader process - the post-drop stage of Mirai, Gafgyt, HailBot and the ELF variants of the 'Unknown Loader' family.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FolderPath startswith "/tmp/" or FolderPath startswith "/dev/shm/" or FolderPath startswith "/var/tmp/" or FolderPath startswith "/run/" or FolderPath startswith "/mnt/"
| where InitiatingProcessFileName in~ ("sh", "bash", "dash", "ash", "zsh", "busybox", "wget", "curl", "perl", "python", "python3", "sshd", "cron", "crond")
| where not(FolderPath has_any ("/tmp/systemd-", "/tmp/snap."))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Expect noise from build systems, package managers extracting to /tmp, and monitoring agents. Allowlist by FolderPath prefix for known tooling (e.g. /tmp/pip-, /tmp/go-build). Pair with the file-hash reputation or newly-dropped-file correlation for higher fidelity.

## 3) Outbound C2 from binary running out of a world-writable Linux directory

**Tactic:** CommandAndControl  
**ATT&CK:** T1571 - Non-Standard Port  
**Severity:** Medium  
**Purpose:** Surfaces Mirai/Gafgyt bot check-ins where the implant lives in /tmp or /dev/shm and beacons to a public IP, often on a non-standard port. Behavior-based so it survives the rotation of ip:port ThreatFox indicators.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFolderPath startswith "/tmp/" or InitiatingProcessFolderPath startswith "/dev/shm/" or InitiatingProcessFolderPath startswith "/var/tmp/" or InitiatingProcessFolderPath startswith "/run/" or InitiatingProcessFolderPath startswith "/mnt/"
| where RemoteIPType == "Public"
| summarize ConnCount = count(), DistinctRemoteIPs = dcount(RemoteIP), RemotePorts = make_set(RemotePort, 20), RemoteIPs = make_set(RemoteIP, 20), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ConnCount, DistinctRemoteIPs, RemoteIPs, RemotePorts
```

**Tuning notes:** Allowlist self-updating agents or installers that temporarily execute from /tmp. Raise fidelity by filtering to RemotePort !in (80, 443) or by requiring DistinctRemoteIPs > 20 (scanning/DDoS behavior typical of Mirai).

## 4) ClickFix: malicious command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** ClearFake and the ClickFix/FakeCaptcha 'Unknown Loader' campaigns instruct victims to paste an attacker-supplied command into Win+R. Windows records that string in the Explorer RunMRU registry key, giving a very high-fidelity behavioral artifact of the social-engineering step.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl", "certutil", "bitsadmin", "msiexec", "rundll32", "regsvr32", "wscript", "cscript", "conhost", "cmd /c", "cmd.exe /c", "iex", "invoke-expression", "invoke-webrequest", "frombase64string", "-enc", "-w hidden", "http://", "https://", @"\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Admins legitimately type cmd/powershell into Run - consider filtering out short values (strlen(RegistryValueData) < 40) and allowlisting IT admin accounts/workstations. Values ending in '\1' are the MRU ordering entry and can be dropped.

## 5) ClickFix/FileFix: Explorer spawning an interpreter with download or hidden-execution flags

**Tactic:** Execution  
**ATT&CK:** T1204.004 - Malicious Copy and Paste  
**Severity:** High  
**Purpose:** Captures the execution stage of ClickFix and FileFix lures (ClearFake, OffLoader/Unknown Loader) where explorer.exe - the Run dialog or the File Explorer address bar - directly launches a script interpreter or LOLBin carrying a remote-download or encoded payload.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "rundll32.exe", "regsvr32.exe", "certutil.exe", "bitsadmin.exe", "conhost.exe", "forfiles.exe")
| where ProcessCommandLine has_any ("-w hidden", "-windowstyle hidden", "-nop", "-noprofile", "-enc", "-encodedcommand", "frombase64string", "iex", "invoke-expression", "invoke-webrequest", "iwr ", "downloadstring", "downloadfile", "http://", "https://", ".hta", "webdav", "davwwwroot", @"\\")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessId, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Allowlist internal admin scripts launched from shortcuts and software-deployment tooling that is started from Explorer. If the environment uses signed .hta help files or intranet UNC launchers, exclude those specific paths/domains rather than the whole pattern.

## 6) Browser process spawning a script interpreter or LOLBin

**Tactic:** Execution  
**ATT&CK:** T1059.001 - PowerShell  
**Severity:** High  
**Purpose:** ClearFake/EtherHiding and FakeCaptcha chains frequently result in the browser directly launching cmd.exe, powershell.exe or mshta.exe after the victim interacts with the injected page. Browsers very rarely create these children legitimately.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "vivaldi.exe", "iexplore.exe")
| where FileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "mshta.exe", "wscript.exe", "cscript.exe", "curl.exe", "msiexec.exe", "certutil.exe", "bitsadmin.exe", "rundll32.exe", "regsvr32.exe", "installutil.exe", "schtasks.exe")
| where not(FileName =~ "cmd.exe" and ProcessCommandLine has_any ("\\chrome_installer", "setup.exe --", "crashpad"))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Browser updaters and enterprise extension/native-messaging hosts can trip this; allowlist by InitiatingProcessCommandLine or by specific child command lines. Keep rundll32 only if your environment does not use browser-launched PDF/print handlers.

## 7) Payload execution from a remote WebDAV / UNC share

**Tactic:** CommandAndControl  
**ATT&CK:** T1570 - Lateral Tool Transfer  
**Severity:** Medium  
**Purpose:** The WebDAV-tagged 'Unknown Loader' and FileFix variants stage payloads on attacker WebDAV servers and execute them via \\host@port\path or DavWWWRoot UNC references, bypassing mark-of-the-web and local file detections.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FolderPath startswith @"\\" or ProcessCommandLine has_any ("DavWWWRoot", "@SSL\\", "@80\\", "@443\\", "@8080\\")
| where not(FolderPath has_any (@"\\sysvol\\", @"\\netlogon\\"))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Environments that run software from internal DFS/file shares will generate volume - allowlist the known internal UNC prefixes (\\corpfs\, \\dfs\) and keep the @port / DavWWWRoot clauses, which are almost never benign. Pair with DeviceImageLoadEvents for davclnt.dll loads on the same device for confirmation.

## 8) AsyncRAT loader: .NET LOLBin launched from a script host or user-writable path

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218 - System Binary Proxy Execution  
**Severity:** High  
**Purpose:** AsyncRAT/BoratRAT ps1 loaders routinely hollow or proxy-execute through signed .NET utilities (aspnet_compiler.exe, RegAsm.exe, RegSvcs.exe, InstallUtil.exe, MSBuild.exe) spawned by PowerShell, wscript or an archive tool. Detects the injection host rather than the rotating C2 indicators.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("aspnet_compiler.exe", "RegAsm.exe", "RegSvcs.exe", "InstallUtil.exe", "MSBuild.exe", "AddInProcess.exe", "AddInProcess32.exe", "jsc.exe", "Microsoft.Workflow.Compiler.exe", "CasPol.exe")
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe", "cmd.exe", "wscript.exe", "cscript.exe", "mshta.exe", "explorer.exe", "winword.exe", "excel.exe", "outlook.exe", "winrar.exe", "7zfm.exe", "rundll32.exe", "regsvr32.exe")
    or InitiatingProcessFolderPath has_any (@"\appdata\", @"\temp\", @"\downloads\", @"\programdata\", @"\users\public\")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, ProcessId, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Developer workstations and build servers legitimately run MSBuild/RegAsm from cmd and PowerShell - scope out build-agent device groups or exclude MSBuild when the command line references a .sln/.csproj under a source directory. aspnet_compiler.exe with no -v/-p arguments is almost always malicious.

## 9) Autorun registry value pointing to a user-writable path or script interpreter

**Tactic:** Persistence  
**ATT&CK:** T1547.001 - Registry Run Keys / Startup Folder  
**Severity:** High  
**Purpose:** AsyncRAT and the loader families in this feed establish persistence by writing Run/RunOnce values that reference an EXE/PS1/VBS staged under AppData, Temp, ProgramData or Public, or that invoke PowerShell directly.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Explorer\Shell Folders", @"\Windows\CurrentVersion\Policies\Explorer\Run")
| where RegistryValueData has_any (@"\appdata\", @"\temp\", @"\programdata\", @"\users\public\", @"\downloads\", ".ps1", ".vbs", ".bat", ".js", ".hta", "powershell", "pwsh", "mshta", "wscript", "cscript", "rundll32", "-enc", "frombase64string")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Allowlist known LOB apps that legitimately autorun from %LOCALAPPDATA% (Teams, OneDrive, Slack, Zoom updaters) by RegistryValueName or value path. Writes performed by msiexec.exe/TrustedInstaller during installs can be excluded via InitiatingProcessFileName.

## 10) Scheduled task created to run a script or user-profile payload

**Tactic:** Persistence  
**ATT&CK:** T1053.005 - Scheduled Task  
**Severity:** Medium  
**Purpose:** Complements the Run-key rule: AsyncRAT and ClickFix loaders commonly register a schtasks job that re-launches a PowerShell/VBS stub from AppData or Temp at logon or on a short interval.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("schtasks.exe", "at.exe") or (FileName in~ ("powershell.exe", "pwsh.exe") and ProcessCommandLine has_any ("Register-ScheduledTask", "New-ScheduledTaskAction"))
| where ProcessCommandLine has_any ("/create", "-create", "Register-ScheduledTask")
| where ProcessCommandLine has_any (@"\appdata\", @"\temp\", @"\programdata\", @"\users\public\", ".ps1", ".vbs", ".js", ".hta", "powershell", "mshta", "wscript", "cscript", "-enc", "frombase64string", "/sc minute", "/sc onlogon")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Exclude software deployment and patching tools (SCCM/Intune/backup agents) by InitiatingProcessFileName or task-name prefix. Tasks created under SYSTEM by installers are usually benign; focus on tasks created by interactive user sessions.

## 11) Burst of Linux host reconnaissance commands following interactive SSH login

**Tactic:** Discovery  
**ATT&CK:** T1082 - System Information Discovery  
**Severity:** Medium  
**Purpose:** Mirrors the DShield TTY-log research: after a successful SSH login, bots and hands-on-keyboard actors immediately run a stereotyped recon chain (uname, cpuinfo, free, whoami, crontab) before dropping a payload. Aggregating three or more distinct recon commands per session reduces noise versus single-command alerting.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("sshd", "bash", "sh", "dash", "zsh", "ash")
| extend cmd = tolower(ProcessCommandLine)
| where cmd has_any ("uname -a", "uname -m", "/proc/cpuinfo", "/proc/meminfo", "lscpu", "free -m", "nproc", "whoami", "id -u", "cat /etc/passwd", "cat /etc/shadow", "crontab -l", "history -c", "w ", "last ", "ifconfig", "ip addr", "netstat -an", "ps aux", "df -h", "cat /etc/os-release")
| summarize ReconCommandCount = dcount(cmd), Commands = make_set(ProcessCommandLine, 25), FirstSeen = min(Timestamp), LastSeen = max(Timestamp) by DeviceId, DeviceName, AccountName, InitiatingProcessId, InitiatingProcessFileName
| where ReconCommandCount >= 3
| project FirstSeen, LastSeen, DeviceName, DeviceId, AccountName, InitiatingProcessFileName, InitiatingProcessId, ReconCommandCount, Commands
```

**Tuning notes:** Monitoring/inventory agents and login MOTD scripts generate similar bursts - allowlist their service accounts and parent processes. Tighten by requiring the session to also include a download or chmod command (correlate with the Mirai dropper rule) or by restricting to internet-facing hosts.
