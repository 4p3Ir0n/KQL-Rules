## 1) PowerShell Dynamic Module Invocation via ExportedCommands Array Index (Command Line)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** Faithful translation of Sigma rule 0c3ebe9f-df09-4e00-be0f-73d4ca8d62f6: detects powershell.exe/pwsh.exe launched with obfuscated command lines that enumerate Microsoft.PowerShell.Utility exported commands and invoke cmdlets indirectly by array index to evade string-based detection of Invoke-Expression / Invoke-RestMethod.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe", "pwsh.exe") or ProcessVersionInfoOriginalFileName in~ ("powershell.exe", "pwsh.dll")
| where ProcessCommandLine has_any ("Get-Module ", "gmo ")
| where ProcessCommandLine contains "ListAvailable"
    and ProcessCommandLine contains "Microsoft.PowerShell.Utility"
    and ProcessCommandLine contains "ExportedCommands"
    and ProcessCommandLine contains "Values"
| where ProcessCommandLine contains "["
| project Timestamp, DeviceId, DeviceName, AccountDomain, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** The Sigma '[*]' is a wildcard meaning any bracketed index; the KQL uses 'contains "["' which is permissive — tighten with `matches regex @"\[\s*\d+\s*\]"` if noisy. Legitimate admin/automation scripts rarely combine all four tokens; if a specific DevOps tool triggers, allowlist by InitiatingProcessFileName or signed script path.ature

## 2) Obfuscated PowerShell Script Block Enumerating ExportedCommands by Index

**Tactic:** Execution  
**ATT&CK:** T1027.010  
**Severity:** High  
**Purpose:** Translation of Sigma rule 4ff4ad3e-9fb5-4a70-9962-d6ea58090318 to script-block telemetry: detects obfuscated scripts that resolve cmdlets dynamically from the Microsoft.PowerShell.Utility module's ExportedCommands collection by array index, a common AMSI/string-detection evasion used by loaders.

```kusto
DeviceEvents
| where Timestamp > ago(1d)
| where ActionType in ("PowerShellCommand", "ScriptContent", "AmsiScriptDetection")
| extend Script = tostring(AdditionalFields)
| where Script has_any ("Get-Module ", "gmo ")
| where Script contains "ListAvailable"
    and Script contains "Microsoft.PowerShell.Utility"
    and Script contains "ExportedCommands"
    and Script contains "Values"
| where Script contains "["
| project Timestamp, DeviceId, DeviceName, ActionType, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, AdditionalFields, ReportId
```

**Tuning notes:** Requires Script Block Logging / Defender script telemetry ingestion; AdditionalFields field names vary by sensor version, adapt extraction (e.g. parse_json(AdditionalFields).Command). If script block content is not available in DeviceEvents in your tenant, run the equivalent against the process-creation variant instead.

## 3) ClickFix / FakeCaptcha: Clipboard-Pasted Run Dialog Command Execution

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** Detects the ClickFix / FakeCaptcha social-engineering chain used by ClearFake and 'Unknown Loader' families, where the victim pastes an attacker-supplied command into the Windows Run dialog, spawning powershell/mshta/curl from explorer.exe with encoded or remote-fetch payload markers.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","cmd.exe","curl.exe","wscript.exe","cscript.exe","msiexec.exe","conhost.exe")
| where ProcessCommandLine has_any ("-enc","-EncodedCommand","FromBase64String","IEX","Invoke-Expression","Invoke-RestMethod","iwr ","curl ","DownloadString","DownloadFile","http://","https://","\\\\","webdav","Verification","captcha","I am not a robot","# \u2713")
| where not(ProcessCommandLine has_any ("Get-Help","Microsoft.Windows.Shell"))
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Explorer-spawned shells are common for admins; baseline per-user. Highest fidelity signals are '-enc', 'FromBase64String', and UNC/WebDAV paths. Consider joining to DeviceEvents RunMRU registry writes (HKCU\\...\\RunMRU) for confirmed Run-dialog origin, and lower severity for interactive admin workstations.

## 4) .NET LOLBin Abuse (InstallUtil / aspnet_compiler / MSBuild) Spawned by Script Host

**Tactic:** DefenseEvasion  
**ATT&CK:** T1218.004  
**Severity:** High  
**Purpose:** AsyncRAT and related .NET RATs frequently inject or execute via trusted .NET utilities started by a script interpreter or from a user-writable directory, evading application control and signature detection.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("InstallUtil.exe","aspnet_compiler.exe","MSBuild.exe","RegAsm.exe","RegSvcs.exe","jsc.exe","csc.exe")
| where InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","cmd.exe","wscript.exe","cscript.exe","mshta.exe","explorer.exe","winword.exe","excel.exe","outlook.exe")
    or ProcessCommandLine has_any (@"\AppData\", @"\Temp\", @"\ProgramData\", @"\Users\Public\")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
```

**Tuning notes:** Developer workstations and CI agents run MSBuild/csc legitimately — scope out build servers and developer device groups, or exclude when parent is devenv.exe/dotnet.exe. InstallUtil and aspnet_compiler executions are rare in most enterprises and can be alerted on with minimal filtering.

## 5) GitHub/Developer-Platform Used as C2 Channel by Non-Browser Process

**Tactic:** CommandAndControl  
**ATT&CK:** T1102  
**Severity:** Medium  
**Purpose:** The Blinder Tunnel campaign (Iran-nexus, fake Dubai Airports recruitment lures) uses GitHub for command-and-control. Detects non-browser, non-developer processes making connections to GitHub/raw content endpoints, especially from user-writable paths.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemoteUrl has_any ("github.com","raw.githubusercontent.com","api.github.com","gist.githubusercontent.com","objects.githubusercontent.com")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","git.exe","code.exe","devenv.exe","dotnet.exe","gh.exe","python.exe","node.exe","msedgewebview2.exe")
| where InitiatingProcessFolderPath has_any (@"\AppData\", @"\Temp\", @"\ProgramData\", @"\Users\Public\", @"\Downloads\")
    or InitiatingProcessFileName in~ ("powershell.exe","pwsh.exe","mshta.exe","rundll32.exe","regsvr32.exe","wscript.exe","cscript.exe","curl.exe")
| summarize ConnCount=count(), FirstSeen=min(Timestamp), LastSeen=max(Timestamp), Urls=make_set(RemoteUrl, 20), RemoteIPs=make_set(RemoteIP, 10) by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceName, DeviceId, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ConnCount, Urls, RemoteIPs
```

**Tuning notes:** Expand the browser/dev-tool exclusion list to cover internally approved tooling and package managers (pip, npm, nuget, choco, winget). Periodic beaconing (regular interval, low byte count) to api.github.com from a single unsigned binary is the highest-confidence pattern — consider adding interval analysis.

## 6) Executable or Archive Payload Launched from Email/Download Path with Recruitment-Themed Name

**Tactic:** InitialAccess  
**ATT&CK:** T1566.001  
**Severity:** Medium  
**Purpose:** Blinder Tunnel delivers malware via fake recruitment lures (e.g., Dubai Airports job offers). Detects execution of files from download/attachment directories whose names use job/CV/recruitment themes or double extensions, a durable lure-delivery behavior.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FolderPath has_any (@"\Downloads\", @"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\Users\Public\", @"\Content.Outlook\", @"\INetCache\")
| where FileName endswith ".exe" or FileName endswith ".scr" or FileName endswith ".js" or FileName endswith ".vbs" or FileName endswith ".hta" or FileName endswith ".lnk"
| where FileName has_any ("cv","resume","job","career","recruit","vacancy","offer","airport","application","salary","contract","invoice")
    or FileName matches regex @"\.(pdf|doc|docx|xls|xlsx|jpg|png)\s*\.(exe|scr|js|vbs|hta|lnk)$"
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** The keyword list is lure-specific and will drift; keep it as a tunable parameter and prioritize the double-extension regex, which is campaign-agnostic. Exclude HR/recruiting-team devices and known installer names. Enrich by joining SHA256 to EmailAttachmentInfo to confirm email delivery.

## 7) Linux/IoT Shell Dropper Chain: Remote Download Piped to Shell (Mirai/Gafgyt Pattern)

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** Medium  
**Purpose:** Mirai, Gafgyt, HailBot and related IoT botnets propagate by executing a staged shell script that curls/wgets architecture-specific binaries (ARM/MIPS) into /tmp or /dev/shm, chmods them and executes. Detects the loader behavior on Defender for Endpoint Linux hosts rather than the rotating C2 IPs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("sh","bash","dash","busybox","wget","curl","tftp","ftpget","chmod")
| where ProcessCommandLine has_any ("wget","curl","tftp","ftpget")
    and ProcessCommandLine has_any ("/tmp","/dev/shm","/var/tmp","/var/run","-O-","| sh","|sh","| bash","chmod +x","chmod 777")
| where ProcessCommandLine has_any ("http://","https://","ftp://","tftp")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Applies to onboarded Linux servers/containers. Package managers, cloud-init and CI/CD bootstrap scripts use curl-pipe-to-shell legitimately — allowlist by InitiatingProcessFileName (cloud-init, ansible, apt) and by known build hosts. Arch-suffix binary names (arm7, mips, x86_32) in the command line are a strong Mirai-specific escalation signal.
