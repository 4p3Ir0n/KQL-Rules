## 1) ClickFix / ClearFake: Suspicious command pasted into the Windows Run dialog (RunMRU)

**Tactic:** Execution  
**ATT&CK:** T1204.004 - User Execution: Malicious Copy and Paste  
**Severity:** High  
**Purpose:** ClearFake and IClickFix lure victims with a fake CAPTCHA / 'fix it' page that instructs them to press Win+R and paste an attacker-supplied command. The pasted string is recorded in HKCU\...\Explorer\RunMRU, giving a very high-fidelity, durable signal that is independent of the rotating delivery domains.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet", "RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| where isnotempty(RegistryValueData)
| where RegistryValueData has_any ("powershell", "pwsh", "mshta", "curl ", "certutil", "bitsadmin", "msiexec", "rundll32", "wscript", "cscript", "conhost", "forfiles", "cmd /c", "cmd.exe /c", "/c start", "iwr ", "irm ", "iex", "-enc", "-e ", "FromBase64String", "http://", "https://", "\\\\")
    or RegistryValueData matches regex @"[\u2705\u2714\u2611]"
| extend PastedCommand = tostring(split(RegistryValueData, "\\1")[0])
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, PastedCommand, InitiatingProcessFileName, ReportId
```

**Tuning notes:** RunMRU normally contains short app names (cmd, mmc, \\fileserver\share). Allowlist admin/helpdesk workstations and known internal UNC paths by RegistryValueData prefix or by InitiatingProcessAccountName. The regex for check-mark/emoji characters catches the 'verification ✅' padding used to hide the real command off-screen — remove it if your estate produces unicode noise.

## 2) ClickFix lineage: explorer.exe directly spawning a script host with remote-download arguments

**Tactic:** Execution  
**ATT&CK:** T1059.001 - Command and Scripting Interpreter: PowerShell  
**Severity:** High  
**Purpose:** After the victim pastes the ClickFix command, the interpreter is launched as a direct child of explorer.exe (Run dialog) rather than from a shell or scheduled task. Combining that lineage with download/execute arguments catches ClearFake/IClickFix stage-1 regardless of which domain is serving the payload.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe", "pwsh.exe", "mshta.exe", "cmd.exe", "wscript.exe", "cscript.exe", "curl.exe", "certutil.exe", "bitsadmin.exe", "rundll32.exe", "msiexec.exe", "conhost.exe")
| where ProcessCommandLine has_any ("http://", "https://", "iwr", "irm", "Invoke-WebRequest", "Invoke-RestMethod", "DownloadString", "DownloadFile", "WebClient", "-enc", "-ec ", "-EncodedCommand", "FromBase64String", "-w hidden", "-windowstyle hidden", "-nop", "-noprofile", "Start-BitsTransfer", "mshta", ".hta")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, SHA256, ReportId
```

**Tuning notes:** Users legitimately launch powershell.exe from the Run box, so the value is in the argument set, not the lineage alone. Allowlist internal management URLs/hosts and signed IT automation scripts. Consider raising severity when ProcessCommandLine contains both a URL and an execution primitive (iex / Start-Process / FromBase64String).

## 3) Fileless download-and-execute PowerShell one-liner (ClearFake / EtherHiding stage-2)

**Tactic:** Execution  
**ATT&CK:** T1059.001 - Command and Scripting Interpreter: PowerShell  
**Severity:** High  
**Purpose:** ClearFake retrieves its next-stage loader from blockchain smart contracts (EtherHiding) and executes it in memory. The resulting command lines consistently combine a web fetch cmdlet with an in-memory execution primitive and hidden-window / bypass flags.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("powershell.exe", "pwsh.exe")
| extend Cmd = tolower(ProcessCommandLine)
| where Cmd has_any ("downloadstring", "downloaddata", "downloadfile", "invoke-webrequest", "invoke-restmethod", "net.webclient", "start-bitstransfer", "iwr ", "irm ", "curl ", "wget ")
| where Cmd has_any ("iex", "invoke-expression", "| i`ex", "frombase64string", "[reflection.assembly]::load", "start-process", "-command &", "invoke-command")
    or Cmd has_any ("-enc", "-encodedcommand")
| where Cmd has_any ("-w hidden", "-windowstyle hidden", "-nop", "-noprofile", "-ep bypass", "-executionpolicy bypass", "-noni", "-noninteractive") or InitiatingProcessFileName in~ ("explorer.exe", "mshta.exe", "wscript.exe", "cscript.exe", "winword.exe", "excel.exe", "chrome.exe", "msedge.exe", "firefox.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Software distribution, Chocolatey/winget bootstrap scripts and some vendor installers match this pattern. Allowlist by InitiatingProcessFolderPath (e.g. SCCM/Intune agent paths) and by known internal download hosts extracted from the command line. Tightening to parents in the browser/explorer set reduces volume substantially.

## 4) Vidar-style infostealer: non-browser process reading browser credential and cookie stores

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003 - Credentials from Web Browsers  
**Severity:** High  
**Purpose:** Vidar (and the stealers commonly dropped by ClickFix chains) harvest 'Login Data', 'Web Data', cookie and token databases directly from browser profile folders. Detecting a non-browser process touching these files is a durable behavioural signal that survives hash and C2 rotation.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FileName in~ ("Login Data", "Login Data For Account", "Web Data", "Cookies", "Network Action Predictor", "key4.db", "key3.db", "logins.json", "cookies.sqlite", "places.sqlite", "formhistory.sqlite", "Local State")
| where FolderPath has_any (@"\User Data\", @"\Mozilla\Firefox\Profiles\", @"\Opera Software\", @"\BraveSoftware\", @"\Chromium\")
| where not(InitiatingProcessFolderPath has_any (@"\Google\Chrome\", @"\Microsoft\Edge\", @"\Mozilla Firefox\", @"\BraveSoftware\", @"\Opera\", @"\Vivaldi\"))
| where InitiatingProcessFileName !in~ ("chrome.exe", "msedge.exe", "firefox.exe", "brave.exe", "opera.exe", "vivaldi.exe", "msedgewebview2.exe", "backup.exe", "MsMpEng.exe")
| summarize FilesTouched = make_set(FileName, 20), FolderSample = any(FolderPath), Hits = count(), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName
| where Hits >= 2 or array_length(FilesTouched) >= 2
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, FilesTouched, FolderSample, Hits
```

**Tuning notes:** Backup agents, endpoint DLP, browser-migration tools, profile-sync and forensic/IR tooling read these files legitimately — allowlist them by InitiatingProcessSHA256 or folder path. Raise priority when InitiatingProcessFolderPath is under \Users\*\AppData\Local\Temp, \Downloads or \ProgramData.

## 5) Infostealer support-DLL staging in user temp directories

**Tactic:** Collection  
**ATT&CK:** T1005 - Data from Local System  
**Severity:** Medium  
**Purpose:** Vidar and related C/C++ stealers drop legitimate Mozilla/SQLite helper DLLs (freebl3, mozglue, nss3, softokn3, sqlite3, msvcp140, vcruntime140) next to themselves in a temp/ProgramData working directory in order to decrypt browser secrets offline. A burst of these specific DLL writes outside an installer path is a strong stealer indicator.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileModified")
| where FileName in~ ("freebl3.dll", "mozglue.dll", "nss3.dll", "softokn3.dll", "nssdbm3.dll", "sqlite3.dll", "msvcp140.dll", "vcruntime140.dll")
| where FolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\ProgramData\", @"\Users\Public\", @"\Downloads\")
| summarize DllSet = make_set(FileName, 10), Paths = make_set(FolderPath, 5), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName
| where array_length(DllSet) >= 3
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, DllSet, Paths
```

**Tuning notes:** Legitimate installers and self-extracting archives (Firefox/Thunderbird updates, some Electron apps, vendor setup.exe) also unpack these DLLs to temp — allowlist by InitiatingProcessSHA256/signer. Lower the array_length threshold to 2 for a broader hunt, raise to 4 to cut noise.

## 6) Loader self-deletion via timeout/ping-delayed cmd delete chain

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070.004 - Indicator Removal: File Deletion  
**Severity:** Medium  
**Purpose:** Vidar and many ClickFix-delivered loaders clean up after exfiltration with a cmd.exe one-liner that sleeps (timeout/ping/choice) then deletes the payload and its working directory. The pattern is durable across builds and independent of hashes.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "cmd.exe"
| extend Cmd = tolower(ProcessCommandLine)
| where Cmd has_any ("timeout ", "ping ", "choice /", "waitfor ")
| where Cmd has_any (" del ", "del /f", "del /q", "erase ", "rmdir ", "rd /s")
| where Cmd has_any ("&", "&&", "|")
| where Cmd has_any (@"\temp\", @"\appdata\", @"\programdata\", @"\users\public\", @"\downloads\", "%temp%", "%appdata%")
| project Timestamp, DeviceId, DeviceName, AccountName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, ReportId
```

**Tuning notes:** Some legitimate installers and uninstallers use the same self-delete idiom; allowlist by InitiatingProcessSHA256/signer. Pivot on the InitiatingProcess to see whether it previously touched browser credential stores or made external connections — that combination is near-certain stealer activity.

## 7) Binary executing from user temp/ProgramData making outbound web C2 connections

**Tactic:** CommandAndControl  
**ATT&CK:** T1071.001 - Application Layer Protocol: Web Protocols  
**Severity:** Medium  
**Purpose:** Stealer and loader payloads delivered by ClearFake/IClickFix execute from AppData\Local\Temp, ProgramData or Users\Public and immediately beacon out over 80/443/8080 (including Vidar's dead-drop resolver profile lookups). Anchoring on execution location plus external egress catches the family without relying on its rotating C2 domains.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType == "ConnectionSuccess"
| where RemotePort in (80, 443, 8080, 8443, 2095, 2083)
| where InitiatingProcessFolderPath has_any (@"\appdata\local\temp\", @"\appdata\roaming\", @"\programdata\", @"\users\public\", @"\downloads\", @"\windows\temp\")
| where InitiatingProcessFileName !in~ ("msedge.exe", "chrome.exe", "firefox.exe", "teams.exe", "onedrive.exe", "setup.exe", "msiexec.exe")
| where not(ipv4_is_private(RemoteIP))
| summarize Connections = count(), RemoteIPs = make_set(RemoteIP, 15), RemoteUrls = make_set(RemoteUrl, 15), Ports = make_set(RemotePort, 5), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, Connections, Ports, RemoteIPs, RemoteUrls
```

**Tuning notes:** Installers, updaters and portable apps run from Temp/Downloads legitimately — allowlist by InitiatingProcessSHA256 or code-signing. Enrich by joining to DeviceFileEvents for recently-downloaded (MotW) files, and add a prevalence filter (first-seen-in-org binary) to sharpen results.

## 8) Mirai/Gafgyt loader: shell fetch-chmod-execute chain on Linux endpoints

**Tactic:** Execution  
**ATT&CK:** T1059.004 - Command and Scripting Interpreter: Unix Shell  
**Severity:** High  
**Purpose:** Mirai and Gafgyt variants propagate via a one-line dropper that uses wget/curl/tftp to pull architecture-specific ELF payloads into a writable directory, chmod 777s them, runs them and deletes the files. This lineage detection works for all ARM/MIPS/x86 variants regardless of the rotating payload-hosting IPs.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("sh", "bash", "dash", "ash", "busybox", "wget", "curl", "tftp", "ftpget", "chmod")
| extend Cmd = tolower(ProcessCommandLine)
| where Cmd has_any ("wget", "curl", "tftp", "ftpget", "busybox")
| where Cmd has_any ("chmod 777", "chmod +x", "chmod 755", "/bin/busybox")
    or Cmd matches regex @"(wget|curl|tftp)[^|;&]*(;|&&|\|\|)\s*(chmod|\./)"
| where Cmd has_any ("/tmp/", "/dev/shm", "/var/run", "/var/tmp", "/mnt/", "./")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, SHA256, ReportId
```

**Tuning notes:** Container build steps, CI runners and config-management (Ansible/Chef/Puppet) scripts produce similar chains — scope out build hosts by DeviceId/DeviceGroup or allowlist known artifact repository hostnames appearing in the command line. On appliances/IoT, any match is almost always malicious.

## 9) Mirai-style internal scanning / telnet-SSH propagation fan-out

**Tactic:** Discovery  
**ATT&CK:** T1046 - Network Service Discovery  
**Severity:** Medium  
**Purpose:** Once installed, Mirai bots scan large address ranges on telnet (23/2323), SSH (22) and common IoT management ports (5555, 7547, 37215) attempting default-credential logins. High distinct-destination fan-out from a single host on those ports is a reliable post-infection behaviour.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where RemotePort in (22, 23, 80, 2323, 5555, 7547, 8080, 37215, 52869)
| where ActionType in ("ConnectionAttempt", "ConnectionSuccess", "ConnectionFailed")
| summarize DistinctTargets = dcount(RemoteIP), PortSet = make_set(RemotePort, 10), SampleTargets = make_set(RemoteIP, 20), Attempts = count()
    by bin(Timestamp, 1h), DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName
| where DistinctTargets >= 100
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, DistinctTargets, Attempts, PortSet, SampleTargets
```

**Tuning notes:** Exclude sanctioned vulnerability scanners, NAC and asset-discovery servers by DeviceId or InitiatingProcessFileName. Tune DistinctTargets (100/hour) to your environment size; on flat OT/IoT segments a threshold of 50 may be appropriate. Restricting to telnet ports only (23/2323) yields the highest fidelity Mirai signal.
