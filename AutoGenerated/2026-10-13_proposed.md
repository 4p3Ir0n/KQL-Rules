## 1) Double-Extension File Dropped (e.g. invoice.pdf.exe)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1036.007  
**Severity:** Medium  
**Purpose:** Translates Sigma rule b4926b47: detects files written with a deceptive double extension (document/image extension followed by an executable or archive extension), a common masquerading technique that abuses Windows hiding known extensions.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileRenamed","FileModified")
| extend FN = tolower(FileName)
| where (FN endswith ".exe" or FN endswith ".iso" or FN endswith ".rar" or FN endswith ".svg" or FN endswith ".zip")
| where FN has_any (".doc.",".docx.",".gif.",".jpeg.",".jpg.",".mp3.",".mp4.",".pdf.",".png.",".ppt.",".pptx.",".rtf.",".svg.",".txt.",".xls.",".xlsx.")
    or FN endswith ".rar.exe" or FN endswith ".zip.exe"
| where not(FN endswith ".svg.svg")
| where not(FolderPath startswith "/usr/share/icons/")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, FileSize, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** Backup/versioning tools and some media pipelines legitimately produce names like 'report.pdf.zip' — allowlist specific InitiatingProcessFileName values (backup agents, archivers invoked by IT) or folder paths. Prioritize drops under %TEMP%, Downloads, %AppData%, and files written by browsers, mail clients, or archive utilities.

## 2) Vidar-Style Stealer: Mass Staging of Browser Crypto DLLs in User-Writable Paths

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003  
**Severity:** High  
**Purpose:** Vidar and related infostealers drop legitimate NSS/SQLite/VC runtime DLLs (freebl3, mozglue, nss3, softokn3, sqlite3, msvcp140, vcruntime140) into %TEMP%/ProgramData to decrypt browser credential stores offline. Detects a single non-installer process writing several of these DLLs in a short window.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated","FileModified")
| where FileName in~ ("freebl3.dll","mozglue.dll","nss3.dll","softokn3.dll","nssdbm3.dll","sqlite3.dll","msvcp140.dll","vcruntime140.dll")
| where FolderPath has_any (@"\AppData\Local\Temp", @"\AppData\Roaming", @"\ProgramData", @"\Users\Public", @"\Windows\Temp")
| summarize DllCount = dcount(FileName), Dlls = make_set(FileName, 10), Paths = make_set(FolderPath, 5), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine, InitiatingProcessAccountName, bin(Timestamp, 30m)
| where DllCount >= 3
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, DllCount, Dlls, Paths
```

**Tuning notes:** Software installers and self-extracting updaters (Firefox/Thunderbird updaters, Electron app installers, vendor setup.exe in %TEMP%) can legitimately stage these DLLs — allowlist by InitiatingProcessSHA256/signer or by known installer names. Lower the DllCount threshold to 2 for high-sensitivity environments, and correlate with the browser-credential-file-access detection for confirmation.

## 3) Browser Credential and Cookie Stores Read by Non-Browser Process

**Tactic:** CredentialAccess  
**ATT&CK:** T1555.003  
**Severity:** High  
**Purpose:** Core stealer TTP (Vidar, Lumma, HijackLoader payloads): a process that is not the owning browser touches Login Data, Web Data, key4.db, logins.json, or cookie databases across multiple browser profiles.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where FileName in~ ("Login Data","Login Data For Account","Web Data","Cookies","key4.db","key3.db","logins.json","cookies.sqlite","places.sqlite","Local State")
| where FolderPath has_any (@"\Google\Chrome", @"\Microsoft\Edge", @"\Mozilla\Firefox", @"\BraveSoftware", @"\Opera", @"\Vivaldi", @"\Chromium", @"\Yandex")
| where InitiatingProcessFileName !in~ ("chrome.exe","msedge.exe","firefox.exe","brave.exe","opera.exe","vivaldi.exe","yandex.exe","chromium.exe","MsMpEng.exe","SearchIndexer.exe","backgroundTaskHost.exe")
| summarize TargetCount = dcount(strcat(FolderPath, FileName)), Targets = make_set(FileName, 12), Profiles = make_set(FolderPath, 10), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine, InitiatingProcessAccountName
| where TargetCount >= 3
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, TargetCount, Targets, Profiles
```

**Tuning notes:** Allowlist backup/sync agents, enterprise browser-migration tools, DLP/EDR scanners and password-manager importers by InitiatingProcessSHA256 or signer. Processes running from %TEMP%, %AppData%, or unsigned binaries should be treated as high confidence; raise TargetCount if your backup tooling is noisy.

## 4) Loader Self-Deletion via Timeout/Ping Chained to Del

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070.004  
**Severity:** Medium  
**Purpose:** Vidar, HijackLoader and similar loaders commonly clean up by spawning cmd.exe with a timeout/ping delay followed by deletion of their own executable from a user-writable directory.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe")
| extend CL = tolower(ProcessCommandLine)
| where CL has_any ("timeout ", "ping ", "choice /t", "start-sleep")
| where CL has_any ("del ", "erase ", "rmdir ", "remove-item")
| where CL has_any ("&", "&&", ";", "|")
| where CL has_any (@"\appdata\local\temp", @"\appdata\roaming", @"\users\public", @"\programdata", @"\windows\temp", @"\downloads")
| where InitiatingProcessFolderPath has_any (@"\AppData\", @"\ProgramData\", @"\Users\Public\", @"\Windows\Temp\", @"\Downloads\") or InitiatingProcessFileName in~ ("wscript.exe","cscript.exe","mshta.exe","rundll32.exe","regsvr32.exe")
| project Timestamp, DeviceId, DeviceName, AccountName, ProcessCommandLine, FileName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Some legitimate installers and uninstallers use the same delete-after-delay trick; allowlist signed installer SHA256s and known software-deployment parents. Confidence increases sharply when the deleted path equals InitiatingProcessFolderPath (self-deletion) — add that comparison if your data quality supports it.

## 5) ClickFix / FakeCaptcha: Attacker Command Pasted into Windows Run Dialog

**Tactic:** Execution  
**ATT&CK:** T1204.004  
**Severity:** High  
**Purpose:** ClearFake/FakeCaptcha ('ClickFix') lures instruct victims to paste a command into the Run dialog, which leaves a RunMRU registry value. Detects script-host or download commands recorded in Explorer's RunMRU key.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has @"\Explorer\RunMRU"
| extend Cmd = tolower(tostring(RegistryValueData))
| where Cmd has_any ("powershell","pwsh","mshta","curl ","certutil","bitsadmin","wscript","cscript","rundll32","regsvr32","msiexec","conhost","-enc","frombase64string","iex ","invoke-expression","invoke-webrequest","irm ","http://","https://","\\\\")
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Administrators and helpdesk staff legitimately paste UNC paths and management commands into Run; allowlist admin workstations/accounts or drop the '\\\\' and 'msiexec' keywords if noisy. Pair with a follow-up hunt for explorer.exe spawning powershell/mshta within minutes on the same device for confirmation.

## 6) Explorer Spawning Script Host with Remote Download (ClickFix Follow-On)

**Tactic:** Execution  
**ATT&CK:** T1059.001  
**Severity:** High  
**Purpose:** After a ClickFix/FakeCaptcha paste, explorer.exe directly spawns powershell/mshta/curl that retrieves and executes a remote payload (HijackLoader, Vidar, CoinMiner). Detects user-initiated download-and-run chains from the Run dialog.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName =~ "explorer.exe"
| where FileName in~ ("powershell.exe","pwsh.exe","mshta.exe","curl.exe","certutil.exe","bitsadmin.exe","wscript.exe","cscript.exe","rundll32.exe","regsvr32.exe","msiexec.exe")
| extend CL = tolower(ProcessCommandLine)
| where CL has_any ("http://","https://","-enc","-e ","frombase64string","invoke-expression","iex ","invoke-webrequest","irm ","iwr ","downloadstring","downloadfile","webclient","-w hidden","-windowstyle hidden","javascript:","vbscript:","urlmon")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, ProcessCommandLine, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, ReportId
```

**Tuning notes:** Power users launching scripts from Explorer can trigger this; allowlist specific signed internal scripts/URLs and known admin accounts. Entries resolving to *.workers.dev, pastebin-like hosts, or raw IPs should be escalated immediately.

## 8) Mirai/Gafgyt-Style Download-and-Execute Shell Chain on Linux Devices

**Tactic:** Execution  
**ATT&CK:** T1059.004  
**Severity:** High  
**Purpose:** Mirai-family loaders use busybox/wget/curl/tftp to pull multi-architecture ELF binaries into world-writable directories, chmod them executable and run them in one shell command line.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| extend CL = tolower(ProcessCommandLine)
| where InitiatingProcessFileName in~ ("sh","bash","dash","ash","busybox","zsh") or FileName in~ ("sh","bash","dash","ash","busybox","wget","curl","tftp","ftpget","chmod")
| where CL has_any ("wget ","curl ","tftp ","ftpget ","busybox wget","busybox tftp")
| where CL has_any ("chmod 777","chmod +x","chmod 755","./")
| where CL has_any ("/tmp/","/dev/shm/","/var/run/","/var/tmp/","/mnt/","/home/")
| where CL has_any (";","&&","|")
| project Timestamp, DeviceId, DeviceName, AccountName, FileName, FolderPath, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Container build steps, CI runners and config-management (Ansible/Chef) can match this pattern — allowlist those device groups or parent processes. Architecture-suffixed filenames (arm, arm7, mips, mipsel, x86, aarch64, .sh loaders) and binaries fetched from raw IPs are strong Mirai indicators; follow up on outbound DeviceNetworkEvents to high/uncommon ports from the spawned ELF.

## 9) Signed Binary Sideloading a DLL from a User-Writable Directory

**Tactic:** DefenseEvasion  
**ATT&CK:** T1574.001  
**Severity:** Medium  
**Purpose:** HijackLoader and similar loaders drop a legitimate signed EXE alongside a malicious DLL in %TEMP%/%AppData%/Public and sideload it. Detects image loads of DLLs from user-writable paths where the loading executable resides in the same non-standard directory.

```kusto
DeviceImageLoadEvents
| where Timestamp > ago(1d)
| where FolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| where InitiatingProcessFolderPath has_any (@"\AppData\Local\Temp\", @"\AppData\Roaming\", @"\Users\Public\", @"\ProgramData\", @"\Windows\Temp\", @"\Downloads\")
| extend DllDir = tolower(substring(FolderPath, 0, strlen(FolderPath) - strlen(FileName)))
| extend ExeDir = tolower(replace_string(InitiatingProcessFolderPath, InitiatingProcessFileName, ""))
| where DllDir == ExeDir
| where tolower(FileName) endswith ".dll"
| project Timestamp, DeviceId, DeviceName, InitiatingProcessAccountName, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessSHA256, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
```

**Tuning notes:** Portable apps, Electron/Teams-style updaters and installer bootstrappers legitimately load DLLs from their own temp directory — allowlist by InitiatingProcessSHA256/signer and by known updater names. Prioritize cases where the EXE is signed by a reputable vendor but the DLL is unsigned or recently written (join to DeviceFileEvents on SHA256 within the last hour).

## 10) High-Relevance Antivirus Detection Names (Hacktool, Mimikatz, Ransom, Webshell)

**Tactic:** Execution  
**ATT&CK:** T1588.001  
**Severity:** Medium  
**Purpose:** Defender equivalent of Sigma rule 78bc5783: surfaces antivirus detections whose threat names indicate offensive tooling, credential dumpers, webshells, C2 beacons or ransomware rather than generic PUA noise.

```kusto
DeviceEvents
| where Timestamp > ago(1d)
| where ActionType in ("AntivirusDetection","AntivirusDetectionBlocked","AntivirusMalwareBlocked","AntivirusMalwareActionFailed")
| extend AF = parse_json(tostring(AdditionalFields))
| extend ThreatName = tostring(coalesce(AF.ThreatName, AF.MalwareName, AF.Name)), WasRemediated = tostring(AF.WasRemediated)
| where isnotempty(ThreatName)
| where ThreatName has_any ("HackTool","HKTL","HTool","Mimikatz","mikatz","Metasploit","Meterpreter","Mpreter","Cobalt","COBEACON","Sliver","Nighthawk","Koadic","Impacket","PowerSploit","Lazagne","PWDump","PWCrack","DumpCreds","SharpDump","Seatbelt","Sbelt","Chopper","Webshell","Backdoor.ASP","Backdoor.JSP","Backdoor.PHP","Keylogger","Shellcode","Rozena","Swrort","Ransom","Filecoder","Phobos","TeslaCrypt","Tescrypt","Cryptor","CRYPTES","Potato","Adfind","FastReverseProxy","Exploit.Script.CVE","TurtleLoader","Splinter","Valyria")
| where not(ThreatName has_any ("Crack","Keygen","Anti-Ransomware","anti_ransomware_service","cyber-protect-service"))
| project Timestamp, DeviceId, DeviceName, ActionType, ThreatName, WasRemediated, FileName, FolderPath, SHA256, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessAccountName, ReportId
```

**Tuning notes:** AdditionalFields key names vary by sensor version — validate ThreatName extraction in your tenant and extend the coalesce list if empty. Security-team tooling on pentest/admin hosts will match (Mimikatz, Impacket); allowlist those device groups. Unremediated detections (WasRemediated == 'false') should be escalated first.
