## 1) Atlassian Java Application Server Spawning Shell or Recon Utility

**Tactic:** Execution  
**ATT&CK:** T1190  
**Severity:** High  
**Purpose:** Detects post-exploitation command execution following attacks against internet-facing Atlassian products (Confluence, Jira, Bitbucket, Bamboo, Crowd, Fisheye/Crucible) such as CVE-2026-21589, where web-root file exposure is typically chained into webshell drops or direct OS command execution.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("java.exe", "java", "tomcat9.exe", "tomcat10.exe", "catalina.sh")
| where InitiatingProcessFolderPath has_any ("atlassian", "confluence", "jira", "bitbucket", "bamboo", "crowd", "fisheye", "crucible")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "sh", "bash", "dash", "whoami.exe", "whoami", "net.exe", "net1.exe", "curl.exe", "curl", "wget", "certutil.exe", "bitsadmin.exe", "python3", "id", "uname")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, ReportId
| order by Timestamp desc
```

**Tuning notes:** Atlassian plugin installers, health-check scripts and backup jobs legitimately spawn shells; baseline per-server and allowlist known maintenance command lines (e.g. scheduled 'sh -c' backup wrappers). If your Atlassian install path is non-standard, replace the InitiatingProcessFolderPath keyword list with your actual install directory. Consider also pairing with DeviceFileEvents for new .jsp/.jspx files under the web root.

## 2) Ahsay AhsayCBS Backup Server Spawning OS Commands

**Tactic:** Execution  
**ATT&CK:** T1059  
**Severity:** High  
**Purpose:** Detects command injection exploitation of Ahsay AhsayCBS (CVE-2026-105134 / chained CVE-2026-105133) by alerting when the AhsayCBS Java/Tomcat service process spawns interpreters or download utilities.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFolderPath has_any ("ahsay", "AhsayCBS", "cbs\\", "/cbs/")
     or InitiatingProcessCommandLine has_any ("AhsayCBS", "ahsaycbs", "rps/api")
| where FileName in~ ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe", "certutil.exe", "bitsadmin.exe", "curl.exe", "sh", "bash", "curl", "wget", "python3", "perl")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ReportId
| order by Timestamp desc
```

**Tuning notes:** AhsayCBS legitimately invokes shell helpers for backup/restore and replication tasks — baseline for 7 days and allowlist recurring, parameter-stable command lines. Tighten by requiring suspicious arguments (-enc, -nop, 'IEX', '/c echo', pipes to bash) if volume is high.

## 3) Exchange PowerShell Cmdlet History Logs Deleted (Sigma translation)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070  
**Severity:** High  
**Purpose:** Translation of Sigma rule a55349d8 — detects deletion of Exchange PowerShell cmdlet infrastructure logs, an anti-forensics action used to destroy evidence of administrative/attacker cmdlet activity on Exchange servers.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType == "FileDeleted"
| where FolderPath has "\\Logging\\CmdletInfra\\LocalPowerShell\\Cmdlet\\"
| where FolderPath has "_Cmdlet_" or FileName has "_Cmdlet_"
| project Timestamp, DeviceName, DeviceId, FileName, FolderPath, InitiatingProcessAccountDomain, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Exchange log rotation/cleanup scripts and disk-space maintenance tooling delete these files legitimately — allowlist specific service accounts and the scheduled task/initiating process that performs rotation. Alert strongly when the deleting process is cmd.exe/powershell.exe run interactively or by a non-service account, or when many files are deleted in a short window (add a summarize by InitiatingProcessId with a count threshold).

## 4) EVTX File Created in Uncommon Location (Sigma translation)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070.001  
**Severity:** Medium  
**Purpose:** Translation of Sigma rule 65236ec7 — detects creation of .evtx files outside the standard winevt\Logs directory, indicating event log export/staging for exfiltration or tampering with default log locations to evade monitoring.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileRenamed", "FileModified")
| where FileName endswith ".evtx"
| where not (FolderPath startswith "C:\\Windows\\System32\\winevt\\Logs\\")
| where not (FolderPath startswith "C:\\ProgramData\\Microsoft\\Windows\\Containers\\BaseImages\\" and FolderPath has "\\Windows\\System32\\winevt\\Logs\\")
| project Timestamp, DeviceName, DeviceId, ActionType, FileName, FolderPath, FileSize, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Backup agents, DFIR/collection tooling (wevtutil epl, KAPE, Velociraptor), and vendor support bundles legitimately write .evtx elsewhere — allowlist those InitiatingProcessFileName/FolderPath values and known collection share paths. Prioritize events where the destination is Temp, Public, Downloads, or a removable/network drive, or where the initiating process is powershell.exe/wevtutil.exe launched interactively.

## 5) Nslookup TXT Record Download Cradle Spawned by PowerShell (Sigma translation)

**Tactic:** CommandAndControl  
**ATT&CK:** T1071.004  
**Severity:** High  
**Purpose:** Translation of Sigma rule 1b3b01c7 — detects PowerShell invoking nslookup to query TXT records, a DNS-based download cradle used to retrieve payloads or C2 instructions encoded in DNS TXT responses.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName =~ "nslookup.exe" or ProcessVersionInfoOriginalFileName =~ "nslookup.exe"
| where InitiatingProcessFileName in~ ("powershell.exe", "pwsh.exe")
| where ProcessCommandLine has_any (" -q=txt ", " -querytype=txt", " -type=txt", "-q=txt ", "-type=txt ")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessParentFileName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Legitimate use is rare but occurs in DNS/mail administration scripts (SPF/DKIM/DMARC validation) — allowlist by the queried domain substring (e.g. your own domains, '_dmarc', 'selector._domainkey') or by known admin hosts/accounts. Also consider a variant watching for cmd.exe-parented nslookup TXT loops.

## 6) Linux Web Server or App Process Spawning Shell (Web Shell Activity)

**Tactic:** Execution  
**ATT&CK:** T1505.003  
**Severity:** High  
**Purpose:** Detects web shell command execution on Linux infrastructure as described in the Unit 42 AI-powered espionage campaign: nginx/apache/php-fpm/tomcat worker processes spawning shells, interpreters, or recon/credential-access utilities.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where InitiatingProcessFileName in~ ("nginx", "httpd", "apache2", "php-fpm", "php", "php7.4", "php8.1", "java", "tomcat", "node", "uwsgi", "gunicorn", "lighttpd", "caddy")
| where FileName in~ ("sh", "bash", "dash", "zsh", "ksh", "python", "python3", "perl", "ruby", "curl", "wget", "nc", "ncat", "socat", "whoami", "id", "uname", "ip", "ifconfig", "crontab", "chmod", "base64", "openssl", "ssh", "scp")
| project Timestamp, DeviceName, DeviceId, AccountName, FileName, ProcessCommandLine, FolderPath, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, InitiatingProcessAccountName, ReportId
| order by Timestamp desc
```

**Tuning notes:** Some web apps legitimately shell out (image processing via ImageMagick wrappers, deployment hooks, health checks). Baseline per application server and allowlist stable command lines. Raise severity when the child command line contains reverse-shell patterns ('/dev/tcp/', 'bash -i', 'nc -e', 'python -c', 'base64 -d | sh') or touches /etc/shadow, ~/.ssh, or cloud credential files.
