## 1) Suspicious Double Extension File Dropped (Sigma: b4926b47)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1036.007  
**Severity:** Medium  
**Purpose:** Detects files written to disk with a deceptive double extension (e.g. invoice.pdf.exe, photo.jpg.vbs), a common masquerading technique that abuses Windows hiding known file extensions by default.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileRenamed", "FileModified")
| where isnotempty(FileName)
| where FileName matches regex @"(?i)\.(docx?|gif|jpe?g|mp3|mp4|pdf|png|pptx?|rtf|svg|txt|xlsx?)\.(bat|exe|iso|rar|svg|vbe|vbs|zip)$"
    or FileName endswith ".rar.exe"
    or FileName endswith ".zip.exe"
| where not(FileName endswith ".svg.svg" or FileName endswith ".png.svg" or FileName endswith ".jpg.svg" or FileName endswith ".jpeg.svg")
| where not(FolderPath startswith "/usr/share/icons/")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, SHA256, FileSize, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine
```

**Tuning notes:** Expect noise from archive/installer tooling that names output like name.zip.exe (self-extracting archives) and from backup products. Allowlist by InitiatingProcessFileName (e.g. 7zFM.exe, WinRAR.exe, setup bundlers) and by signed-publisher folders. Highest fidelity when the writer is a browser, mail client, or archive extractor and the drop path is Downloads/Temp/%AppData%.

## 2) Exchange PowerShell Cmdlet History Log Deleted (Sigma: a55349d8)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070  
**Severity:** High  
**Purpose:** Detects deletion of Exchange CmdletInfra LocalPowerShell cmdlet history logs, a common anti-forensics step after an attacker runs Exchange management cmdlets (mailbox export, transport rule abuse) on a compromised Exchange server.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType == "FileDeleted"
| where FolderPath has @"\Logging\CmdletInfra\LocalPowerShell\Cmdlet\"
| where FolderPath has "_Cmdlet_" or FileName has "_Cmdlet_"
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, InitiatingProcessAccountDomain, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName
```

**Tuning notes:** Exchange's own log housekeeping (Microsoft.Exchange.Diagnostics.Service.exe / DiagnosticsAggregation) and approved log-rotation or backup jobs will trigger this; allowlist those specific InitiatingProcessFolderPaths. Deletions initiated by cmd.exe, powershell.exe, explorer.exe, or any interactive user account should be treated as high priority. Scope to Exchange server device group to reduce volume.

## 3) EVTX File Created in Uncommon Location (Sigma: 65236ec7)

**Tactic:** DefenseEvasion  
**ATT&CK:** T1070.001  
**Severity:** Medium  
**Purpose:** Detects creation of .evtx event log files outside the standard winevt\Logs directory, which may indicate log tampering/relocation to evade monitoring, or staging of event logs for exfiltration and credential mining.

```kusto
DeviceFileEvents
| where Timestamp > ago(1d)
| where ActionType in ("FileCreated", "FileRenamed")
| where FileName endswith ".evtx"
| where not(FolderPath startswith @"C:\Windows\System32\winevt\Logs\")
| where not(FolderPath startswith @"C:\ProgramData\Microsoft\Windows\Containers\BaseImages\" and FolderPath has @"\Windows\System32\winevt\Logs\")
| project Timestamp, DeviceId, DeviceName, ActionType, FileName, FolderPath, FileSize, SHA256, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessParentFileName
```

**Tuning notes:** Backup/DR agents, SCCM/MDT, support-bundle collectors (MSDT, TSSv2), and admin troubleshooting via wevtutil epl / Get-WinEvent export are the main FPs — allowlist those initiating processes and known collection share paths. Prioritize drops into %TEMP%, %AppData%, C:\Users\Public, or web-accessible directories, and correlate with subsequent archive creation or outbound transfer.

## 4) Run Key or Startup Persistence Pointing to User-Writable Temp Path

**Tactic:** Persistence  
**ATT&CK:** T1547.001  
**Severity:** Medium  
**Purpose:** Detects Vidar/VShell-style persistence where an autorun registry value or startup folder entry references a binary or script in AppData, Temp, ProgramData, or Public — a durable behaviour that outlives the family's rotating indicators.

```kusto
DeviceRegistryEvents
| where Timestamp > ago(1d)
| where ActionType in ("RegistryValueSet","RegistryKeyCreated")
| where RegistryKey has_any (@"\CurrentVersion\Run", @"\CurrentVersion\RunOnce", @"\CurrentVersion\Explorer\Shell Folders", @"\Windows\CurrentVersion\Policies\Explorer\Run", @"\CurrentVersion\Winlogon")
| where RegistryValueData has_any ("\\AppData\\Local\\Temp\\","\\AppData\\Roaming\\","\\Users\\Public\\","\\ProgramData\\","\\Windows\\Temp\\","\\Downloads\\")
    or RegistryValueData has_any ("powershell","mshta","wscript","cscript","rundll32","regsvr32","curl ","FromBase64String")
| project Timestamp, DeviceId, DeviceName, ActionType, RegistryKey, RegistryValueName, RegistryValueData, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessParentFileName
```

**Tuning notes:** Some legitimate per-user apps (Teams, Slack, Zoom updaters, OneDrive) install into %LocalAppData% and will match — allowlist by RegistryValueName and the specific vendor folder. Treat values written by script hosts, rundll32, or freshly-created binaries as highest priority; enrich with the FileProfile of the referenced path.

## 5) Linux Mirai/VShell Implant: Payload Download to Tmp Followed by chmod and Execution

**Tactic:** Persistence  
**ATT&CK:** T1543.002  
**Severity:** High  
**Purpose:** Detects the canonical Mirai/Gafgyt and ELF backdoor (VShell) infection chain on Linux endpoints: wget/curl pulling a binary or dropper shell script into a world-writable directory, chmod +x, then direct execution.

```kusto
DeviceProcessEvents
| where Timestamp > ago(1d)
| where FileName in~ ("wget","curl","busybox","tftp","ftpget","chmod","sh","bash","dash")
| where ProcessCommandLine has_any ("/tmp/","/var/tmp/","/dev/shm/","/run/shm/","/mnt/")
| where (ProcessCommandLine has_any ("http://","https://","tftp","ftpget") and FileName in~ ("wget","curl","busybox","tftp","ftpget"))
    or (FileName =~ "chmod" and ProcessCommandLine has_any ("777","+x","755"))
    or (FileName in~ ("sh","bash","dash") and ProcessCommandLine has_any (" -c ","| sh","|sh"))
| summarize Stages = make_set(FileName, 10), CmdLines = make_set(ProcessCommandLine, 10), EventCount = count(), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, bin = bin(Timestamp, 10m)
| where array_length(Stages) >= 2
| project FirstSeen, LastSeen, DeviceId, DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, Stages, CmdLines, EventCount
```

**Tuning notes:** Legitimate CI/CD runners, container build steps, and configuration-management agents (Ansible, Chef, Puppet) routinely download+chmod into /tmp — allowlist by AccountName (build service accounts) or by InitiatingProcessFileName. Mirai specifics worth promoting: command lines referencing multiple CPU architectures (arm, mips, mpsl, x86, arc, spc) in sequence, or a parent of dropbear/sshd/telnetd indicating exploitation of an exposed service.

## 6) Linux Host Beaconing to Non-Standard High Port by Binary in World-Writable Path

**Tactic:** Impact  
**ATT&CK:** T1496  
**Severity:** Medium  
**Purpose:** Detects Mirai/Gafgyt bot and VShell ELF backdoor C2 behaviour: an executable running from /tmp, /dev/shm, /var/tmp or a deleted path making repeated outbound connections to uncommon high ports, without relying on the rotating ip:port indicator list.

```kusto
DeviceNetworkEvents
| where Timestamp > ago(1d)
| where ActionType in ("ConnectionSuccess","ConnectionAttempt","ConnectionRequest")
| where InitiatingProcessFolderPath has_any ("/tmp/","/var/tmp/","/dev/shm/","/run/shm/","/var/run/","(deleted)")
    or InitiatingProcessFolderPath matches regex @"^/(tmp|dev|run)/\.[^/]+"
| where RemotePort !in (80, 443, 22, 53, 123, 8080, 8443)
| where not(ipv4_is_private(RemoteIP))
| summarize ConnCount = count(), DistinctIPs = dcount(RemoteIP), Ports = make_set(RemotePort, 20), RemoteIPs = make_set(RemoteIP, 20), FirstSeen = min(Timestamp), LastSeen = max(Timestamp)
    by DeviceId, DeviceName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, InitiatingProcessAccountName
| where ConnCount >= 5
| project FirstSeen, LastSeen, DeviceId, DeviceName, InitiatingProcessAccountName, InitiatingProcessFileName, InitiatingProcessFolderPath, InitiatingProcessCommandLine, InitiatingProcessSHA256, ConnCount, DistinctIPs, Ports, RemoteIPs
```

**Tuning notes:** Allowlist monitoring/telemetry agents and package managers that temporarily execute from /tmp. A very high DistinctIPs value with a single destination port strongly suggests Mirai scanning/propagation (telnet 23/2323, SSH brute, or 7547) rather than C2 — consider splitting that pattern into its own higher-severity rule. Tighten ConnCount threshold per environment baseline.
