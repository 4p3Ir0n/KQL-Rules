# Detection-refresh automation

A daily "detection-as-code" pipeline that keeps this repo's KQL rules current with
what attackers are actually exploiting.

```
ingest.py  ──►  generate.py  ──►  validate.py  ──►  run.py  ──►  Pull Request
(threat intel)  (Claude drafts   (static KQL      (writes
                 behavioral KQL)  syntax+schema)   AutoGenerated/<date>_proposed.md)
```

## What it does

1. **Ingest** — pulls the last few days of threat intel from four sources, each
   normalized into a common shape (see `ingest.py`):
   | Source | Kind | Notes |
   |---|---|---|
   | [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog) | `vulnerability` | Actively-exploited CVEs. Free, no auth. |
   | [abuse.ch ThreatFox](https://threatfox.abuse.ch/) | `ioc_family` | Fresh IOCs aggregated by malware family. Needs `ABUSE_CH_AUTH_KEY`. |
   | [SigmaHQ](https://github.com/SigmaHQ/sigma) | `sigma_rule` | Recently added/changed community rules, translated toward Defender KQL. Uses `GITHUB_TOKEN`. |
   | Vendor RSS | `threat_report` | Vendor blogs / advisories (Microsoft, DFIR Report, CISA, Unit 42, SANS ISC). Configurable. |

   Sources are merged round-robin up to `max_threats_per_run` so no single feed
   dominates. Any source that fails is logged and skipped.
2. **Generate** — asks Claude to draft *behavioral* KQL for each item (translating
   Sigma rules, detecting malware-family TTPs, etc.), mapped to a MITRE ATT&CK
   tactic. Uses structured outputs for clean JSON.
3. **Validate** — static checks only (no tenant): balanced syntax, real Advanced
   Hunting source tables, known columns. Table errors block; column mismatches warn.
4. **Propose** — writes passing detections to `AutoGenerated/<date>_proposed.md`
   and the workflow opens a **PR for your review**. Hand-curated tactic files are
   never modified automatically.

## Guardrails (by design)

- **Human-in-the-loop:** proposals land as a PR, never a direct commit to `main`.
- **Behavioral over IOC:** the model is prompted to favor durable behavioral logic
  over IPs/hashes that expire in days.
- **Static validation only:** without a Defender tenant, queries are checked for
  syntax and schema, not real results. See "Adding live validation" below.

## Running locally

```bash
pip install -r automation/requirements.txt
cd automation
python ingest.py      # smoke-test the feed
python validate.py    # smoke-test the validator
python run.py         # full pipeline (needs ANTHROPIC_API_KEY for the generate step)
```

`ingest.py` and `validate.py` run with no credentials. `run.py` will ingest and
validate without a key, but the generate step is skipped unless Anthropic
credentials are present.

## Enabling it in CI

Repository secrets (**Settings → Secrets and variables → Actions**):

| Secret | Required? | Purpose |
|---|---|---|
| `ANTHROPIC_API_KEY` | **Required** | Drafting detections with Claude. |
| `ABUSE_CH_AUTH_KEY` | Optional | Enables abuse.ch ThreatFox. Get a free key at [auth.abuse.ch](https://auth.abuse.ch/). Without it, that source is skipped. |
| `GITHUB_TOKEN` | Auto-provided | Raises the SigmaHQ GitHub API rate limit. Injected by Actions; no setup needed. |

Disable any source you don't want by setting `enabled: false` in `config.yaml`.
The workflow (`.github/workflows/update-detections.yml`) runs daily at 06:00 UTC and
can also be triggered manually from the **Actions** tab.

## Adding live validation (optional, needs a tenant)

Static validation can't tell whether a query returns sensible results. To add real
validation, register an Azure AD app with the Microsoft Graph
`ThreatHunting.Read.All` permission and call the Advanced Hunting API
(`POST /security/runHuntingQuery`) from a new `validate_live.py`, gating each query
on a successful (even if empty) response. Wire it in after the static pass in
`run.py`.
